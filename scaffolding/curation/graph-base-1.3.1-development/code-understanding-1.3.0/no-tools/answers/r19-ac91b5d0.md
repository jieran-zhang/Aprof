# 代码理解说明

## 范围与证据

两个入口独立运行，不构成前后级。`source/DELTA.json:1–42` 仅记录测试标识符和 include 文件名更改，明确没有改变数值常量、API 或生产源码。

以下以 **V-host** 指 `source/vector/op_host/nacre.asc`，**V-plan/V-kernel** 指 `source/vector/op_kernel/nacre_plan.h`、`nacre_stage.asc`，**C** 指 `source/cube/mica.asc`。地址覆盖及容量数字均为静态推导；硬件解释依据所给 `910c-hardware.md` 的 A3/2201 内容，不代表编译或实测结果。

## 入口 V：逐元素指数变换

### 算法与实际分派

输入、输出都是连续一维 ND、25019 个 BF16，各占 **50038B**。host 解析 dtype、构造 tiling，分别复制输入与 tiling 到 GM，以 `laneCount` 启动，流同步后回传输出（V-host:38–63）。入口实际进入 `StageNacre<bfloat16_t>`，并非 half 分支（V-kernel:85–93）。

V-plan:27–28 将 base 融入 FP32 参数：
\[
g=0.5\log 2,\quad b=-\log 2,\qquad y=\operatorname{BF16}(\exp(gx+b)).
\]
理想实数关系是 \(2^{0.5x-1}\)。实现先将 BF16 转 FP32，依次执行独立的 `Muls→Adds→Exp`，再以 `CAST_RINT` 转回 BF16（V-kernel:55–63）；不能当作无限精度幂运算或一次融合乘加。指数近似、溢出和特殊值的逐位结果没有测试证据。一般参数下 `base<=0` 实际采用自然指数参数，不计算该 base 的对数。

### 分核、循环和尾块

由 V-plan:22–25：
- `useful=ceil(25019/4096)=7`，查询核数为 3，故启动 **3 个 block**；
- `laneExtent=ceil(25019/3)=8340`，窗口固定为4096元素。

结合 V-kernel:11–15、26–33，得到半开区间：

| block | GM 元素区间 | 输入/输出起始字节偏移 | 各轮有效元素数 |
|---|---|---:|---|
| 0 | `[0,8340)` | 0 | 4096、4096、148 |
| 1 | `[8340,16680)` | 16680 | 4096、4096、148 |
| 2 | `[16680,25019)` | 33360 | 4096、4096、147 |

共9个窗口，互不重叠且覆盖全部元素，无归约、广播或核间通信。

### 数据、存储和同步

每核分配输入/输出队列各一个8192B槽，以及两个16384B FP32计算缓冲，显式 UB 数据区共 **49152B**（V-kernel:16–23、76–82）。`VECIN/VECCALC/VECOUT` 均是 UB 逻辑角色，不是不同物理存储层。这里队列深度和物理槽数都为1，没有双缓冲证据。

每轮路径为：

`GM —MTE2/DataCopyPad→ UB BF16 —V/Cast及计算→ UB BF16 —MTE3→ GM`

拷贝 `blockCount=1`，`blockLen=count*2` **字节**，两侧 stride 为0（V-kernel:37–42、69–73）。尾轮有效长度为296/296/294B；A3普通非对齐路径在 UB 按32B补齐至320B，空间足够。`isPad=false` 不承诺补零；计算仅使用有效 `count`，写回也只写有效字节。

`Alloc/EnQue/DeQue/Free` 组织生产消费与槽复用，TPipe/TQue 和编译器同步承担搬入就绪、计算就绪及复用依赖；源码没有显式 HardEvent。FP32缓冲跨轮复用，不能仅由 C++ 调用顺序推断机器流水已经完成，也不能因没有手写 flag 就断言没有同步。深度1和逐轮调用次序均不足以证明实际搬运/计算重叠率。

## 入口 C：矩阵乘后经 GM 交接激活

### 数值语义与工作划分

A 为 half `[512,128]`，B 为 half `[128,128]`，输出为 half `[512,128]`，GM 均连续 ND。A/C 各131072B，B为32768B。常量与启动见 C:199–215、242–247。

每元素先进行完整 K=128 的矩阵乘，L0C 使用 float；Fixpipe 转成 half 写入 C，再由 Vector 读回，执行 half `LeakyRelu` 并原位覆盖：
\[
h=\operatorname{half}(\operatorname{Mmad}(A,B)),\qquad
C=\operatorname{LeakyRelu}(h,\operatorname{half}(0.001)).
\]
因此 half 舍入发生在激活**之前**，负斜率本身也先转换为 half；不是对未舍入 float 累加值直接激活后才转换。无 bias，Fixpipe 的 ReLU 开关为 false（C:113–127、165–166）。

`numBlocks=(512/256)*(128/128)=2`，入口为 `__mix__(1,2)`（C:188）。在2201混合执行契约下，对应 **2个 AIC 与4个 AIV任务**，不表示设备总核数。

- AIC 0/1 分别处理 C 的行 `[0,256)`、`[256,512)`；A/C基址偏移为0、32768个half，即0、65536B；各读完整B（C:33–44）。
- AIV编号v以 `v/2` 选择对应AIC输出，再以 `v%2` 选择其中128行（C:150）。四个任务最终分别处理行 `[0,128)`、`[128,256)`、`[256,384)`、`[384,512)`；全局起点为0、16384、32768、49152个half。
- 每AIC仅一个 `256×128` 输出tile、一次完整K的 Mmad；没有 M/N tile遍历、K分段累加或尾块。LoadData循环仅用于布局搬运。

### 2201数据路径、占用与依赖

C:52–68、113–138 的数据流是：

`GM ND → L1 NZ → L0A ZZ / L0B ZN → L0C float NZ → GM half ND → AIV UB → GM`

依次由 MTE2、MTE1、M、FIX、MTE2/V/MTE3承担。AIC/AIV具有独立片上存储，本实现通过**同一输出GM区域**交接，不是L0C直接进入AIV UB。

每AIC显式分配：
- L1：A 65536B、B 32768B，合计98304B；
- L0A：65536B；L0B：32768B；
- L0C：131072B，即128KiB。
每AIV的 UB 为 `128*128` 个half，即32768B。以上按存储分别计，非总UB占用，也不含隐含资源；L0C数据区已达资料所列128KiB标称容量，不等于证明资源检查通过。

ND→NZ参数使用原矩阵行跨度 K/N，均128元素。half分形为16×16、512B（C:65–68；资料H09）。2201分支（C:75–91）具体为：
- A：16次LoadData，每次8个分形，源分形步长16；源起点 `i*256` half，目标起点 `i*2048` half，NZ→ZZ。
- B：8次，每次8个分形，源步长8，源/目标起点同上述公式，`ifTranspose=true` 得到ZN。此为局部分形布局转换，不是数学上的 \(B^\mathsf T\)。

显式依赖链（C:70–129）：
`MTE2_MTE1` 保证L1就绪；`MTE1_M` 保证L0A/B就绪；`M_FIX` 保证L0C结果就绪。随后 `CrossCoreSetFlag<0x2,PIPE_FIX>(0)` 与AIV侧Wait配对，使对应两个AIV在FIX完成写回后才读GM。核内事件不能替代这一跨核依赖。

AIV一次搬128行，每行256B，GM行间隔与UB间隔均为0；`tileLen=16384`。输入padding左右均0，本例行长已32B对齐。`MTE2_V`、`V_MTE3` 分别保护激活读入和结果写出（C:143–176）。末尾 `PipeBarrier<PIPE_ALL>` 是核内收尾，host流同步后才D2H（C:194、244）。
