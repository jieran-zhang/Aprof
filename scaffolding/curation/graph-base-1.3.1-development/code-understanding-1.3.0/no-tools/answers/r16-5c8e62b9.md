# Maximum 代码理解说明

以下将源码事实、API/平台知识与静态推断分开说明；没有编译、运行或性能测量结果。

## 1. 输入输出、算法与 host 流程

**源码事实：**`source/op_host/maximum.asc:26–33,42–60` 接受同一 dtype 的两个连续 ND 张量，支持 float16、float32、bfloat16、int8、int32、int64。host 按输入元素数精确分配、读文件并 H2D；根据 tiling 分配输出，再启动 kernel、同步 stream、D2H 并写文件。题设明确没有额外分配余量。

`source/op_kernel/maximum_tiling.h::ComputeMaximumTiling:29–55` 表达的是右对齐广播：
- rank 为两输入 rank 的最大值，范围为 1～8；不足的前导维补 1。
- 对应维相等或一方为 1 才兼容，输出维取最大值。
- 输入维为 1 时记录零 stride，其余记录连续布局 stride；stride、地址索引均以**元素**为单位。
- `sameShape` 比较原始 shape 是否完全相等，不是比较广播后的形状。

数学目标为逐元素广播 maximum。对本题有限整数值，理想输出为：
- P、Q：`[[3,4,8],[7,7,9]]`
- R：`[[3,7,8],[3,7,9]]`

但实际 kernel 并非所有分支都实现通用广播，尤其 P 不能据此认定正确。

**数值语义：**标量路径使用 `av > bv ? av : bv`，相等或浮点无序比较时选第二个操作数（`maximum_kernel.asc:142–149`）。向量路径使用 `AscendC::Max`。材料不足以证明两者在 NaN、正负零上的行为完全一致；本题数值不涉及这些情况。

## 2. 三次调用的 tiling 与实际任务

三次都得到：

| 字段 | P、Q、R |
|---|---|
| `rank / outShape / totalLength` | `2 / [2,3] / 6` |
| `x1Stride` | `[3,1]` |
| `sameShape` | `0` |
| `tileElements` | `4096` |
| `useful` | `max(1,ceil(6/4096))=1` |
| `blockNum / blockLength` | `min(4,1)=1 / 6` |

P、Q 的 `x2Stride=[1,0]`；R 将 `[3]` 补成 `[1,3]`，得到 `[0,1]`。依据为 tiling 文件 35–54 行。**固定查询到 4 个 Vector 核不等于启动 4 个任务**：host 第 58 行实际只启动一个 block，block 0 处理输出元素区间 `[0,6)`。

分配字节数：

| 调用 | x1 | x2 | y |
|---|---:|---:|---:|
| P | 12 B | 4 B | 12 B |
| Q | 24 B | 8 B | 24 B |
| R | 12 B | 6 B | 12 B |

### P：float16，[2,3] 与 [2,1]

入口选择 `DispatchMaximum<half>`；因 `sameShape=0`，无条件进入 `KernelMaximumHalfLastAxisBroadcast`，**不检查输入是否确为末轴向量广播**（kernel 153–182 行）。

该类设置 `begin=0,end=6,row=3`，把 x1、y 声明为 6 个 half，把 x2 的 GlobalTensor 长度声明为 `row=3`（84–97 行）。声明长度不会扩充实际仅 2 个 half 的 x2 分配。

循环受 block 剩余量、4096 和当前行剩余量共同限制，实际两轮（99–114 行）：

| `off` | `count` | x1/y 元素起点、字节偏移 | x2 元素起点 |
|---:|---:|---|---:|
| 0 | 3 | 0，0 B | `0%3=0` |
| 3 | 3 | 3，6 B | `3%3=0` |

每轮两个输入各搬 `3×2=6 B`，做 3 个 half 的向量 Max，再写回 6 B。x2 每轮均请求元素 `[0,1,2]`，而实际只有 `[3,7]`：
- 元素 2 对应字节 `[4,6)`，超出 4 B 分配；
- 它不是每行复制一个标量，而是两行都拿 `[3,7,越界值]` 比较。

**可支持的结论：**P 存在确定的越界读，完整输出及是否成功执行不可保证。若越界没有中断执行且其他有效通道正常，已知比较将给出第一行前两项 `[3,7]`、第二行前两项 `[3,7]`，已不符合目标广播。这不能作为整个非法访问调用的保证输出。问题来自明确请求过多有效字节，不是仅因 DMA 对齐而猜测的越界。

### Q：float32，相同 shape 组合

入口选择 float；`sameShape=0` 后进入 `MaximumScalar<float>`（164–168 行），不会执行 half 专用类。

`MaximumScalar:131–150` 对 `linear=0…5` 逐个反解坐标，按 stride 得到：
- `ai=[0,1,2,3,4,5]`
- `bi=[0,0,0,1,1,1]`

因此 x1/y 字节偏移为 `0,4,8,12,16,20`，x2 字节偏移为 `0,0,0,4,4,4`。所有访问均在分配范围内。每个元素直接读 GM、比较、写 GM；本分支没有 UB 队列和向量 Max。

**静态结果：**按标量比较语义，Q 输出 `[[3,4,8],[7,7,9]]`。

### R：float16，[2,3] 与 [3]

分派及两轮循环与 P 完全相同；kernel 没有读取 R 的广播 stride。区别是 x2 实际恰有 3 个 half，即 6 B，重复读取 `[3,7,6]` 合法，也恰好符合按行重复末轴向量的数学广播。

两轮分别比较 `[1,4,8]`、`[2,5,9]` 与 `[3,7,6]`，**静态结果为** `[[3,7,8],[3,7,9]]`。每轮的 6 B 搬运和 3 元素计算都是短段，且不会跨行；不是执行 4096 个有效元素。

## 3. 其他分支、数据与依赖

`KernelMaximumSame<T>`（kernel 6–77 行）按
`offset=blockIdx*blockLength` 分配连续区间，长度截断到输出末尾；每核再以 4096 元素分 tile，尾块取实际剩余量。两个输入和输出均从相同 offset 访问。

- float16、float32、int32 同 shape：直接向量 `Max`。
- bfloat16 同 shape：两个输入转 float，float Max，结果以 `CAST_RINT` 转回。
- int8 同 shape：分别经 half 转 float，Max 后经 half 转回 int8；int8 数值在中间格式中可精确表示。
- int64 无论 shape 是否相同都走标量。
- 非 half 的不同 shape 都走通用标量广播；bfloat16 标量先转 float 比较，再选择原输入值。
- half 的所有不同 shape 都走上述特化。因此 host 接受的通用广播范围大于 half kernel 实际覆盖范围；若 x1 也需扩展，或 x2 不能按末轴向量重复，该类忽略 stride 的寻址不保证正确，可能越界。

向量类使用两个深度为 1 的 `VECIN` 队列和一个深度为 1 的 `VECOUT` 队列。P/R 各队列分配 `4096×2=8192 B`，合计 24 KiB UB，虽每轮仅使用 3 个有效元素。`DataCopyExtParams.blockLen` 使用**字节**，`Max` 的 count 使用**元素**。同 shape 的 bfloat16/int8 分支另有 float/half 临时 UB。

源码顺序是搬入→入队/出队→计算→输出入队/出队→搬出→释放；不存在显式双缓冲或跨核同步。各 block 输出区间独立；广播输入可以重复读。

## 4. 910C 行为及证据边界

**平台/API知识：**目标 device 为 `__NPU_ARCH__=2201`。这些向量类体现 GM→UB 搬运、Vector 计算、UB→GM 写回，通常分别由 MTE2、Vector、MTE3 执行；队列 API 提供相应生产者/消费者依赖管理。`DataCopyPad` 用于支持这里不足普通搬运对齐长度的有效字节传输，不能据短传输本身断言越界。Q 则是标量控制、整数坐标运算及 GM 标量访问，不会因为启动在 AI Core 上就自动变成源码中的向量 Max 路径。

kernel 79–81 行注释明确说明 half 广播采用向量比较是为了规避 dav-2201 的 half 标量算术限制；但这只解释实现意图，不证明其覆盖所有广播。源码没有 host `NPU_ARCH` 分支，不能将其与 device 宏混用，也无需引入 3510 对照。

三次调用都只有一个 block；队列深度和顺序代码不足以证明实际搬运/计算重叠程度。没有测量，不能断言带宽、延迟或瓶颈。host 也未显式检查维度乘积溢出、零维等所有边界；上述具体结论限于题给合法正维 shape、既定 API 语义及实际执行所选分支。
