本题有两个独立入口，DELTA.json仅记录标识符更名，未改变数值或API。以下依据源码与固定rawdocs作静态解释；实际目标为910C、__NPU_ARCH__=2201，3510仅作契约对照。

入口V处理连续一维张量，输入输出均为25019个BF16，共50038字节。source/vector/op_host/nacre.asc读取二进制输入，将输入及NacrePlan传入GM，启动nacre_entry，等待stream完成后回传并写出结果。MakeNacrePlan（op_kernel/nacre_plan.h:18）将底数折入gain、bias，计算exp(gain×x+bias)。本题gain=0.5ln2≈0.346573591，bias=−ln2≈−0.693147182，故理想数学结果是2^(0.5x−1)。实际执行包含FP32逐步计算、Exp近似和BF16舍入，不能等同于无限精度公式；一般base≤0时源码按自然指数处理。

分核规则为useful=max(1,ceil(n/4096))=7，laneCount=min(3,7)=3，laneExtent=ceil(25019/3)=8340。StageNacre::Init以GetBlockIdx()×8340为元素偏移，三块分别覆盖半开区间[0,8340)、[8340,16680)、[16680,25019)，长度8340、8340、8339；对应GM字节区间[0,16680)、[16680,33360)、[33360,50038)。每块依次处理4096、4096及148/148/147个元素，总计9个窗口，各核范围互不重叠。

StageNacre::Process、CopyIn、Compute、CopyOut（nacre_stage.asc:26—74）按窗口执行GM→UB→向量计算→GM。输入、输出队列各深度1，各分配4096×2=8192字节；另有两个4096×4=16384字节的FP32临时区，显式UB合计49152字节，即48KiB。BF16先以CAST_NONE扩展成FP32，再分别Muls、Adds、Exp，最后CAST_RINT转回BF16；RINT为最近偶数舍入。源码另支持FP16和FP32，FP32路径不需要上述临时区。

两次DataCopyPad均令blockCount=1、blockLen=count×sizeof(T)，此处blockLen单位为字节。完整窗口搬8192字节，尾窗口搬296、296、294字节。按rawdocs的DataCopyPad_GMToUB契约，尾部在UB内补齐至320字节；isPad=false不保证补零，但计算只覆盖count个有效元素，写回也只写有效字节，因此不把填充写入相邻分块。GM地址可非32字节对齐。输入EnQue/DeQue衔接MTE2与V，输出队列衔接V与MTE3，FreeTensor管理槽位复用；没有跨核数据依赖。代码采用单槽逐窗口流程，没有双缓冲预取安排；不能据此量化实际流水重叠或性能。

入口C的main（source/cube/mica.asc:197）固定A为[512,128]、B为[128,128]，均为连续ND的half；输出为[512,128]的half。A、B、C分别占131072、32768、131072字节。整体先算S=A×B，再对已转为half的S执行LeakyRelu：非负值保持，负值乘half(0.001)，该系数实际约0.00100040436。由于先将矩阵乘结果舍入为half，再执行half激活，不能解释为先在FP32完成激活、最后才转half。

numBlocks=(512/256)×(128/128)=2；mica_entry以__mix__(1,2)启动，即2个AIC工作块和4个AIV工作块。按rawdocs的simd_builtin_keywords.md，GetBlockIdx返回类型内的逻辑核号：AIC为0、1，AIV为0至3。StageMica::Init中AIC的A、C偏移分别为b×256×128个half，即b×65536字节；B不偏移，两核各读取整个B。AIV先用j/2定位对应AIC输出，再用j%2选择半块，最终处理C的行[128j,128(j+1))，字节起点依次为0、32768、65536、98304，各覆盖32768字节。

这里singleCoreM=baseM=256、singleCoreK=baseK=128、singleCoreN=baseN=128，每个AIC只执行一个完整tile。Process没有M/N/K分块循环，singleCoreK未参与循环控制；一次Mmad完成全部128维归约。全矩阵含512×128×128=8388608次乘加，按乘加计两次运算为16777216次运算。这些是数学工作量，不是硬件指令条数。

AIC侧LocalMemAllocator分别管理L1、L0A、L0B、L0C（mica.asc:50—61）。每核L1中的A、B为64KiB、32KiB，合计96KiB；L0A为64KiB，L0B为32KiB，FP32的L0C为128KiB。每个AIV另分配128×128个half，即32KiB UB。两入口采用不同内存管理方式，C没有使用TPipe/TQue。

GM→L1的两次DataCopy使用Nd2NzParams（65—68行），将A的256×128、B的128×128由ND转为NZ。srcDValue=128是源行距，单位元素；dstNzNStride=1表示相邻行隔32字节；dstNzC0Stride分别256、128，表示相邻16列条带隔8192、4096字节。尺寸均已对齐，无须补列。以16×16 half、512字节为一个分形，令m16、k16、n16为分块坐标，则A在L1的分形编号为16k16+m16，B为8n16+k16。

2201路径（75—91行）中，A执行16次LoadData，每次repeatTimes=8、srcStride=16：源从第i个分形开始，每次跳8192字节，目的从i×4096字节开始连续放8个分形。因此A的分形顺序变为8m16+k16，形成L0A所需Zz。B执行8次LoadData，每次8个分形、源步距8×512=4096字节，目的从i×4096字节开始连续放置，并转置每个16×16分形，得到L0B的Zn。这里转置服务于物理布局，数学输入仍是[K,N]的B。

Mmad（115行）参数为m=256、n=128、k=128，输入half、累加输出float；cmatrixInitVal=true将C初值清零，不读取原输出作为累加项。结果在L0C为Nz。Fixpipe（125行）用V220参数将其转为ND并以F322F16转为half，按文档采用RINT；reluEn=false，unitFlag=0。srcStride=256的单位是16×sizeof(float)=64字节，实际条带间隔16384字节；dstStride=128的单位是half元素，即输出行距256字节。

同步形成明确的生产消费链：MTE2_MTE1等待GM→L1完成，MTE1_M等待L1→L0完成，M_FIX等待矩阵计算完成。随后CrossCoreSetFlag<2,PIPE_FIX>(0)在FIX前序任务完成后通知本组两个AIV；模式2不是所有AIC之间的全局屏障。AIV等待后，ApplyGate（143—176行）以128个数据块、每块256字节、零间隔把半块C搬入UB；MTE2_V后执行16384元素的原地LeakyRelu，V_MTE3后写回原区域。入口末尾PipeBarrier<PIPE_ALL>()等待本核流水，host的stream同步覆盖整个任务。C通过GM中间结果完成协作，并非直接L0C→UB；逻辑GM流量为192KiB输入读取，加三次128KiB结果写入/读取/写回，共576KiB，不等于实际HBM流量。

3510静态分支只替换L1→L0代码（92—106行）：A以LoadData2DParamsV2{0,0,16,8,16,16,false,0}一次描述128个分形，保持Nz；B以{0,0,8,8,8,8,true,0}描述64个分形并转为Zn。V2的mStep单位为16元素，kStep单位为32字节，srcStride/dstStride单位为512字节。rawdocs的Mmad.md确认2201要求A为Zz，3510要求A为Nz；B的Zn、C的Nz以及本题half×half→float组合相同。LoadData_2D_V2.md明确V2支持3510、而不支持A3，故不能把该分支用于910C。

两分支其余分核、分配、GM中转、Mmad及激活源码相同，但同名调用不保证相同硬件语义。CrossCoreWaitFlag_ISASI.md规定：A3上modeId、pipe不作为硬件输入，等待阻塞全部流水；3510上pipe生效，本调用省略pipe而采用PIPE_S，不能直接称为全流水等待。GM→L1的3510原型新增默认false的enableSmallC0，而参数文字又要求配置；源码未显式传入。Fixpipe仍无条件使用V220，文档的3510示例则使用FixpipeParamsArch3510；材料未提供本调用跨架构兼容的编译证据。因此只能确认布局分支的意图及契约差异，不能宣称整个3510入口已适配或已运行。

当前C实现依赖完整tile和上述固定形状，没有通用尾块、N方向分核或多轮K累加路径。材料足以推导地址、工作量和同步关系，但没有构建产物、设备数值或性能观测，不能确认完整编译兼容性、误差界或实际吞吐；910C标签也不能替代可见资源查询，V题给出的3个Vector核仅用于本次分核推导。
