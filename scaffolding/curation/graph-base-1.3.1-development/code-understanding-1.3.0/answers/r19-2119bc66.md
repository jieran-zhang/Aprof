本题计算C[m,n]=ΣₖA[m,k]·Bfile[n,k]，M=N=K=8192。A按[M,K]、B文件按[N,K]连续存储，后者是逻辑B[K,N]的转置存储；代码IS_B_TRANSPOSE=true与之匹配。输入和输出均为half，Cube中以float累加，最后转回half，无偏置或激活。每个GM矩阵占8192²×2=134217728字节，即128MiB。host使用sizeof(int16_t)计算文件字节数，并不表示整数乘法。

以下源码位置均指source/baseline/mmad.asc，variant除209行外相同。main（575行起）读取x1_gm.bin、x2_gm.bin并复制到设备，启动kernel后同步stream，将结果写入output.bin；data_utils.h只负责二进制读写。参数直接作为模板常量传入，没有独立的动态tiling结构。题设两个架构宏均为2201，SCENARIO_NUM=1，因此执行Process；ProcessL2Cache和3510分支不生效。

分核由InitComputeParams（273行起）确定：block号b对应p=b%4、q=b/4，覆盖行起点2048p、列起点1536q，完整归约全部8192个K。启动24个block，构成4×6个输出区域；q=0…4宽1536，q=5从7680列开始、宽512。每核M方向16个128行tile，N方向分别6或2个256列tile，循环顺序为N→M→K。每个输出tile为128×256，K按64分成128轮；共20×96+4×32=2048个输出tile、262144次Mmad。所有尺寸整除，当前输入没有实际尾tile或K补齐。24是启动block数，不能据此断言物理核数。

令输出tile左上角为(m₀,n₀)=(2048p+128u,1536q+256v)。第j轮读取A的[m₀:m₀+128,64j:64j+64]和Bfile的[n₀:n₀+256,64j:64j+64]。GM中A、B包首地址分别为m₀×8192+64t、n₀×8192+64t，t是包起始K轮号；这些偏移以half元素计，换字节乘2。C写回首偏移m₀×8192+n₀，各行跨度8192个half，即16384字节。

DataCopyInA/B（340行起）经MTE2执行GM→L1的ND2NZ转换：A每包128×(64×8)，Bfile每包256×(64×4)，各65536个half、128KiB。srcDValue=8192是GM行跨度；dstNzC0Stride分别128、256，单位是32字节，因而相邻K方向16列带的起点分别相差4096、8192字节。dstNzNStride=1表示相邻行片段相距32字节。每个输出tile重新装包，不跨输出tile保留A/B的复用。

Process（43行起）用静态LocalTensor描述固定地址，构造地址以字节计、长度以元素计，并非队列分配。A1/B1共同位于L1：A Ping/Pong分别占[0,128)、[128,256)KiB，B分别占[256,384)、[384,512)KiB。A2属于独立L0A，两个槽起点0、32KiB，各有效16KiB；B2属于独立L0B，起点同为0、32KiB，各32KiB。相同数值地址不表示A2/B2别名。CO1是L0C，起点0，128×256个float占128KiB，仅一份累加区。

选block0的首个输出tile，即C[0:128,0:256]。以下为前10轮读取切片的物理起点，统一以KiB计；L0列分别适用于L0A和L0B，L0C始终为0。P/Q表示Ping/Pong。

其推导为：A槽=floor(j/8)%2，槽内偏移(j%8)×128×64×2字节；B槽=floor(j/4)%2，偏移(j%4)×256×64×2字节；L0槽=j%2。DataLoadA（395行起）在2201使用LoadData3DParamsV2，l1H=1、l1W=128、channelSize=kExtension=64、mExtension=128，将A的NZ切片组织成L0A的ZZ布局。DataLoadB使用2D搬运、不转置：每轮执行4次LoadData，每次repeatTimes=16，每次搬16×512=8192字节，源和目的起点均递增4096个half，合计32KiB，形成逻辑[K,N]的L0B ZN布局。B的转置存储已由索引和布局解释，不能再把它理解为额外改变数学乘法。

ProcessLoop（138行起）的预取顺序是：循环前装入A Ping的K[0,512)、B Ping的K[0,256)；j=0计算指令之后，依次发起B Pong的K[256,512)、A Pong的K[512,1024)；j=3释放并重装B Ping为K[512,768)；j=7依次重装B Pong为K[768,1024)、A Ping为K[1024,1536)。因此j=8读取的B Ping已是新包，而A Pong仍是j=0时预取的包。这里描述指令与依赖顺序，不代表已经观测到搬运和计算的时间重叠。

事件按方向和ID共同区分。MTE1_MTE2的ID0/1保护A两槽、ID2/3保护B两槽：首次预置可写状态，每次GM搬入前Wait；一个包最后一次L1→L0读取完成后Set，允许MTE2覆盖。反方向MTE2_MTE1在装包后Set，仅在该包首次消费时Wait。因此前10轮的就绪等待为j=0的A0/B2、j=4的B3、j=8的A1/B2；释放发生在j=3的B2、j=7的A0/B3。

baseline每轮在装L0前等待M_MTE1的当前槽ID0/1；首次状态预置，随后由Compute末尾在Mmad完成后Set。于是同槽建立“第j轮Cube读完→第j+2轮MTE1覆盖”的关系。Compute（501行起）另有MTE1_M的Set/Wait，保证本轮A/B都装入L0后才计算。j=0清零L0C，后127轮累加。前127轮unitFlag=2保留L0C可累加状态，末轮=3置为可读；CopyOut的Fixpipe以unitFlag=3读取后恢复可写，保护下一输出tile对同一L0C的复用。Fixpipe默认CFG_ROW_MAJOR，执行NZ→ND和F322F16，转换模式为CAST_RINT；srcStride=128的单位是16×sizeof(float)=64字节，dstStride=8192的单位是half元素。循环末尾排空反向事件，kernel末尾还有PIPE_ALL屏障。

variant仅删除209行的M_MTE1等待。它仍保留L1就绪/复用保护、本轮MTE1→M就绪同步和L0C单元标志，却失去L0同槽读后写依赖：j=2可能覆盖j=0仍在使用的输入。更早的契约问题发生在j=0：初始化已Set(M_MTE1,0)，没有Wait消耗，Compute又Set同方向同ID；j=1对ID1也如此。固定SetFlag_WaitFlag_ISASI.md明确事件必须配对，未经消耗重复Set属于未定义行为，并列有随后PIPE_ALL卡死的情形。事件是标志位而非累计计数，末尾两个Wait不能补回中途等待。因此不能把variant描述成只减少等待且执行仍有保证，也不能由静态材料断言某次运行必定产生特定错误值或必定超时。
