该程序实现连续一维张量的逐元素指数变换，输出长度、顺序和存储类型与输入相同。依据 source/op_kernel/exp_tiling.h 的 ComputeExpTiling，令 L=log(base)（base>0），否则 L=1，host 预先计算 multiplier=scale×L、shift'=shift×L；kernel 计算 y[i]=exp(x[i]×multiplier+shift')。因此正底数时数学目标是 base^(scale×x[i]+shift)，非正底数走自然指数路径。本题为 y[i]=2^(0.5x[i]−1)，代表输入 −2、0、2 的数学结果分别为 0.25、0.5、1。

source/op_host/exp.asc 的 main 将 bfloat16 映射为 dtype=2，每元素占2字节，故输入、输出各为25019×2=50038字节。它初始化设备，查询向量核数（题面固定为3），计算 tiling，创建 stream，分配 host、device 输入输出及 device tiling。data_utils.h 的 ReadFile 按二进制读取指定字节数，不进行文本解析或类型转换；文件不足会失败，也没有要求文件恰好在该处结束。输入和 tiling 拷入设备后，main 以 tiling.blockNum 启动 exp_kernel；等待 stream 完成，再将50038字节结果拷回并由 WriteFile 写入文件，最后释放资源。输出文件没有形状或类型头信息，需按调用时的 dtype 解释。

ComputeExpTiling 先算 useful=max(1,ceil(25019/4096))=7，再得到 blockNum=max(1,min(3,7))=3、blockLength=ceil(25019/3)=8340，tileElements 固定为4096。它不按 UB 容量动态选 tile，也不将分核长度调整到32字节对齐。multiplier 约为0.3465735912，传入 kernel 的 shift'约为−0.6931471825，二者均以 float 保存；命令行的−1已在 host 乘上 log(2)。

source/op_kernel/exp_kernel.asc 的 KernelExp<T>::Init 用 GetBlockIdx()×blockLength 得到元素偏移，再将本核长度截为 min(blockLength,totalLength−offset)。下表区间均为左闭右开，字节地址相对各自输入或输出 GM 基址：

|逻辑核|元素区间|字节区间|各 tile 的有效元素数|
|---|---|---|---|
|0|[0,8340)|[0,16680)|4096、4096、148|
|1|[8340,16680)|[16680,33360)|4096、4096、148|
|2|[16680,25019)|[33360,50038)|4096、4096、147|

Process 中 off 按元素递增4096，每轮执行 CopyIn、Compute、CopyOut。GM 字节起点为2×(核号×8340+off)，三核分别是0/8192/16384、16680/24872/33064、33360/41552/49744。总计9个 tile，其中6个完整 tile、3个尾 tile；有效计数为6×4096+148+148+147=25019，无遗漏或重复，最后一次写回结束于字节50038。

CopyIn 为输入队列分配 LocalTensor，构造 DataCopyExtParams{1,count×sizeof(T),0,0,0}，随后调用 GM→UB 的 DataCopyPad 并入队。这里1是连续搬运块数，blockLen 的单位是字节；入方向 srcStride 单位为字节、dstStride 单位为32字节块，二者均为0且只有一块。完整 tile 的 blockLen=8192，尾 tile 为296、296、294字节。

shared/rawdocs 中 DataCopyPad_GMToUB.md 的 A3 契约允许 GM 源地址1字节对齐，要求 UB 目的地址32字节对齐。因此核1、核2起点相对对齐基址分别余8、16字节，不构成该接口的违规。pad={false,0,0,0}没有指定补零；本代码也未调用 SetPadValue。尾块在 UB 中补齐到320字节，分别增加24、24、26字节 dummy，文档规定左右 padding 都为0时 dummy 默认取该搬运块首元素值。Compute 只处理 count 个有效元素，所以这些 dummy 不参与有效结果计算。

Compute 先将输入出队并分配输出。此次 T=bfloat16_t，输入通过 Cast(...,CAST_NONE,count) 转入 fpIn_ 的 float 张量 fi，再依次执行 Muls(fo,fi,multiplier,count)、Adds(fo,fo,shift',count)、Exp(fo,fo,count)，最后以 CAST_RINT 转回 bfloat16 输出。按 Cast.md，bfloat16→float 为无精度损失的扩展；CAST_RINT 为最近偶数舍入，而不是简单截断。计算路径是独立的 float 乘、加和自然指数调用，不能当作无限精度幂运算或一次融合乘加。上述三个示例的理想结果都可由 bfloat16 表示，但设备 Exp 的近似、浮点舍入及特殊值行为不能由数学式保证逐位结果。

源码还支持 float16 和 float32。float16 与 bfloat16 一样先扩展为 float 完成三步计算，最后转 half 时使用 CAST_NONE；Cast.md 说明发生精度损失时该模式表示 CAST_RINT，因此此处也不能解释成“完全不舍入”。float32 分支直接在输入、输出队列张量上计算，省去两次 Cast 和两个 float 临时区。相同 numel 下，float32 输入输出各100076字节，元素切分仍相同，GM 字节偏移及搬运长度变为16位类型的两倍。入口按 dtype 选择模板；host 会拒绝其他类型字符串，kernel 的最终 else 则直接落到 bfloat16，并不再次验证编号。

资源方面，Init 为 inQ_、outQ_ 各分配1块完整 tile 大小的缓冲区，TQue 模板深度也均为1。bfloat16/half 每块8192字节，两个 VECCALC TBuf 各4096×4=16384字节，合计每核显式申请49152字节，即48KiB；尾 tile 仍复用这些完整缓冲区。float32 两个队列各16384字节、不分配临时区，合计32KiB。这是张量缓冲区申请量，不等于全部运行时资源占用。VECIN、VECOUT、VECCALC 在此均对应 UB 中的逻辑用途，并非三种独立物理内存。

按 workload/sdk-contract.md，本题目标是910C/Atlas A3、__NPU_ARCH__=2201；当前算法使用 AIV 的 Membase SIMD 路径，没有 Cube 矩阵运算，也没有3510的 RegBase/SIMT 路径。GM→UB 由 MTE2 承担，float 运算由 Vector 承担，UB→GM 由 MTE3 承担。CopyOut 将输出出队，以同样的有效 blockLen 调用 DataCopyPad 后释放张量；DataCopyPad_UBToGM.md 规定搬出时丢弃对齐 dummy，故尾块不会将320字节全写入 GM。三核主数据逻辑上各读写一次，总读、总写各50038字节；这不等于实际总线事务量。

队列生命周期是输入 Alloc→搬入→EnQue→DeQue→计算消费→Free，输出 Alloc→计算生产→EnQue→DeQue→搬出→Free。依据核内同步概述，TPipe/TQue 框架提供自动同步，表达 MTE2完成后 Vector 才能消费、Vector完成后 MTE3 才能搬出，以及缓冲区安全复用的依赖；FreeTensor 也不能被理解为此刻所有硬件均已停下。源码未手写 flag 或 barrier，连续 Vector 操作的实际依赖处理还涉及编译器自动同步。两个队列的 InitBuffer num 都是1，按其文档未开启 double buffer；每个方向没有两块缓冲交替处理相邻 tile，但输入输出缓冲独立，且硬件流水异步，不能由函数调用顺序断言三条流水全程串行或必然充分重叠。

各核只写自己的区间，无需归约或跨核同步；host 的 stream 同步保证结果完成后再回传。题面给出的3是本次核数查询值，不能外推为910C整卡总核数或多 die 使用情况。实现适用于已声明的连续一维数据，不处理任意 stride、广播或布局转换；非正 base 被按自然指数处理，并未报域错误。源码也未完整防护极大长度的整数溢出、非有限参数或零长度分配。当前材料支持上述静态数据路径和 API 契约判断，但没有构建、设备执行、可用 UB 实测、生成指令或性能证据，因而不能据此确认逐位数值、确切流水重叠程度或运行耗时。
