## 这次修复如何影响选择

[原因台账](CAUSES.md)逐项区分选择前已有事实、修复新增事实、事后统计与计时；[证据清单](EVIDENCE.json)保留15项历史材料身份和必要源码上下文。R14/R15历史报告、结果、交接及未准入状态不改写。

- **数据相关执行路径**：代码理解追踪值域／特殊值、条件、触发粒度、输出覆盖和实际工作。整 plane 回退不能按单点命中率摊薄；原始生成范围不缩小合法输入契约。R14 的66/66 plane和约1897万次源码整数FMA求值只能说明该输入上的执行工作，不能换算成设备耗时或因果收益。
- **完整方案的收支**：比较保留、减少和新增工作，包含初始化、扫描、pack、转换、恢复、慢路径及同步。API调用数、descriptor block、逻辑字节和未观测的物理流量分开。新增准备成本须与可节省阶段、真实复用和低新增成本替代竞争；没有时间依据就保留符号和数量级，不编造加速比。
- **事实进入决定**：影响选择的事实落到继续试验、修改范围、暂缓或补证据的理由及判别预测。性能未知仍可有依据地试验；已被否定的假设不能继续包装为unknown。没有总分、固定候选数或强制换Action。
- **修复后的返回**：正确性修复新增整域回退、扫描、软件算术、阶段或明显改变覆盖时，即使未越过C2自由度，也重新比较受影响成本并形成不可变后继决策；超出计划边界再返回C2。可以保留原意图、同轮修复，不要求测量中间版本。

核心规则集中在[Action选择规则](../../../../skill-libs/graph-base/1.3.1/workflows/references/action-selection.md)，代码理解、完整方案、C1/C2/C3及角色入口引用该规则。[纸面分析示例](CASES.md)展示如何使用已有工作量、覆盖、代价和历史字段，不是新增工作表。

## Action与P/O知识

新增两项通用意图，不新增一级分类，也不创建算子／case专用Action：

| 变更 | 内容和边界 |
|---|---|
| `reuse_derived_results` | 复用坐标、系数、索引等派生结果；核对依赖轴、生产消费、保存层级、重计算替代和完整生命周期，与原输入复用分开。 |
| `simplify_buffer_event_management` | 简化动态管理工作，保留所有必要完成依赖；不能以删queue、少调用证明收益。 |
| P：Vector生产消费链 | 新增融合规划叶，比较重计算、片上保存、GM表及融合；明确所有权、数据通路、布局准备和共同资源。补强坐标邻域与融合链正文。 |
| O：派生结果复用、静态租约 | 新增两个配方，覆盖失效窗口、消费者最后读、地址／元素单位、事件发布消费和0/1 tile排空。 |
| 既有cache／归约／数值知识 | 使用原`align_cache_policy`、`restructure_reduction`；说明输入／输出方向、后继消费者、固定SDK的默认RW限制、局部加权和、最终Cast、严格误差边界及保护成本。 |

来源仍限五仓库固定修订，新增9项来源归档（含所需许可），正文自足。[来源与覆盖](SOURCE-COVERAGE.json)、[构建身份及历史正文归档](BUILD.json)和[独立技术复核](review/independent-technical-review.md)可核对边界。当前D含55个Symptom、28个Problem、30个Action、89条关系，共202记录；P共45记录、O共53记录。关系数沿用本轮实际D6基线，没有为补齐路径增边。

独立复核在注册前发现并解除两个实质问题：新Action依赖尚未形成的计划自由度造成C1就绪循环；全槽初始化却仅排空用过的槽会遗留token。最终正文分别由C2共同计划承担许可检查、按“已发布且未消费”闭合事件，不以删除门禁放宽实施安全。

## 24次无工具A/B：事实判断持平，方法覆盖改善

[完整行为报告](evaluation/EVALUATION.md)包含六组两次独立A/B、逐题选择及P/O正文、原始请求／答案、协议修订、审计、成本和评分锁。使用相同模型、题目、源码、资料选择策略和20k输出预算，24次均完成、零工具调用、零正式重试和截断。

冻结的事实评分 **A 96/96、B 96/96**，本轮没有证明事实准确率提升。A已经能够据源码正确识别整域回退、pack成本、广播修复及无效历史；评分不因缺新Action扣分，也不因B采用新名字加分。

可观察的覆盖变化：B两次用注册的派生复用意图及配方形成具体生产／消费／生命周期方案；Maximum类中，两次将静态buffer/event作为有额外事件成本的备选，主方案仍分别选择cache或搬运合批；跨轮题中派生索引复用替代了A的相关缺口或控制／写回方案。未强迫采用新方法，也不要求前后改变Action。

B每题输入平均增加7,964 tokens（约3.42%）。这次把127／131篇资料预展开至约23～25万输入tokens，评测的是显式材料的使用，**不验证按需检索或低成本日常上下文中的效果**。最初12k输出预算的失败preflight完整披露并排除；统一20k后两版全量重跑，没有择优保留。缓存和并发不同，不能把请求耗时差解释为新版更快。

## 遗留边界

本轮不开展新硬件实验、不训练边权、不收集memory。没有编译、oracle、NPU异步或真实计时证据；不得声称性能、HAP、瓶颈因果正确性或长期自主任务成功率提升。自然语言中的成本比较是否足够，仍需结合实际答案审阅，字段/hash校验不能代替这一判断。本次自主题的P预展开范围为elementwise/indexing/layout，不覆盖新增under-fusion生产消费叶的自主选用；该叶完成来源、技术和构建检查，行为覆盖仍待独立任务补充。较窄六组题目的事实满分也说明后续宜用更有区分度、较小按需上下文的独立任务检验泛化；本次没有追加额外试验预算。
