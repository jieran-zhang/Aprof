# 已尝试路线

### 1. 三线性算术向量化：保留，明确容量与调用代价

仅为纸面方案：保持坐标、判界、间接读取和逐邻点乘加次序，将三线性算术批量化；nearest 六个 case 保持原样，完整正确性仍须覆盖20例。

为避免依赖未证实的原地 alias，可采用保守布局：8个邻值、6个轴权重、2个乘法临时区、2个交替累加区，共18个 FP32 数组。原 `fpBuf` 计入累加区，不另重复计费；FP16 另保留输出 half 区。令其余实际 scratch、对齐和预留为 R：

- FP16：`U=74T+R` 字节；
- FP32：`U=72T+R` 字节。

这是拟定布局，不是 R0 已有分配。按材料 `buffer-lifetime/recipes/reuse.md`，独立静态分配不能仅凭用途错峰就取最大值。

FP16 下：
- T=1024：74KiB，剩54KiB；
- T=1536：111KiB，须 R≤17KiB；
- T=2048：148KiB，**不合法**。
- 全套双槽在1024同样超预算；768双槽为111KiB，但不代表已有重叠。

因此暂以1024单槽为保守起点，不因容量允许就扩大。具体 scratch 未闭合前，不能宣布实施合法。

令各核有效长度为 Lb，批次数 `J(T)=Σceil(Lb/T)`。每三线性批次按表达式模型约需24次 Mul、8次 Add、1次零初始化；再加一次写回，FP16另一次 Cast，即约 **34/35次 API 调用**，不含同步，也不等于机器指令数。缩 tile 会增加这些调用；128KiB 本身不改变 kernel launch 数，仍拟为一次。

减少的是逐输出 Scalar 算术；新增邻值/权重 UB 写入、Vector 读写与依赖。随机 X 读取、FP16 标量扩位、坐标重算均保留。FP32 批量写回也是方案变化，不能另重复归因。

### 2. 跨通道几何复用：容量可行性增强，仍暂缓

依据 `coordinate_neighborhood.md`，几何构造可由 NCS 次降至 `NS·ceil(C/Ct)`，但 X 值仍依赖通道，不能算作输入值复用。

举例保存8个64位空间偏移、6个FP32轴权重及4字节有效标记，三线性描述约92字节/点；逐通道消费并保留FP16输出区时约 `98St+R`。St=1024约98KiB，1536已超预算。nearest 描述可更小，尤其值得继续比较 case5。

代价是长存活表、描述读取、跨通道访问及任务数变化：约为 `N·ceil(C/Ct)·ceil(S/St)`。它不是向量化方案的免费附加项；组合须重算共同峰值，且派生几何复用的注册意图缺口仍未补齐。

# 剩余机会

- **选择未翻转**：128KiB 排除部分大 tile/双槽参数，却未排除上述两条路线；无时间证据，尚不能判断净收益。
- 地址递增、热点字段缓存容量代价小，也覆盖 nearest；但编译器是否已外提未知，不能据源码重复认定收益。
- 任意 grid 不保证源窗口局部性；暂不采用整窗驻留。缓存 hint、删除全流水屏障也缺当前访问或完成边证据。
