# transpose：R2静态复核

R1未实施、未编译、未测量；父本仍为原种子。

20case样本验证逆映射与perm双射，连续suffix仅case1/14（128/127元素）；case13保持batch前缀可降14个256×256转置。case6可视作B=2的9×65536转置，case10可视作133221×373，case12为B=3的91×4001；能合轴不代表小C专用Gather API适用。int64/NaN原始位必须保留。先实施通用矩形和suffix，若32×32转换temp超预算退16×16而非缩dtype。

同Action继续的依据是新增全矩阵公式/地址边界复核，性能预测仍not_tested。逻辑映射检查成立；物理owner裁切会改变搬运成本，完整源工作预测现为unresolved，机器指令也未验证。

条件后继：以bitwise搬运设计三组：case1/14保留连续末轴128/127，按suffix一次DataCopyPad；2D置换case2/3/4/5/7/8/9/11/17/18/19与case13的batched二维采用M×N矩形UB tile（候选16×16、32×32），连续输入行→片内位保持转置→连续输出行。int64按两个uint32通道同时保持8字节元素配对，不做数值Cast。复杂perm case6/10/12可合相邻轴再比较矩形；15/16/20保留通用索引fallback。预算2*A(tileM*tileN*s)+索引表+Tmp+reserve≤UB；逻辑矩形可无交，但DMA物理写许可尚未证明；必须采用后述物理块owner裁切方案。

实际UB、SDK接口及原oracle全量正确性齐备后可进入隔离实施；本轮没有C3。

物理写条件修正：逻辑矩形无交不能证明不同核的DMA物理写块无交。实际A、GM基址对齐、DataCopyPad尾写粒度/可见性和最终短块不越界均未核验；必须按真实物理块同owner并裁切/汇集输出行段，之后才可将constraint.output_ownership设true。

物理写所有权后继：先核验目标搬出接口的真实物理写粒度A、GM基址对齐、A与元素字节s的整除关系及非对齐尾写契约，A尚未知，不固定成32B或64B。令Q=ceil(totalBytes/A)，按q/r将连续物理块编号分配给核；核c唯一拥有[A*b_c,min(A*(b_c+n_c),totalBytes))。矩形tile只作为计算/搬入分块，每条输出行段须与本核物理字节区间求交后发射；同一物理块即使跨两行也只能由同一核写，必要时该核汇集该块多行片段再单次写回。禁止跨owner补齐写，最后不足A字节只用已验证不越过分配末端的接口或原合法尾路径。API/粒度未证时保留原scalar fallback，不声称矩形DMA就绪。裁切可能重复输入搬运，必须重新计算成本。

case7的1023×1023 float16行跨度2046B；若仅举例A=64，则[1984,2048)横跨第0行末62B与第1行首2B，必须归同一owner。A=64仅示例，未声明目标硬件粒度。
