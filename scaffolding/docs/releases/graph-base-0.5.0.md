# graph-base 0.5.0 验收记录

0.5.0 从 0.4.2 / `c5ceeafd1f0ec6d7f7a6aa065f17e2286f458a2d` 发布。
本版减少每次优化重复准备、启动进程和过早采集完整 profile 的成本。
runtime 仍为 0.2.1；schema、v0001/v0002 及 0.4.1/0.4.2 发布包保持原字节。

## 默认流程

1. 一个协调者、一个有证据的假设、一个隔离候选；各 skill 表示职责，不要求逐个启动 agent。
2. 复用已校验的输入/reference、环境证据及不变的规划；每个候选重新绑定源码身份。
3. 修改后执行完整正确性。失败立即停止，不消耗完整 profiling 预算。
4. 代表性及回归 case 先做六对 AB/BA 设备计时。明显退化停止；边界结果只允许一次预先声明的扩展，否则记为不确定。
5. 值得继续的候选重新执行完整 workload、至少 30 对独立计时，再补假设所需的五次独立机制采集，进入现有 gate。
6. 保存一份权威候选记录及其证据引用，由它生成报告；未执行兼容 gate 的尝试不虚构 episode、收益或训练 reward。

完整 profiling 默认后置，但合法图路由需要缺失的机制证据时必须先补诊断。
不存在的 extractor 保留 unknown；源码推断或六对快测不能替代机制 predicate。
规划变化仍返回相应阶段。完整正确性、来源回放、5% CV、held-out 回归及
95% speedup LCB ≥ 1.03 等现有正式门槛不变，不新增更高的筛选收益阈值。

910C/A3 继续使用 msprof。950 的 npu-compute 支持与离线验收边界沿用
[0.4.2 记录](graph-base-0.4.2.md)，本版没有新增 950 真机采集结论。

## 可独立使用的工具

- `prepare_workload.py`：用 workload、显式依赖内容、命令、环境及 producer 身份定位缓存；核验输入/reference 与日志后才允许命中。失败尝试保留，不缓存候选正确性。
- `device_paired_timing.py` 和 `device_timer.h`：每个 case 保持 baseline/candidate 两个进程，串行交替 AB/BA，使用 ACL event 测量完整算子调用。保留原始样本、源码/二进制/输入身份、实际命令和验证结果。

两者随稳定包发布，不依赖采集脚手架。工程需要接入自己的生成器、oracle
和完整调用计时边界；它们不是所有算子的自动适配器。详细配置见
[独立包说明](../../../skill-libs/graph-base/0.5.0/skills/ascendc-aprof-profiling/references/prepared-timing.md)。

## 本机设备验收

在隔离目录使用现有 exp 工程，设备为本机 A3，逻辑/物理编号均为 0；
保留 CANN 9.0.0 和驱动。将相同实现复制为两个角色，验证准备、正确性及
计时协议；没有实现优化 patch，也没有候选收益结论。

| 项目 | 实测耗时 | 结果 |
| --- | ---: | --- |
| 接入计时头后的 baseline 构建 | 22.47 秒 | 构建通过 |
| 20-case 输入/reference 首次准备（本地临时盘） | 9.17 秒 | 生成和 hash 核验通过 |
| 同一准备缓存再次读取 | 1.69 秒 | 完整性核验后命中 |
| 两个角色各 20-case 完整正确性 | 90.88 秒 | 40/40 通过，缓存 oracle 与原 verifier 结果一致 |
| case 1、7 的六对探索计时 | 15.34 秒 | 每角色预热 10 次，每个样本含 100 次完整调用 |
| 全部 20 case 各 30 对正式协议计时 | 194.18 秒 | 采集完成；case 17 的 CV 超限，正式投影被拒绝 |

正式协议运行的最大 CV 为 9.64%，超出 5% 阈值。保留首次完整结果，没有为
获得通过而反复采样，也没有补做本次比较的机制 profile 或正式 gate。
探索报告的 `stable=false` 表示没有正式计时准入资格；实际波动看各 case 的 CV。
两类运行均仅输出 draft，不直接选择 production best。

上述耗时是单次特定工程的组成步骤，没有测量完整优化会话，也不证明每次
优化可在 20–30 分钟完成。生成数据、Python 导入和进程启动的节省可直接观察；
优化效果仍取决于假设质量、算子实现、编译和正式验证。

首次共享盘验证遇到 inode 配额耗尽，保留失败日志和清理回执后，改在本地
临时盘重新生成输入继续验收。首次 CPU 数据生成还显式关闭了 Torch 的 NPU
自动加载，避免未声明的 CANN 环境依赖；没有修改系统安装。
