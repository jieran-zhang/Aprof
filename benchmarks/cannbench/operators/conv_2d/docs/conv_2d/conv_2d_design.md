# conv_2d design

The custom device pipeline is:

1. AIV im2col converts NCHW into ND matrix `A[M,K]`, where `M=N*Hout*Wout` and `K=Cin*Kh*Kw`. Padding is materialized as zero.
2. AIC `AscendC::MatmulImpl` multiplies `A[M,K]` by the logically transposed OIHW filter `B[N,K]`, producing FP32 `C[M,N]`.
3. AIV postprocess adds bias, converts matrix order back to NCHW, and casts once to the requested output dtype.
4. For BF16 with `K >= 2048`, one AIV correction launch scans the output and recomputes only cancellation-sensitive values with `abs(y) < 0.0625`. It decodes raw BF16 operands, performs integer IEEE-754 FP32 additions in source `ci -> kh -> kw` order, adds bias, and casts once to BF16.

BF16 inputs are expanded to FP32 by an AIV kernel before Cube contraction. This avoids BF16 Cube long-K partial-rounding drift and preserves mathematical FP32 accumulation. The sparse correction makes the remaining low-output reduction order explicit without replacing the dense Cube computation. A direct one-block AIV launch uses `GetBlockIdx()` only: dav-2201 does not expose a second independently scheduled correction loop through `GetSubBlockIdx()`. FP16 uses native Cube input with FP32 output; FP32 stays FP32.

All AIV GM write partitions are aligned to `32 / sizeof(dtype)` elements. Gathered values first enter a 1024-element UB tile; `DataCopyPad` performs aligned GM writes. Postprocess uses an FP32 UB tile plus an optional B16 output tile. Maximum live UB is 8 KiB per AIV core. Matmul L1/L0/UB scheduling is generated by `MatmulApiTiling` for Ascend910B/dav-2201.

The host performs file I/O, H2D/D2H, tiling construction, allocation, and direct kernel launches only. It does not compute convolution values. Verification computes both the primary mathematical BF16 reference and the unchanged default PyTorch backend result; the latter is diagnostic-only when its known ACL reduction defect is present.
