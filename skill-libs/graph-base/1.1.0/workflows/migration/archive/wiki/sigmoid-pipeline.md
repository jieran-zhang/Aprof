# sigmoid 两槽流水观察

> 本页保留历史协议下的观察与结论。1.1.0 新会话使用[统一计时协议](../skills/ascendc-aprof-profiling/references/unified-timing.md)，不照搬历史配对采集或置信区间门槛。

## 适用条件

在现有 tile 与算法不变、输入输出队列生命周期可证明合法时，可测试双槽
buffer、预取下一 tile、延后输出回收与最后一 tile drain。必须核算显式和隐式
UB 使用，确认零/单 tile 与尾部事件顺序。

## 证据与反例

历史 sigmoid 候选将队列深度 1→2；20-case normal/swapped task-sum suite
约 1.303×，40 个 case/config 点估计均大于 1。但末次 A/A 有 22 个精度不足
的 cell，case10/swapped 的进程内 CV 超限。case20 的 MTE2 active time 反而
升约 15.6%；仅凭总时间下降不能认定重叠机制解释了全部收益。

来源：`l1:sigmoid001-pipeline-final-v1`。

## 验证与结论

需独立复核输出顺序、事件/队列安全、容量与全 case 正确性，再用统一协议的完整覆盖计时
和针对性 trace 分别判断性能与重叠。当前为有条件的研究观察，不是生产规则。

## 2026-10-14 独立复验

910C/A3（9392）、CANN 9.0.0 上，baseline 与两槽候选各通过声明 20 case 和额外 57 case，前置 A/A 通过。独立正式 20×30 对计时观察到几何平均 1.317478×、95% 加速下界 1.313086×，20 case 均更快，最大逐 case CV 为 1.878%。但后置同源 A/A 的 case 8 在其中一个测量角色上的跨会话均值漂移为 3.563358%，超过预设 2% 上限（另一角色为 1.433158%）；两角色在每次会话内的偏差和 CV 单独仍通过。

因此该提案在控制实验门禁停止，未采集机制 profile，未晋升。正式样本原样保留为未获准发布的观测，不把控制失败改写成候选回退，也不通过重采样或放宽阈值获得接受。拟修改单个 optimization skill 的 before/after 草案保留在演化事件的证据中，尚未应用。详见 evolution.jsonl 的 1.0.0-sigmoid-pipeline-independent-20261014。

## 第二轮：双进程周期仍未通过计时准入

本轮只执行了 baseline 对自身的协议诊断，未重新运行两槽候选 A/B。
v2 的两个独立进程周期使用相反启动顺序及对称预热。六个控制 case 的
前置 A/A 通过，但全量 20×30 对 baseline/baseline 会话仍失败：
FP16 `[8192,8192]` 的 case 4 总体角色偏差为 4.2631%，两个周期分别为
3.8885% 和 4.6363%；case 6、8、11 的某个周期也超过 2%。

该会话的常规正式报告为 `stable=true`，不能代替逐 case、逐周期的
同源角色控制。反向启动后 case 4 的偏差方向仍相同；现有证据不足以
归因为启动顺序、分配位置或硬件状态。按预登记停止规则，后置 A/A、
独立确认和候选验收均未运行，不以第一轮的 1.317478× 观察晋升。
证据见演化事件 `1.0.0-sigmoid-round2-control-20261014`。

## 2026-10-15：Task v5 尝试在源码审查预算处停止

首次 Task v5 尝试的独立审查累计使用 15,736 token，超过预设 8,000。
任务实际退出 2；未构建、未采集硬件数据、未形成源码审查结论。这是评估
流程拒绝，不是两槽流水的性能或正确性反例。该尝试已关闭，原始日志由
任务后的收集流程保存，见演化事件 `1.0.0-sigmoid-task-v5-review-budget-20261015`。
