# ColSplit/RowSplit 与分段合并

## 两层切分问题与适用域

输入按真实连续性表示为 `[A1,R,A0]`，AR 为 A0=1，ARA 为 A0>1。完整 R 及必要计算区放不进 UB 时：AR 沿连续 R 列切成 chunk（ColSplit）；ARA 沿 R 行切，每次搬 `[Rc,V]` 的 A0 连续片（RowSplit）。切 A0 只是把不同输出分给不同任务，不构成跨核归约。

必须区分“同一核顺序读取多个 chunk”和“多个核分别计算同一输出的 R 段”。前者只解决容量，状态在核内，无 workspace 与全局同步；后者增加并行任务并引入 partial 写、全局完成关系、merge 和额外 launch。R 再大仍可由一核流式遍历，不能仅因为放不下就宣称必须跨核。

跨段合并前冻结状态类型、单位元、合并公式、顺序、finalize 和特殊值规则。sum 合并 partial sum，mean 合并 sum+count 最后除总数，不能平均不同长度 chunk 的 mean；variance 合并 (n,μ,M2)；softmax 不能简单相加分片归一化结果；norm 先合并变换后的统计量再开方/取幂一次。

## 输出所有权与同步协议

先将独立输出拆为 P 个组，每组最多 V 个输出（AR 可一行一个标量组）。基线流式方案的组 g 唯一属于一个核，该核从 r=0 遍历到 R，只有它写最终输出。

若输出组不足且允许跨 R 并行，选 S 个 split，任务 `(g,s)` 的线性编号为 `g*S+s`。split s 拥有 `[floor(s*R/S),floor((s+1)*R/S))`，段内再按 Rc 分 UB chunk；选 S≤R，或明确空段状态。每个 `(g,s)` 只写自己的 workspace 槽，唯一 merge 任务 g 读全部 S 槽并写最终输出。workspace 地址使用字节 stride 与明确的类型视图，不能把字节偏移又当作元素下标。

最容易核验的完成关系是同一执行流按序启动 producer kernel 和 merge kernel；merge 启动时 producer 全部完成。来源展示单 kernel SyncAll 草图，它只在目标支持、启动模式/驻留/参与核集合与工作区发布协议均证明合法后才是候选。普通 PipeBarrier/队列同步只保证核内依赖，不能代替跨核完成关系；不能让 core0 先读尚未完成的 partial。

## 字节容量与额外成本

令 `L_in=A_a(V_valid*s_in)`，`L_acc=A_a(V_valid*s_acc)`；AR 时 V_valid=1 且一块连续输入的字节为 A_a(Rc*s_in)。ARA chunk 的输入大小 Rc*L_in。d_in 是输入 buffer 实际份数，K_cast 是独立升精度工作区份数，B_state/B_chunk 是持久状态与本块状态的字节数。

`B_chunk_live = d_in*Rc*L_in + K_cast*Rc*L_acc + B_state + B_chunk + B_out + T_api(Rc,V_align) + B_other ≤ B_available`（ARA）。

AR 将前两项替换为 `d_in*A_a(Rc*s_in)+K_cast*A_a(Rc*s_acc)`。最终选 Rc/V 时同时验 API 的 count、blockCount、repeat 和偏移字段范围。不同阶段物理区共用前要证明生命周期不重叠；source 中固定 4KB 临时区、64 列、255 行不能用作所有芯片的常量。

对跨核方案，定义 H 为一个输出组的已序列化 partial 状态字节，a_ws 为工作区槽合法对齐，`slot=A_aws(H)`，则 `W=P*S*slot`，producer→merge 额外 GM 交通约 `2W`（一次写入、一次读取，实际 padding 搬运按实现计）。H 不等于输出字节：FP32 sum 为 V*4，Welford 需 mean/M2/count，argmax 需 value/index。若使用 SoA 分区，分别对各数组求和并记录 count 精确类型。

必要原始输入量仍为 `A1*R*A0*s_in`；streaming sum 本身不因 chunk 个数增加而重读整行，但 softmax/归一化多遍会增加扫描。候选比较用：

`T_split ≈ T_producer(P*S,R/S,Rc,V)+T_merge(P,S)+T_extra_launch+T_workspace`。

这是待实测的成本分解，没有固定跨核收益阈值。当 P 已足够、R/S 过短、状态 H 很大或 merge 重读昂贵时，单核流式常更值得先比较；跨核方案必须在完整端到端计时中包含 merge 与 workspace 初始化。

## 合并状态与数值边界

| 操作 | partial 与 merge | finalization / 额外约束 |
| --- | --- | --- |
| sum | 0；按约定顺序相加 | FP32/更高精度与重排仍按误差合同验证 |
| mean | (sum,count)；两者分别合并 | 总 sum/总 count，count 不受存储 padding 影响 |
| max/min | 极值或首个有效段；按 oracle 比较 | NaN 传播、±0、空段规则不能由 `>` 猜测 |
| argmax/min | (value,global_index) | 局部 index 加真实 R 段起点；相等时按合同取最早/最晚 |
| variance/std | (n,μ,M2) 的 Welford 合并 | 全部完成后才除 n−correction/开方 |
| norm/softmax | 各自可合并的统计状态 | 不能对每段先完成输出归一化 |

最大值 initialized=-∞ 并用 `>` 更新仅在声明的特殊值规则下成立；存在全 NaN、首个 NaN 或 tie 规则时先选首个有效元素或显式 NaN 状态。浮点求和不满足逐位结合律，S/Rc/合并树是数值实现的一部分，C3 不能为了 tile 改动偷偷换树。

索引应使用足够范围的整数类型。若某 A3 Select 路径用 float 暂存整数，只能覆盖已证明可精确表示的索引范围（FP32 连续整数至 2^24），超范围回退整数索引方案；不能把 half 最大有限数当其精确连续索引上限。

## 可执行双阶段伪代码

```python
# producer：S=1 时可直接 finalize，避免写 workspace。
for g, s in owned_group_splits(P, S):
    lo, hi = s*R//S, (s+1)*R//S
    state = identity_or_empty_state(op)
    for r0 in range(lo, hi, Rc):
        rv = min(Rc, hi-r0)
        x = load_valid_strided_tile(g, r0, rv, V_valid[g])
        part = local_reduce(x, rv, V_valid[g], op)
        state = merge_in_frozen_order(state, part)
    write_unique_slot(g, s, state)
# 两个 kernel 的执行顺序建立所有 producer 完成关系。
for g in owned_merge_groups(P):
    state = identity_or_empty_state(op)
    for s in frozen_merge_order(S):
        state = merge(state, read_slot(g, s))
    write_unique_output(g, finalize_once(state))
```

## 有界 Ascend C 片段

以下是 ARA FP32 sum 的一个已就绪 chunk。xChunk 物理布局 `[rCount,vAlign]`；sumState/chunkSum 为独立 float LocalTensor；tmpByte 为按同 shape/pattern/reuse 查询的 uint8_t 临时区。所有 count>0，容量和 API 支持已验证，输入队列已完成搬入。

```cpp
uint32_t shape[2] = {rCount, vAlign};
AscendC::ReduceSum<float, AscendC::Pattern::Reduce::RA, false>(
    chunkSum, xChunk, tmpByte, shape, true);
AscendC::Add(sumState, sumState, chunkSum, vValid);
```

sumState 在首块前按有效 lane 初始化 0，完成所有 chunk 后才搬出有效 vValid。AR 的 local reduce 使用基础四参数 ReduceSum，并以当前 rv 而非 Rc/R_align 为 count。DataCopyPad 的 ARA 搬入 blockLen 为 `vValid*sizeof(T)` 字节、srcStride 为 `(A0-vValid)*sizeof(T)`（限该已核验重载），UB 行 stride 与 vAlign 一致；rCount 的 uint16 字段必须在转换前验证。

## 多轴、替代路径与验证

多轴归约保留交替 A/R 轴，外层遍历真实输入片段，将内层 AR/ARA partial 合并到同一输出状态；只有数学上允许且误差合同接受时才能改变多轴次序。可用规则 stride copy 或连续 slice 循环，950 的 NDDMA 是额外搬运候选，910C/A3 不因支持普通 DataCopyPad 就获得该能力。

验证 R 不能整除 Rc/S、最后 rCount、S=1/S=R、V尾片、空输入、单输出、多个输出组、不同 dtype、workspace 槽无重叠、producer 全覆盖、merge 唯一写和最大容量。跨核数值对照需包含同组不同切分与大数/小数混合；只测 producer 正确不算整个算法正确。失败回到已验证单核流式或原框架基线，记录具体 entry/key 与互斥的 tiling 域。

来源事实为 AR/ARA 分载、Group Reduce 两阶段和 Welford/索引增量；字节序列化、独立 kernel 同步路径与成本比较为工程推导。来源审读完成，未验证 NPU 性能；平台/SDK 适用范围须按实际 910C/A3 或 950 分别核实。

## 复盘不能只看 producer：分核收益与合并成本分开

固定 Group Reduce 文档直接陈述两阶段 partial→merge；多轴归约资料直接陈述按 A/R 结构遍历与同一扫描计算多个统计量。本节代价式是规划推导，不继承来源示意 `SyncAll` 的通用合法性，仍按前文已确认的跨 kernel 完成关系执行。

令 G 为独立输出组数、R 为每组输入数、S 为分片数、b 为每个 partial 状态的字节数。单状态 sum 的 b 是累加 dtype 宽；Welford 是 count/mean/M2 完整状态及实际对齐，不能仅计一个 float。分核方案产生 GS 份 partial，GM workspace 的逻辑写读至少 `2GSb` 字节，另有每组 S−1 次状态合并、两阶段调度及槽位对齐开销。提高 S 可能增加可并行任务，但不会减少输入总读取和必须的归约工作。

对比 S=1 的核内流式归约时，应同时列出：producer 每核工作、merge task 数、partial 写读、临时峰值、数值树与输出组数。G 已足够供核时，盲目增加 S 常只添加中转；G 太小且 R 长时，S>1 可以作为待测方案。不能把“R 大”推成固定分核阈值。

输入值复用例如同一遍扫描求 sum 与 squareSum，派生状态复用例如保留已生成 partial，重算则可能节省活跃状态却增加输入重读。选择前冻结允许的数学表达和舍入顺序；sum/squareSum 不是任意精度条件下 Welford 的等价替代。R2 若 producer 改快而整体未改善，应重新检查 merge/中转/任务分布，而非自动认定归约机制错误；若数值失败，性能预测仍未测试。
