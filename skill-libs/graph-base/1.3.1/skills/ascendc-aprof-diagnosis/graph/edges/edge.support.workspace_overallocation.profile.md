# symptom.profile.workspace_overallocation → problem.workspace_overallocation

## 关系与对象绑定

symptom.profile.workspace_overallocation —supports→ problem.workspace_overallocation。

- target→target：同一task与parent实现，绑定同一target身份；host声明的workspace段、真实并发槽和kernel索引范围
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.profile.workspace_overallocation=true
- constraint.diagnosis.workspace_overallocation.profile_scope_verified=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

该profile复合观察需同时满足对象、有效域、窗口、单位与模型要求，并按本边检查区分“GM workspace与UB/L1/L0容量分属不同资源”。满足后仍需比较替代解释，相关性不单独确立机制。

- 联合host、tiling字段、kernel slot/index和上层workspace ABI核验
- 区分已分配未访问、主动清零、实际读写，不能仅据大小推性能

## 例外与代价

- 库契约保留区、并发跨task存活或kernel索引要求该范围时不能缩小
- 只见host固定分配而缺少下层Process/框架契约时保留缺口
