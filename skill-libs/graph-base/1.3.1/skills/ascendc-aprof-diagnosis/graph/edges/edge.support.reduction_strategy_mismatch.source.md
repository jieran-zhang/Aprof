# symptom.source.reduction_strategy_mismatch → problem.reduction_strategy_mismatch

## 关系与对象绑定

symptom.source.reduction_strategy_mismatch —supports→ problem.reduction_strategy_mismatch。

- target→target：同一task与parent实现，绑定同一target身份；合轴后AR或ARA归约的A1/R/A0域及partial状态
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 依据与判别

该源码复合观察绑定合轴后AR或ARA归约的A1/R/A0域及partial状态，与机制链“全载/行列切分/跨核方案未适配R长度、独立A量和容量 → 可能产生欠并行、重复读、过多partial或不合适的广播路径 → 主归约及合并/后变换成本超出可行替代方案”相容，因此只形成待核验候选与profile预测。它不证明现象已在profile出现，也不是因果充分条件。

- AR按连续行与ARA按R×A0块分别计算，不能把临时区估算通用化
- 对Group Reduce同时核算partial写读、同步、合并和精度顺序

## 例外与代价

- 当前分支已经满足容量和任务模型且成本来自bank/同步时，不把所有归约慢都归此项
- 缺少合轴或scratch规则时不能裁定替代分支可行
