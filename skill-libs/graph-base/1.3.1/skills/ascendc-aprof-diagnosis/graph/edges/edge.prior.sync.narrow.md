# problem.excessive_sync_scope → action.narrow_sync_scope

## 关系与对象绑定

problem.excessive_sync_scope —mitigated_by→ action.narrow_sync_scope。

- target→target：同一task与parent实现，绑定同一target身份；tile或归并循环中的全局/全流水同步及真实依赖
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

- constraint.capacity=true

## 依据与判别

仅当该Problem在绑定对象/阶段上仍有可核验解释力时，把等待限定到真实生产消费流水或必要参与核边界才是对应候选。联合条件继承A全部原硬前提，C2可比较未知条件，C3不能越过门禁。

- 核内独立group与跨核round边界分别审查
- 保留所有可见性和退出闭合条件，核对不同原语的目标模式/流水支持

## 例外与代价

- 每轮确有跨核归并依赖时，不能删轮末同步
- 源码有SyncAll但不在热路径或只执行一次，不足以证明性能成本
- 精细事件与核间协议更复杂
- 错误收窄会破坏可见性、造成死锁或数据覆盖
