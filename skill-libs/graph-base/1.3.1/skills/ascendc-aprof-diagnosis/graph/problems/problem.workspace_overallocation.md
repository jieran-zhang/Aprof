# workspace 配置引入额外成本

## 对象、阶段与适用域

- host声明的workspace段、真实并发槽和kernel索引范围
- host workspace分配
- kernel初始化、读写和槽轮转

旧scope=all保留作检索范围，机制成立仍须核对目标架构、dtype、shape和API支持。

## 机制链

- 按最大shape、总task数或过量槽数预留workspace而实际只需有限并发槽
- 多余区间可能增加分配/清零/传输或挤压其他算子内存
- 仅当实际触及这些成本时才成为性能机制，纯保留字节是资源风险

## 预测、支持检查与反证

- 按真实shape和并发槽缩放可降低内存占用；时延仅在触及多余区间时可能改善，属prediction
- 联合host、tiling字段、kernel slot/index和上层workspace ABI核验
- 区分已分配未访问、主动清零、实际读写，不能仅据大小推性能
- 库契约保留区、并发跨task存活或kernel索引要求该范围时不能缩小
- 只见host固定分配而缺少下层Process/框架契约时保留缺口

## 具体替代解释

- problem.onchip_capacity_pressure：GM workspace与UB/L1/L0容量分属不同资源；检查：分别列GM段与片上buffer
- problem.chunk_merge_overhead：partial必需workspace可能很大，但合并成本不全由过量分配造成；检查：比较必要partial字节与额外预留字节

## 候选动作与成本

action.size_workspace_by_shape：按runtime shape、真实并发槽和合法索引边界计算每段workspace。

原硬前提：symptom.source.workspace_overallocation=true；constraint.workspace_ownership=true；constraint.semantic_equivalence=true；constraint.capacity=true。

- 需同步修改host公式、kernel偏移和调用契约
- 缩小空间可能暴露异步重叠与跨实例生命周期问题

## 限制与缺口

- FA按并发槽分配规则只对其生命周期成立的段适用
- SquaredRelu入口不足以证明其host保留区可删除，不能据固定16MB直接断言浪费
- 本轮无同任务profile、无case_support、无收益或发生频率声明；源码形态只支持待核验候选。
