# 非连续访问破坏有效搬运

## 对象、阶段与适用域

- 带明确shape、layout、stride和有效索引域的输入或输出切片
- host选取切分轴
- kernel GM地址生成与DataCopy

旧scope=all保留作检索范围，机制成立仍须核对目标架构、dtype、shape和API支持。

## 机制链

- 切分或遍历轴跨过物理连续内轴
- 相同有效元素分解成离散事务、短块或额外padding
- 发射与实际流量增加使有效字节带宽下降

## 预测、支持检查与反证

- 合法交换遍历/切分轴后短块数应减少；这是prediction
- 若要额外转置，节省搬运未必覆盖格式转换成本
- 沿至少两个连续tile手工核对GM地址差，区分逻辑索引与实际事务
- 使用相同shape、dtype、缓存状态的连续形态作参照
- 原地址已连续且事务数符合模型，则不能归因于跨轴
- 稀疏索引语义本身要求离散访问时，重排空间受owner和输出顺序约束

## 具体替代解释

- problem.tiny_transfer_setup_amplification：离散布局是几何原因，setup是每次发射固定成本，可共存；检查：固定单块字节后比较stride；固定stride后比较合并
- problem.broadcast_strategy_mismatch：广播的零stride重复输入应另计复用和展开成本；检查：标出哪些轴因广播而重复、哪些轴物理不连续

## 候选动作与成本

action.reorder_contiguous_access：沿连续内轴重新组织合法tile或使用目标支持的批量strided搬运。

原硬前提：symptom.source.noncontiguous_access=true；constraint.layout_semantics=true；constraint.semantic_equivalence=true；constraint.capacity=true。

- 额外转置/索引表及UB暂存
- 重排可能损失输入复用或改变每核负载

## 限制与缺口

- DataCopy stride的字节/datablock单位按具体API核对
- 不把arch35 NDDMA能力用于arch22
- 本轮无同任务profile、无case_support、无收益或发生频率声明；源码形态只支持待核验候选。
