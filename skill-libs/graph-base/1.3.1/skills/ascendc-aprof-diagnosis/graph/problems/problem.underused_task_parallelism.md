# 已有独立任务并行度未暴露

## 对象、阶段与适用域

- 当前workload的独立任务域、实际BlockDim及可用同类核
- host任务分解与启动
- kernel任务领取

旧scope=all保留作检索范围，机制成立仍须核对目标架构、dtype、shape和API支持。

## 机制链

- 独立可并行工作未充分分解或启动核数过少
- 有效任务数少于可用同类核且每任务有足够长工作
- 部分核空闲，关键路径仍由少数核串行承担

## 预测、支持检查与反证

- 合法增加任务可能缩短每核关键路径，但归并和调度可能抵消；这是prediction
- 先考虑已有独立外轴，再评估Split-K/Split-KV与partial成本
- 读取目标核数API与kernel mode，不用来源的48/64等样例数字
- 微小任务或算法依赖使增并行开销大于节省时，本机制不构成可执行理由
- BlockDim大但逻辑任务只有一个并不能证明已吃满核

## 具体替代解释

- problem.core_tail_imbalance：有足够任务仍可能分配失衡，欠并行主要是总可用任务不足；检查：比较总任务及每核分布
- problem.chunk_merge_overhead：增加拆分会减少主阶段却增加partial归并；检查：比较saved critical path与partial写读+同步+merge

## 候选动作与成本

action.decompose_tasks_dynamically：按合法独立域或可归并的分段动态分解任务并按workload派发。

原硬前提：symptom.profile.tasks_below_available_cores=true；symptom.source.fixed_or_undersubscribed_tasking=true；constraint.semantic_equivalence=true；constraint.capacity=true；symptom.workload.tiny_or_overhead_limited=false；constraint.task_ownership=true。

- 更多partial与workspace
- 跨核归并、调度及同步开销和精度顺序变化

## 限制与缺口

- 小workload是该解释的条件性反证，不能跨shape推广
- StreamK源阈值属于该代码，不设为通用分界
- 本轮无同任务profile、无case_support、无收益或发生频率声明；源码形态只支持待核验候选。
