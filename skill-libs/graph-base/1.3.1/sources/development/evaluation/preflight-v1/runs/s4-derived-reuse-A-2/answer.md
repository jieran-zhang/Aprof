# 一、当前实现理解：两例共同事实及数量差异

## 1. 实际路径与数学依赖

入口 `grid_sampler_3d_kernel:190–197` 对当前 FP32 输入执行：

```text
GridSampler3DScalar<float>
  → 每个 linear 调用 GridSampler3DOne<float>
  → 标量读取 grid、坐标变换、reflection、floor
  → 按源码顺序读取八邻居并累加
  → 标量写 out[linear]
```

**不是 Half 路径，也不是已有派生几何复用实现。**Half 类中的 UB、Cast、DataCopyPad 和屏障不属于当前执行路径。

令 `p=linear % S`，`nc=linear / S`；本任务 N=1，因此 `nc=c`。外部物理偏移为：

\[
X[c,z,y,x]=c\cdot32768+z\cdot1024+y\cdot32+x,\qquad
Y[c,p]=c\cdot4096+p.
\]

grid 的物理偏移为 `3p+{0,1,2}`，不依赖通道。

对每轴，源码首先执行：

\[
u=((g+1)\cdot32-1)\cdot0.5
\]

随后使用 `GridReflect` 原式：低端 −0.5、高端 31.5、span=32，经过 distance、整数 flips、extra、奇偶反射及 `[0,31]` clamp。再生成下取整坐标、上下邻居及六个因子：

```text
wx0, dx, wy0, dy, wz0, dz
```

每个输出从 `result=+0.0f` 开始，严格按源码第125–132行顺序执行八项：

\[
r_{k+1}=r_k+(((v_k\,w_{x,k})\,w_{y,k})\,w_{z,k}),\quad k=0,\ldots,7.
\]

这里的括号和累加顺序是数值契约的一部分。**不能预先合成三个权重的乘积再乘 X，也不能改成树形归约或 FMA。**

依赖关系是：

```text
grid[p] → 坐标/边界变换 → 邻居、有效性、六因子
                                      ↓
X[c,对应邻居] ─────────────────────→ 八项顺序累加 → Y[c,p]
```

派生几何不依赖 c，但输入值 X 和结果依赖 c。几何相同不意味着跨通道可以复用 X 值。

## 2. 当前分核、所有权与存储

`tiling.h:40–45` 依据传入 `cores` 和输出数选择 blockNum，FP32 的 blockLength 向上对齐到16元素，即64B。核 b 处理：

\[
[b\cdot blockLength,\ \min((b+1)blockLength,CS)).
\]

各区间不交叠，覆盖有效输出；空末核跳过循环。实际 `cores`、启动代码和设备可用 AIV 数不在输入内，不能给出固定核数。

当前 FP32 路径：

- 输入、grid、输出及 tiling 均通过 GM 指针访问；
- 没有显式 UB 数据分配、DMA tile、Vector 运算或跨核归并；
- 输出逐值写一次；
- 不存在当前可删的几何 GM 中间表，也不存在当前两 kernel 间融合机会；
- 不能把这些标量 GM 访问计成同数量的 MTE DMA 发射。

## 3. 可复算工作量

记 \(E=CS\)。下表是源码逻辑量，不是 HBM 流量或编译后指令数。

| 项目 | a：C=1 | b：C=128 |
|---|---:|---:|
| 输出 E | 4,096 | 524,288 |
| 坐标/几何生成次数 | 4,096 | 524,288 |
| grid 标量读取 | 12,288个 float，49,152B | 1,572,864个 float，6,291,456B |
| `GridRead` 调用 | 32,768 | 4,194,304 |
| X 有效读取上界 | 131,072B | 16,777,216B |
| 插值乘法 | 98,304 | 12,582,912 |
| 插值加法 | 32,768 | 4,194,304 |
| 输出有效字节 | 16,384B | 2,097,152B |
| 完整 X 分配大小 | 131,072B | 16,777,216B |
| grid 唯一数据大小 | 49,152B | 49,152B |

几何每次还包括三轴 unnormalize/reflection、三次 floor、三次差值和三次补因子等，不能只用上述32次插值运算概括全部 Scalar 工作。

在 reflection 正常产生有限 `[0,31]` 坐标的情况下，下邻居合法，上邻居在下坐标为31时越界；每点有效邻居数为：

\[
V_p=(1+[x_0<31])(1+[y_0<31])(1+[z_0<31]).
\]

因此实际 X 读取为 \(C\sum_pV_p\) 个 float，不能无条件写成8E。

### 数值契约的一个原有疑点

“grid 有限”不保证 `((g+1)*32-1)*0.5` 不溢出，也不保证 `distance/span` 可转换为 int64。源码没有处理这些范围外中间值。两方案都必须保留原 helpers，**不能擅自加入取模、饱和或有限值替换来改变行为**。后续应明确原 oracle/目标编译语义如何定义这些极端有限 grid；这是原实现的数值覆盖疑点，不是本轮可以自行收窄输入域的许可。

# 二、子例 a：C=1

## 1. 主要方案 A：标量取样，Vector 批量完成原乘加

### 工作变化与覆盖

每核仍拥有原来的连续 linear 区间，在核内分成最多 T 个输出的 tile。建议纸面初值 **T=128元素，单槽、无预取**，不是最优 tile 声明。

对 tile 内每个输出：

1. 用原标量 helpers 计算坐标、reflection、floor 和六因子；
2. 仍以原 k 顺序调用 `GridRead<float>`，把八个值和六因子写入本核 UB；
3. 批量执行八轮，每轮三次独立 Mul、一次 Add；
4. 统一写回该 tile 的有效输出。

覆盖全部当前 a 输出。坐标与反射仍为 Scalar，数据相关 X 读取也仍为 Scalar；其他元数据域保留原入口路径。

### 减少、保留、新增工作

令：

\[
L=\sum_b\left\lceil E_b/T\right\rceil
\]

为全部非空核的 tile 数。

- 从逐输出 Scalar 路径移出的运算：**24E 次乘法、8E 次加法**。
- 新增 Vector API：**32L 次**，每次处理本 tile 有效 count；在 T=128 时，a 的 \(L\ge32\)，实际取决于分核边界。
- 原 E 次标量 GM 输出存储，改为 L 次有效长度 DMA 写回。
- grid 和 X 的有效逻辑读取不减少，几何生成次数仍为4096。
- 每输出新增 UB 标量写：八样本、六因子、一个初始零，共 **15次，60B**。
- 三次 Mul 和一次 Add 均使用独立目的区时，Vector 逻辑 UB 读写约为 **384B/输出**；另有输出搬出读取4B/输出。连同上述 staging，约 **448B/输出**。这是局部逻辑访问账，不能当作真实 UB 总线事务量。
- a 对应约1,835,008B的上述局部访问量。还新增初始化、Vector 依赖与 DMA 完成等待。

因此它不是“无代价向量化”：减少 Scalar 算术，换来 UB staging、批量发射及同步。

## 2. 最有竞争力的完整替代 A′：只合并输出写回

A′保持 `GridSampler3DOne<float>` 原计算，把结果写入单份 VECOUT UB，再以 DataCopyPad 搬出。

- 几何、八邻居读取、24E乘法和8E加法全部保持。
- E次标量 GM 写变成E次 UB `SetValue` 和L次 DMA。
- 只需 \(A(4T)\) 字节输出区；T=128时为512B，再加框架预留。
- 不需要八样本和六因子的 staging，也不引入 FP32 Vector 乘加等价性问题。
- 新增输出滞留和每 tile 完成边，但比 A 的工作集及同步明显简单。

**本轮选择 A 的理由：**a 没有跨通道几何复用，剩余主要机会是逐输出数据计算。A直接改变131,072次插值乘加，而 A′只改变16KiB最终输出的写法。A值得作为有依据的条件试验；但如果目标 Vector 与 Scalar 数值语义不能闭合，或 staging/同步抵消算术收益，A′是更强的安全替代，而非继续盲目增加 buffer。

对 a 预计算几何表并不有利：复用次数为1，几何次数和 grid 读取均不减少，却新增表写读。整幅 X 驻留也未选：每 owner 重载131,072B，且任意 grid 不保证各空间 tile 的读取局部性，容量与重复全载代价均需另算。

## 3. Action 实例 A

**纸面实例 `A-vector-interpolation`：**

- 注册 Action：`action.vectorize_scalar_loop`，输入所给 v0006 正文。
- parent：所给原始 `GridSampler3DScalar<float>`。
- target/stage：`GridSampler3DOne<float>:125–132` 的插值数据运算。
- workload：当前 a，FP32、NCDHW、N=1、C=1、32³、S=4096、bilinear/reflection/alignCorners=false。
- effect：仅把八项乘加按输出维批量表达；坐标生成和取样保持。
- 结构前提 `scalar_element_loop`：由第146–147行及第125–132行成立。
- 完整数值等价、实际容量：**条件项，尚不能填 true**。
- 性能假设：可能减少 Scalar 数据算术及输出存储工作；没有 `scalar_hot` 或加速证据。

统一 DMA 输出是该批量数据路径的配套实现，不另登记一份相同节省量，也不为了文件/API数量拆 Action。

# 三、子例 b：C=128

## 1. 首选方案 B：同 owner 复用派生采样几何

### 关键事实

b 与 a 的本质差异不是简单“大128倍”：

- 原实现针对每个通道重新读取同一 grid；
- unnormalize、reflection、floor、六因子和空间邻居地址均不依赖 c；
- 当前每输出仍独立完整生成这些状态，没有已有表可以“保持片上”。

因此 B 的主要目标是**消除跨通道重复构造派生状态**，而不只是少读原始 grid。

### 完整骨架

取 `Ct=128`、`St=16`作为纸面初值：

- 每个任务独占一个 `[全部128通道, 连续16空间点]` 输出矩形；
- 共 \(4096/16=256\) 个独立任务；
- 先为16点生成几何记录；
- 然后按 c 外层、p 内层顺序读取对应通道的 X，按原 k 顺序累加并写回；
- 本轮不附加 Vector 化或 DMA 输出汇总，避免把不同性能效应合并后无法解释。

记录保存：

- 八个合法源空间 offset，uint32；
- 八个有效标记，uint8；
- 六个原始 FP32因子。

无效邻居先标记，消费时返回原 `+0.0f`，不得先读越界再 mask。offset只有在原判界成立时生成；合法空间 offset最大32767，可安全存 uint32。**不存合成权重。**

### 全部工作变化

一般 Ct 下：

\[
G_{\rm new}=S\left\lceil C/Ct\right\rceil,\qquad
Tasks=\left\lceil C/Ct\right\rceil\left\lceil S/St\right\rceil.
\]

当前 Ct=128：

- 几何生成：524,288 → **4,096次**，少520,192次。
- grid读取：6,291,456B → **49,152B**，少6,242,304B逻辑请求。
- 空间邻居判界和空间 offset构造也可按记录只做一次；通道基址仍需逐通道加入。
- **X有效读取不减少**，仍为 \(128\sum_pV_p\) 个 float。
- **插值24E乘法、8E加法不减少**，仍用原顺序。
- 输出仍为524,288次标量写，有效2,097,152B。

新增代价：

- 记录有效payload为 **64B/点**；全调用生成记录payload共262,144B，但只保留当前任务的空间片。
- 每点22个记录字段写入，共90,112次局部字段写；按朴素 c→p 消费，每输出读取22字段，记录payload逻辑读取上界为 **64E=33,554,432B**。
- 各通道需反复访问记录，延长记录存活；新增任务调度和局部取表地址工作。
- task数由原输出线性分区变为256个空间矩形；是否足够利用目标核必须依据实际可用 AIV 数检查，不能默认。
- 访问顺序改变，可能影响 X/cache局部性；NCDHW下每个通道的16个输出仍连续，但跨通道跨整个输入/输出平面。

这是以较多局部状态访问，换取大量 reflection等重复构造；净收益未测。

## 2. 最有竞争力替代 B′：采用 A 的批量乘加

B′保持原线性所有权和逐输出几何：

- 仍生成524,288次几何，grid逻辑读取仍为6,291,456B；
- 移出 Scalar 的插值算术为12,582,912乘法和4,194,304加法；
- T=128时 \(L\ge4096\)，新增至少131,072次 Vector API调用；
- UB基础容量仍为9216B，不随总 C乘128；
- staging/Vector/搬出局部逻辑访问约 **234,881,024B**；
- X有效读取不减，统一DMA写回2MiB输出；
- 不改变外部布局、不新增GM workspace，也不引入几何表。

**优先 B 而非直接选 B′的理由：**B针对当前b特有的128次几何重复，尤其保留原 reflection算法即可减少其重复执行；B′虽然覆盖更多插值算术，却保留这项显著重复，并增加较大的 UB访问。不能仅因 B′已有 Action就停止比较。

若 B 的记录取表、任务数或跨通道访存代价过高，B′可能胜出；具体判别不是“有没有更多数据”，而是：

- B是否实际把几何生成降到4096次；
- 表读取和新任务次序是否成为新增长路径；
- B′是否真正减少编译后的Scalar算术，以及其 staging/屏障成本。

## 3. 明确 Action 能力缺口

B不能合法归入：

- `hoist_invariant_control`：这里主要移动的是浮点坐标、reflection和插值派生状态，不只是控制/地址前缀；
- `reuse_input_tiles`：保存的是新计算的几何，不是原始输入切片；
- `keep_intermediate_onchip`：当前没有该几何表的GM写读往返；
- `reduce_memory_traffic`：它可表达原grid读取减少，但不能借此暗中授权独立的派生数学状态生成与复用变换。

任务内提案可命名为 **`proposal.reuse_derived_sampling_geometry`**，需要新增意图正文明确：

1. G/B/H不依赖复用轴；
2. 保存原数值边界和因子表示；
3. 记录生成、所有消费者、失效及容量；
4. 输出矩形owner和访问顺序变化；
5. 重算、局部保存、GM两阶段表三者成本；
6. 数值、地址、同步硬条件与收益预测分离。

**这只是未注册提案，不宣称已自主完成图注册。**当前 B 的正式实施状态为 `conditional_plan / intent_gap`；原始实现保留，不自动把竞争替代切换成已选实施方案。

# 四、统一 C2：所有权、布局、资源、同步和 KEEP

| 项目 | A：a主方案；亦适用于B′ | B：b首选条件骨架 |
|---|---|---|
| 所有权 | 保持原 blockLength线性区间；核内tile不得跨owner | 每任务唯一拥有一个通道块×空间块矩形 |
| 布局 | 外部NCDHW/grid不变；样本和六因子按输出lane组织 | 外部不变；几何按offset、mask、factor的SoA保存 |
| 数值 | 原helpers、八项顺序、每项三乘后加；不预合权重/FMA | 原helpers生成一次；原因子按位保存；每c按原次序消费 |
| GM workspace | 0B新增 | 0B新增；不做跨核几何表 |
| 核间同步 | 无新增 | 无；几何仅本owner使用 |
| 核内同步 | staging完成→Vector；各Vector依赖；结果→MTE3；搬出结束→复用 | 几何生成完成→读记录；全部c读完→覆盖记录 |
| 物理槽 | 一组；不宣称流水重叠 | 一组长期记录，无轮转预取 |

### A 的容量

采用八样本、六因子、两个乘积临时区、两个交替累加区：

\[
U_A=18A(4T)+B_{\rm API}+B_{\rm framework}.
\]

其中16份数据区可置VECCALC，两份累加区置VECOUT，最终直接从VECOUT写出，**不采用没有A3依据的GM→VECCALC扩展通路**。

T=128时显式数据区9216B。仍须满足：

\[
U_A\le U_{\rm available}.
\]

Scalar寄存器/栈另列，不能加入或替代UB账。实际SDK的API预留和可用UB未知，不能以“9216B看起来很小”填写容量已通过。

### B 的容量

若每个offset/factor平面和mask平面分别按32B对齐：

\[
U_B=8A(4St)+8A(St)+6A(4St)+B_{\rm fixed}.
\]

St=16时显式几何分配为 **1152B**，不是仅按payload算出的1024B。所有通道消费结束前，不得复用这一区域。若后续改成Vector输出、预取或私有数组，必须重新核算，不能直接继承本容量结论。

### 派发与 fallback

- 不按case名派发。
- A仅对本轮声明的a元数据启用条件实现；B仅为当前b的条件提案。
- 其他dtype、形状、插值、padding、alignCorners等走原完整路径。
- 原工程没有给出TilingKey接线，不凭空增加 `TILING_KEY_IS`。可在现有入口内用真实元数据条件选择本地helper，保持四参数ABI；若实际工程要求key，由C2在看到host启动链后冻结。
- 输入/输出别名契约未提供。批量延迟写回和B的访问重排都要求证明不会覆盖未来的X/grid输入；不能用错误的 `restrict`代替该证明。

### KEEP依据

- **没有已提供的正式父计划，不能声称 P_KEEP。**应先提取当前线性所有权计划；这一步不是并行优化收益。
- A保留原owner，但改变核内布局/通路，应交付新共同计划。
- B实质改变owner、任务次序和派生状态生命周期，明确需要P_CHANGE，且受Action缺口阻断。
- 缺模板、未运行router、容量unknown都不是KEEP理由。

# 五、C3准确实施步骤及正文对实现的实际约束

## A：获准补齐硬条件后的步骤

1. **冻结原实现和条件谓词**，保留原fallback；核验输入只读及输出不破坏未来读取。
2. Init阶段一次分配上述18份独立buffer，不在热循环分配，不使用未经证明的alias。
3. 每tile计算 `valid=min(T,end-pos)`；只对valid个输出调用原几何和 `GridRead`逻辑，按原k顺序填八样本、六因子，并把初始累加区置为原 `+0.0f`。
4. staging完成后建立Scalar写UB→Vector读的合法完成关系。可参考原Half路径的 `SetValue`后保守完成边，但仍须按目标SDK审查。
5. 对k=0…7依次：
   - `termA = sample[k] * wx[k]`
   - `termB = termA * wy[k]`
   - `termA = termB * wz[k]`
   - `accNext = accCurrent + termA`
   
   使用独立读写区，按真实V依赖同步，交替两个acc；不改算术括号。
6. 最终acc就绪后，以无mode的A3 `DataCopyPad`写回 `valid*4` 字节；UB分配按T对齐，GM长度不补齐。
7. 等MTE3读完输出区再复用。初版可采用保守单槽完成边，记录约32L条Vector依赖及每tile的staging/搬出完成成本；不得宣称已经重叠。
8. 实施前补齐具体FP32 Mul/Add的Scalar/Vector舍入、次正规数和编译器收缩行为。若不等价，恢复原算术，不能放宽oracle。
9. 后续有执行授权时，依次代码审查、构建、完整正确性、再统一计时；本轮均未执行。

## B：只交付未注册提案的实现草案

注册缺口关闭且C2批准后才可：

1. 实现互斥矩形任务及尾部映射，证明每个 `(c,p)`恰有一个owner。
2. 每空间片用原helpers生成offset、有效标记和六因子；无效offset不被解引用。
3. 对全部通道依次消费记录；通道基址使用宽整数；八项仍按源码顺序计算。
4. 保留当前标量输出通路，不夹带Vector化、DMA汇总或cache策略变化。
5. 全部通道消费完后才覆盖记录；无跨核发布，无GM表。
6. 若改Ct/St、增加输出暂存、改成全局几何表或改变输出写回通路，返回C2。
7. 没有Action资格、实际容量或数值证明时，**不把该草案报告为C3 completed**。

## 已读P/O正文如何实际改变本轮判断

- **`planning.indexing.coordinate_neighborhood`**：完整绑定了G/B/H/F、NCDHW stride和八邻域顺序；使b选择空间块×复用轴骨架，并要求a的Ct=1不虚报复用收益。其来源并非完整GridSampler移植，未赋予插值API资格。
- **`planning.elementwise.continuous`**：仅借用连续输出区间、有效tile和所有权原则；不把采样器误认成“同下标输入”的完整elementwise模板。
- **`buffer-lifetime.reuse`、`scalar-control.constant_lifetime`**：明确区分值复用、存储复用和控制外提，直接阻止把B塞进不适用Action；同时要求把记录/数组的活跃代价单列。
- **`vector-api.batch`**：A采用valid count而非误用mask；普通FP32 repeat为64元素，但不据此推断所有API尾规则，也不将32个不同依赖运算合成一次调用。
- **`memory-transfer.coalesce`、`tiling-tail.valid-length`**：A统一同owner连续输出、有效字节写回，GM不向上补写；A′也由此成为明确替代。
- **`pipeline-sync.pipeline`及fallback**：初版保持单槽最浅依赖，不因新增buffer或队列声称已流水化。
- **`precision-boundaries.numeric/bounds`**：禁止权重重结合、FMA、先越界读取再mask及擅改极端值行为。
- **`gather_output_owned`、`strided-pad`**：只支持输出独占及规则搬运原则；任意grid的源地址不是规则矩形，本轮没有用它们虚构A3 GM Gather或源窗口连续性。
- cache正文没有提供当前标量指针访问可直接受某GlobalTensor hint控制的证据；且NORMAL也不保证命中，故本轮不追加cache Action。

## 当前状态

原始源码保持不变，是唯一实际实现；正确性和性能均未由本轮验证。a已形成注册Action支持的条件试验计划；b已形成更优先的派生几何复用提案，但存在明确注册意图缺口。无正式晋升、无加速比。

|---|---|---|

## 必须区分的后继检查

**实施合法性补项：**

1. 原oracle对极端有限grid及原浮点到int64转换范围的定义。
2. 输入/输出别名和调用期间输入版本不变的契约。
3. 目标SDK的FP32 Mul/Add、Scalar→Vector完成关系、DataCopyPad实际重载。
4. 当前可用UB、框架/API预留、实际AIV核数及启动接线。
5. b的派生状态复用Action资格；未关闭前不得正式实施B。

**试验判别项，不是缺省安全门禁：**

- 编译器是否已消除部分原Scalar控制或算术，候选是否引入spill；
- a的算术节省能否覆盖staging及屏障；
- b的几何次数是否按计划减少，记录读取和256任务映射是否形成新增代价；
- 实际GM请求、HBM/L2和Task时间分别如何变化。

后继应先复用本理解和成本账，只更新真实发生变化的部分；未测结果不能作为机制反证，也不能作为继续同方案或自动增加新Key的依据。
