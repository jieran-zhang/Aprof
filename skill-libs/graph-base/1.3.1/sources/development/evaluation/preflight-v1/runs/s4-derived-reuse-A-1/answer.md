## 结论与交接状态

本轮选择如下，均为**纸面候选，不是已实施或已验收结果**：

- **a，C=1：保留原采样计算和原跨核输出分区，仅把本核连续输出暂存后批量写回。**
- **b，C=128：按“通道块×空间块”组织任务，在同一 owner 内保留原始 grid 块，供多个通道重复消费，并批量写回各通道的连续空间片。采样几何仍逐输出重算。**

b 中更值得关注的竞争方案是**共享派生几何**：反射坐标、下取整结果和轴向权重不依赖通道，可以减少大量重复计算。但输入材料明确规定，现有 `reuse_input_tiles` 和 `hoist_invariant_control` **不能自动承载这种变换**。因此本轮将它保留为独立能力提案，不夹带进原始 grid 驻留方案。

没有运行 router、计算文件 hash、修改源码、编译或上板。以下采用材料正文进行人工路由与参数化交接；正式记录还需绑定实际源码、模板版本/hash。容量和具体 SDK 的 Scalar/UB/DMA 完成协议是实施前门禁，收益未测则不是统一否决理由。

# 一、两例共用的当前代码理解

## 1. 实际执行路径

入口 `kernel.asc:190–197` 对本 workload 走：

```text
grid_sampler_3d_kernel
  → GridSampler3DScalar<float>
  → 每个 linear 调用 GridSampler3DOne<float>
  → reflection + 三线性八邻域
  → 直接 Scalar 写 GM 输出
```

不是 FP16 分支，也不是预计算几何的派生实现。当前 FP32 路径没有显式 UB 分配、DataCopy tile、Vector 算术或核间通信，不能把 FP16 类中已有的缓冲和屏障当成本路径事实。

令 \(P=DHW=32768\)，输出偏移为 \(cS+p\)，输入偏移为：

\[
cP+(zH+y)W+x.
\]

每个输出依次执行：

1. 从 `linear` 解码 \(p,c,n\)；
2. 读取同一空间点的三个 grid 分量；
3. 按源码顺序反归一化；
4. reflection、clamp；
5. 三轴 floor、差值和补权重；
6. 按源码 k=0…7 顺序读取邻居并累加；
7. FP32 原样输出。

当前核 b 独占：

\[
[b\,blockLength,\ \min((b+1)blockLength,outputNumel)).
\]

FP32 `blockLength` 为 16 元素倍数，即 64B 所有权边界；不存在跨核部分和。

## 2. 数学与数据依赖

对每个邻居，必须保留类似以下运算组织：

\[
result \mathrel{+}=((value\cdot w_x)\cdot w_y)\cdot w_z.
\]

尤其不能未经授权改成：

\[
result \mathrel{+}=value\cdot(w_xw_yw_z),
\]

也不能改成其他插值结合方式、树形求和或任意 FMA 路径。几何共享与合并乘积不是一回事。

依赖关系为：

```text
grid[n,p,:] → 坐标/边界/邻域/轴权重
                           ↓
x[n,c,邻域] → k 顺序的乘法与累加 → y[n,c,p]
```

- grid 和几何不依赖 c；
- x 的值依赖 c；相同邻域不代表不同通道读取同一个原值；
- 不同输出之间没有数学递推；
- 同一调用 grid 不变，只支持本调用内复用，不支持跨调用缓存。

## 3. 一个不能忽略的数值边界

“grid 有限”**不保证所有中间量有限且可转 int64**：极大有限 grid 可能在反归一化时溢出，或者使 `GridReflect` 的 `distance/span` 超出 int64 转换范围。源码没有显示对此的额外定义。

本轮两个所选方案均保留原坐标运算，不据“有限”擅自替换反射公式、缩窄索引或取消判界。后续若采用派生几何特化，需要明确原辅助函数的有定义域，或增加保守守卫并让未满足域继续原路径；不能悄悄把这部分输出改为零。

## 4. 源码级工作量

以下为逻辑请求或表达式次数，不是 HBM 流量、编译后指令数或时间占比。

| 项目 | a：C=1 | b：C=128 |
|---|---:|---:|
| 输出数 \(M=CS\) | 4,096 | 524,288 |
| 几何生成次数 | 4,096 | 524,288 |
| grid float 读取数 \(3M\) | 12,288 | 1,572,864 |
| grid 逻辑读取字节 | 48 KiB | 6 MiB |
| `GridRead` 调用数 \(8M\) | 32,768 | 4,194,304 |
| 有效 x 读取字节上界 \(32M\) | 128 KiB | 16 MiB |
| 输出字节 \(4M\) | 16 KiB | 2 MiB |
| 邻居加权乘法表达式 \(24M\) | 98,304 | 12,582,912 |
| 顺序累加表达式 \(8M\) | 32,768 | 4,194,304 |

越界邻居在 `GridRead` 内返回零，不发生对应 x 读取，所以 x 字节是上界。两个例子的唯一 grid 大小都是 **48 KiB**。

当前请求层总量上界分别为 192 KiB、24 MiB，尚未计 tiling 字段读取，也不能等同实际外存事务。

# 二、子例 a：C=1

## 1. 关键事实与选择理由

此时每个 grid 点只有一个通道消费者：

- 跨通道原始 grid 驻留没有可删除的重读；
- 跨通道派生几何共享也没有可减少的生成；
- 输出则是本核独占的连续 FP32 区间，目前逐元素写 GM；
- 任意 grid 不保证输入邻域在相邻输出间具有局部性。

因此选择**仅批量输出写回**。这不是认定输出是主瓶颈，而是一个覆盖完整输出、数值计算不变、资源有界的试验。

## 2. 主方案与最有竞争力的可实施替代

### 主方案：只缓冲输出

保留 `GridSampler3DOne<float>` 的计算和调用次序。每核按 T 个输出收集结果，然后写出有效区间。

初始参数：

\[
T_a=\min(256,blockLength)
\]

单位为 float 元素；本例 `blockLength` 为正的 16 元素倍数，故 \(T_a\) 也是 16 元素倍数。

设有效 owner 长度为 \(L_b\)，新写回片段数为：

\[
L_a=\sum_{b:L_b>0}\left\lceil L_b/T_a\right\rceil.
\]

变化为：

- 原来的 4096 次源码级 GM Scalar 赋值，改成 4096 次 UB 结果写入和 \(L_a\) 次批量 GM 写出；
- 输出有效字节仍为 16 KiB；
- 几何、grid 读取、x 读取和所有乘加工作保持；
- 新增单槽输出区、片段控制及完成等待；
- 不能把原 Scalar store 数与新 DMA 数的比例称为 DMA 发射加速比。

若核很多、每个 owner 只有很短区间，\(L_a\) 会接近有效核数，此时大 T 并不产生更多合并机会。

### 最有竞争力的可实施替代：grid 也连续搬入，再批量输出

C=1 且空间连续，可将每片的 `grid[p:p+v,3]` 一次搬到 UB；Scalar 从 UB 读三个原值，仍执行完整原采样计算。

与主方案相比：

- grid GM 有效字节仍是 48 KiB，没有输入复用节省；
- 约增加 \(L_a\) 次 MTE2 搬入；
- 将 12288 次源码级 grid GM 标量读取重定向为同数量的 UB 原值读取；
- 数据区从 \(A(4T_a)\) 增至：

\[
A(12T_a)+A(4T_a),
\quad A(z)=AlignUp(z,32).
\]

T=256 时为 4096B，而只缓冲输出是 1024B，均另计框架占用。

**本轮不选该替代**：它可能改善连续 grid 访存，但 C=1 没有删读依据，需额外付搬入和等待；相较之下，先单独检验输出通路更容易解释整体结果。缺测量没有证明替代无效。

### 更大方向为何不直接采用

- **向量化完整采样**：独立输出允许批量表达，但输入材料没有给出可直接采用的 A3 反射、floor、间接取数全链资格。不能用 Compare/Select 的一般正文补造完整采样 API。
- **全输入体积驻留**：每通道输入为 128 KiB，恰等于本例八邻域请求字节上界，但多 owner 可能重复全载，且还需本地取数、输出区和预留。容量未知，不能授权。
- **字段缓存/地址外提**：可能有价值，但只改变控制，不能替代对 4096 次采样数据计算和写回的比较；本轮不额外叠加。

## 3. Action 实例

纸面实例 **A-WB**：

- 注册意图：`action.batch_writeback`；
- parent：题给原始 `GridSampler3DScalar<float>`；
- target：a 的最终 FP32 输出；
- stage：`kernel.asc:146–147`；
- 覆盖：a 的全部输出；其他元数据保持原路径；
- `fragmented_writeback`：由连续输出逐元素 GM 赋值这一源码结构支持，不表示已测得瓶颈；
- `output_ownership`：沿用原 owner 区间；
- 数值约束：采样表达式、k 顺序、dtype 不变；
- capacity：以下公式条件成立后才能置 true。

无需为建立输出暂存、尾写和配套同步再登记额外 Action。

## 4. a 的 C2 计划

- **算法**：原 Scalar 采样，增加输出聚合。
- **owner**：完全保留原 `begin/end`。
- **布局**：外部 NCDHW 和 grid 排布均不变；UB 输出按本片 linear 顺序紧凑排列。
- **workspace**：新增 GM workspace 为 0。
- **容量**：

\[
U_a=A(4T_a)+F_a\le U_{\mathrm{available}},
\]

其中 \(F_a\) 是实际 SDK/框架预留及其他实际分配，不能填成未经确认的零。

- **生命周期**：输出槽从首次结果写入活到 MTE3 最后读取完成；之后才能覆写。
- **同步**：结果产生→搬出就绪、搬出完成→槽复用两条边必须落实。首版采用单槽、保守完成边，不声称流水重叠。
- **KEEP**：没有输入的完整父计划可引用，不能写 P_KEEP。记录 P_CHANGE，同时区分：
  - 原算法和 owner 是“提取已有计划”；
  - 输出 UB、搬出通路和生命周期是实际计划变化。

# 三、子例 b：C=128

## 1. 关键事实与方案选择

每个 grid 点的原始三分量在全部 128 个通道中相同。当前实现却逐输出读取和计算。

本轮选择：

> 同一 owner 处理一个通道块的连续空间片，先搬入一次原始 grid 片，逐通道从该只读片读取原值，继续逐输出计算原几何，最后批量写出每通道的空间片。

选择它的依据不是“比几何共享一定快”，而是：

1. 原始 grid 的同地址同值复用可以明确证明；
2. 现有注册 Action 和具体输入驻留正文准确覆盖它；
3. 不需改变反射和插值计算组织；
4. 可在很小的显式 UB 数据区中检验删读与写回聚合；
5. **并未把派生几何机会宣告解决**。

## 2. 主方案的完整工作变化

纸面初值：

\[
C_t=8,\qquad S_t=64.
\]

二者分别为通道数、空间点数，不是性能最优阈值。

任务为：

\[
[c_0:c_0+8,\ p_0:p_0+64].
\]

本例恰有：

\[
Q=\frac{128}{8}\frac{4096}{64}=1024
\]

个独立任务。每任务生成 512 个输出。

任务内部：

```text
搬入 grid[p0:p0+64, 3]
for c in 本任务8个通道:
    for p in 本任务64个空间点:
        从驻留原始grid读 gx/gy/gz
        完整执行原几何和八邻域累加
        写本通道输出UB
    批量写出该通道64个结果
```

### 逻辑工作账

| 项目 | 原实现 | 主方案 |
|---|---:|---:|
| grid 逻辑读取字节 | 6 MiB | 768 KiB |
| grid 搬入片数 | 无此 DMA 分片结构 | 1024 |
| 几何生成次数 | 524,288 | **524,288，不减少** |
| x 有效读取上界 | 16 MiB | 16 MiB |
| 输出有效字节 | 2 MiB | 2 MiB |
| 输出批量写出次数 | 原为逐元素 Scalar 写 | 8192 |
| 显式数据区 | 无 UB tile | 1024B |

grid 读量公式为：

\[
12NS\left\lceil C/C_t\right\rceil
=12\cdot4096\cdot16
=786432\text{B}.
\]

删除的逻辑 grid GM 请求为：

\[
12NS\left(C-\left\lceil C/C_t\right\rceil\right)
=5.25\text{ MiB}.
\]

新增和保留代价：

- 每输出仍有三个 UB 原值读取，仍有完整几何和八邻域算术；
- 原有全通道平面扫描改成通道块内的空间片扫描，改变缓存复用距离；
- 增加任务解码、1024 次 grid 搬入、8192 次输出搬出及对应完成边；
- grid 驻留区不能在八个通道消费结束前覆盖；
- 采用单输出槽，每次写完才能处理下一通道的同槽结果；
- 逻辑删读不能直接记为 HBM 减少 5.25 MiB；原读取可能已被缓存服务。

## 3. 最有竞争力的替代：同任务内共享派生几何

保持同样的 \(8\times64\) 矩形任务，先为每个 p 生成一次：

- `x0,y0,z0`：三个 int64；
- `dx,wx0,dy,wy0,dz,wz0`：六个 float。

每点载荷为：

\[
3\cdot8+6\cdot4=48\text{B}.
\]

随后八个通道消费记录，但仍保持 `((value*wx)*wy)*wz` 和 k 顺序；不预乘最终八权重。

### 在辅助函数有定义的域内

几何生成可从：

\[
CS=524288
\]

降为：

\[
S\lceil C/C_t\rceil=65536,
\]

减少 458752 次几何生成，即减少对应反归一化、反射、floor、差值和补权重工作。**不减少 x 的跨通道取数。**

若使用明确的 UB SoA 表加单通道输出：

\[
U_D=48S_t+4S_t+F_D=3328+F_D\text{B}.
\]

若每点再保留一个 uint32 安全/有效域标记，则为：

\[
U_D=56S_t+F_D=3584+F_D\text{B}.
\]

代价还包括：

- 每记录一次写入、每输出读取派生状态；
- 按 48B 载荷的直接表述，记录写载荷约 3 MiB、读取载荷约 24 MiB，均为逻辑本地访问，不是外存流量；
- 更多活跃 Scalar 状态、UB 读写和可能的寄存器/栈代价；
- 特殊数值域守卫、记录有效性及生命周期；
- 若扩大到 \(C_t=128\)，几何可进一步降到 S 次，但空间任务只剩 64 个，需重新比较可用核和最长核。

### 为什么本轮不把它作为已注册实施成员

这是**派生数值计算复用**，不是原始输入驻留，也不是单纯控制外提。材料中的以下边界直接改变了选择：

- `action.reuse_input_tiles` v0006 明确不自动覆盖新计算的坐标、权重；
- `action.hoist_invariant_control` v0006 明确不自动覆盖改变数值计算组织的几何生成与驻留；
- `planning.indexing.coordinate_neighborhood` 允许分析该骨架，但要求缺合法意图时保留提案。

因此登记任务内能力提案 **“按依赖轴生成并复用派生几何状态”**，状态为 **unadmitted，未注册**。它应独立要求证明数值顺序、复用轴、记录有效域、容量和所有权。不能虚构一个已存在的 Action ID，也不以“方案里已有其他注册成员”放宽意图边界。

这是一条很强的后继机会；本轮选择原始 grid 驻留并不是性能上排除了它。

## 4. 其他会改变选择的竞争方向

- **NCDHW→通道连续布局再向量采样**：仅 b 的完整输入转置就需约 32 MiB 有效读写，随后还有采样和可能的输出转换。它可能换来更好的通道批量计算，但不是免费局部重排，且完整 Vector 数值链尚无资格依据，本轮不选。
- **仅批量输出**：无需改变 owner，也无需 grid 输入区，是成本更低的退路。它保留 6 MiB grid 逻辑读和全部几何；若主方案的任务重排或 UB 取值成本抵消删读，应重新比较它。
- **L2 hint**：没有证据说明当前策略错误；既有原始指针读取也不能不经核验就实例化 GlobalTensor hint 路线。NORMAL/PERSISTENT 等不能代替本地原值保留。
- **增加并行或拆八邻居归约**：当前输出已有大量独立任务，没有需要拆 k 的依据；拆 k 还会引入部分和及舍入顺序问题。

## 5. b 的 Action 实例

### B-GRID：`action.reuse_input_tiles`

- target：原始 `grid[n,p:p+S_t,3]`；
- stage：原 `kernel.asc:106–109` 的读取及其全部通道消费者；
- parent：原始 FP32 Scalar 实现；
- 窗口：同一调用、同一矩形任务的最多八个通道；
- 原值保持：VECIN grid 区只读，不作原地数值计算，不与输出区别名；
- 同区域证明：同组通道读取完全相同的三个分量及相同有效 p 区间；
- 失效：任务结束后即可覆盖；不同任务、调用不得沿用旧值。

### B-WB：`action.batch_writeback`

- target：每个 `(n,c,p0:p1)` 连续输出片；
- stage：原逐元素输出赋值；
- 每片 64 个结果全部产生后写回；
- 不跨通道空洞，也不覆盖其他 owner。

两个成员有不同目标：一个删原始输入重读，一个合并最终输出写出。共同 grid 读量只计算一次，不再叠加 `reduce_memory_traffic` 宣称第二份节省。

## 6. b 的 C2 统一计划

### 所有权与分配

任务编号：

\[
q=g_c\cdot64+g_p,\quad
g_c\in[0,16),\quad g_p\in[0,64).
\]

对应：

\[
c_0=8g_c,\qquad p_0=64g_p.
\]

将 Q=1024 个任务按商余分配给 B 个启动 block：

\[
start_b=b\lfloor Q/B\rfloor+\min(b,Q\bmod B),
\]

\[
count_b=\lfloor Q/B\rfloor+[b<Q\bmod B].
\]

每个输出恰属于一个矩形、一个 block。每通道空间片长 256B，p 起点为 64 的倍数，保留清晰的物理输出边界。

Host 可在该精确元数据分支将 `blockNum` 设为 `min(available,1024)`；`available` 仍来自现有 `cores` 参数，不写死硬件核数。实际 launch 是否使用该字段未在输入中展示，C3 接线前必须核对。

### 布局与通路

- 外部输入/输出 NCDHW 不变；
- grid：GM 紧凑三分量片→VECIN，只读驻留；
- 输出：单通道连续空间片→VECOUT→GM；
- x：仍按原 `GridRead` 在 GM 间接读取；
- 无输入转置、无 GM 几何表、无核间共享 UB。

### workspace、容量和生命周期

新增 GM workspace：

\[
W_b=0.
\]

显式 UB：

\[
U_b=A(12S_t)+A(4S_t)+F_b
=768+256+F_b
=1024+F_b.
\]

grid 和输出同时存活，必须相加，不能取 max；二者不共享存储。无高阶 Select/Broadcast API，不能误加其 scratch，也不能漏计实际框架预留。

依赖：

```text
MTE2 写 grid → Scalar 读取 grid
所有8个通道最后读取 grid → 下一任务 MTE2 覆写 grid

Scalar 产生输出槽 → MTE3 读取输出槽
MTE3 最后读取输出槽 → 下一通道覆写输出槽
```

首版单槽、保守串行完成，不增加双缓冲。不存在核间归约或跨核 ready/free。

### KEEP 依据

b 改了任务和输出 owner 映射，必须 **P_CHANGE**。两个成员都要落实局部实现，不能 O_KEEP。派生几何仍逐输出生成不是遗漏实现，而是本计划明确的数值组织边界。

# 四、共同 C3 实施步骤与正文实际影响

以下是准确实施要求，不表示本轮已经打 patch。

## 1. 派发与 ABI

保留现有四参数 kernel ABI、tiling 结构和通用函数。

只新增互斥的精确元数据分支：

- FP32、N=1、D=H=W=32、S=4096、bilinear、reflection、alignCorners=false、C=1；
- 相同条件、C=128；
- 其他所有元数据走原 FP32/FP16 fallback。

无需仅为本轮增加新的外部 kernel entry 或 TilingKey ABI。可在交接中为三个逻辑路径给稳定标识，但不能声称源码已有实际 key 启动证据。原始 `outD/outH/outW` 仍保留，计算只依赖其乘积 S，不按 case 名分派。

## 2. a 的修改步骤

1. 初始化一个输出 UB 槽，按 \(A(4T_a)\) 字节分配。
2. 保留原 `begin/end`，空 owner 不发搬出。
3. 每片计算 `valid=min(T_a,end-offset)`。
4. 原样调用 `GridSampler3DOne<float>`，将结果按顺序放入输出槽。
5. 在结果到搬出的合法完成点后，用无 mode 的 A3 `DataCopyPad` 写出：
   - `blockCount=1`；
   - `blockLen=valid*sizeof(float)`，单位为字节；
   - 两端 stride=0；
   - 不写 UB padding。
6. 等 MTE3 完成读槽后再覆盖，最终退出排空。

## 3. b 的修改步骤

1. 将原采样函数中的“读取三个 grid 原值”与后续计算分离，形成接受 `gx,gy,gz` 的内部函数。
2. 原 `GridSampler3DOne` 继续可用，并调用同一数值主体，避免候选和 fallback 公式漂移。
3. 新主体仍逐输出执行反归一化、reflection、floor、轴权重和八次累加；不得保存或跨 c 复用这些派生值。
4. 初始化独立 VECIN grid 槽和 VECOUT 输出槽。
5. 按 C2 的任务编号解码矩形，搬入一次有效 `3*validS` 个 grid float。
6. 在输入完成后，逐通道、逐 p 取原始三分量并执行采样。
7. 每通道结果完整后写出 `validS*4` 字节，完成后复用输出槽。
8. 全部通道最后一次 grid 读取完成后，才开始下一任务覆写该 grid 槽。

若选择进一步缓存派生坐标、扩大 \(C_t\)、改变输出矩形、增加预取槽或全局几何表，均超出本计划，返回 C2。

## 4. 同步和 SDK 的具体实施门禁

材料支持 A3 无 mode DataCopyPad 的方向、单位和有效字节规则，也有原 FP16 路径的 Scalar `SetValue` 后屏障及后续流水示例。但输入没有展示目标工程 SDK 版本及完整 Scalar/LocalTensor 同步契约。

因此实施前应具体核对：

- FP32 `SetValue/GetValue` 在所用 UB 位置的支持；
- MTE2→Scalar 读取本地 grid 的完成/可见性；
- Scalar 写 UB→MTE3 读取输出的完成/可见性；
- 单槽复用和退出排空；
- 实际可用 UB、编译器额外资源。

首版可采用 SDK 已支持的保守完成协议，但不能把“放一个任意方向 barrier”当作证明。无法闭合则保持原路径，不通过修改数
