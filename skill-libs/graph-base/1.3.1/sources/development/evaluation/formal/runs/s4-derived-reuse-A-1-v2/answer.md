## 结论与交接状态

本轮按**原始 `GridSampler3DScalar<float>`**分析，不把“几何已经预计算”当成父本事实。

- **子例 a，C=1**：选择一个注册 Action——**连续输出在本核 UB 汇总后批量写回**。保持全部坐标、反射、取数及插值运算原样，只改变输出搬出。它是有依据的静态试验，实施前仍须闭合目标 SDK 的标量 UB 写入完成协议和可用 UB。
- **子例 b，C=128**：最值得优先规划的是**同 owner 跨通道复用派生几何**。但当前材料中的注册 Action **不能准确承载这项独立变换**，因此本轮明确提出能力缺口，交付条件化 C2 和准确的实施草案，**不伪装成已注册、可直接进入 C3 的方案**。最强注册替代是仅驻留原始 grid、仍逐输出重算几何；它可以独立试验，但不等于解决派生几何重复。

两例均未修改、编译或运行；正确性、性能均为 **not_measured**。以下纸面实例名仅用于交接，不是假造的文件 hash、router 回执或机器验收结果。

## 一、共同理解：实际路径、数学与数据依赖

### 1. 当前实际执行路径

依据 kernel 第190–197行，FP32 调用进入：

```text
grid_sampler_3d_kernel
  → GridSampler3DScalar<float>
  → 对本核连续 linear 区间逐元素调用 GridSampler3DOne<float>
  → GM 标量写 out[linear]
```

当前路径没有使用第151–188行 Half 类中的 UB、Cast、DataCopyPad 或屏障；不能把那些代码里的策略算到当前 FP32 基线上。

令 \(S=4096\)、输入空间大小 \(I=32^3=32768\)、输出数 \(M=CS\)。原索引为：

\[
s=linear\bmod S,\quad nc=\lfloor linear/S\rfloor,\quad
c=nc\bmod C,\quad n=\lfloor nc/C\rfloor .
\]

本任务 \(N=1\)，grid 地址为 \(3s+j\)，与 c 无关；X 地址为：

\[
cI+(zH+y)W+x .
\]

所以：

- **grid 原值跨通道相同**；
- **坐标、反射结果、下界坐标和单轴权重也不依赖 c**；
- **X 值依赖 c**，几何相同不意味着各通道的 X 是同一输入切片。

### 2. 数值与读取顺序

每轴严格沿用源码：

\[
u=((g+1)\cdot32-1)\cdot0.5
\]

再执行第58–68行 reflection：以 \([-0.5,31.5]\) 为反射区间，最后 clamp 到 \([0,31]\)。随后计算下界、差值及补权重。

对正常得到合法反射坐标的点，记每轴权重为 \(a_k,b_k,d_k\)，结果必须保持：

```text
result = +0
k=0…7：
    value = 原 GridRead 对应邻居；越界返回 +0
    result += ((value * a_k) * b_k) * d_k
```

必须保留：

- 第125–132行 k=0…7 的顺序；
- 单项乘法结合次序，不改成“先乘三轴权重，再乘 X”；
- 越界先判定、后取数，不能越界读取后乘零；
- 原 FP32 路径，不插入 half 转换，不擅自改变 FMA/舍入配置。

**继承的边界疑点**：grid“有限”本身不能保证 `GridUnnormalize` 不溢出，也不能保证 reflection 中 `distance/span` 可表示为 int64。原源码对极大有限 grid 的转换行为尚未由当前材料闭合。本轮不以取模反射、截断或饱和转换替换它，也不偷偷把输入域收窄到 `[-1,1]`；后续需向原 oracle 明确极大有限值行为。以下数量中，合法反射坐标的邻域界限均附此前提。

### 3. 当前分核和同步

tiling 第40–45行按输出元素数决定：

\[
B=\min(A,\lceil M/16\rceil),\quad
L=16\left\lceil\frac{\lceil M/B\rceil}{16}\right\rceil ,
\]

其中 \(A=\max(1,cores)\)，不是已知物理核数。核 b 拥有：

\[
[bL,\min((b+1)L,M)).
\]

所有输出只计算、写入一次，无核间归约。当前 FP32 路径无显式 UB 生命周期或跨流水事件；这不证明编译后的执行时间完全串行，也不证明访存是 MTE DMA。

### 4. 可复算的源码工作量

令 \(V=\sum_s K_{\rm valid}(s)\)。反射坐标合法时，每点至少下界邻居有效，\(S\le V\le8S\)。

| 项目 | a：C=1 | b：C=128 |
|---|---:|---:|
| 输出 M | 4,096 | 524,288 |
| 几何生成次数 | 4,096 | 524,288 |
| grid 标量读元素数 \(3M\) | 12,288 | 1,572,864 |
| grid 逻辑请求字节 | 49,152 B | 6,291,456 B |
| grid 唯一原值字节 | 49,152 B | 49,152 B |
| 有效 X 标量读数 | V | 128V |
| X 有效请求字节范围 | 16,384–131,072 B | 2,097,152–16,777,216 B |
| 输出字节 | 16,384 B | 2,097,152 B |
| 插值乘法 \(24M\) | 98,304 | 12,582,912 |
| 顺序累加 \(8M\) | 32,768 | 4,194,304 |

每次几何另含三次 unnormalize、三次 padding/reflection、三次 floor，以及差值/补权重计算。上表是**源码逻辑操作和有效请求**，不是编译后指令数、HBM 流量或时间占比。

## 二、子例 a：选择批量输出写回

### 1. 选择依据与覆盖

C=1 时，每个 s 只使用一次 grid 并生成一次几何：

- 跨通道原始 grid 驻留和派生几何复用都没有复用倍数；
- 任意 grid 不保证相邻输出访问相邻 X，不能由输出连续推定源窗口局部；
- 整个 X 为131,072 B，已与最多131,072 B 的有效标量请求同量级。全 X 搬入再本地寻址既可能读入未使用位置，也可能被多个空间 owner 重复搬入，不宜仅凭“能放片上”选择。

输出则确定连续、独占，当前有4096次标量 GM 写。因此选择：

**方案 `a-output-batch`：本核每 T 个输出先写 UB，生成完整片段后以一次有效长度 DMA 搬出。**

仅优化 FP32 目标路径的输出阶段；全部输入访问和数学运算保持原样。其他形状、dtype、模式使用原路径。

### 2. Action 实例

采用已给出的 **`action.batch_writeback`，D v0006**：

- **target**：FP32 输出 `out`，原 kernel 第146–147行写回；
- **stage**：每个输出完成后至最终 GM 写回；
- **workload**：本例元数据，尤其 C=1；
- **implementation/parent**：输入所给原始 Scalar 实现；
- **结构依据**：同 owner 的相邻有效输出被逐元素写回，调用内没有中途外部消费者契约；
- **不变量**：输出覆盖和 owner 不变；计算、异常值与舍入不变；DMA 不越过核边界或有效尾部。

这里不是声称原先已有4096次 MTE3 发射。原先是4096次**标量 GM 写**；候选引入 UB 汇总和 DMA。

### 3. 全部工作变化及最强替代

设本核有效长度为 \(L_b\)，总输出片数：

\[
J=\sum_{b:L_b>0}\left\lceil L_b/T\right\rceil .
\]

| 工作 | 基线 → 主方案 |
|---|---|
| 几何、GridRead、插值 | 完全保留 |
| 标量 GM 输出写 | M → 0 |
| 标量 UB 输出写 | 0 → M |
| DMA 有效输出字节 | 0 → \(4M=16,384\) B |
| DMA 输出片数 | 0 → J |
| 显式输出存储 | 0 → `AlignUp(4T,32)` B/核 |
| 新增依赖 | UB 生成完成→搬出；搬出读完→覆写同槽 |

建议纸面初值 **T=64**，数据区256 B；不是测得最佳值。容量许可范围可为正的16倍数，且搬运长度、计数字段均合法。当前核边界为16元素，单核尾片也可保持64 B倍数。若每核恰好仅一小片，仍需比较暂存和屏障成本，不能由全局 M/T 推断实际 J。

**最有竞争力替代：批量 Vector 插值。**

可保留反射、floor 和离散 GridRead 为 Scalar，将每个 k 的样本及轴权重组织为向量，按“三次 Mul、一次 Add”处理 T 个输出：

- 可替换的算术域是 \(24M\) 次 Scalar 乘法、\(8M\) 次 Scalar 累加；
- 粗略为每片24个 Mul、8个 Add 的批量表达，API 内部拆分另计；
- 仍保留逐点几何和至多8M次离散 X 读取；
- 新增样本/权重暂存、Scalar→Vector 完成边、Vector内部依赖、输出暂存及尾处理；
- 必须证明目标 Scalar 与 Vector FP32 的舍入、次正规数和收缩行为符合原契约，不能只用“都是 FP32”通过。

它触及的工作规模比输出写回大，**不是因为无性能实测而被排除**；本输入材料尚未闭合上述精确数值/API条件，当前不能给它 `semantic_equivalence=true`。本轮输出方案保持原数学路径，合法性缺项更小且具体，故先选输出搬出试验。

另一个较轻替代是每片批量搬入连续 grid：新增 `AlignUp(12T,32)` B 和每片一次 CopyIn，但仍需3M次本地标量读取、全部几何和 X 访问。C=1 不删任何重复原值读取；不将它算作输入驻留收益，也不作为本方案必要成员加入。

### 4. a 的 C2 共同计划

采用 `planning.indexing.coordinate_neighborhood` 的**输出连续空间块骨架**：

- G/B/H/F 分别绑定上述原 unnormalize、reflection、floor/权重和顺序插值；
- X/grid保持 GM 原布局，输出保持 NCDHW；
- 完整保留现有 linear 分区，不调整核数、owner和顺序；
- 核内输出切片 T，单物理输出槽，workspace=0；
- 输出槽生命周期覆盖本片全部 Scalar 写入至 DMA 最后读取完成；
- 无核间同步，不引入双缓冲或预取。

容量条件：

\[
U_a=\operatorname{AlignUp}(4T,32)+U_{\rm SDK/fixed}\le U_{\rm available}.
\]

当前可用 UB、框架预留及目标 SDK 的合法标量 UB 访问/完成协议未给出，因此是**条件计划**，不是资源 ready。

**KEEP依据**：没有输入绑定的完整有效 parallel plan，不能直接写 P_KEEP。本轮应记 **P_CHANGE**，其中跨核部分只是“提取并保持已有分区”，真正变化是核内输出暂存、通路和生命周期；O 为实际写回改变，不是 O_KEEP。

### 5. a 的 C3 准确步骤及正文影响

在条件补齐后，一次候选完成：

1. 保留原 kernel ABI、FP16 分支和通用 Scalar fallback。
2. 只在本轮元数据谓词命中时进入输出暂存路径；不按 case 名称分派。
3. Init 一次申请32 B对齐、`AlignUp(4T,32)` B 的合法输出 UB 区，不在热循环反复分配。
4. 每片取 `valid=min(T,end-pos)`，逐 i 调用**原 `GridSampler3DOne<float>`**，用 Scalar 写 UB 对应位置。
5. 按目标 SDK 核验的 Scalar UB生产→MTE3消费完成协议发布该片；采用保守完成边亦须确认其支持，不能只靠程序顺序。
6. 用 A3 无 mode 的 UB→GM DataCopyPad，`blockCount=1`、`blockLen=4*valid` 字节、stride为0；仅写有效区间。
7. 等 MTE3 读完后才复用槽；空 owner不发搬运，末片同样排空。
8. 复核实际分支、UB分配、全部输出覆盖和未变数学表达式，再交后续审查、构建与原 oracle验证。本轮不执行这些步骤。

实际采用的 O 正文及影响：

- **`implementation.memory-transfer.coalesce`**：将合并限制在同 owner、相邻、已全部生成的输出，不跨核拼片。
- **`implementation.tiling-tail.valid-length`**：分开有效元素、UB申请字节和 `blockLen`；不扩大 GM 尾写。
- **`implementation.precision-boundaries.bounds/numeric`**：不改乘法结合和累加顺序，保留原 FP32 函数。
- **`implementation.pipeline-sync.fallback`**：首版选择单槽浅路径，明确最后读者完成；不把队列/槽存在解释成已重叠。

## 三、子例 b：优先派生几何复用，明确 Action 能力缺口

### 1. 主要机会

同一次调用中，每个 s 的 grid不变，原代码却跨128通道重复：

- 读同一 grid三元组；
- unnormalize和reflection；
- floor；
- 构造差值和补权重。

因此最值得先规划的是：

**方案提案 `b-derived-geometry-reuse`：一个 owner拥有一段空间点的全部128通道；按空间片构造一次派生记录 D，再逐通道消费。**

采用保守表示：

```text
D[s] = x0,y0,z0：各 int64
       dx,dy,dz,wx0,wy0,wz0：各 float
```

每点48 B。不预乘三轴权重，不缩窄坐标或权重；消费者仍使用原 `GridRead`及原八项表达式。

### 2. 工作变化、残余与新增代价

几何生成由：

\[
CS=524,288\quad\longrightarrow\quad S=4,096
\]

即减少520,192次几何构造。grid逻辑请求由6,291,456 B降为49,152 B；这与同一次构造减少关联，**只计一次，不再另加一份“输入复用收益”**。

保留：

- 每输出8项有序插值，乘法、累加数量不变；
- X跨通道不同，有效请求仍为128V；
- 原 bounds判断和地址形成可以继续逐输出执行；
- 输出仍为2,097,152 B，每值只算、写一次。

新增：

- D写入 \(48S=196,608\) B 的本地数据；
- 若每个消费者完整读取记录，D读取 \(48CS=25,165,824\) B 的本地数据；
- 按九个字段计，最多约 \(9S\) 次字段存储及 \(9CS\) 次字段读取；实际生成代码待确认；
- 更长 D生命周期，通道遍历切换和多个短输出段；
- 更改 owner：从原 linear连续片改成“空间片×全部通道”。

这些本地读取不能当作免费；也不能与减少的 GM字节直接相减得到时间收益。

### 3. 最强注册替代：只驻留原始 grid

实例可用 **`action.reuse_input_tiles`**，目标只绑定原始 `grid[s,0:3]`，不是 D：

- 同一个空间 owner保留原 grid片；
- 128个通道消费者仍分别执行原 G/B/H；
- grid逻辑 GM请求同样从6 MiB降至48 KiB；
- 驻留仅 `AlignUp(12St,32)` B；
- 本地写入49,152 B，本地读取6,291,456 B；
- 几何仍做524,288次，插值与X请求不变。

与主提案相比，它省容量、本地字段流量和实现复杂度，但保留了127/128可共享的反射/floor/权重构造。若几何编译成本低、D字段重载代价大，原始grid驻留可能更好；若reflection及其转换链显著，D复用更值得尝试。现在不能给两者排出实测速度，但后者确实针对更大的重复计算，故作为优先咨询方案。

**两阶段 GM几何表**是另一竞争骨架：几何全局生成S次，随后保留原连续输出 owner。按48 B记录，新增至少196,608 B表写和25,165,824 B表读，还需额外 kernel边界/发布、workspace及启动接线；当前可见 ABI没有workspace参数和启动链，不能把它列为已可实施。故优先核内D，不选全局表。

内部转为通道连续布局还会增加X转换和输出回转；当前输入16,777,216 B，若完整 out-of-place转换，仅X额外读写就有33,554,432 B，且没有跨调用缓存摊销。不凭“通道向量化”忽略这笔一次性代价。

### 4. Action 能力审查：不强套现有名字

本提案的独立目标是**改变派生几何计算组织并保存数值结果**。已给 Action正文明确约束：

- `hoist_invariant_control` 不自动覆盖派生坐标、权重生成与驻留；
- `reuse_input_tiles` 保存的是输入原值，不是新计算的D；
- `keep_intermediate_onchip`要求父实现存在同一中间tensor的GM往返；原代码不存在D表；
- `restructure_broadcast`不能仅因几何跨c相同，就自动授权整个插值派生计算重排。

因此登记一个**任务内待注册意图提案**：派生坐标/权重状态按依赖轴复用。必要条件至少包括：

1. G/B/H不依赖被复用轴c；
2. 保留全部原数值边界和权重表示；
3. D完整写入、最后消费者结束前不覆盖；
4. 新owner输出完整互斥、别名与可见性合法；
5. D及全部同时存活状态满足容量；
6. 元数据适用域及fallback完整。

**当前缺口是没有适用注册意图，不是缺性能profile。** 本轮不把此提案当正式注册Action，不授权C3借替代Action夹带实施；也不因已有原始grid驻留Action便宣布主要机会已解决。

### 5. b 的条件化 C2 共同计划

采用 **`planning.indexing.coordinate_neighborhood` 的“复用轴块×空间块”骨架**，不是仅借用 Gather模板名称。

#### 所有权

取空间所有权粒度 \(g=16\)，共 \(Q=S/g=256\) 个空间单元。使用启动中的B个block，按q/r均分这些单元：

\[
q=Q//B,\ r=Q\bmod B,\quad
u_b=bq+\min(b,r),\quad m_b=q+[b<r].
\]

核b拥有空间区间 \([16u_b,16(u_b+m_b))\) 的**全部通道**。各核输出集合互斥，并集是完整 `[C,S]`。

- 若B>256，部分核为空，必须直接走空任务路径；
- 当前可用核数、真实启动方未给出，不写死910C核数；
- 可保留现启动和tiling ABI，核内按该映射解释；若后续调整实际BlockDim，须核对未提供的launcher并回C2绑定。

#### 核内片与布局

- \(St\)可选16、32、64等16的倍数，实际片长裁剪到owner范围；
- D用九个独立对齐SoA区，避免未确认的结构体padding；
- D构造后，依次消费c=0…127，每个c内按s递增；
- X/grid/y外部布局完全不变；
- 首版输出继续原Scalar GM写，不夹带批量写回；
- workspace=0，无跨核通信或归约。

容量：

\[
U_b=
3\,A(8St)+6\,A(4St)+U_{\rm fixed/SDK}
\le U_{\rm available},\qquad A(z)=AlignUp(z,32).
\]

St为16倍数时显式D区为48St：St=16需768 B，St=64需3072 B。**这些只是已列数据区，不证明总资源已通过**。不把D放自动私有数组而宣称零代价；若改放私有数组，应另审寄存器、栈和spill。

#### 生命周期和同步

```text
Scalar构造D全部有效字段
 → 保证本地写入对消费者可见
 → 128个通道按原顺序读取D并计算
 → 最后通道最后一次D读取完成
 → 下一空间片才覆盖D
```

不添加跨核barrier，不以 `volatile`替代完成协议。目标LocalTensor标量读写和依赖协议必须核验。

**KEEP依据**：owner、循环组织和D生命周期均改变，明确 **P_CHANGE**；不能P_KEEP。因注册意图缺失，O状态为“未获实施资格/能力缺口”，不是O_KEEP，也不是NOOP。

### 6. b 的 C3 交接与当前停止点

**当前C3不得落地该主提案。** 注册意图及合法性闭合后，准确实现顺序应为：

1. 固定新的方案/计划身份；元数据域只含本轮声明的FP32、N=1、32³、S=4096、C=128、bilinear/reflection/alignCorners=false，其余进入原fallback。
2. 保留原kernel入口ABI；接入空间owner映射，核对实际启动B与tiling一致。
3. Init一次分配九个D区；不跨调用保留任何缓存。
4. 对当前有效空间片，逐点执行原第107–124行同等运算，保存三个int64下界和六个float因子。
5. 对每个c、s，读取对应记录，生成上界坐标，按原bounds/stride读X，严格执行第125–132行八项表达式并写唯一输出。
6. 完成全部128通道消费后复用D；空owner不构造地址、不等待未发生的生产。
7. 核对fallback、数值表达式、输出覆盖和D容量。若改用Vector、增加输出DMA、全局几何表或改变Ct，须按变更范围重新审查C2及Action，不能作为局部自由度悄悄加入。
8. 后续才进行目标SDK审查、构建、原oracle完整正确性和整个候选计时。

正文对方案的实际影响：

- **P `coordinate_neighborhood`**：明确“几何同、X不同”，促成空间owner跨c，而不误报X读减少。
- **O `buffer-lifetime.reuse`的值/存储区别**：D是保留同一个派生值，不能按不交叠临时区取max，也不能借输入驻留Action通过。
- **O `scalar-control.constant_lifetime`**：要求比较重算与活跃状态，不凭“不变量”一词授权预计算。
- **O `precision-boundaries.numeric`**：因此保留六个单轴因子，拒绝预乘八个三轴权重。
- **O `memory-transfer.input-tile-residency`**：仅支持上述原始grid替代；它的原值、owner、最后消费者条件不能自动证明D方案。
- **P `layout.transpose`**：要求完整计算转换与中转字节，因而本轮不选择内部通道连续化。
