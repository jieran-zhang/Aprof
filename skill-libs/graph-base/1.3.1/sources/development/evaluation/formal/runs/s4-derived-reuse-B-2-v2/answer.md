## 结论与交接状态

本轮选择两个不同的纸面方案，不组合成一个“大而全”候选：

- **子例 a，C=1：选择保持原标量计算、在本核汇集连续输出后批量写回。**采用一个 `action.batch_writeback` 实例。它不减少坐标计算和邻居读取，只改变输出通路。C2 给出有容量门禁的单槽方案；由于实际可用 UB 未提供，状态为 **conditional_plan**，不能宣称已具备实施资格。
- **子例 b，C=128：选择同一空间点的几何结果生成一次，由同一核依次供全部通道消费。**采用一个 `action.reuse_derived_results` 实例。首版使用固定标量状态，不引入 UB 几何表、GM workspace 或第二个 kernel。它是具体可实施的源码级试验设计，但编译资源、完整正确性和收益均未验证。

两者均保留原始实现作为互补元数据域的 fallback。**没有执行工具、修改源码、编译或测量；以下不是 C3 completed，也不虚构路由回执、hash 或正确性通过。**正式后继应将本文选择绑定到 action-decision/v3、handoff/v4 及实际源码身份；不能用本文中的名称代替文件 hash。

# 一、共同的当前实现与数值边界

## 1. 实际执行路径

当前入口在源码 190–197 行选择 `GridSampler3DScalar<float>`，不会进入 151–188 行的 half 缓冲、Cast、DataCopyPad 路径。

令：

\[
I=DHW=32768,\qquad S=4096,\qquad M=NCS=4096C.
\]

输出线性位置为：

\[
\ell=(nC+c)S+p,
\]

其输入平面基址为 `(n*C+c)*I`，grid 地址为 `(n*S+p)*3`。因此：

- 输出按通道平面连续写，平面内 \(p\) 连续；
- grid 不依赖 \(c\)；
- 输入值依赖 \(c\)，不同通道不是同一原值，不能因几何相同而合并读取。

tiling 41–45 行按 FP32 的 **16 元素、64B 所有权边界**分配连续输出区间。核数取决于传入的 `cores`，不能补写为某个固定物理核数。每核最终区间由源码 143–145 行裁剪。

当前 FP32 路径是 GM 标量读取、标量计算、GM 标量写出；没有源码可见的 UB 数据区、DMA 分块或跨核同步。也没有证据证明实际硬件流水完全串行。

## 2. 数学及严格数据依赖

每轴先按原顺序执行：

\[
u=((g+1)\cdot32-1)\cdot0.5,
\]

然后调用原 `GridReflect`：本例反射端点为 \(-0.5,31.5\)，span 为 32，反射后 clamp 到 `[0,31]`。

随后得到六个整型邻居坐标、三个小数部分和三个补权：

\[
x_0,y_0,z_0,\ x_1,y_1,z_1,\quad
dx,dy,dz,\quad 1-dx,1-dy,1-dz.
\]

每个输出必须保留源码 125–132 行的 **k=0…7 顺序**。每项仍是：

```text
((value * xWeight) * yWeight) * zWeight
```

再累加到初值 `0.0f`。不能改为预先计算三轴权重乘积后执行 `value*weight`，也不能改成分层插值、pairwise 或 FMA。数学实数等价不代表原舍入边界等价。

`GridRead` 必须先判界再读取。正常、可定义的反射结果下，floor 坐标在 `[0,31]`，上邻居仍可能等于 32；不能删去判界后无条件读取，也不在本轮跳过零权项。

### 有限 grid 的一个必要限制

“grid 有限”本身并不保证源码所有中间步骤安全：极大有限值可能使 unnormalize 溢出，或使 `distance/span` 超出 `int64_t` 转换范围。输入材料未规定这些情况下的 oracle 行为。

本轮不替换反射算法、不增加钳位来“修复”此问题，也不宣称基线对全部有限 FP32 grid 已有全域正确性证明。后继必须明确这一原有契约缺口；下述方案均保留原坐标 helper，不借优化缩小输入域。

## 3. 源码逻辑工作量

下表是逻辑请求/运算上界，不是 HBM 字节、指令数或时间：

| 项目 | a：C=1 | b：C=128 |
|---|---:|---:|
| 输出数 \(M\) | 4,096 | 524,288 |
| 几何生成次数 | 4,096 | 524,288 |
| grid float 读取数 \(3M\) | 12,288 | 1,572,864 |
| grid 逻辑读取字节 | 49,152 B | 6,291,456 B |
| `GridRead` 求值数 \(8M\) | 32,768 | 4,194,304 |
| 输入值读取字节上界 \(32M\) | 131,072 B | 16,777,216 B |
| 输出有效字节 \(4M\) | 16,384 B | 2,097,152 B |
| 加权乘法／累加次数 | \(24M/8M\) | \(24M/8M\) |

实际合法输入读取数由每点有效邻居决定。空间访问分布未知，不能假定源窗口局部，也不能把整个输入体积当作每次调用必须读完的数据量。

# 二、子例 a：C=1

## A1. 当前路径与关键事实

本例只有一个输出通道平面，4096 个输出各自读取不同的 grid 三元组。**跨通道几何复用次数就是 1**，派生几何保存没有可消除的重复生成。

主要路径仍是：

```text
grid[p] → 原坐标变换/反射 → 原8邻居读取与有序累加 → out[p]
```

输出连续、每个值只计算一次、没有中间消费者。因此输出可延迟到本核一个小块完成后统一写回，而不改变可见的 kernel 完成边界。

## A2. 选定完整方案：本核连续输出批量写回

登记实例 **A-WB**：

- Action：`action.batch_writeback`
- 父实现：输入给出的原始 `GridSampler3DScalar<float>`
- target：该实例本核独占的 FP32 输出连续区间
- stage：源码 146–147 行的结果写出
- workload 域：`N=1,C=1,D=H=W=32,S=4096,FP32,bilinear,reflection,alignCorners=false`
- 不变量：原计算函数、FP32 结果、每输出计算一次、唯一有效写回均不变。

候选每次计算至多 \(T=64\) 个原输出，把结果逐个放入一份输出 UB，再用一次 UB→GM DataCopyPad 写出。

令核 \(b\) 有效长度为 \(L_b\)，非空核数为 \(B_+\)，则：

\[
Q_a=\sum_b \left\lceil L_b/64\right\rceil .
\]

变化为：

- 原来的 4096 次源码 GM 标量赋值，被 \(Q_a\) 次 DMA 有效块写出替代；
- 新增 4096 次 UB `SetValue`；
- 新增每块生产完成、搬出及复用完成关系；
- 输出有效字节仍为 **16,384B**；
- 所有坐标、反射、floor、邻居读取及加权累加工作原样保留。

\(Q_a\) 不能直接写成 64：核分区可能产生短块。它满足：

\[
64\le Q_a <64+B_+ .
\]

这是从标量写通路转到缓冲 DMA，不是“已经存在的 DMA 发射数下降”，更不能据此断言 MTE 是瓶颈。

### 新增容量与初始化

单份最大输出数据区：

\[
U_a=\operatorname{AlignUp}(4T,32)=256\text{ B}.
\]

另计实际 SDK/框架预留。有效槽在搬出前全部由计算结果定义，不需要整槽清零；尾部 dummy 不参与计算、不写入 GM。

**容量门禁：**

\[
256+U_{\rm framework/API}\le U_{\rm available}.
\]

这里没有提供右侧实值，因此只批准条件方案，不把“256B 很小”当作容量已经通过。

## A3. 最有竞争力替代：几何保持 Scalar，批量执行加权算术

替代方案保留原坐标和合法 GM 标量取数，将八组邻居值及六组轴权放入 UB，然后用分离的 Mul/Add 按 k 顺序执行批量计算。

对 \(Q_a\) 个批次：

- 最多保留 32,768 次合法性检查后的邻居取数；
- 约 \(32Q_a\) 次算术 API 调用：每 k 三次乘法、一次累加；
- 数学乘加总量不变，但从逐输出 Scalar 算术转为批量 Vector；
- 一个便于审查、尚未压缩存储的布局为八组值、六组轴权、一个 temp 和一个 result：

\[
U_{\rm vec}=16\operatorname{AlignUp}(4T,32)+U_{\rm API}
=4096+U_{\rm API}\text{ B}\quad(T=64).
\]

还新增值/权重写入 UB、Vector 依赖和输出搬出。完整坐标反射、floor 与离散 GM 取数仍是 Scalar，并没有整体向量化。

这是强替代，因为它覆盖的算术比纯写回多。但当前材料没有提供足以确认本次 Scalar→Vector FP32 乘加在全部舍入、次正规数及融合策略下等价的目标证据，不能直接标记 `semantic_equivalence=true`。更不能把整个反射路径替换为未经核验的 Vector 除法和整型转换。

**本轮选择写回方案的原因：**C=1 没有几何复用收益；写回方案直接作用于确定连续、单 owner 的输出，并保留完整数值计算轨迹。向量算术替代不是因未测收益被否决，而是其具体数值/API 合法性尚未闭合，准备及同步成本也明显更高。

全输入体积预载则可能读入未被请求的元素，并且每个空间 owner 都可能重复载入 128KiB；没有地址局部性证据，本轮不选。

## A4. C2 共同计划及 KEEP 依据

- **所有权：**完全保留原 `begin/end/blockLength/blockNum`。
- **布局：**输入、grid、输出外部布局不变；仅输出块在 UB 中连续保存。
- **workspace：**0B，不增 kernel。
- **物理 buffer：**单份输出槽，无双缓冲、无共享 arena。
- **同步：**Scalar 写 UB 完成后才可由 MTE3 读；MTE3 读完后才可覆写或退出。首版采用材料已展示的保守 `PIPE_ALL` 完成边，不声称重叠。
- **分派：**保留现有 kernel entry 与 ABI，在 FP32 路径中用上述真实元数据谓词选择候选，其余域执行原代码；无需新增生产 Tiling Key。
- **KEEP：**没有已有完整计划身份可引用，因此正式记录应为 **P_CHANGE——提取原所有权并新增输出暂存通路**，不能伪报 P_KEEP。O 也发生改变，不是 NOOP。

`planning.elementwise.continuous` 不能完整套用：GridSampler 的输入不是同下标逐元素输入。这里只参考它的连续输出独占原则；完整算法按 `planning.indexing.coordinate_neighborhood` 绑定原 G/B/H/F。

## A5. C3 精确实施步骤及正文影响

在容量与目标 API 门禁满足后：

1. 保留原 float 通用函数作为 fallback，不修改 half 路径。
2. 在候选初始化阶段一次分配 `64*sizeof(float)` 的输出 TBuf，使用匹配的输出位置和 GlobalTensor。
3. 按原核区间循环，取 `valid=min(64,end-offset)`。
4. 对每个有效 i，原样调用 `GridSampler3DOne<float>`，结果写入本地槽。
5. 完成本地生产依赖。
6. 使用 A3 无 mode 的 UB→GM DataCopyPad：`blockCount=1, blockLen=valid*4, srcStride=dstStride=0`。
7. 等搬出读完本地槽后再复用；最后一块同样排空。无任务核不发 copy。
8. 不混用同一输出区间的 Scalar GM 写和 DMA 写。

实际采用正文：

- `implementation.memory-transfer.coalesce`：决定只汇集同 owner 连续输出，不跨核拼块。
- `implementation.tiling-tail.valid-length`、`precision-boundaries.bounds`：决定搬出用有效字节，不能向上写满 UB。
- `pipeline-sync.fallback`：决定先采用单槽浅路径，保留最后异步消费者完成边。

这些条目改变了具体通路、尾长和同步设计，不是仅列阅读路径。新增两类块级完成等待可能抵消写出优势，后继必须计入，而非默认删去。

# 三、子例 b：C=128

## B1. 当前路径与关键事实

本例每个 \(p\) 的几何重复生成 128 次：

\[
D[p]=H(B(G(grid[p],metadata))),
\]

D 不依赖 c，但 `X[c,*]` 依赖 c。当前以通道为主的输出连续遍历没有显式保存跨通道 D。

这是**派生结果复用**，不是输入值驻留，也不只是 TilingData/地址控制外提。源码没有几何 GM 中间表，因此也不存在可删除的“原有几何 GM 往返”。

## B2. 选定完整方案：单点几何跨全部通道消费

登记实例 **B-DERIVED**：

- Action：`action.reuse_derived_results`
- 父实现：原始 FP32 Scalar 路径
- target：原坐标变换及源码 119–124 行产生的几何状态
- stage：每空间点几何生成→128 个通道的邻域消费
- workload：题设 C=128 域
- 复用窗口：同一调用、同一 n/p、同一 owner 内，c=0…127。

首版使用 \(S_t=1,C_t=128\)：

```text
本核空间点 p:
    按原函数生成 D[p] 一次
    for c = 0..127:
        原 GridRead + 原 k=0..7 左结合乘法/有序累加
        scalar 写 out[c*S+p]
    全部通道消费结束后，才生成下一个 p 的 D
```

D 保存六个 `int64_t` 坐标和六个 float 轴权，共 **72B 的值载荷**。使用固定命名标量，不用动态索引数组；72B 不代表编译器实际栈大小或寄存器分配量。

### 减少、新增与保留工作

几何生成次数：

\[
CS=524288\longrightarrow S=4096,
\]

减少 **520,192 次**。

grid 逻辑读取：

\[
6,291,456\text{ B}\longrightarrow49,152\text{ B},
\]

减少 **6,242,304B 的逻辑请求**。这是同一次几何复用带来的共同变化，不能再登记一份输入驻留收益。

仍保留：

- \(8CS=4,194,304\) 次邻域求值；
- 输入值读取字节上界 16,777,216B；
- \(24CS\) 次源码乘法、\(8CS\) 次累加；
- 524,288 个 Scalar 输出写；
- 每通道的输入平面基址、合法读取和输出地址计算。

新增或改变：

- 几何状态跨 128 次消费者存活；
- 每点执行一个 128 通道循环，访问顺序由 c-major 改为 p-major；
- 相邻通道输入平面相距 **131,072B**，输出相距 **16,384B**；
- 当前点全部通道结束后才前进到下一点，可能削弱输入平面局部性，并扩大活跃输出 cache 行集合；
- 编译器可能出现更长活跃范围或 spill；不能宣称标量保存免费。

**不预计算八个合成权重**，所以不会偷换原 `((v*wx)*wy)*wz` 的舍入组织。

## B3. 最有竞争力替代及取舍

### 替代一：空间小块保存几何，通道为内层的块级消费

例如 \(S_t=16,C_t=128\)：生成 16 个 D，然后每个通道连续计算 16 个输出。

- 几何次数仍为 4096；
- 同样消除上述重复 grid 请求；
- 几何载荷至少：

\[
16\times72=1152\text{ B},
\]

若用独立 SoA TBuf，按真实各数组对齐核算；若用私有数组，仍有栈/spill 风险；
- 可以获得每通道 64B 连续输出计算窗口；
- 增加几何表写入、读取、索引及存储管理；若再 DMA 写回，则加入输出槽和块级同步。

这是本轮主方案最强的局部替代。**首版选择 \(S_t=1\)**，是为了在保留最大几何复用的同时，不先引入几何表 API、UB 容量门禁和额外本地表访问。代价是访问局部性较差；若这一代价在后继证据中突出，St=16 是明确的重规划方向，而不是默认继续扩大状态。

### 替代二：每次调用生成全局几何表，再按原通道连续消费

按上述 72B 表示：

\[
W_D=4096\times72=294912\text{ B}.
\]

每次调用至少新增：

- 表写 294,912B；
- 128 次完整消费的逻辑表读：

\[
128\times294912=37,748,736\text{ B};
\]

- 总新增表写读 **38,043,648B**，另有准备、发布完成及消费者同步；
- 若用两个 kernel，新增一次 launch，并要求输入 kernel ABI/host 调用序列支持 workspace。

它也把几何生成降至 4096 次，并保留通道连续输出，但不是跨调用免费缓存。与本地单点方案相比，新增 GM 表流量很大；当前源码又没有 workspace 实参。它必须靠减少的反射/floor 等生成时间偿还表访问和额外阶段，不能只凭“只生成一次”判优。本轮不选。

原所有权下只做批量写回仍是安全竞争方向，但它保留全部 524,288 次几何生成；本例明确的 128 倍几何重复，使派生复用更值得本轮检验。这里不据次数推加速比。

## B4. C2 共同计划及合法性

### 所有权与分核

将空间域按 16 点、64B 输出边界切分。令可用核参数为 A：

\[
B=\min(\max(1,A),256),\qquad
L_p=16\left\lceil\frac{S}{16B}\right\rceil.
\]

核 b 独占：

\[
p\in[bL_p,\min((b+1)L_p,S)),\quad c\in[0,128).
\]

这些矩形互不重叠，联集覆盖全部输出；不产生 partial、不需要归并或原子。每通道的核间边界仍在 16 个 float 边界上。若末尾启动核无有效点，直接跳过计算。

这会改变原输出线性分区，属于 **P_CHANGE**，不是局部 O 自由度。

### 布局、资源与同步

- 外部输入/输出 NCDHW 和 grid 布局完全不变。
- workspace：**0B**；不增 kernel、不改入口 ABI。
- 显式 UB 分配：**0B**。
- 私有派生状态：72B 值载荷，另有原输出计算临时状态。
- D 从生成到最后通道消费始终只读；输出 accumulator 每通道独立初始化。
- 全部计算与写出保留原 Scalar 路径，不新增跨流水或跨核消费者；不需要为这个标量状态添加 DMA ready/free。
- 实际寄存器、栈和 spill 仍需目标编译检查。没有新增 UB 不等于编译资源已通过。

### Action 门禁逐项状态

- `derived_reuse_domain`：源码证明 D 仅依赖 n/p、grid 和只读 metadata，不依赖 c。
- `dependency_lifetime`：候选明确全部 128 个消费者结束后才覆盖 D。
- `target_api`：主路径只使用当前已出现的 Scalar 类型、helper 和 GM 读取，不引入 Gather/Vector 新重载。
- `semantic_equivalence`：保持坐标 helper、坐标整型宽度、各乘法及累加次序；正式仍需完整 oracle。极端有限 grid 的原有契约缺口不能在此伪填为已解决。
- `capacity`：无新增显式 UB/GM；私有状态分配及可执行资源由编译确认，不能声称已经通过。

### 分派与 KEEP

在现有 entry 内新增题设真实元数据的候选分支；host 对该分支使用空间分核公式，其余元数据继续使用原公式和原实现。保持 `GridSampler3DTilingData` 字段布局不变，但候选域中 `blockLength` 的含义必须由同一 host/kernel 分支一致解释为空间点数，不能让通用路径误读。

不需要为 a、b 人工增加 Tiling Key。没有旧完整计划可引用，不能 P_KEEP；本成员 O 也改变，不是 NOOP。

## B5. C3 精确步骤及 P/O 正文实际影响

1. 提取只计算几何的本地 helper，逐句保留原 107–112、119–124 行表达式与类型。
2. 提取消费 D 的 helper：保留原 `GridRead` 判界和 125–132 行八项表达式。
3. 实现空间点 owner 循环及 c 循环，不引入八权重合成、不做零权跳读。
4. 每通道计算 `xBase=c*32768`、输出位置 `c*4096+p`；宽整数先乘后加，验证最后位置。
5. 同步修改 host 候选域的 blockNum/blockLength，空核不进入循环。
6. 原 float 通用路径、half 路径和未列形状的分派保持原样。
7. 检查实际生成物是否真的只在 c 外调用几何生成；检查是否发生结构体按值复制、数组化或 spill，不能以源码移动完成就认定预测兑现。

采用正文：

- **P `planning.indexing.coordinate_neighborhood` 完整采用其条件骨架**：G、B、H、F 已逐项绑定原源码；它决定空间×通道矩形所有权，并明确几何复用不减少各通道 X 读取。
- **O `implementation.buffer-lifetime.derived-results`**：决定先采用单点固定状态，明确生成者、128 个消费者和最后使用点，而非把派生值误登记成输入驻留。
- **O `implementation.precision-boundaries.numeric`**：直接阻止合成八权重、改 FMA 或重排八项累加。
- **O `implementation.scalar-control.constant_lifetime`**：决定不使用动态索引私有数组，并把长存活/spill 列为竞争代价。

这些资料提供的是条件化工程方法，不是上游完整 GridSampler 移植或 910C 性能证据。

1. **原极端有限 grid 契约**：明确中间溢出、超范围 float→int64 的支持行为及 oracle；不能以普通随机值覆盖全域。
