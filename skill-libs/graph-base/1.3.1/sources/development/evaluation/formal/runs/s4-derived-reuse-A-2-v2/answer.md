## 结论与状态

本轮只做纸面分析和交接，不修改源码、不编译、不运行。原始实现仍保留，正确性与性能均为 **not_measured**。

- **子例 a，C=1：选择“保持原标量采样计算，按本核连续区间暂存并批量写回”的条件化试验。** 用一个已注册的 `action.batch_writeback` 实例即可表达，不附加字段缓存、流水或向量化动作。实施前须确认目标 SDK 的缓冲/API 合法性和实际可用 UB。
- **子例 b，C=128：优先方案是“空间块拥有全部通道，逐空间点生成一次几何，立即供128个通道消费，再按通道连续写回”。** 它有明确的静态工作减少依据，但当前材料中**缺少承载“派生采样几何生成与跨通道复用”的注册 Action**。因此交付完整条件化 C2/C3 提案，**本轮不把它登记成正式可实施候选，也不借输入驻留或控制外提绕过意图缺口**。这不是因收益未测而否决；阻塞是注册意图及相应数值/资源条件尚未闭合。

以下将源码事实、推导、拟议保证和待验证事项分开。

## 一、两例共同的当前实际路径与数值依赖

### 1. 实际执行路径

入口 `grid_sampler_3d_kernel` 第190–197行对当前 FP32 输入调用：

```text
GridSampler3DScalar<float>
  → 每个 linear 调用 GridSampler3DOne<float>
  → Scalar 读取 grid、生成坐标、reflection、生成邻居
  → Scalar 从 GM 读取邻居并顺序累加
  → Scalar 直接写 out[linear]
```

**没有执行 `GridSampler3DHalf`，也没有派生几何表、Vector 插值、DMA 输入块或输出 UB。** 因而不能把 half 分支的 Cast、1024元素缓冲和屏障计入当前成本，更不能据此诊断当前 FP32 路径同步过宽。

外部 grid 的 `[N,S,3]` 是这里的展平描述；给出的 host 函数仍接收五维 grid，令 `S=outD*outH*outW`。本轮不得顺便修改该接口。

### 2. 数学与数据依赖

令 \(V_{\rm in}=DHW=32768\)，\(p=linear\bmod S\)，本例 \(N=1\)，则：

\[
X[c,z,y,x]\text{ 的元素偏移}=cV_{\rm in}+1024z+32y+x,
\qquad Y[c,p]\text{ 的元素偏移}=cS+p.
\]

每个坐标按第71–74行先做 FP32 unnormalize：

\[
u=((g+1)\times32-1)\times0.5,
\]

再按第58–68行做 reflection。对原实现中转换、除法均有定义且结果正常的域，最终坐标被 clamp 到 \([0,31]\)。随后生成三轴 floor、相邻坐标、分数和互补分数。

每个邻居项必须保持源码的计算组织：

\[
t_k=((X_k\,w_{x,k})\,w_{y,k})\,w_{z,k},
\quad r_0=+0,\quad r_{k+1}=r_k+t_k,\quad k=0,\ldots,7.
\]

以下替换均未获授权：

- 先计算 \(w_xw_yw_z\)，再乘 \(X_k\)；
- 改成分层 lerp、树归约或 Cube 点积；
- 用 FMA 替换原可见的乘法/加法舍入；
- 权重为零时直接跳过该项；
- 先越界读取，再用 mask 抹掉；
- 用取模、近似倒数或别的 reflection 公式替换原函数。

`GridRead` 第85–95行先判界，越界返回 `0.0f`，这个零仍进入后面的乘法和顺序累加。

**依赖轴是本轮关键事实：**

- 坐标、reflection、floor、六个轴权重、邻居空间偏移只依赖 \(p\)，不依赖 \(c\)。
- 邻居输入值依赖 \(c\)。跨通道几何相同，**不代表输入 X 原值相同**。
- 输出相互独立，没有跨输出归约，也没有跨调用复用窗口。

### 3. 有限 grid 不等于所有中间量均安全

grid 虽然有限，但没有幅值上界。极大有限 FP32 值仍可能使 unnormalize 溢出，或使 `GridReflect` 中 `distance/span → int64_t` 超出可表示范围。输入材料没有给出这种情况下原设备转换的完整语义。

因此：

- a 的方案不改动该计算，保留原路径行为，但不据此宣称原实现已对所有有限 grid 正确；
- b 的新计算组织必须保留异常/超范围域的原路径，或者先取得原转换的明确契约，不能将其统一变成零、边界值或新近似。

# 三、子例 a：C=1

## A1. 选择及竞争方案

### 主方案：原计算不动，仅连续输出批量写回

对每核原有区间 \([begin,end)\)，每次计算最多 \(T\) 个输出，逐个调用**原来的** `GridSampler3DOne<float>`，将结果写入一个 FP32 输出 UB 槽，再一次搬出有效区间。

建议初始纸面参数：

- \(T=256\) 元素，一物理输出槽；
- 输出数据区 \(A_{32}(4T)=1024\) B；
- 这是试验初值，不是已知最佳粒度；
- 合法候选域为 \(T\in16\mathbb N,\ 16\le T\le256\)，且满足实际 UB/API 约束。缩小 T 是本 C2 授权的实现参数调整。

令第 \(b\) 个有效核拥有 \(L_b\) 个输出，则：

\[
K_a(T)=\sum_{b:L_b>0}\left\lceil L_b/T\right\rceil.
\]

原来4,096次 Scalar GM 输出赋值，改成：

- 4,096次 Scalar UB `SetValue`；
- \(K_a(T)\) 次 UB→GM 搬出；
- 每槽填充后及搬出后各一条保守完成边；
- 有效输出字节仍为16,384 B。

\(T=256\) 时，若有 \(B\) 个有效核，\(K_a\le16+B-1\)。不能将这些调用数差直接换算成微秒或加速比。

**覆盖与残余：**覆盖 a 全部输出写回；几何生成、全部邻居读取、所有乘加、越界判断和通用 fallback 均保持原样。C=1 没有跨通道几何重算可消除。

### 最有竞争力替代：保留 Scalar 几何/取数，向量化插值算术并批量写回

完整变化不是“加几条 Vector 调用”：

1. 每 tile 仍生成 T 份几何，仍进行最多 \(8T\) 次 Scalar GM 邻居读取。
2. 将8路邻居值、六路轴权重写入 UB。
3. 对每个 k 顺序执行三次 FP32 乘法和一次加法，八项不得重排。
4. 有效输出批量搬出。

一个不依赖未证 alias 能力的保守布局为：

\[
U_{\rm vec}=17A_{32}(4T)+F_{\rm vec},
\]

其中8路邻居、6路权重、临时乘积、旧累加器、新累加器各占独立区；\(F_{\rm vec}\) 包含实际 API 预留和其他状态。T=256 时，仅这些显式数据就是17,408 B。

每 tile 新增最多：

- \(14T\) 次 Scalar UB 数据填入；
- 32条批量算术调用，必要的 V 内依赖及搬出依赖；
- 若需显式初始化 \(+0\) 累加器，另计初始化；
- mask/有效尾长、浮点下溢、符号零及编译后融合行为审查。

它可能减少98,304次 Scalar 乘法和32,768次 Scalar 加法对应的数据处理，但不会减少几何和随机源读取。其竞争力在算术批量化；代价在 gather 暂存、更多 Scalar UB 写、容量和同步。

**本轮选写回试验的理由：**a 的几何没有复用轴；完整向量化不能直接消除源 gather，且增加大量暂存工作。批量写回能以一个小槽独立检验一个清楚的通路变化，并完全保留数值函数。这里不是断定写回为主瓶颈，也不是因没有 profile 排除向量化；后者保留为有依据的条件候选。

### 其他会影响选择的机会

- **整通道 X 驻留：**每核需128KiB输入区；若多个空间 owner 都全载，读取量可达 \(B\times128\) KiB，而原逻辑邻居读上界仅128KiB。没有当前坐标局部性证明，不优先。
- **局部窗口/halo：**任意 grid 不保证相邻输出邻域相邻，不得假定小窗口。
- **字段缓存/地址外提：**可以合法分析，但不处理主要逐元素数学和离散读取；编译器消除情况未知，不作为本轮替代主方向。
- **cache hint：**原路径是裸 GM 指针，没有已绑定的 GlobalTensor hint 证据，不凭默认值套 L2 重排配方。

## A4. C3准确实施步骤及正文影响

1. 保留第98–135行计算函数；新增 FP32 输出缓冲类，在 Init 一次分配，不在热循环调用 `InitBuffer`。
2. 使用一个受同一 `TPipe` 管理、目标 UB→GM 重载支持的位置，优先 VECOUT；不照搬 half 分支的 raw/Cast 缓冲。
3. 对原核区间循环：
   - `valid=min(T,end-pos)`；
   - 对 `i<valid` 仅调用一次原 `GridSampler3DOne<float>(...,pos+i,t)`；
   - `SetValue(i,result)`；
   - 采用经核验的保守完成协议，确保 Scalar UB 填入对 MTE3 可见；
   - `DataCopyExtParams{1,valid*4,0,0,0}`，只搬有效字节；
   - 等待 MTE3 读完槽后才能下一次填入。
4. 不同时对该候选输出使用 Scalar GM 写和 DMA 写，避免制造新的混写协议。
5. 核验空 owner、原区间末端、`valid`、分配长度和64B所有权边界；实际 SDK 若对 Scalar UB 写→DMA 可见性另有要求，补齐其合法协议，不能仅凭屏障名称猜测。
6. 后续获得执行授权后才做代码审查、构建、全输出 oracle 和完整调用计时。

实际采用的正文作用：

- `planning.indexing.coordinate_neighborhood`：绑定 G/B/H/F 与原采样语义，保持独占输出骨架。
- `planning.elementwise.continuous`：**只参考连续输出片段所有权原则，不声称输入同形连续这一完整模板适用。**
- `implementation.memory-transfer.coalesce`：决定“同 owner、结果全部生成后、仅有效区间”才能合并写。
- `implementation.tiling-tail.valid-length`、`precision-boundaries.bounds`：使有效长度、UB对齐容量和 API 字节数分开。
- `pipeline-sync.fallback`：采用单槽最浅完成链，而不是无证据引入流水。
- `precision-boundaries.numeric`：阻止改写乘法结合、累加顺序或舍入。

# 四、子例 b：C=128

## B1. 当前路径的差异与优先机会

b 仍是同一个原始 Scalar 函数，只是输出循环扩大128倍。grid 唯一数据仍只有48KiB，但源码将相同 \(p\) 的几何生成128次。

这同时包含两个不同机会：

1. **原输入 grid 复用：**减少相同原始坐标的重复 GM 读取；
2. **派生几何复用：**减少 unnormalize、reflection、floor、分数和邻居空间地址的重复构造。

不能将两者合成两份独立收益，也不能仅做第一项便宣称第二项已解决。

## B2. 优先完整方案：空间块拥有全部通道，几何即产即用

### 任务与执行顺序

取空间块 \(S_t=16\)，一个任务拥有：

\[
Y[0:128,\ p_0:p_0+16].
\]

4096个空间点形成256个任务。每任务：

```text
for i = 0..15:
    p = p0+i
    按原浮点顺序生成该 p 的几何
    for c = 0..127:
        按 k=0..7 读取本通道邻居并按原表达式累加
        写 UB_out[c*16+i]
for c = 0..127:
    搬出该通道的16个连续输出
等待所有搬出完成，再复用输出槽
```

此处不需要保存整个空间块的几何表：一份当前点几何立即供全部通道消费，随后退休。它避免了 `St×几何记录` 的持久表及每输出重新读取整条记录。

### 全部工作变化

| 工作 | 原实现 | 候选正常快路径 |
|---|---:|---:|
| 几何生成组数 | 524,288 | 4,096 |
| reflection、floor各自调用数 | 1,572,864 | 12,288 |
| grid 原始读取字节 | 6,291,456 B | 49,152 B |
| 邻居读取 | \(128\sum_pv_p\) | 不变 |
| 每输出24乘、8加 | 保留 | 全部保留 |
| 输出有效字节 | 2,097,152 B | 不变 |
| 输出生产 | 524,288次 Scalar GM 写 | 524,288次 Scalar UB 写 |
| 输出搬出 | 无显式 DMA | \(256\times128=32,768\) 次，每次64B |

正常域中少做520,192组几何生成。**这不是128倍加速预测**：输入值读取和全部插值乘加仍在，跨通道访问距离、Scalar 发射、UB暂存和搬出成本均会改变。

新增代价包括：

- 通道内层的源平面跨距为128KiB；相邻两次不同通道读取不是连续输入；
- 每任务128个短写回及同步管理；
- 256任务的分配与最长核尾部；
- 当前几何跨128次消费的长标量存活期；
- 编译后寄存器/栈/spill未知，不能将私有变量字节算作 UB；
- 极端坐标的原路径处理及其分支成本。

### 数值和极端坐标域

候选保留六个轴权重，**不保存预乘八权重**，从而继续执行 `((value*wx)*wy)*wz`。

若后继不能证明原转换对全部有限输入的行为，可采用有明确证明的保守运行时快域，例如三轴均满足 \(|grid|\le2^{20}\)：仍执行原表达式，只用这个界保证中间值及整数转换范围安全；其余点对每个通道调用原 `GridSampler3DOne<float>`。这不是新增近似。

若安全快域点数为 \(S_{\rm safe}\)，实际几何组数为：

\[
S_{\rm safe}+128(S-S_{\rm safe}),
\]

不是无条件4096。快域检查、标记及 fallback 产生的工作必须计入。该值域 guard 若改变最终计划，需在C2冻结，不能由C3随意补一个阈值。

## B3. 最有竞争力的已注册替代：原始 grid 驻留＋批量输出

这是可用 `action.reuse_input_tiles` 和 `action.batch_writeback` 准确表达的替代：

- 按完整通道或通道组分 owner；
- 每 owner 搬入一份完整 grid，48KiB，在本调用所有本 owner 通道消费前保持只读；
- 坐标、reflection、floor仍逐输出重算；
- 输出按原通道连续顺序，以 T 元素批量写回。

若有 \(B_g\) 个 grid 驻留 owner：

\[
B_{\rm grid,GM}=B_g\times49152,
\qquad
U_{\rm alt}=49152+A_{32}(4T)+F_{\rm actual}.
\]

相对6MiB逻辑 grid 读取，只有 \(B_g<128\) 才减少请求字节；各核不共享 UB。若每核仅一个通道，\(B_g=128\)，全载不会减少这笔逻辑字节，只改变搬运粒度和读取层级。

其余变化：

- 原来的 \(3E\) 次 GM 坐标读取改为 \(3E\) 次 UB 坐标访问；
- 新增每 owner 的 grid DMA、就绪完成边和48KiB常驻；
- 几何524,288组、邻居请求和插值算术不变；
- 输出新增 SetValue、批量搬出与完成边；
- 若扩展向量插值，还须叠加 a 中的数组、调用与精度成本，不能称为免费配套。

**为何优先比较几何复用：**后者可消除127/128的重复几何构造，同时使 grid 原始读取缩至一次/点；原始 grid 驻留只解决原值装入，保留大量 reflection 和转换。前者的代价则是访问顺序、长标量存活和短行写回。两者净时间仍未知；若编译后几何复用导致明显 spill、跨平面访问劣化或32,768次写回占优，原始 grid 驻留或原通道顺序可能更好。

单独批量写回也适用于 b，但本轮不因它易于注册，就把主要重复几何机会隐藏掉。

## B4. Action能力缺口与决定

当前注册动作不能准确承载优先变换：

- `hoist_invariant_control` v0006明确不自动覆盖派生坐标/权重计算重排；
- `reuse_input_tiles`只代表原始输入切片，不代表保存或共享新生成几何；
- `keep_intermediate_onchip`要求当前存在对应 GM 中间写读；本父本没有几何 GM 表；
- `restructure_broadcast`不能仅凭数学上的跨通道共享，就自动授权采样几何生成重排；
- `vectorize_scalar_loop`不适用于一个仍保持 Scalar 算术、主要改变复用轴和计算次数的方案。

因此提出任务内意图缺口：

> **“按明确依赖轴生成并复用派生邻域几何”**：生成者绑定原G/B/H，消费者绑定各通道F；必须证明派生状态不依赖通道、原逐输出数值路径保持、所有消费者位于同一合法 owner/window，并分别核算私有状态、输出缓冲和同步。

这是**待审阅 Action 提案，不是已注册 ID**。正式实施还需明确该提案的安全谓词、数值边界及版本策略。`batch_writeback` 可作为其独立输出成员，但不能以该合法成员替整个方案取得准入。

**本轮 b 的状态：conditional_plan / intent_blocked，保持原源码。** 不记录 P_KEEP/O_KEEP，也不把未实施写成 NOOP 优化结果。

## B5. C2共同计划与C3交接

### 条件化 C2

| 项目 | 拟冻结内容 |
|---|---|
| 计划标识 | `B-spatial-owner-geometry-paper-v1` |
| 任务 | 256个 \(128\times16\) 输出矩形 |

| UB容量 | \(A_{32}(4\times128\times16)+F_{\rm actual}=8192+F_{\rm actual}\) B |

这是实际任务/owner变化，正式准入后为 **P_CHANGE**。不是“提取已有计划”，也不能沿用 a 的容量证明。

### C3在缺口解决后才可实施的步骤

1. 原实现保持为独立可调用 fallback；冻结父源码身份。
2. 实现C2指定空间任务映射，先核对所有 \(Y[c,p]\) 恰被一个任务覆盖。
3. 抽出与原源码逐操作一致的几何生成，不预乘权重、不替换 reflection。
4. 实现已批准的安全值域/异常域策略；超范围不得套零或Clamp替代。
5. 每个点生成一次几何，通道内层消费，输入偏移仍加 `c*32768`。
6. 每输出保持原k顺序，直接生成最终值，写 `out[c*16+i]`，不引入部分和或重复算输出。
7. 全部结果就绪后逐通道搬出16元素；维护真实 Scalar UB生产→MTE3及槽复用完成边。
8. 核对私有数组/结构体是否落栈或spill；不能因UB只有8KiB就宣称资源已闭合。
9. 若改为几何表、转置、跨核共享、更多输出槽或更大通道/空间块，返回C2，不沿用本计划。

正文的实际影响：

- `planning.indexing.coordinate_neighborhood`完整绑定本任务G/B/H/F，直接形成复用轴×空间块骨架，并要求区分几何与X值复用。
- `buffer-lifetime.reuse`及`scalar-control.constant_lifetime`使本方案选择“当前点即产即用”，而不是默认建立大几何表；同时要求单列私有状态风险。
- `memory-transfer.coalesce`使输出保持每通道16点连续片，而不是跨通道误当连续GM。
- `precision-boundaries.numeric/bounds`阻止权重预乘、近似reflection、非法地址先读后mask及对齐扩大写域。
- `pipeline-sync.pipeline/fallback`要求真实完成边；本轮不声称浅槽已经实现流水重叠。
