## 结论与证据边界

两个子例选择相同的纸面试验：**最近邻路径按“两个通道 × 一段空间点”组织任务，在同一 owner 内生成一次派生采样索引，供两个通道消费**。绑定已注册的 `action.reuse_derived_results`，不把它混称为字段外提或原输入驻留。

- 子例 a 从 **L0** 分析和交接；L1 保留为漏写失败历史，L2 保留独立源码身份，但不作为更快父本。
- 子例 b 对应从 **Pine** 分析和交接；Fir、Oak 分别对应 L1、L2。
- 选择状态为 **纸面 conditional_plan**：算法、地址和资源需求可具体描述；真正实施前仍须闭合输入输出别名、启动接线、目标 SDK 和编译资源条件。
- 没有执行 router、校验器、构建或硬件测试；以下是依据所给正文进行的人工路由与交接，不伪造 hash、运行回执或 C3 completed。
- 两例仅标识不同，没有支持“改名改变优化选择”的来源。函数名不作为算法识别、分派或性能依据。

# 子例 a：L0 / L1 / L2，`GridSampler3DScalar`

## 一、当前实际路径、数学与数据依赖

### 1. 实际执行路径

本历史对象明确为 `GridSampler3DScalar<float>`，因此入口走源码 194–196 行的 **FP32 Scalar 分支**，不是 `GridSampler3DHalf`。

外部 grid 的逻辑视图为 `[N,S,3]`；给出的 host helper 实际接收五维 `[N,Do,Ho,Wo,3]`，将三个输出空间维展平为 `S`。不能据逻辑展平视图擅自修改现有 shape ABI。

对输出线性索引 \(l\)：

\[
p=l\bmod S,\quad nc=\lfloor l/S\rfloor,\quad
c=nc\bmod C,\quad n=\lfloor nc/C\rfloor .
\]

grid 三个坐标仅依赖 \((n,p)\)，不依赖 \(c\)；输入值仍依赖 \((n,c)\)。

当前 nearest、zeros、alignCorners=false 时，每轴执行：

\[
u=((g+1)\cdot16-1)\cdot0.5,
\qquad j=\operatorname{RoundEven}(u).
\]

三个整数坐标均有效时：

\[
Y[n,c,p]=X[n,c,j_z,j_y,j_x],
\]

否则返回 FP32 的 `0.0f`。必须先判界再读，不能先读非法地址再乘零。

本输入 grid=0，因此三个连续坐标均为 7.5，ties-to-even 得到 8。每个通道的源空间偏移为：

\[
8\cdot256+8\cdot16+8=2184.
\]

故实际读取 `x[c*4096+2184]`；x 全为 1，所以完整输出为 2048 个 1。这只是当前数据推导，不能将 kernel 改为常量填 1。

### 2. 其他路径必须保持

源码 119–132 行的三线性分支不是当前执行路径。后继 fallback 保留：

- `GridFloor`、padding、坐标变换；
- k=0…7 的邻居顺序；
- 每项的乘法结合形式与逐项累加；
- 越界贡献零；
- 输出转换及原特殊值行为。

尤其不能把八邻居改为 pairwise、预乘合并权重或 FMA。FP16 路径还有软件 half→float 转换、UB 中 FP32 结果、`CAST_NONE` 和 DataCopyPad，不能借当前 FP32 试验顺便改动。

### 3. 当前所有权和存储

由 tiling 41–45 行，FP32 分核粒度为 16 元素，即源码注释意图中的 64B 边界。设传入可用核数为 \(A=\max(1,\text{cores})\)：

\[
B=\min(A,128),\qquad
L=16\left\lceil\frac{\lceil2048/B\rceil}{16}\right\rceil .
\]

block \(b\) 处理：

\[
[bL,\min((b+1)L,2048)).
\]

L0 每次 `++linear`，非空区间完整覆盖且逻辑上互斥。实际 launch 是否使用 `t.blockNum` 未给出，属于接线待核验项；不能把 host 计算值冒充实际启动证据。

FP32 路径直接以 GM 指针逐元素读写，没有显式 UB、DMA tile 或手工事件，也没有跨核归并。不能把 Half 分支的三次 `PIPE_ALL` 当作当前热点。

## 二、关键事实与历史重新判读

| 对象 | 原始事实 | 可得结论 |
|---|---|---|
| L0 | passed，覆盖 2048 输出 | 当前合成记录域内完整正确性通过；不是一般输入域证明 |
| L1 | 唯一变化为 `linear+=2`；1024 错误 | 漏掉一半输出，不是合法减少计算 |
| L2 | 与 L0 字节相同；passed，覆盖 2048 输出 | 数学实现未变化，保留独立保存身份 |
| T0 | 1.0ms，launch 前至 stream synchronize 后 | 是完整同步窗口的合成记录，不是硬件测量 |
| T1 | 0.4ms，同步窗口 | 对应错误实现，不能进入正确候选排名 |
| T2 | 0.2ms，enqueue 后、synchronize 前结束 | 未包含完成等待，不能与 T0 比完整调用耗时 |

因此不存在可采纳的“L1 更快”或“L2 五倍加速”结论。将 L1 修成完整覆盖后，实际求值和写回由 1024 恢复为 2048；必须重新比较，不能沿用原 0.4ms 的选择依据，也不能线性外推修复后时间。

当前数据的源码请求模型如下，不是 HBM 流量：

| 工作 | 次数 / 有效逻辑字节 |
|---|---:|
| 几何生成 | 2048 组 |
| grid 标量读取 | 6144 个 float，24576B |
| 三轴 unnormalize / RoundEven | 各 6144 次 |
| 有效 x 读取 | 2048 个 float，8192B |
| 输出写入 | 2048 个 float，8192B |
| 合计有效数据读写，不含 tiling | 40960B |

grid 唯一数据为 3072B；当前数据真正访问的 x 唯一数据仅 32B。重复请求可能已被缓存服务，但没有命中率、实际事务或时间证据，不能据此宣称带宽饱和或缓存策略错误。

## 三、完整方案与最有竞争力替代

### 主方案 S-a：同 owner 跨两个通道复用派生索引

初始参数：

- \(C_t=2\) 个通道；
- \(S_t=16\) 个空间点；
- 每任务拥有两个通道各 16 个输出，共 32 个输出；
- **逐点生成、立即供两个通道消费**，不建立整片几何数组。

任务数：

\[
T=N\left\lceil C/C_t\right\rceil\left\lceil S/S_t\right\rceil
=1\cdot4\cdot16=64.
\]

派生记录只包含当前点的有效标记和合法源空间偏移。索引不跨 batch 或空间点复用，不缓存通道相关的 x 值。

#### 数值保护与触发粒度

为避免把原始非有限值或超大值的浮点到整数转换行为当作已经证明的纯函数，本试验采用保守的**逐点、逐通道组保护**：

1. 读取该点三个原始 FP32 grid 值；
2. 三者全部落在 `[-1,1]` 时，沿源码原表达式和 `GridRoundEven` 生成共享索引；
3. 否则该点的两个通道各调用原 `GridSampler3DOne<float>`。

保护不扫描整行或整 plane；一个点失败只使该通道组的两个输出走原路径。非有限值不会被改成零，也不新增 clamp。fallback 保留原实现行为，但这不等于证明原实现已定义所有非有限值转换语义。

当前 grid=0，全部点进入复用路径；覆盖由输入事实确定，不是“异常值很少”的猜测。

#### 工作变化

当前数据下：

\[
G_{\rm new}=NS\lceil C/2\rceil=1024
\]

组几何生成，较原来减少 1024 组。

- grid 读取：6144 → 3072 个 float，减少 12288B；
- unnormalize、RoundEven：各 6144 → 3072 次；
- 最近邻边界判定：每两个通道共用一次；
- x 读取仍为 2048 次，输出仍写 2048 次；
- 有效逻辑数据读写变为 **28672B**；
- 新增每组约 6 次范围比较及组合判断，共 1024 组；
- 新增任务解码、通道地址递进和两个输出流交错；
- 无预处理 kernel、GM 索引表、布局转换、UB 初始化或新增 DMA。

设某一元数据域有 \(Q=NS\lceil C/C_t\rceil\) 个点组，安全保护通过比例为 \(f\)。准备读取始终为 \(3Q\) 个 grid 元素；失败点另执行原来的 \(C_t\) 次生成。当前整除情形：

\[
\text{完整几何求值组数}=Q[f+C_t(1-f)].
\]

当 \(f=0\) 时，原完整求值没有减少，却额外增加 \(3Q\) 次 grid 读取与保护判断。这一明确代价限制了试验的推广价值；不能把当前全通过覆盖推广成全部输入均获益。

#### 选择理由及敏感条件

本方案不仅省少量字段 load，还削减三个轴的坐标变换、ties-to-even 与边界构造，且不依赖 x=1 或重复源索引。

代价是任务从原最多 128 个分片变为 64 个任务，并交错写两个相距 \(S\) 的输出流。选 \(C_t=2\) 是有界试验参数，不声称最优：

- \(C_t=8\) 可把几何降到 256 组，却只有 16 个任务，且每点交错八个输出流；
- 本轮不扩大到八通道，避免把全部复用收益建立在更强的任务收缩和写局部性代价上；
- 若实际可用核数大于 64、索引生成已被编译器消除大量工作，或交错写开销明显，原连续输出方案可能更优。

### 最强替代 A-a：原连续 owner 内缓存最近一次有效 x 原值

保留 L0 的输出分区和逐通道连续遍历。每个 channel 段保存一个 `(源偏移, 原始float值, valid)` 记录；下一个输出访问同一有效源偏移时复用该原值，未命中则正常读取。越界仍先判界，不缓存非法读取。

这是 **原输入值复用**，不是派生几何复用。

设原有效 block 区间与 channel 平面的非空交段总数为 \(R\)。当前 grid=0，各段内全部命中同一个源点：

- x 读取：2048 → \(R\)；
- 减少 \(4(2048-R)\)B；
- 几何仍生成 2048 组，grid 仍读 24576B；
- 输出仍写 8192B；
- 新增最多约 \(2048-R\) 次 cache-tag 比较及状态维护；
- 不改任务数、输出顺序或 UB 分配；
- 段结束失效，不跨 dispatch 保留缓存。

对连续完整分区，\(8\le R\le B_{\rm effective}+7\)。确切值由实际 blockLength 和 launch 决定。一般数据中，设有效读取数为 \(V\)、段内 tag 命中数为 \(H\)，则只减少 \(4H\)B；无命中时保留全部读取并增加 tag 判断。

**本轮仍优先主方案**：当前主方案减少 12KiB grid 请求以及一半完整几何生成；该替代最多消除接近 8KiB x 请求，坐标算术完全保留。替代的优势是保持原输出局部性和任务数，且当前数据确实高命中，因此不是次要占位项。若主方案受交错写或任务数限制，它应优先重开。

暂不将两者联合：联合会引入第二类数据相关状态及比较成本，且共享减少量不能重复计数；目前一个派生复用实例已足以构成可解释试验。

### 其他明显机会的处理

- **批量写回**：可把每个 owner 的结果暂存后 DMA 写出；仍需 2048 次 Scalar 求值和 UB SetValue，新增 UB、完成边和搬出，不能把原 2048 次标量 store 说成 2048 次 DMA。当前优先解决重复几何。
- **全输入窗口/Gather 向量化**：x 总大小 128KiB，但任意 grid 没有局部窗口保证；完整加载还会搬入大量未用数据。缺对应 Gather、舍入和特殊值等价链，不能直接实施。
- **字段缓存/地址递推**：可减少控制，但原路径已经 GM tiling 指针直读；不能虚构整结构拷栈。编译器 CSE 未知，暂不以小字段缓存取代主要机会。
- **删同步、管理简化、Cube、融合、workspace 缩减**：当前 FP32 分支没有相应结构依据。
- **缓存 hint**：没有证明当前 hint 错配，且当前使用裸 GM 指针；不凭重复访问就加 PERSISTENT 或 bypass。

## 五、统一 C2 计划

### 所有权与分派

冻结一个特化组：

- 元数据谓词为上述 FP32、尺寸、S、插值和 padding/align 条件；
- 不检查 x=1 或 grid=0 来选择 entry；
- 其他元数据全部进入原通用 fallback；
- 当前点保护失败也进入原数值求值，不改变整个调用的分派。

设实际可用 AIV 数为 \(A\)，特化启动：

\[
B'=\min(\max(1,A),64).
\]

任务 \(t\in[0,64)\)：

\[
c_0=2\lfloor t/16\rfloor,\qquad p_0=16(t\bmod16).
\]

唯一拥有：

\[
c\in[c_0,c_0+2),\quad p\in[p_0,p_0+16).
\]

用任务级商余分配：

\[
q=64/B',\quad r=64\bmod B',
\]
\[
t_{\rm begin}=bq+\min(b,r),\quad
t_{\rm count}=q+[b<r].
\]

各矩形互斥，联集为全部 2048 输出。每个通道内的任务边界为 16 float；在输出基址满足原 64B 对齐合同的前提下，不同 owner 不共享该边界块。

### 布局、容量、workspace、同步

- X、grid、Y 外部布局完全不变；无 NCDHW→其他格式转换。
- 每任务逐 p，再消费两个 c；写地址为 `c*S+p`。
- 派生记录可用一个合法空间偏移和有效标记，不截窄为未经证明的 int32。
- 新增用户 UB：**0B**；新增 GM workspace：**0B**。
- 私有标量需求为 \(O(1)\)，不使用 `D[St]` 自动数组；寄存器/栈与 spill 由编译结果确认，不能称其免费。
- 无跨核归并、事件或全核屏障。记录覆盖只需遵循两个 Scalar 消费结束的程序依赖。
- 不新增 `restrict`，不借其消除真实别名。
- 若需要改成 UB 表、整片暂存或 GM 几何表，必须返回 C2，不能视为本计划的局部参数调整。

### KEEP 判断与身份

没有输入给出的完整父计划，不能声称 `P_KEEP`。应记录：

1. **提取已有计划**：L0 的线性输出分区及 Half fallback；
2. **实际 P_CHANGE**：特化域改为 Ct×St 矩形 owner；
3. fallback 保持原算法和资源，不代表所有未知域已通过验证。

纸面 key 可冻结为 `uint64 1=本特化组，0=互补fallback`，共同外部 C entry 仍为 `grid_sampler_3d_kernel`。现有工程没有展示 TilingKey 启动机制，因此这是计划身份，不是假称已接线：C3 在同一 entry 内用冻结元数据谓词实现唯一分支，不擅自引入不适用的 `TILING_KEY_IS`。host 必须同步使用特化 blockNum；新 blockLength 不参与该分支，fallback 继续使用原公式。

## 六、C3 准确步骤及 P/O 正文的实际影响

### 人工 P/O 采用记录

- **P：`planning.indexing.coordinate_neighborhood`，完整采用已绑定的 nearest 子骨架。**  
  G 绑定原 unnormalize，B 为 zeros 不改坐标，H 为原 RoundEven 和边界检查，K=1，F 为合法读取或返回零。正文使本轮明确区分“几何不依赖 c”和“x 仍依赖 c”，并选择无几何数组的逐点复用。
- **P：`planning.indexing.gather_output_owned`，仅参考输出独占原则。**  
  不把 GridSampler 宣称为 GatherElements，也不采用来源转置 workspace 或尾轴 API。
- **O：`implementation.buffer-lifetime.derived-results`。**  
  正文直接影响生成位置、复用轴、最后消费者和重算替代比较；没有照搬 RoPE 的 Gather API。
- **O：`implementation.precision-boundaries.numeric`。**  
  促使保留 ties-to-even、特殊值 fallback、三线性顺序和 finalCast，拒绝仅凭实数公式相同替换。
- **O：bounds、valid-length、dispatch。**  
  分别用于宽整数地址核验、16 点有效区间和真实元数据接线。dispatch 正文还限制了“不为增加 Key 而增加入口”。
- **O scalar-control 正文仅用于比较。**  
  它们明确已有 GM 指针直读、字段缓存与派生数值复用不同，因此没有把主方案错误登记为 `hoist_invariant_control`。

### 实施交接步骤

1. 从 L0 建立隔离候选，保留 L1/L2 及原记录；不修改原快照。
2. 原 `GridSampler3DOne`、Half 类和通用 fallback 保留；新增最近邻索引生成小函数，算术逐字保持原表达式与 helper。
3. host 与 kernel 使用相同特化谓词；host 设置 \(B'\)，kernel 按上述任务商余映射。
4. 每任务遍历 16 点：读三个 grid 值并保护；通过时生成一份索引供两个通道读取，否则两个通道分别调用原求值函数。
5. 每个输出恰写一次，**不能保留 L1 的步长 2**，也不依赖输出初始化为零。
6. 不添加 UB 表、全域清零、预处理 kernel、Vector Round/Cast、cache hint 或新的同步。
