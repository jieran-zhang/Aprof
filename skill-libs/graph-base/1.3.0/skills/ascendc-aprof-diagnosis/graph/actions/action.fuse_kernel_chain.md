# 融合兼容的生产消费链

## 变换与作用对象

把满足完整语义和执行契约的生产消费链组合，并让中间值在合法层级直通。

连续launch的生产者/消费者kernel及GM中间tensor；阶段：host launch序列；生产kernel输出；后继kernel消费。

## 实例绑定与原硬前提

实例必须给出精确template_hash、task与parent实现、目标和阶段；参数逐项给单位、来源及有效域，关联已确认C2计划。未知信息不从样例常量或聊天推断。

- target
- stage

- implementation

- symptom.source.missing_kernel_fusion=true
- constraint.fusion_boundary=true
- constraint.semantic_equivalence=true
- constraint.capacity=true

原invariants：完整语义和精度；有效元素覆盖和唯一写回；容量、同步与所有权合法。

## 预期效果与代价

把满足完整语义和执行契约的生产消费链组合，并让中间值在合法层级直通；预期变化仅为prediction：合法融合可能减少launch及GM中间字节，但增大活跃峰值；这是prediction

- 更大片上/寄存器存活集与编译体积
- owner、同步、dispatch或workspace结构变化需C2重新批准

## 未知与返回规划

任一硬前提缺失、unknown或proxy则needs_evidence；明确不满足则blocked。C2可比较条件方案，C3须完成全部原前提及invariants核验。

- 目标/阶段、owner或有效元素域变化
- 算法、归并/同步拓扑、workspace owner、融合、通路或dispatch域超出已确认C2计划自由度
- 工作量、dtype、平台、容量或profile反证使原干预假设失效

## 平台与workload限制

- Vector寄存器链融合文档只支持存活分析原则，跨kernel可行性须单独证明
- 本轮没有融合实测案例，不声称通用收益
