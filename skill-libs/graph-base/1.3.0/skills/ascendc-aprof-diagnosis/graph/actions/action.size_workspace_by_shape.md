# 按 shape 和槽位所有权配置 workspace

## 变换与作用对象

按runtime shape、真实并发槽和合法索引边界计算每段workspace。

host声明的workspace段、真实并发槽和kernel索引范围；阶段：host workspace分配；kernel初始化、读写和槽轮转。

## 实例绑定与原硬前提

实例必须给出精确template_hash、task与parent实现、目标和阶段；参数逐项给单位、来源及有效域，关联已确认C2计划。未知信息不从样例常量或聊天推断。

- target
- stage
- workload
- implementation

- symptom.source.workspace_overallocation=true
- constraint.workspace_ownership=true
- constraint.semantic_equivalence=true
- constraint.capacity=true

原invariants：完整语义和精度；有效元素覆盖和唯一写回；容量、同步与所有权合法。

## 预期效果与代价

按runtime shape、真实并发槽和合法索引边界计算每段workspace；预期变化仅为prediction：按真实shape和并发槽缩放可降低内存占用；时延仅在触及多余区间时可能改善，属prediction

- 需同步修改host公式、kernel偏移和调用契约
- 缩小空间可能暴露异步重叠与跨实例生命周期问题

## 未知与返回规划

任一硬前提缺失、unknown或proxy则needs_evidence；明确不满足则blocked。C2可比较条件方案，C3须完成全部原前提及invariants核验。

- 目标/阶段、owner或有效元素域变化
- 算法、归并/同步拓扑、workspace owner、融合、通路或dispatch域超出已确认C2计划自由度
- 工作量、dtype、平台、容量或profile反证使原干预假设失效

## 平台与workload限制

- FA按并发槽分配规则只对其生命周期成立的段适用
- SquaredRelu入口不足以证明其host保留区可删除，不能据固定16MB直接断言浪费
