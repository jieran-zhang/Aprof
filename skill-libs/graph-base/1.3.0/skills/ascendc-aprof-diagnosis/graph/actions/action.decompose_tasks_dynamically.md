# 重新分解任务并选择核数

## 变换与作用对象

按合法独立域或可归并的分段动态分解任务并按workload派发。

当前workload的独立任务域、实际BlockDim及可用同类核；阶段：host任务分解与启动；kernel任务领取。

## 实例绑定与原硬前提

实例必须给出精确template_hash、task与parent实现、目标和阶段；参数逐项给单位、来源及有效域，关联已确认C2计划。未知信息不从样例常量或聊天推断。

- target
- stage
- workload
- implementation

- symptom.profile.tasks_below_available_cores=true
- symptom.source.fixed_or_undersubscribed_tasking=true
- constraint.semantic_equivalence=true
- constraint.capacity=true
- symptom.workload.tiny_or_overhead_limited=false
- constraint.task_ownership=true

原invariants：算子语义与精度要求保持；有效写回无重叠且覆盖完整；资源与依赖约束经核验。

## 预期效果与代价

按合法独立域或可归并的分段动态分解任务并按workload派发；预期变化仅为prediction：合法增加任务可能缩短每核关键路径，但归并和调度可能抵消；这是prediction

- 更多partial与workspace
- 跨核归并、调度及同步开销和精度顺序变化

## 未知与返回规划

任一硬前提缺失、unknown或proxy则needs_evidence；明确不满足则blocked。C2可比较条件方案，C3须完成全部原前提及invariants核验。

- 目标/阶段、owner或有效元素域变化
- 算法、归并/同步拓扑、workspace owner、融合、通路或dispatch域超出已确认C2计划自由度
- 工作量、dtype、平台、容量或profile反证使原干预假设失效

## 平台与workload限制

- 小workload是该解释的条件性反证，不能跨shape推广
- StreamK源阈值属于该代码，不设为通用分界
