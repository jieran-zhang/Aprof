# 平衡混合流水阶段工作量

## 变换与作用对象

在数学和owner契约允许下联合调整AIC/AIV阶段tile、工作分担或交接粒度。

具有依赖交接的AIC与AIV阶段及同一tile的中间状态；阶段：host混合kernel模式与任务粒度；AIC QK/PV；AIV softmax/rescale与交接。

## 实例绑定与原硬前提

实例必须给出精确template_hash、task与parent实现、目标和阶段；参数逐项给单位、来源及有效域，关联已确认C2计划。未知信息不从样例常量或聊天推断。

- target
- stage
- workload
- implementation

- symptom.source.mixed_pipeline_imbalance=true
- constraint.cross_engine_dependencies=true
- constraint.semantic_equivalence=true
- constraint.capacity=true

原invariants：完整语义和精度；有效元素覆盖和唯一写回；容量、同步与所有权合法。

## 预期效果与代价

在数学和owner契约允许下联合调整AIC/AIV阶段tile、工作分担或交接粒度；预期变化仅为prediction：改变tile或后处理分担可能平衡阶段关键路径；这是prediction；把总AIC时间等于总AIV时间不作为目标，重叠与依赖决定收益

- 扩大中间区/workspace并改变buffer深度
- 重分阶段可能改变同步拓扑，需返回C2核算

## 未知与返回规划

任一硬前提缺失、unknown或proxy则needs_evidence；明确不满足则blocked。C2可比较条件方案，C3须完成全部原前提及invariants核验。

- 目标/阶段、owner或有效元素域变化
- 算法、归并/同步拓扑、workspace owner、融合、通路或dispatch域超出已确认C2计划自由度
- 工作量、dtype、平台、容量或profile反证使原干预假设失效

## 平台与workload限制

- 混合核的角色不同，不能把逐核时间差直接当负载不均
- arch22 FA阶段示例不证明其他混合算子的通路相同
