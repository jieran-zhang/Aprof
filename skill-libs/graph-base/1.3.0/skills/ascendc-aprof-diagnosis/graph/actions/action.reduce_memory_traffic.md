# 减少可消除的内存流量

## 变换与作用对象

消除可证明冗余的输入读取或中间写读，比较总GM流量与关键路径。

同一调用中连续大块输入/输出及GM带宽窗口；阶段：host工作量与访问模型；kernel稳态MTE传输。

## 实例绑定与原硬前提

实例必须给出精确template_hash、task与parent实现、目标和阶段；参数逐项给单位、来源及有效域，关联已确认C2计划。未知信息不从样例常量或聊天推断。

- target
- stage
- workload
- implementation

- symptom.source.memory_bandwidth_saturation=true
- constraint.traffic_reducible=true
- constraint.semantic_equivalence=true
- constraint.capacity=true

原invariants：完整语义和精度；有效元素覆盖和唯一写回；容量、同步与所有权合法。

## 预期效果与代价

消除可证明冗余的输入读取或中间写读，比较总GM流量与关键路径；预期变化仅为prediction：若保持路径而减少实际字节，传输时间应随之下降；这是prediction；只合并已足够大的搬运可能不再改善稳态带宽

- 驻留或融合会增加片上峰值及同步管理
- 压缩或重计算可能增加算术量和精度风险

## 未知与返回规划

任一硬前提缺失、unknown或proxy则needs_evidence；明确不满足则blocked。C2可比较条件方案，C3须完成全部原前提及invariants核验。

- 目标/阶段、owner或有效元素域变化
- 算法、归并/同步拓扑、workspace owner、融合、通路或dispatch域超出已确认C2计划自由度
- 工作量、dtype、平台、容量或profile反证使原干预假设失效

## 平台与workload限制

- 无目标持续带宽基准时不判饱和
- 数据搬运样例的峰值估算和具体收益不跨平台使用
