# symptom.profile.chunk_merge_overhead → problem.chunk_merge_overhead

## 关系与对象绑定

symptom.profile.chunk_merge_overhead —supports→ problem.chunk_merge_overhead。

- target→target：同一task与parent实现，绑定同一target身份；被分段的归约/KV/K域及其partial、合并阶段
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.profile.chunk_merge_overhead=true
- constraint.diagnosis.chunk_merge_overhead.profile_scope_verified=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

该profile复合观察需同时满足对象、有效域、窗口、单位与模型要求，并按本边检查区分“少分段可欠并行，多分段可合并昂贵，是资源取舍”。满足后仍需比较替代解释，相关性不单独确立机制。

- 比较saved_critical_path与partial_write+sync+read+merge，而非只比较活跃核数
- 检查局部独立归并是否可在跨核同步前完成

## 例外与代价

- 分段仍显著缩短全链关键路径时，不能因存在merge就判过度
- partial格式或归并精度未确认时不能改为简单求和
