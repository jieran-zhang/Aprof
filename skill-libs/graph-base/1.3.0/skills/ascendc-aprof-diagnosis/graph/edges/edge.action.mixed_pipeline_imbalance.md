# problem.mixed_pipeline_imbalance → action.rebalance_mixed_stages

## 关系与对象绑定

problem.mixed_pipeline_imbalance —mitigated_by→ action.rebalance_mixed_stages。

- target→target：同一task与parent实现，绑定同一target身份；具有依赖交接的AIC与AIV阶段及同一tile的中间状态
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.source.mixed_pipeline_imbalance=true
- constraint.cross_engine_dependencies=true
- constraint.semantic_equivalence=true
- constraint.capacity=true
- constraint.diagnosis.mixed_pipeline_imbalance.target_stage_bound=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

仅当该Problem在绑定对象/阶段上仍有可核验解释力时，在数学和owner契约允许下联合调整AIC/AIV阶段tile、工作分担或交接粒度才是对应候选。联合条件继承A全部原硬前提，C2可比较未知条件，C3不能越过门禁。

- 按tile流水甘特而非单看aic_ratio/aiv_ratio比较
- 联合核算中间buffer、workspace、握手频率与tile改变

## 例外与代价

- AIC/AIV本来执行不同工作且互不等待时，时间不等不能支持失衡
- 等待来自过宽屏障或事件错误时先区分同步机制
- 扩大中间区/workspace并改变buffer深度
- 重分阶段可能改变同步拓扑，需返回C2核算
