# symptom.source.fixed_or_undersubscribed_tasking → problem.underused_task_parallelism

## 关系与对象绑定

symptom.source.fixed_or_undersubscribed_tasking —supports→ problem.underused_task_parallelism。

- target→target：同一task与parent实现，绑定同一target身份；当前workload的独立任务域、实际BlockDim及可用同类核
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.source.fixed_or_undersubscribed_tasking=true
- constraint.diagnosis.underused_task_parallelism.source_scope_verified=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

该源码复合观察绑定当前workload的独立任务域、实际BlockDim及可用同类核，与机制链“独立可并行工作未充分分解或启动核数过少 → 有效任务数少于可用同类核且每任务有足够长工作 → 部分核空闲，关键路径仍由少数核串行承担”相容，因此只形成待核验候选与profile预测。它不证明现象已在profile出现，也不是因果充分条件。

- 先考虑已有独立外轴，再评估Split-K/Split-KV与partial成本
- 读取目标核数API与kernel mode，不用来源的48/64等样例数字

## 例外与代价

- 微小任务或算法依赖使增并行开销大于节省时，本机制不构成可执行理由
- BlockDim大但逻辑任务只有一个并不能证明已吃满核
