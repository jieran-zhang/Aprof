# symptom.source.tail_concentrated → problem.core_tail_imbalance

## 关系与对象绑定

symptom.source.tail_concentrated —supports→ problem.core_tail_imbalance。

- target→target：同一task与parent实现，绑定同一target身份；同次调用各核任务集合、有效长度及最长核
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.source.tail_concentrated=true
- constraint.diagnosis.core_tail_imbalance.source_scope_verified=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

该源码复合观察绑定同次调用各核任务集合、有效长度及最长核，与机制链“任务数量或单位任务成本在核间不均 → 少量核承担集中尾部、变长或causal工作 → 其他核提前完成/等待，调用时长由最长核决定”相容，因此只形成待核验候选与profile预测。它不证明现象已在profile出现，也不是因果充分条件。

- 比较max/min任务数之外也计算变长与causal工作量
- 让任务成本模型与逐核时间排序对应，而非只比较平均利用率

## 例外与代价

- AIC/AIV不同角色的时长差不能当同类核负载不均
- 逐核工作量均衡但统一等待长，应改查同步或共享带宽
