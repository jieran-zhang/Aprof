# symptom.profile.control_metadata_overhead → problem.control_metadata_overhead

## 关系与对象绑定

symptom.profile.control_metadata_overhead —supports→ problem.control_metadata_overhead。

- target→target：同一task与parent实现，绑定同一target身份；热循环中重复读取的TilingData字段、mask、索引和分支
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.profile.control_metadata_overhead=true
- constraint.diagnosis.control_metadata_overhead.profile_scope_verified=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

该profile复合观察需同时满足对象、有效域、窗口、单位与模型要求，并按本边检查区分“重复控制与逐元素数据处理不同”。满足后仍需比较替代解释，相关性不单独确立机制。

- 区分按任务变化、按tile变化与循环常量，不能全局缓存动态字段
- 将TilingData大结构拷贝与少量热点字段重复读取分别核算

## 例外与代价

- 编译器已折叠/外提或字段随loop变化时，源码重复不等于运行重复成本
- 增局部缓存导致寄存器压力上升时需比较spill
