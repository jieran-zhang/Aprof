# symptom.source.noncontiguous_access → problem.noncontiguous_access

## 关系与对象绑定

symptom.source.noncontiguous_access —supports→ problem.noncontiguous_access。

- target→target：同一task与parent实现，绑定同一target身份；带明确shape、layout、stride和有效索引域的输入或输出切片
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.source.noncontiguous_access=true
- constraint.diagnosis.noncontiguous_access.source_scope_verified=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

该源码复合观察绑定带明确shape、layout、stride和有效索引域的输入或输出切片，与机制链“切分或遍历轴跨过物理连续内轴 → 相同有效元素分解成离散事务、短块或额外padding → 发射与实际流量增加使有效字节带宽下降”相容，因此只形成待核验候选与profile预测。它不证明现象已在profile出现，也不是因果充分条件。

- 沿至少两个连续tile手工核对GM地址差，区分逻辑索引与实际事务
- 使用相同shape、dtype、缓存状态的连续形态作参照

## 例外与代价

- 原地址已连续且事务数符合模型，则不能归因于跨轴
- 稀疏索引语义本身要求离散访问时，重排空间受owner和输出顺序约束
