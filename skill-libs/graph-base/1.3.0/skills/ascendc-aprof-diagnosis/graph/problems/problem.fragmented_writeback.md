# 碎片化写回

## 对象、阶段与适用域

- 同一输出tensor的相邻有效区间及MTE3/Fixpipe写回点
- host输出分片
- kernel CopyOut或Fixpipe epilogue

旧scope=all保留作检索范围，机制成立仍须核对目标架构、dtype、shape和API支持。

## 机制链

- 已就绪的相邻输出被分成多个小写回
- 输出流水重复支付发射与对齐成本
- 短写回和等待进入尾部关键路径，即使输入搬入已高效仍可能受限

## 预测、支持检查与反证

- 批量写回可减少输出发射，实际有效输出字节应保持；这是prediction
- 把输入MTE2与输出MTE3/Fixpipe分别计数，避免把读瓶颈当写瓶颈
- 核对输出连续性、唯一写回、buffer何时可释放
- 各输出只有在不同依赖阶段就绪，等待汇总反而延长关键路径时不支持合并
- 写回已为大包且接近带宽上限时转查带宽

## 具体替代解释

- problem.tiny_transfer_setup_amplification：共同固定发射成本，但本项绑定输出就绪和写回通路；检查：分离MTE2与MTE3/Fixpipe并检查输出区间
- problem.memory_bandwidth_saturation：短写回低效与大包写带宽饱和有不同基准；检查：核对有效输出bytes/issue与同方向带宽

## 候选动作与成本

action.batch_writeback：把同owner且同时可释放的相邻输出在片上汇总后批量写回。

原硬前提：symptom.source.fragmented_writeback=true；constraint.output_ownership=true；constraint.semantic_equivalence=true；constraint.capacity=true。

- 延迟buffer释放并增加片上峰值
- 汇总延迟可能推迟下游消费

## 限制与缺口

- Fixpipe和MTE3能力、对齐与尾写语义必须分别核验
- 归约标量输出本身很小，不能仅凭大小认定碎片化
- 本轮无同任务profile、无case_support、无收益或发生频率声明；源码形态只支持待核验候选。
