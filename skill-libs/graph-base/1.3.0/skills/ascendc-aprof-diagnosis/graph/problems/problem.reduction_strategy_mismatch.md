# 归约分解与工作量不匹配

## 对象、阶段与适用域

- 合轴后AR或ARA归约的A1/R/A0域及partial状态
- host归约分支与切核
- kernel载入、归约和后变换

旧scope=all保留作检索范围，机制成立仍须核对目标架构、dtype、shape和API支持。

## 机制链

- 全载/行列切分/跨核方案未适配R长度、独立A量和容量
- 可能产生欠并行、重复读、过多partial或不合适的广播路径
- 主归约及合并/后变换成本超出可行替代方案

## 预测、支持检查与反证

- 按容量与并行重新选分支可能降低重复读或最长核，但会引入归并成本；这是prediction
- AR按连续行与ARA按R×A0块分别计算，不能把临时区估算通用化
- 对Group Reduce同时核算partial写读、同步、合并和精度顺序
- 当前分支已经满足容量和任务模型且成本来自bank/同步时，不把所有归约慢都归此项
- 缺少合轴或scratch规则时不能裁定替代分支可行

## 具体替代解释

- problem.underused_task_parallelism：欠并行只是归约策略失配的一种表现；检查：比较A域任务和合法R拆分空间
- problem.chunk_merge_overhead：跨R拆分可能主阶段更快却使合并占优；检查：分阶段比较而非只看总归约时间

## 候选动作与成本

action.restructure_reduction：按AR/ARA、A/R和容量选择全载或合法切分的归约结构。

原硬前提：symptom.source.reduction_strategy_mismatch=true；constraint.reduction_semantics=true；constraint.semantic_equivalence=true；constraint.capacity=true。

- partial与合并同步、workspace及舍入顺序变化
- 全载可能减少并行或挤占流水buffer

## 限制与缺口

- API scratch需按目标SDK查询/规则计算，不沿用文档4KB等样例常量
- 归约后广播是另一个成本点，不能只调R
- 本轮无同任务profile、无case_support、无收益或发生频率声明；源码形态只支持待核验候选。
