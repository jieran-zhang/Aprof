# 混合计算阶段节拍失衡

## 对象、阶段与适用域

- 具有依赖交接的AIC与AIV阶段及同一tile的中间状态
- host混合kernel模式与任务粒度
- AIC QK/PV
- AIV softmax/rescale与交接

旧scope=all保留作检索范围，机制成立仍须核对目标架构、dtype、shape和API支持。

## 机制链

- AIC和AIV每tile有效工作、任务粒度或吞吐不匹配
- 较快一侧在真实生产消费边界反复等待较慢一侧
- 可重叠链受较慢阶段和握手频率限制

## 预测、支持检查与反证

- 改变tile或后处理分担可能平衡阶段关键路径；这是prediction
- 把总AIC时间等于总AIV时间不作为目标，重叠与依赖决定收益
- 按tile流水甘特而非单看aic_ratio/aiv_ratio比较
- 联合核算中间buffer、workspace、握手频率与tile改变
- AIC/AIV本来执行不同工作且互不等待时，时间不等不能支持失衡
- 等待来自过宽屏障或事件错误时先区分同步机制

## 具体替代解释

- problem.pipeline_serialization：串行是没有重叠，失衡可在充分重叠下仍由慢侧限制；检查：检查稳态重叠及阶段队列等待
- problem.excessive_sync_scope：同步过宽可能制造表面失衡；检查：对照真实依赖与等待范围

## 候选动作与成本

action.rebalance_mixed_stages：在数学和owner契约允许下联合调整AIC/AIV阶段tile、工作分担或交接粒度。

原硬前提：symptom.source.mixed_pipeline_imbalance=true；constraint.cross_engine_dependencies=true；constraint.semantic_equivalence=true；constraint.capacity=true。

- 扩大中间区/workspace并改变buffer深度
- 重分阶段可能改变同步拓扑，需返回C2核算

## 限制与缺口

- 混合核的角色不同，不能把逐核时间差直接当负载不均
- arch22 FA阶段示例不证明其他混合算子的通路相同
- 本轮无同任务profile、无case_support、无收益或发生频率声明；源码形态只支持待核验候选。
