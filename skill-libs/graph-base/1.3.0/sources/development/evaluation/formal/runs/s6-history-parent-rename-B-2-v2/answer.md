## 结论与证据边界

两个子例的优化选择应相同。`L0/L1/L2` 与 `Pine/Fir/Oak`、`GridSampler3DScalar` 与 `RunIndexed` 的改名不改变依赖、地址、覆盖或工作量；输入材料也没有提供改名影响编译优化的证据。

本轮选择一个**派生几何复用的纸面试验方案**：最近邻路径中，同一 owner 生成一个空间点的采样索引，供两个通道消费；不增加 GM 几何表、不整体搬入 X、不更换舍入算法。登记一个 `action.reuse_derived_results` 实例即可，不为分核、标量记录和配套边界处理另凑 Action。

这是有明确工作减少依据的条件化 C2/C3 交接，**没有实施、构建、正确性或收益结论**。正式实施仍需补齐启动接线、输入输出别名合同及源码/模板身份绑定。不会因为缺实测收益统一否决该试验，也不会越过这些安全条件。

# 子例 a：L0/L1/L2，`GridSampler3DScalar`

## 一、当前实际路径、数学与数据依赖

### 1. 当前 workload 实际执行什么

入口第 194–196 行按 dtype 分派。本例指定 `GridSampler3DScalar<float>`，因此走 FP32 标量路径，不经过 Half 类的 UB、Cast、DataCopyPad 和三次全流水屏障。

令 \(p\in[0,S)\)，输出为：

\[
Y[n,c,p]=X[n,c,z_n,y_n,x_n]
\]

采样位置无效时返回 `0.0f`。其中三轴坐标按第 71–74 行原表达式计算，再由第 50–56 行 `GridRoundEven` 做 ties-to-even；不能用简单的 `floor(x+0.5)` 替换。

本例：

\[
u=((0+1)\times16-1)\times0.5=7.5,\qquad
\operatorname{RoundEven}(7.5)=8
\]

所以每个通道的所有空间点读取：

\[
X[0,c,8,8,8],\qquad
\text{空间偏移}=(8\times16+8)\times16+8=2184
\]

X 全为 1，因此 2048 个输出都应为 1。这个事实用于解释日志，**不授权按 `x=1,grid=0` 返回常量**。

### 2. 依赖结构

第 101–113 行表明：

- 几何依赖 `grid[n,p,:]`、D/H/W、padding、alignCorners、interpolation；
- **不依赖通道 c**；
- X 的通道基址依赖 c，几何相同不意味着各通道 X 值相同；
- 每个输出独立，无跨输出归约、原子或核间合并；
- NCDHW 中 p 连续，通道间输入跨度为 4096 元素，输出跨度为 256 元素。

通用三线性路径仍须保留第 125–132 行的八项次序，以及每项 `value * wx * wy * wz` 的计算组织。越界先由 `GridRead` 判定再读；不能先越界取数再乘零，也不能因权重为零跳过可能影响非有限值行为的项。本轮不改变该路径。

### 3. 原所有权及数据流

第 143–148 行每核拥有：

\[
I_b=[bL,\min((b+1)L,2048))
\]

其中 FP32 的 \(L\) 向 16 元素对齐。按 tiling 中的 blockNum 启动时，区间无重叠、覆盖全部输出；末端以 outputNumel 裁剪。源码可证明分配公式，**实际 launch 是否使用该 blockNum 没有给出调用端证据**。

FP32 路径为标量 GM 读 grid、标量求坐标和索引、标量 GM 读 X、标量 GM 写 Y。不能把它描述成已有批量 MTE 搬运或已有 Vector 插值。

## 二、历史事实审计：不能据最快数字选父本

| 身份 | 源码与正确性事实 | 计时记录能说明什么 |
|---|---|---|
| L0 | 完整 `++linear`；原日志当前 case passed，覆盖 2048 输出 | T0 为 launch 前至 stream synchronize 后，合成记录 1.0 ms；不是硬件实测，也不足以形成稳定性能基线 |
| L1 | 唯一改动 `linear+=2`；原日志 failed，1024 错误 | T1 0.4 ms 对应少做输出的错误实现，不能作为合法优化收益 |
| L2 | 与 L0 字节相同，但源码 identity 单独保留；当前 case passed，覆盖 2048 输出 | T2 截止于 enqueue 后、同步前，不能与 T0 比较完整调用耗时 |

FP32 block 起点是 16 元素倍数，本例各有效分段长度也为偶数；L1 恰写一半输出。未写部分保持初始化零，与全 1 reference 不同，解释了 1024 个错误。

因此：

- 本轮分析父本选 **L0**，不选 L1。
- L2 可复用字节相同的结构分析，也可引用其独立正确性记录；不能把 T2 当成“同代码快五倍”。
- L1 证明的是覆盖失败，不反证几何复用、向量化或缓存机制。
- 所有原数字继续标为**题目合成原始记录**，不作设备收益证据。

## 三、工作量与主要机会比较

记：

- \(M=NCS=2048\) 个输出；
- \(G\) 表示一次完整最近邻几何构造，按操作类别理解，不是时间；
- \(A\) 为 Host 获得的可用 AIV 数，本题未给实值。

### 1. 原实现的源码工作模型

当前全有效坐标下：

| 项目 | 数量 |
|---|---:|
| 几何构造 | 2048 次 G |
| grid 标量元素读取 | \(3M=6144\) 个 float，即 24576 B |
| X 有效读取 | 2048 个 float，即 8192 B |
| Y 写入 | 2048 个 float，即 8192 B |
| 合计有效逻辑 GM 请求字节 | 40960 B |

这些不是 HBM 字节。当前实际唯一 grid 数据只有 \(256\times3\times4=3072\) B，采样 X 的唯一值只有 8 个 float、32 B；缓存可能已服务大量重复请求，命中和延迟未知。X 总分配为 131072 B，不应将整个 X 大小当作当前必要读取量。

### 2. 选中主方案：两个通道共享一个几何结果

**参数候选：\(C_t=2,\ S_t=16\)。**

任务为互斥矩形：

\[
[n,\ c_0:c_0+2,\ p_0:p_0+16]
\]

每个空间点立即构造一个最近邻记录，随后消费两个通道，再处理下一个 p。记录只跨两个消费者存活，不保存整个空间 tile 数组。

本例任务数：

\[
T=N\frac C{C_t}\frac S{S_t}
=1\times4\times16=64
\]

全快路时：

| 工作 | 原实现 | 主方案 |
|---|---:|---:|
| 几何构造 | 2048 G | 1024 G |
| grid 读取 | 6144 float | 3072 float |
| X 读取 | 2048 float | 2048 float |
| Y 写入 | 2048 float | 2048 float |
| 有效逻辑 GM 字节 | 40960 B | 28672 B |
| GM workspace | 0 | 0 |

新增代价：

- 每个候选记录的数值安全判定、分支和两个消费者循环；
- 更长的索引记录存活期、额外任务状态及可能的寄存器/栈代价；
- p 外、c 内的消费顺序，交替访问两个相距 16 KiB 的输入通道和相距 1 KiB 的输出行；
- 任务从原最多 128 个 16 元素所有权块变为 64 个矩形；当 \(A>64\) 时可能减少活跃核数；
- 并未消除逐输出 X 读取、Y 写入及标量处理。

选择它不是因为改动少，而是：它直接减少坐标变换、RoundEven、边界和空间偏移生成这些实际数据工作；相较全通道复用，保留更多独立任务；相较 GM 表，避免新增阶段和中转；相较向量化，不需要尚未闭合的 Gather/取整替换。

### 3. 数据相关保护必须计入收支

不能把所有同形输入假定为当前的有限零坐标。

拟议保护粒度是**一个空间点、一个两通道组**，不是整 tile 或整通道平面：

1. 读原 grid 三元组，按位检查非有限值；
2. 有限值按原表达式计算 ix/iy/iz；
3. 仅当三轴位于保守的整数转换安全范围，例如 \([-2^{62},2^{62}]\)，才调用原 `GridRoundEven` 并共享结果；
4. 其余情况对该点的两个通道分别调用**未修改的** `GridSampler3DOne<float>`。

这不是将非有限坐标改成零，也不声称原代码的非有限到整数转换语义已经闭合。它只保证新共享路径不重新定义该域；若原 oracle 与原路径存在特殊值缺陷，另行报告，不能借本轮修复偷换语义。

令 \(Q=1024\) 为候选记录数，\(f\) 为快路记录比例：

- 当前输入可静态判定 \(f=1\)，无保护回退；
- 任意同形内容不能假设 f 很高；
- 若回退调用重新读取 grid，则 grid 请求为：

\[
3Q+3C_t(1-f)Q
\]

当 \(f=0\) 时为 9216 个 float，比原 6144 个更多。
- 几何构造包含 \(fQ\) 次快路构造和 \(C_t(1-f)Q\) 次原函数构造；部分回退还已经执行过一次坐标反归一化，必须另计，不能视为免费检查。
- X/Y 的有效读取和完整写回仍必须保留。

如果后续发现保护频繁触发、检查成本或编译生成抵消共享收益，应重新比较保留重算，而不是坚持“理论减少一半”。

### 4. 最有竞争力的替代：全八通道共享

仍用一个 `action.reuse_derived_results` 意图，取 \(C_t=8,S_t=16\)：

| 项目 | 主方案 \(C_t=2\) | 替代 \(C_t=8\) |
|---|---:|---:|
| 任务数 | 64 | 16 |
| 全快路几何构造 | 1024 G | 256 G |
| grid 逻辑读取 | 12288 B | 3072 B |
| X+Y 字节 | 16384 B | 16384 B |
| 总有效逻辑 GM 字节 | 28672 B | 19456 B |
| GM 表、额外 kernel | 无 | 无 |
| 单记录消费者数 | 2 | 8 |

替代方案减少更多几何与检查，且仍可只保留一个记录；但最长任务的消费者工作更多、跨通道轮转更远、只有 16 个独立任务。若实际 \(A\le16\)，其并行损失理由会明显减弱，应提升它的优先级；若几何构造占主成本，即使 \(A>16\) 也可能胜出。

本轮选 \(C_t=2\) 是**未测参数试验选择，不是最优阈值结论**。实际核数和同口径比较将决定是否改为更大复用组。

### 5. 其他会影响选择的机会

- **只合并写回**：原 owner 不变，暂存 T 个 float 后批量写出，可将 2048 次源码标量 GM store 改为约 \(\sum_b\lceil |I_b|/T\rceil\) 个搬出片段。几何和 grid 重读仍为原数量，增加 `AlignUp(4T,32)` B 输出区、标量写 UB 和完成边；当前 UB 可用量未知。它是强残余机会，但不能将标量 store 数直接称作原 MTE3 发射数。
- **GM 几何表**：可生成 NS=256 份表，但每次调用新增表写、消费者读、workspace 和发布依赖。若每记录 b 字节，至少增加 \(256b\) 表写及按实际消费者组织计算的表读；不能把准备阶段移到 Init 就归零。本例不优先。
- **仅缓存 tiling 字段/地址递推**：能处理整数控制，却不消除通道间几何重算。编译器是否已有 CSE 未知，因此不优先于主要数据工作。
- **批量 Vector 最近邻**：机会存在，但必须闭合取整、索引宽度、Gather、尾部和特殊值。材料没有提供可直接替换这条 FP32 GridSampler 链的完整 API 证明，本轮不把它标成可实施。
- **整体搬入源窗口**：当前零 grid 具有局部性，但一般同形 grid 任意；不能据输出连续假设源连续，也不能用当前常量内容形成生产特化。
- FP32 实际路径没有 Half 屏障，故不能把删 Half 屏障选成本例主优化。没有持续带宽、spill、bank 或混合核证据，也不认定这些瓶颈。

## 五、统一 C2 共同计划

### 1. 所有权与分核

固定 64 个任务：

\[
g=\lfloor t/16\rfloor,\quad j=t\bmod16,\quad
c_0=2g,\quad p_0=16j
\]

任务 t 拥有：

\[
Y[0,c_0:c_0+2,p_0:p_0+16]
\]

核 b 处理 \(t=b,b+B,\ldots<64\)，拟用：

\[
B=\min(\max(1,A),64)
\]

每个输出唯一写一次。每个通道的任务写区间为 16 float、64 B；不通过扩大尾写覆盖其它任务。完整当前域无 Ct/St 尾；通用域仍走原实现。

### 2. 布局、记录与通路

- 外部 X/Y 保持 NCDHW，grid 保持 `[N,S,3]` 展平解释。
- 一次只保留一个记录：有效标志和有效时的 uint64 空间偏移；RoundEven 中间仍用原 int64。
- 无效记录直接产生原 `GridRead` 的 `0.0f`，不构造非法 GM 指针。
- 每通道使用自己的 `c*4096` 基址，不复用通道源值。
- 无 GM 表、无布局转换、无新 kernel、无显式 UB 数组。

### 3. 同步、容量和生命周期

记录无异步消费者，不需要新跨核同步或事件。只使用现有标量读写路径；不能再混入 DMA 写同一输出区而不重审可见性。

\[
W_{\rm new}=0,\qquad U_{\rm explicit,new}=0
\]

不因此声称“资源免费”：新循环状态和跨消费者存活记录可能增加寄存器/栈使用，须检查实际编译产物。若改为数组、批量搬出或多槽，需重新计算同时存活分配，不能沿用这份容量结论。

### 4. 分派与 KEEP

专用谓词只使用上述真实元数据，不检查 case 名、历史耗时或 `grid==0`。其它元数据走原通用路径。

原工程没有 tiling-key 字段和已展示的 Host 注册框架，因此不虚构 `TILING_KEY_IS` 接线。纸面可将专用/通用组分别标为内部计划 key 1/0，真实实现优先在现有 entry 中按一致谓词分支，不必修改 ABI。Host 必须同步选择 blockNum；未给出的 launch 接线是实施前补项。

- **不是 P_KEEP**：任务、owner 矩形和消费顺序确实改变。
- 原通用域是“提取并保留原计划”，不能统计为新增并行收益。
- 没有增加管理优化 Action，也没有取消现存事件。
- 缺正式旧计划/hash 不转成 KEEP。
- X/grid/Y 若存在可影响读版本的别名，当前重排不获授权；应保留原路径并回 C2，而不是添加错误的 `restrict`。

## 六、C3 准确实施步骤及 P/O 正文的实际影响

以下是交接步骤，**本轮未执行**。

1. **冻结父本与记录**  
   从 L0 建隔离候选，保留 L1 失败和 L2 独立身份。建立真实源码与模板引用，不计算或编造 hash。

2. **补齐执行合同**  
   核对 launch 使用的 blockNum、可用 AIV 参数来源、输入生命周期及输出别名合同。若这些条件不满足，不能落地新 owner 计划。

3. **实现一致的元数据谓词**  
   Host 与 kernel 对专用域使用同一组条件；其它元数据保持原 tiling 和入口。不给通用 fallback 继承未经验证的新假设。

4. **拆出最近邻记录生成与消费**  
   生成函数保持第 107–112、50–56、89–94 行对应语义；消费者仅加各通道基址、合法时读 X、写原输出地址。不重关联浮点表达式，不改用新取整 API。

5. **加入逐点保护与原函数回退**  
   特殊坐标在整数转换前退出共享生成；按两个通道分别执行原 One。不得整 tile 一票回退，也不得将回退结果写零。

6. **接入 64 个矩形任务**  
   按 C2 映射循环，保证每个 p 的两个消费者完成后才覆盖记录。保留所有 2048 个有效写入；不得继承 L1 的步长。

7. **静态审查**  
   检查最大地址、任务覆盖、宽整数乘加、无效地址不形成、特殊值域、空任务核及重复调用。检查寄存器/栈未知项，不新增 UB 管理或屏障来掩盖问题。

8. **未来获得执行授权后再验证**  
   构建、完整原 oracle、全部输出覆盖和相邻元数据 fallback 验证后，才进行同口径计时。若修复新增扫描、整域回退、数组或同步，应将新成本回传 C1/C2。

实际采用的知识影响：

- **P `planning.indexing.coordinate_neighborhood`**：使任务采用“复用轴块×空间块”，并显式绑定 G/B/H/F、真实 NCDHW stride；没有错误套用 GatherElements 语义。
- **O `implementation.buffer-lifetime.derived-results`**：要求只跨不变轴复用、预算记录读取与活跃状态；因此选单记录立即消费，不建免费 GM 表或隐式 Scalar 数组。
- **O `implementation.precision-boundaries.numeric`**：保留 RoundEven、特殊值路径和三线性次序，不以实数等价替代浮点等价。
- **O `implementation.precision-boundaries.bounds`**：要求先判界再寻址、宽整数检查和完整唯一写回。
- **O `implementation.tiling-tail.dispatch`**：使分派依据是元数据及真实 entry，而不是版本名称或 T2 数字；原工程没有 key ABI，不能凭模板补造。

这些是依据输入正文作出的纸面选择，**未运行 P/O router，也未声称正式路由命中**。

# 子例 b：Pine/Fir/Oak，`RunIndexed`

## 一、实际路径与关键事实

对应关系为：

| 子例 a | 子例 b | 保留的事实 |
|---|---|---|
| L0 | Pine | 完整写 2048 输出；当前 case 原日志 passed |
| L1 | Fir | 步长 2，漏写一半；1024 错误 |
| L2 | Oak | 与 Pine 字节等价的重新保存身份；当前 case 原日志 passed |
| `GridSampler3DScalar` | `RunIndexed` | 仅函数标识不同，仍为 FP32 标量路径 |

本例仍是 grid 0→坐标 7.5→ties-to-even 得 8→读取每通道空间偏移 2184；每输出依赖自己的 X 通道值，几何不依赖通道。原分核、NCDHW 布局、通用三线性次序和边界语义完全相同。

Fir 的较短记录仍因错误覆盖不能用于排名；Oak 的 enqueue 截止记录仍不能与 Pine 的同步完成窗口比较。改名没有修复任何正确性或计时口径问题。

## 二、主方案、替代及成本

选择与子例 a 相同：两个通道共享一个派生索引，\(C_t=2,S_t=16\)。

- Pine：2048 次几何、6144 个 grid float 读取、2048 次 X 读取和 2048 次 Y 写入。
- 候选全快路：1024 次几何、3072 个 grid float 读取；X/Y 必要访问不减。
- 有效逻辑 GM 请求为 40960 B→28672 B，不是 HBM 节省承诺。
- 64 个矩形任务，无 GM workspace、无显式 UB。
- 当前有限零坐标保护全部走快路；一般同形内容仍按逐点保护，回退成本公式与子例 a 相同。
- 最强替代仍为全八通道共享：256 次几何、16 个任务、19456 B 有效逻辑 GM 请求；更多复用与更少并行的竞争未因名称改变。

因此本例**成本没有变化**，不是“选择相同但成本不同”。若仅改标识就改方案，材料中没有可支持的来源。

## 三、实例、C2 与 C3 交接

独立登记：

- 实例：`b.nearest-derived-pair.r1`
- Action：同一冻结正文的 `action.reuse_derived_results`
- 父本：**Pine**
- target：`RunIndexed` 所调用的最近邻几何生成与两通道消费阶段
- 状态：`conditional_plan`

所有条件与子例 a 分别重新绑定到 Pine，不借 L0 的源码 identity 冒充 Pine 的正式引用。两者可以复用语义分析，但真实实现 hash、patch 和验证产物必须各自保留。

共同 C2 完整计划沿用前述矩形映射、布局、单记录生命周期、零 workspace、无新同步及互补 fallback；同样是 **P_CHANGE，不是 P_KEEP**。启动与别名合同仍是具体实施缺项，不因改名自动满足。

C3 按前述八步实施，仅将父本、函数定位和实例身份替换为 Pine/`RunIndexed`。P/O 正文的实际影响也相同：坐标邻域模板决定 owner 骨架，派生结果正文决定保存对象与生命周期，numeric/bounds 保留精度和地址合同，dispatch 正文禁止按 Pine/Fir/Oak 名称分派。不能复制子例 a 的未来正确性或计时结果作为本例已经完成验证。
