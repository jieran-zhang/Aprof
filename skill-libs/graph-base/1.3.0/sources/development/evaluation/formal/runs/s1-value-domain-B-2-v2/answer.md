## 结论与交接状态

**两个子例均选择同一个纸面方案：在现有输出所有权内，将有效 tile 上限收至 256，并把两次四邻居 Gather 合为一次八邻居 Gather。**  
快路将八个独立乘法批量表达；软件路径一次消费八邻居，但仍逐项执行原来的 `GridFma32Bits`，不改变数值语义。

两例的收益机制不同：

- **a：**主要减少无效 Gather lane、索引初始化和 Vector 发射。
- **b：**上述减少仍成立，并减少软件加权函数的调用边界及中间 accumulator 的 UB 反馈；**16384 次软件 FMA 均保留**，不把它们替换为分离乘加。

这是一个有静态依据、可交给后继实施的完整候选，不是已实施或已验证结果。当前仅完成纸面 C1/C2/C3 分析；实际可用 UB、目标 SDK 构建、完整 launch 接线及 oracle 验证仍未闭合，故状态为 **conditional_plan / not_measured**。不生成虚假 hash、路由回执或“正确性通过”记录。

# 一、共同理解：必须以 Weighted 为父本

题目指定实际执行 `GridSampler3DWeighted<float>`，因此原始文件第 190–197 行的旧 Scalar/half 入口只是背景，不能据其判断本次走 Scalar 插值。

记：

\[
I=DHW=4096,\quad S=256,\quad O=NCS=2048,\quad K=8.
\]

### 1. 数学与数值路径

`GridGeometryRange` 第 243–270 行为每个空间点生成：

- 八个 `uint32_t` **字节偏移**；
- 八个 FP32 权重，保持源码的两次舍入：
  \[
  w_k=\operatorname{fl}(\operatorname{fl}(w_xw_y)w_z).
  \]

几何依赖 grid、空间尺寸和插值属性，不依赖通道；本题已经按 `geometryLength=NS=256` 预计算一次。**不能再声称本轮把几何生成从 2048 次降至 256 次。**

消费阶段对每个通道：

1. 整个 4096 元素输入平面进入 UB cache；
2. 扫描整个平面决定 `software`；
3. 搬入对应空间段的八路索引、权重；
4. 两组各四邻居 Gather、加权，按 \(k=0,\ldots,7\) 累加；
5. 写回有效输出。

快路为：

\[
a_{k+1}=\operatorname{fl}\!\left(a_k+\operatorname{fl}(v_kw_k)\right).
\]

软件路径为：

\[
a_{k+1}=\operatorname{FMA32}(v_k,w_k,a_k),
\]

其中 FMA32 是题目保证正确的整数软件实现，不是一次硬件指令。两者不能随意互换。

### 2. 边界与数据依赖

`GridOffsetBytes` 第 194–202 行把越界邻居指向平面末尾的 UB 零哨兵，字节偏移为 \(4I=16384\)。cache 分配包含该位置，并在载入后显式写零。

当前 grid 的反归一化坐标约在 \([1.1,13.9]\)，八邻居均在输入内部；但这只是本次数据事实，**不成为派发条件，也不允许删除 zeros 边界逻辑**。

几何表必须在消费前完成发布。输入 cache 在扫描及所有 Gather 完成前不得覆盖；索引、权重在 DMA 完成后才可消费；输出 acc 在 MTE3 读完前不得复用。`PIPE_ALL` 是核内完成边，不能替代几何生产者到消费者的跨核或跨 kernel 发布。

### 3. 当前容量和工作量

由第 457–460 行：

\[
cb=\left\lfloor\frac{4096+64}{64}\right\rfloor64\times4=16640\text{ B},
\]

\[
T_{\rm old}
=\min\left(1920,
\left\lfloor\frac{196352-8192-cb}{128\times84}\right\rfloor128\right)
=1920.
\]

当前显式静态 UB：

| 区域 | 字节 |
|---|---:|
| cache | 16640 |
| index，\(8T\) 个 uint32 | 61440 |
| weight，\(8T\) 个 float | 61440 |
| value，\(4T\) 个 float | 30720 |
| acc，\(T\) 个 float | 7680 |
| **合计** | **177920** |

源码预算另扣了 8192 B；其实际用途及可用 UB 上限不能由常量自行证明。

设 \(M\) 为**有效 block 与通道平面的交集段数**。真实 blockNum 未给，不固定核数。沿所示 16 元素对齐的连续分区，每段有效长度 \(q\le256\)，且：

\[
\sum q=2048,\qquad 8\le M\le128.
\]

本题每个交集段均小于 1920，因而当前每段都会：

- 初始化 \(8T=15360\) 个索引为哨兵；
- 两次 Gather，共处理 \(8T=15360\) 个 lane；
- 实际有效邻居仅 \(8q\) 个。

这是可消除工作，不是测得的耗时占比。

几何消费读量为：

\[
2048\times(8\times4+8\times4)=131072\text{ B}.
\]

输入平面载入为 \(16384M\) B；输出为 8192 B。加上 grid 读取 3072 B、几何写入 16384 B，完整所示链的有效逻辑 GM 请求为：

\[
158720+16384M\text{ B}.
\]

这不是 HBM 实测流量。

# 二、子例 a

## 1. 当前实际路径与关键事实

每个平面的全部元素均有限且位于 \([-1,1]\)，所以正、负两次阈值扫描均不命中，`software=false`。2048 个输出全部走 Vector 分离乘加。

每次完整平面扫描中：

- `words=128`；
- `wordCount=128`；
- `sourceCount=4096`；
- `tail=0`；
- 每个正/负检查含 4096 个浮点比较、128 个 int32 EQ 和一次 64 元素压缩比较。

因此每次 cache 载入有两次检查；它们不是普通的“一个 bool 判断”。不过本轮不更改扫描或阈值。

有效加权计算仍需：

- 16384 个 FP32 乘法元素；
- 16384 个按序 FP32 加法元素。

当前每段八次 Mul、八次 Add；不能把八次依赖 Add 合成树归约。

## 2. 所选方案

纸面方案 ID：`S1-weighted-eight-neighbor-batch`。

保持原 block 区间、通道边界、几何表和 cache 路径，改为：

- \(T=256\)；
- `value_` 扩为 \(8T\) 个 float；
- 一次 `Gather(values, cache, idx, 0U, 8*T)`；
- 当 `count==T` 时，八路值和权重均为连续完整布局，一次：
  `Mul(values, values, coeff, 8*T)`；
- 然后仍按八路顺序执行 `Add(acc,acc,values[k*T],count)`；
- 短段保留每路有效 `count` 的 Mul，避免读取未定义权重 padding。

### 工作变化

| 工作 | 当前 | 候选 |
|---|---:|---:|
| 每段 Gather API | 2 | 1 |
| 每段 Gather lane | 15360 | 2048 |
| 每段索引初始化 | 15360 个 | 完整段 0；短段 2048 个 |
| 完整段 Mul API | 8 | 1 |
| 短段 Mul API | 8 | 8 |
| 每段 Add API | 8 | 8 |
| 有效乘、加元素数 | 各 16384/调用 | 不变 |
| 几何生成、GM 有效字节、平面扫描 | 原工作 | 不变 |

总 Gather lane 从 \(15360M\) 降至 \(2048M\)，但不能据此推导时间同比下降。

新显式 UB 为：

\[
16640+(32+32+32+4)\times256
=42240\text{ B}.
\]

若保守保留原 8192 B 预算余量，则要求至少 **50432 B 加未列额外开销**的合法空间。

### 覆盖

本题 a 的全部输出执行新 Gather 路径。只有满足 `count==256` 的完整段获得 Mul 合批；其数量取决于实际 block 分区，不能假定有八段完整平面。

软件路径仍有实现，不能以 a 的范围删掉它。同元数据的其他数值输入必须仍合法。

## 3. 最强竞争替代

**同样令 \(T=256\)，但保留两组四邻居 value、Gather 和消费结构；完整组各做一次 \(4T\) Mul。**

它已消除绝大多数大 tile 无效工作，并需要：

\[
16640+84\times256=38144\text{ B}.
\]

相较该替代，主方案：

- 多占 4096 B value 区；
- 每段 Gather 从两次再降为一次；
- 完整段 Mul 从两次再降为一次；
- 不减少必要算术或 GM 字节；
- 第一组消费需等八邻居 Gather 就绪，而非先完成四邻居 Gather。

选择主方案，是因为当前没有展示两组之间的有效流水重叠，额外 4096 B 换来更完整的批量表达，且总分配显著低于父本。若目标 SDK 对该 Gather 布局有额外限制，或八邻居首包等待抵消发射节省，四邻居替代应重新竞争，而不是坚持主方案。

# 三、子例 b

## 1. 当前实际路径与关键事实

每个通道的最后一个元素为 \(2^{125}\)，正阈值检查必定命中：

\[
2^{125}\ge2^{124}.
\]

`GridNeedsFma32` 的 `||` 短路使负向检查不再执行。**触发粒度是整个输入平面，不是被命中的一个元素，也不是采样邻居集合。**

因此：

- 每个被载入平面都令 `software=true`；
- 所有 2048 个输出均走软件路径；
- 软件 FMA 总数为：
  \[
  2048\times8=16384.
  \]

最后元素没有被采样，并不使快路合法。即使全部被采样值都很小，FMA 与分离乘加仍可能产生不同舍入结果。**不能把扫描改成只检查 Gather 值后直接恢复快路。**

## 2. 所选方案及成本变化

采用同一 `S1-weighted-eight-neighbor-batch`，但真实执行的是：

1. \(T=256\)、一次八邻居 Gather；
2. 调用现有通用函数：
   `GridSoftwareWeighted(values,coeff,acc,0,8,T,count)`；
3. 每个输出从 `acc` 读取一次初值，在标量 `uint32_t sum` 中按 \(k=0,\ldots,7\) 调用原 `GridFma32Bits`；
4. 完成八项后写回一次。

这只是把原来两次四项消费拼为一次八项消费。每次 FMA 仍返回相同 binary32 位模式；中间值保存在同宽 `uint32_t`，不添加浮点精度，也不改变累计次序。

### 工作变化

除 a 中共同的 Gather、索引初始化减少外：

| 工作 | 当前 | 候选 |
|---|---:|---:|
| 软件加权调用 | \(2M\) | \(M\) |
| 软件函数入口/出口 `PIPE_ALL` | \(4M\) | \(2M\) |
| acc 标量读取 | 4096 个 | 2048 个 |
| acc 标量写入 | 4096 个 | 2048 个 |
| value/weight 有效标量读取 | 各 16384 个 | 不变 |
| `GridFma32Bits` | 16384 次 | **不变** |
| 平面扫描 | 每载入一次正向检查 | 不变 |
| GM 有效字节 | 原工作 | 不变 |

其显式 UB 同为 42240 B。没有新增整数 FMA 实现、特殊值分类、Select 临时区或精度保护扫描。

### 为什么仍值得试

本方案不声称解决 b 的主要软件算术成本。它保留原并行任务数及每核软件 FMA 工作量，只削减围绕它们的确定冗余工作，因而没有“减少核数导致软件递推集中到少量核”的代价。

相较 a，b 没有执行 Mul 合批收益；但获得了两段软件消费之间 acc 反馈和完成边的减少。净收益可能有限，仍须测量，不据软件路径昂贵统一否决该静态可行试验。

## 3. 最强竞争替代

仍是 \(T=256\)、两组四邻居的方案，显式 UB 38144 B。它保留：

- 两次 Gather；
- 两次软件函数调用；
- 每输出两次 acc 读取与写入；
- 同样的八次软件 FMA。

主方案多占 4096 B，换取上述边界减少；替代可更早开始第一组软件消费。由于当前软件函数两侧的 `PIPE_ALL` 会使两组交接保守完成，主方案有明确的发射和反馈减少依据，但不承诺其大于八邻居 Gather 首包等待。

**直接替换软件 FMA 为 Vector Mul/Add 不作为合法竞争方案。**  
将整数 FMA 本身按输出 lane 向量化可能是更大的残余机会，但输入没有其完整实现和对应整数移位、进位、特殊值 API 合同，本轮不能把“它是整数代码”当作可实施证明。

# 五、统一 C2 计划

## 1. 所有权、布局与派发

- 保留现有：
  \[
  [b\,blockLength,\min((b+1)blockLength,O))

## 2. workspace

几何有效 workspace 保持：

\[
NS\times8\times(4+4)=16384\text{ B},

另计原有框架保留和对齐。生产者唯一写、消费者只读，完成发布及最后消费者生命周期原样保留。无新增 GM workspace。

## 3. 核内生命周期与容量

| 区域 | 生命周期 |
|---|---|
| cache | 平面 DMA 前至扫描及全部邻域读取结束 |
| index | 先作扫描 mask 的死区租约；扫描结束后才搬几何索引 |
| acc | 扫描时作压缩临时区；扫描结束后才初始化输出 accumulator |
| weight | 几何 DMA 完成至八邻居消费结束 |
| value | Gather 完成至全部加权消费结束 |
| acc 输出 | 初始化至 MTE3 最后读取完成 |

扫描 scratch 仍足够：4096 元素要求 128 个 firstMask word，temp 会访问至少 128 个 uint32 位置；新 index 有 2048 个 uint32，acc 有 256 个，均覆盖，但仍须保持扫描结束再覆写的完成边。

所有 TPosition 标签均映射 UB，不分成三个容量池。实际需求为：

\[
U_{\rm alloc}=42240+U_{\rm extra}\le U_{\rm available}.
\]

若继续保守扣除原 8192 B：

\[
50432+U_{\rm unlisted}\le U_{\rm available}.
\]

不能仅凭小于父本分配，就宣称整个目标构建资源已通过。

## 4. 同步与 KEEP 依据

保留：

- cache DMA → 扫描/Gather；
- 扫描最后读写 → index/acc 改作计算用途；
- 几何 DMA → Gather/Mul/软件读取；
- Gather → 加权；
- 八次有序 Add 的 V 依赖；
- 输出就绪 → MTE3；
- MTE3 最后读 → acc 复用。

不另建跨 tile 双缓冲，不宣称发生重叠。

**不能正式标 P_KEEP：**输入没有可引用的完整父计划，且 value 布局、消费粒度和局部容量实际改变。应建立 `P_CHANGE` 后继，注明输出分区部分是“提取已有计划”，不能把它统计成新增并行优化。A1 的 O 也实际改变，不是 O_KEEP，更不是 NOOP。

# 六、C3 准确实施步骤及正文影响

后继应在隔离候选中一次完成，不要求构建不完整中间版本：

1. **冻结父本及身份。**确认当前真实入口确实初始化 Weighted，并取得扩展 tiling 中 `geometryLength`、workspace 和启动序列。
2. **限定元数据域。**在既有选择位置接入本题 FP32、所列 shape、bilinear/zeros/alignCorners=false；其他元数据原样 fallback，不检查输入分布。
3. **修改分配。**该域设置 \(T=256\)，value 改为 `8*T*sizeof(float)`；其他区域按新 T 分配，保留唯一 TPipe。
4. **保留 cache 和扫描。**不动阈值、短路、整个平面触发粒度、特殊值处理或软件 FMA。
5. **修改几何搬入参数。**继续使用原八块 DataCopyPad：
   - `blockLen=count*4` 字节；
   - GM `srcStride=(geometryLength-count)*4` 字节；
   - UB `dstStride=(T*4-AlignUp(count*4,32))/32`。
   本题 count 为 16 元素倍数，但通用有效长度实现仍须正确。
6. **定义 Gather 全执行域。**完整段全部索引被 DMA 覆盖；短段先把 `[8,T]` 索引区置哨兵，再覆写有效部分。一次 Gather 的 count 为 `8*T=2048`。
7. **按原 software 选择消费。**
   - false、完整段：一次连续 2048 元素 Mul，再八次有效 count Add；
   - false、短段：八次有效 count Mul，再八次按序 Add；
   - true：调用原软件函数，`group=0, neighbors=8, stride=T`。
8. **保留有效写回和完成边。**只写 `count*4` 字节，不写 UB padding；结束前等待最后异步读者完成。
9. **审查并验证后才计时。**本轮没有执行这些步骤，不报告 C3 completed。

### 所读 P/O 正文实际改变了什么

- **P `coordinate_neighborhood`：**要求分开几何与通道输入依赖，因此保留已有几何预计算，不虚报几何重算减少；绑定原 \(G/B/H/F\)，不套用 GatherElements 数学语义。
- **O `vector-api.batch`：**只合并独立 lane 运算；八个 Add 有真实 accumulator 依赖，故不合并、不换归约树。
- **O `valid-length`、`strided-pad`：**区分 count、路跨度和 DMA 字节；因此短段不做读取未定义权重的全区 Mul，且同步修改双端 stride。
- **O `buffer-lifetime.reuse`、`bounds`：**要求真实静态分配及最后消费者核算；因此明确 index/acc 的扫描租约，不按词法作用域扣容量。
- **O `numeric`：**FMA/分离运算和局部八项顺序均是数值边界；因此 b 的软件 FMA 全保留，也不缩小触发扫描域。
- **P/O 流水正文：**要求多个独立阶段及事件闭环后才谈重叠；本轮没有为了双缓冲而增加槽位。

没有采用 Compare/Select 替代、缓存 hint、bank padding 或 950 通路，因而不引入其额外 scratch 或能力假设。

## 正确性及性能判别
