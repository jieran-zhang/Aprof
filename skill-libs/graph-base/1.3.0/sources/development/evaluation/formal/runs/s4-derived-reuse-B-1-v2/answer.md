## 结论与交接状态

本轮选择两个**分别绑定子例的纸面方案**，不把它们强行组合：

- **a，C=1：合并连续输出写回**。保持 `GridSampler3DOne<float>` 的全部计算和输入访问，结果先汇集到一个小 UB 输出块，再按有效长度写回。
- **b，C=128：同一 owner 内生成并复用空间几何记录**。采用 `Ct=128、St=16` 的空间块骨架；每个空间点的反射坐标、邻域有效偏移和六个一维系数只生成一次，各通道仍独立读取自己的 X，并严格执行原来的八项乘加。

两者均为 **conditional_plan / not_measured**：方案与实现步骤已给出，但目标可用 UB、具体 SDK 接口资格及数值契约中的一个原始边界缺口尚未闭合，不能标为 C3 completed。本轮未使用工具、未生成源码或 hash、未编译、未运行正确性或性能测试，也不声称实际调用过 router。

# 一、当前实现的共同理解

## 1. 实际分支与所有权

当前入口是 `.asc:190–197` 的 AIV kernel，FP32 进入：

```text
GridSampler3DScalar<float>
  → 每核连续 linear 区间
  → GridSampler3DOne<float>
  → Scalar GM 写 out[linear]
```

**不是 FP16 类，也不是已有几何预计算版本。** FP16 分支的 Cast、UB 缓冲和三个 `PIPE_ALL` 不在本次实际路径，不能据此诊断当前同步或流水问题。

记：

- 输入空间元素数 \(I=DHW=32768\)；
- 输出空间点数 \(S=4096\)；
- 输出元素数 \(M=CS\)；
- \(A=\max(1,\text{cores})\)，实际值未提供。

原 tiling 的 FP32 公式为：

\[
B=\min(A,\lceil M/16\rceil),\qquad
L=16\left\lceil\frac{\lceil M/B\rceil}{16}\right\rceil .
\]

核 \(b\) 负责：

\[
[bL,\min((b+1)L,M)).
\]

有效区间不交叠且覆盖输出；过量尾核可能没有有效元素。这里的 16 个 float 是源码声明的 **64B GM 所有权边界**，不是已测最佳粒度。

外部布局的元素偏移：

\[
X[n,c,z,y,x]=(nc+c)I+1024z+32y+x,
\quad Y[n,c,p]=(nc+c)S+p,
\]
\[
grid[n,p,a]=(nS+p)3+a.
\]

当前 N=1，几何依赖 \(p\)、grid 和空间元数据，**不依赖通道 c**；输入值依赖 c。

## 2. 数学及数值依赖

每轴先按源码顺序执行：

\[
u=((g+1)\cdot32-1)\cdot0.5
\]

随后调用 `GridReflect`，其低、高边界是 \(-0.5,31.5\)，最后 clamp 到 \([0,31]\)。再计算 floor、上下邻居和六个系数：

```text
dx, dy, dz, wx0=1-dx, wy0=1-dy, wz0=1-dz
```

每项保持源码的左结合表达式：

\[
(((v_k\cdot w_{x,k})\cdot w_{y,k})\cdot w_{z,k}),
\]

从 `result=+0.0f` 开始，按 `.asc:125–132` 的 \(k=0,\ldots,7\) 顺序更新。

因此不能：

- 将六个一维系数先合成为八个三维权重后直接乘 X；
- 改为分组或树形累加；
- 无依据地引入或消除 FMA；
- 因某权重为零就跳过原有运算；
- 对越界邻居先读再乘 mask。

反射后的主坐标合法，不意味着 `x1/y1/z1` 都合法：主坐标为 31 时，上邻居为 32，原 `GridRead` 必须返回 `+0.0f`。反射分支、奇偶 flips、边界 clamp 和有效邻居数量均与数据有关，不能由“grid 有限”推断其触发频率。

## 3. 需要明确保留的原始数值缺口

**有限 grid 不足以保证原函数在所有 FP32 有限输入上定义完整。**

- `GridUnnormalize` 的中间乘法可能溢出为 Inf；
- `GridReflect:65` 将 `distance/span` 转成 `int64_t`，极大有限值也可能超出可表示范围；
- 后续 `GridFloor` 同样依赖可合法转换的值。

这不是候选引入的风险，也不能擅自改成 fmod、饱和转换或新 clamp 来修复。下面的等价论证均保持原计算，在原代码已定义的数值域成立。若契约要求**所有有限 FP32 grid 均有确定输出**，必须补充原 oracle/目标转换行为或授权修复；本轮不能替用户补造该语义。a 继承该缺口；b 合并几何生成次数，尤其不能在该缺口未明确时宣称全有限域 `semantic_equivalence=true`。

## 4. 可复算的原始工作量

以下均是源码请求与算术模型，不是 HBM 流量、编译指令数或时间。

| 项目 | a：C=1 | b：C=128 |
|---|---:|---:|
| 输出元素 M | 4,096 | 524,288 |
| 完整几何生成次数 | 4,096 | 524,288 |
| grid 标量读取 | 12,288 float，49,152B | 1,572,864 float，6,291,456B |
| `GridRead` 调用 | 32,768 | 4,194,304 |
| 有效 X 读取上界 | 131,072B | 16,777,216B |
| 插值乘法 | 98,304 | 12,582,912 |
| 插值加法 | 32,768 | 4,194,304 |
| 输出有效字节 | 16,384B | 2,097,152B |

每通道输入平面为 131,072B；输入总大小分别为 128KiB、16MiB。同一通道内部是否大量重复命中源地址，当前 grid 分布不能证明。

# 二、子例 a：C=1

## 1. 关键事实与选择理由

a 没有通道复用轴：

- 几何生成次数已经是 S，保存几何再读取并不能减少生成次数；
- 每个 grid 三元组在当前输出域只被消费一次；
- X 是数据相关离散访问，不能因输出连续就把它改成连续输入 DMA；
- 当前每个输出由 Scalar 单独写 GM，核内输出却是连续区间。

因此本轮选择**输出批量写回**，而不是为了容易套用“不变量”而缓存更多字段，也不为 \(r=1\) 建派生表。

### 主方案 a-W：保持计算，汇集输出后写回

纸面起始参数：`T=128 float`，单物理输出槽。

对每核原有区间分块，逐元素调用原 `GridSampler3DOne<float>`，将结果写入本核 UB；整块或尾块完成后一次 `DataCopyPad` 写有效字节。

变化为：

- 几何、grid/X 读取、全部插值算术：**不变**；
- Scalar GM 输出 store：\(M\) 次变为 0；
- 新增 Scalar UB `SetValue`：\(M\) 次；
- 新增 MTE3 写出：

\[
L_a=\sum_b\left\lceil M_b/128\right\rceil
\]

次，每次最多 512B，输出有效总字节仍为 16,384B；
- 新增单槽容量：

\[
U_a=\operatorname{AlignUp}(4T,32)+F=512+F\text{ B},
\]

其中 \(F\) 是实际框架、编译器及其他必需资源，不能填成零。

不能简单说整个调用只有 32 次写出：原分核边界可能将块切短。准确数量是上式，例如每核只有 16 个输出时，每核仍需一次写出。其收益假设是减少 GM 标量写请求及其地址/控制工作；代价是 UB 写入、DMA 发射和完成等待。它不减少数学工作，也不保证时间下降。

## 2. 最有竞争力替代：只向量化插值消费阶段

真正有竞争力的替代不是字段缓存，而是保留 Scalar 几何和合法取数，将 24 次乘法、8 次累加改为批量 Vector。

可构造 `T_v=64` 的有界版本：

- 8 组邻居值、6 组一维系数；
- 两组独立乘积缓冲、两组交替累加缓冲；
- 每邻居仍做三次 Mul，再按原 k 次序 Add，避免预乘三维权重；
- 无须使用 Compare/Select，也不假定有 A3 GM Gather。

保守数据容量：

\[
U_v=18\operatorname{AlignUp}(4T_v,32)+F+Tmp
=4608+F+Tmp\text{ B}.
\]

全部工作变化：

- Scalar 几何和有效 X GM 取数仍保留；
- 每输出约新增 \(8+6+1=15\) 次 UB 标量填入，共 61,440 次；
- 插值的 131,072 次 Scalar 算术移到 Vector，有效算术量不变；
- 每块 24 次 Mul、8 次 Add，即 \(32L_v\) 次计算 API，另有相关 V 内依赖和搬出完成边；
- 输出也可批量搬出，但这份写回减少只能计一次；
- 增加系数/邻居布局准备、临时区、尾块和更高资源需求。

**本轮不选该替代的原因**：它确实覆盖更大算术机会，但当前材料没有证明目标 Scalar 与所选 Mul/Add 实现的完整舍入、次正规数及 contraction 行为一致；需要具体目标 SDK/编译语义核验。不能把“FP32 且公式相同”当作已满足数值条件。加之它保留整个 Scalar 几何/离散取数，却新增 15 次/输出的 UB 填入和每块 32 次 API，净价值不能仅由被移走的算术数决定。

这不是因缺性能测量否决向量化；它仍是后继优先候选。a-W 的试验目标更窄，但可以完全沿用原算术函数。

### 其他明显机会

整平面 X 驻留并非免费替代：每 owner 读入 128KiB，B 个 owner 最多请求 \(B\times128\)KiB，且要占用相应 UB。当前整个 a 的有效 X 标量读取上界本来只有 128KiB。没有局部窗口证据时，这种全载可能增加大量无用读，不优先。

## 3. Action 实例

登记纸面实例 **`a.AW`**：

- 注册意图：`action.batch_writeback`，采用输入提供的当前正文快照；
- parent：原始 `.asc:1–197`、`.h:1–47`；
- target：FP32 输出 Y；
- stage：`.asc:146–148` 的输出产生/写回；
- workload：a 的完整已列元数据域；
- 参数：T=128 元素、单槽、有效写出 `valid*4` 字节；
- 结构依据：同 owner 连续输出、原调用内没有中间输出消费者；
- 不变量：原函数、原算术顺序、原输入读取、完整覆盖及唯一写回不变；
- 未闭合：实际可用 UB、Scalar UB 写入至 MTE3 读取的目标 SDK 完成契约、前述原数值域缺口。

不额外登记“减少流量”实例：这里输出有效字节不减少，不能重复描述收益。

# 三、子例 b：C=128

## 1. 关键事实与选择理由

b 中同一 `grid[p]` 与全部空间元数据被 128 个通道重复使用。原代码却在每个输出重新执行三轴 unnormalize、reflection、floor 和系数生成。

与此同时：

- X 的通道平面不同，不能复用通道 0 的采样值；
- 八项乘加仍是每个输出必须执行的工作；
- NCDHW 中 p 连续，c 跨平面；
- 直接改成“一个 p 后遍历全部通道”会产生较差的输出局部性，因此选 **16 点几何块，而非只保存单点后跨通道散写**。

## 2. 主方案 b-D：Ct=128、St=16 的本地几何复用

每个 owner 获得若干空间块 `[p0,p0+16)`，处理全部 128 个通道。

### 几何记录

对每点保存：

- 8 个 `int32_t` 空间偏移；非法邻居使用 -1；
- 6 个 FP32 一维系数，保持原值和符号零。

采用 SoA：

```text
offset[k][p]，k=0..7
dx[p], dy[p], dz[p], wx0[p], wy0[p], wz0[p]
```

记录不保存预乘的三维权重。合法偏移为 0…32767，可精确存入 int32；必须先按原边界条件判合法，才生成或窄化偏移。

每空间块显式容量：

\[
U_D=8A(4St)+6A(4St)=14A(4St).
\]

`St=16` 时：

\[
U_D=896\text{ B},\qquad U_b=896+F\text{ B}.
\]

本轮不追加输出 DMA 缓冲，仍使用 Scalar GM 写回，避免把独立写回方向夹进同一 Action。

### 工作变化

| 工作 | 原始 b | b-D |
|---|---:|---:|
| 完整几何生成 | 524,288 | 4,096 |
| grid 读取字节 | 6,291,456B | 49,152B |
| 几何记录写入 | 无 | \(56S=229,376\)B UB payload |
| 几何记录读取 | 无 | 至多 \(56CS=29,360,128\)B UB payload |
| X 读取及插值算术 | 每输出执行 | **不变** |
| 输出字节/计算次数 | 每输出一次 | **不变** |
| 新 GM workspace | 0 | 0 |

几何生成减少 520,192 次，grid 逻辑读减少 6,242,304B。这两项有关联，不能将其分别换算成独立时间收益后相加。

每输出仍有 8 个偏移有效性判断、最多 8 个 X 读取、24 次乘法和8次累加。非法偏移先产生 `+0.0f`，随后仍执行原乘加；不先读非法地址，也不跳过该项。

原始邻居界检查和空间偏移构造可移入记录生成阶段，通道基址仍逐通道更新。记录读取本身会形成新的 Scalar UB 工作，不能称几何复用“没有消费成本”。

## 3. 最有竞争力替代：不复用几何，直接批量化插值

该替代保留原输出连续分区，采用 a 中所述的有界 Vector 消费路径：

- 移走每输出 32 次 Scalar 插值算术，共 16,777,216 次；
- 几何仍生成 524,288 次，grid 仍读取 6MiB；
- Scalar X 间接取数仍保留；
- 约新增 \(15CS=7,864,320\) 次 UB 标量填入；
- 需要约 \(32L_v\) 次 Vector API、输出 DMA 和依赖；
- T=64 时显式数据区至少 4608B，另计真实 scratch/框架资源；
- 必须核验同样的数值/API条件。

**本轮选择 b-D 而非该替代**：b 的几何跨通道重复是确定的 128 次结构事实；b-D 用 896B 本地记录避免大部分生成，保持原消费算术，并不需要新 Gather、Compare/Select 或 Vector 数值替换。代价是约 28MiB 的 UB 记录读取及输出任务重排，而非高额 GM 中转。

这不证明几何是主瓶颈。若后继发现几何生成已被编译器显著消除，或记录读取/任务组织成为主要成本，而八项 Scalar 消费仍占优势，应重新比较上述 Vector 方向。

### GM 几何表是另一强替代，但本轮不选

完整表为 \(56S=229,376\)B，每调用生成一次：

- 至少写表 229,376B；
- 若每通道读一遍，逻辑表读 29,360,128B；
- 合计新增约 28.22MiB GM 表写读；
- 还需额外 launch 或合法跨核发布协议，以及 workspace ABI 接线。

它能保留更多通道×空间独立任务，但与本地全通道复用相比，几何生成次数已经同为 S，没有更多生成可省，新增 GM 中转必须由并行度等收益偿还。当前已有 256 个空间块，不先承担此成本；也不假定它们一定足够利用所有实际核。

## 4. Action 实例

登记纸面实例 **`b.AD`**：

- 注册意图：`action.reuse_derived_results`；
- 临时机制：原始 GridSampler 的通道无关几何重复生成；不虚构已有 Problem 图边；
- parent：原始 `.asc:98–134`、`.h:24–47`；
- target：`D[p]=H(B(G(grid[p], metadata)))`；
- stage：几何生成及八邻居消费；
- workload：b 的完整已列元数据域；
- 参数：Ct=128、St=16、14 组 SoA、单物理记录槽；
- 消费者：本 owner 的全部 128 个通道；
- 失效点：本空间块最后一个通道消费完成；
- 必需条件：派生依赖不含 c、FP32 边界不变、记录不被提前覆盖、目标 UB 读写接口合法、容量闭合。

不把该实例登记为 `reuse_input_tiles` 或 `hoist_invariant_control`：保存的是新计算的坐标/系数/偏移，不是原始 grid/X 驻留，也不只是地址前缀。

# 四、统一 C2 共同计划

## 1. 所有权、布局、workspace 与同步

| 项目 | a-W | b-D |
|---|---|---|
| 输出 owner | 保留原 linear 连续区间 | 空间16点块×全部128通道 |
| 核内顺序 | 原 linear 顺序 | 生成16点记录；c 外层、块内 p 内层 |
| 外部布局 | NCDHW 不变 | NCDHW 不变 |
| 新本地布局 | 单槽 FP32 输出 | 8偏移+6系数 SoA |
| 新 GM workspace | 0 | 0 |
| 跨核归并/同步 | 无 | 无 |
| 显式 UB | 512B | 896B |
| 输出方法 | 统一 DMA 写回，不混 Scalar GM 写 | 统一 Scalar GM 写，不追加 DMA |

b 的 256 个空间块用 q/r 分给

\[
B_b=\min(A,256)
\]

个核。核的块数相差至多1；每块有2048个输出。每个通道的块内输出为16个 float，起点和长度均为64B，跨核不共享这条所有权边界。**元素数量均衡不等于已测时间均衡**，反射和有效邻居数量仍随 p 改变。

a 的单槽完成关系：

```text
Scalar 产生并写 UB
→ 目标 SDK 规定的就绪完成边
→ MTE3 读取 UB、写有效 GM
→ 等 MTE3 最后读完成
→ 下一块才覆盖同槽
```

b 的记录完成关系：

```text
生成并完整写 D
→ 记录读就绪
→ 128个通道只读消费 D
→ 最后读取完成
→ 下一空间块覆盖 D
```

不引入跨核共享 D，也不使用核内 `PIPE_ALL` 冒充跨核发布。

## 2. 容量门禁

必须实际满足：

\[
512+F_a\le U_{\text{available}},\qquad
896+F_b\le U_{\text{available}}.
\]

分配按独立 TBuf、真实对齐和隐含预留核算。没有实际可用容量证据，不能仅因这两个数较小就授权实施。

这里不认定 baseline 存在片上容量压力；它当前没有显式 UB 数据区。容量是新方案门禁，不是已证瓶颈。

## 3. 分派与通用 fallback

只优化已列元数据域：

```text
FP32，N=1，D=H=W=32，S=4096，
bilinear，reflection，alignCorners=false，
C分别为1或128。
```

outD/outH/outW 的合法组合仍按原 host 校验和乘积解释，不按 case ID 分派。其他元数据全部保留原实现。

当前工程没有展示框架 TilingKey 机制，因此：

- 保留现有 C entry `grid_sampler_3d_kernel`；
- 在该 entry 中使用互斥元数据谓词选择 a、b 或原 fallback；
- 可为纸面 dispatch 表定义 uint64 逻辑 ID：0=fallback、1=a-W、2=b-D，但**不是已经接入框架的 TilingKey**，不擅自新增 ABI 字段；
- b 的 host 启动核数与 kernel 空间块分配必须同步修改；a 保持原 blockNum/blockLength。

## 4. KEEP 判断与许可自由度

两方案均不是 P_KEEP：

- a 改变输出通路和 buffer 生命周期；
- b 改变任务 owner、遍历和派生状态生命周期。
- 输入没有已有冻结计划/hash，不能用“没改数学”拼出 P_KEEP。

C2 首先提取原计划，再记录上述实际 P_CHANGE；提取本身不算并行优化。

C3 可在容量闭合后调整 a 的块长；b 若改变 Ct/St、跨核共享 D、增加 GM 表、改变输出通路或 dispatch 域，须返回 C2。不能把缺文档或未知条件编码为 KEEP。

# 五、C3 准确实施步骤与 P/O 正文的实际影响

## a-W 的步骤

1. 保留原 `GridSampler3DOne<float>`、`GridRead` 及数值辅助函数。
2. 在 a 的互斥分支初始化一个 `VECOUT` 单槽 TBuf，按 `AlignUp(4T,32)` 申请。
3. 保留原 begin/end。每块计算 `valid=min(T,end-pos)`，只调用 valid 次原函数。
4. 使用 FP32 `SetValue` 填入结果，不增加 Cast。
5. 按目标 SDK 核验 Scalar UB 写完成至 DMA 读的完成协议。
6. 使用 A3 无 mode 的 UB→GM `DataCopyPad`：
   - `blockCount=1`；
   - `blockLen=valid*sizeof(float)`，单位字节；
   - 两端 stride 为0；
   - 不写 dummy。
7. 等 MTE3 读取完该槽后复用，退出前完成最后搬出。
8. fallback 与 FP16 分支不变。

**采用正文的影响**：

- `implementation.memory-transfer.coalesce` 将合并边界限制在同 owner、连续、全部已产生的输出内，而非跨核凑大块；
- `valid-length` 要求分清 valid 与分配长度，尾块不向上写 GM；
- `strided-pad` 明确 UB→GM 的字段单位和 dummy 丢弃规则，避免套用 GM→UB 参数；
- `pipeline-sync` 的最浅完成骨架使本轮采用单槽、显式回收，不因新增 TBuf 宣称已实现重叠。

## b-D 的步骤

1. 将 `.asc:107–112、119–124` 的原几何表达式提取为记录生成逻辑，操作顺序、dtype、反射函数保持不变。
2. 按原八邻居顺序检查 z/y/x 有效性；合法后生成空间偏移，否则存 -1。不得先构造可被误读的非法 GM 地址。
3. 保存六个原 FP32 系数，不预乘三维权重。
4. 初始化一次14组受 TPipe 管理的 TBuf；明确每组 `St*4` 字节及实际对齐。使用目标 SDK 支持的 Scalar local 写/读接口；不能未经核验直接把 UB 当普通 C++ 指针数组。
5. host 与 kernel 一致实施256个空间块的 q/r 分配。
6. 每块记录生成并就绪后，遍历 c=0…127，再遍历有效 p：
   - X 基址为 `c*32768`；
   - 每 k 先判偏移，再合法读或取 `+0.0f`；
   - 保持原三次乘法及八次累加顺序；
   - 写 `Y[c*4096+p]` 一次。
7. 最后消费者结束后覆盖记录；不保留跨调用缓存。
8. 不额外混入 Vector 算术、X 全平面驻留、输出 DMA 或缓存 hint 改动。

**采用正文的影响**：

- `planning.indexing.coordinate_neighborhood` 直接改变 owner 为复用轴块×空间块，并要求分别绑定 G/B/H/F、真实 stride 与越界读取；其来源不是现成 GridSampler 移植证明；
- `implementation.buffer-lifetime.derived-results` 要求把生成、存储、128次消费和最后完成点作为一个完整变换，明确记录读取成本；
- `buffer-lifetime.reuse` 区分值保留与不同值共槽，本轮不额外登记 buffer 别名复用；
- `precision-boundaries.numeric` 排除了预乘三维权重、改变累加树以及“越界项乘0即可”的替换；
- `gather_output_owned` 只提供输出独占与 Scalar 间接取数的原则，不能把 GatherElements 语义或950 GM Gather能力移植进来。

缓存正文也影响了拒绝理由：NORMAL 不保证命中，PERSISTENT 在材料版本不支持；原始代码还是裸 GM 指针，不能把 GlobalTensor hint 的效果直接归到现有读取指令。
