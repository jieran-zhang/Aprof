该程序意图实现连续 ND 张量的逐元素广播 maximum：从末轴对齐两个 shape，缺失轴补 1，大小为 1 的轴重复取值，输出各轴取两者较大尺寸。P、Q 的数学结果均应为 [[3,4,8],[7,7,9]]，R 应为 [[3,7,8],[3,7,9]]；但当前不同 dtype 的执行路径并不等价。

source/op_host/maximum.asc 的 main 解析 shape、dtype 和二进制文件，按实际元素数分配输入 GM；调用 ComputeMaximumTiling 后按 totalLength 分配输出，再上传输入及 tiling，启动 maximum_kernel。最后同步 stream、回传并写出同 dtype 的连续二进制结果，文件不含 shape 元数据。依题面无额外分配余量：P 的 x1/x2/y 分别为 12/4/12 字节，Q 为 24/8/24 字节，R 为 12/6/12 字节。

source/op_kernel/maximum_tiling.h 的 ComputeMaximumTiling 接受秩 1～8，右对齐 shape，检查各轴相等或其中之一为 1。步长单位为元素，输入尺寸为 1 的轴置零，其余保留连续 ND 步长。三次调用都有 rank=2、outShape=[2,3]、totalLength=6、x1Stride=[3,1]、sameShape=0；P/Q 的 x2Stride=[1,0]，R 将 [3] 补成 [1,3]，得到 [0,1]。tileElements 固定为 4096；useful=max(1,ceil(6/4096))=1，查询到 4 个 Vector 核仍只启动 blockNum=1，blockLength=ceil(6/1)=6。唯一 block 的输出区间是元素 [0,6)，不是四核分摊。

source/op_kernel/maximum_kernel.asc 的 maximum_kernel 根据 dtype 调用 DispatchMaximum。int64 总走 MaximumScalar；half 同形走 KernelMaximumSame，异形全部走 KernelMaximumHalfLastAxisBroadcast；其余 dtype 同形走向量路径，异形走标量广播。half 异形分派没有检查 x1 是否已具有输出布局、x2 是否确为可重复的末轴向量，也不使用 tiling 中的广播步长。代码注释称其目的是避免 dav-2201 的 half 标量运算，保持 half 比较在 Vector 单元完成。

P 因而进入 HalfLastAxisBroadcast。Init 得到 begin=0、end=6、row=3，将 x1/y 声明为 6 个 half，将 x2 声明为 3 个 half。后者只是 GlobalTensor 的长度声明，不会把 host 实际分配的 2 个 half 扩成 3 个；rawdocs 的 GlobalTensor/SetGlobalBuffer.md 明确要求声明长度不得超过实际数据长度。Process 每次取 min(end-off,4096,row-off%row)，所以执行两段 (off,count)=(0,3)、(3,3)。每段从 x1[off] 与 x2[off%3] 各连续搬 3 个 half，再做 Max，写到 y[off]。

以各自 GM 基址为零点、字节区间采用左闭右开表示：P 两段的 x1/y 区间分别为 [0,6)、[6,12)，x2 两次均请求 [0,6)，而实际 x2 只有 [0,4)。因此每次都多读元素 x2[2]，即字节 [4,6)。即使暂时只看有效地址，两行均会把前两项与 [3,7] 比较，而非第一行重复 3、第二行重复 7：名义上的前两项比较都给出 [3,7]，已偏离正确广播。由于请求越界，不能给 P 指定一个确定完整输出，也不能保证部分结果实际被写出；是否报错、读到何值以及能否完成，材料均不足以确定。

Q 进入 MaximumScalar<float>。它将每个 linear 从末轴开始用取模、整除还原坐标，再累加 coord×stride 得到输入下标。linear=0～5 时，ai 为 0,1,2,3,4,5，bi 为 0,0,0,1,1,1。因此 x1 与输出的字节偏移均为 0,4,8,12,16,20，x2 为 0,0,0,4,4,4，每次访问一个 4 字节 float。直接从 GM 读取 av、bv，执行 av>bv?av:bv，再写 GM；这里没有 UB 队列或 DataCopyPad。所有逻辑访问均在分配范围内，给定有限数值下，源码结果为 [[3,4,8],[7,7,9]]。

R 与 P 使用相同的两段向量流程，但实际 x2 正好有 3 个 half，[0,6) 是合法区间。两段分别比较 [1,4,8] 与 [3,7,6]、[2,5,9] 与 [3,7,6]，所以结果为 [[3,7,8],[3,7,9]]。x1/y 第二段从基址加 6 字节开始，x2 两次从基址开始；每段搬入两个 6 字节块并搬出一个 6 字节块。

P/R 的每次搬运参数都是 DataCopyExtParams{1,6,0,0,0}：一个数据块，blockLen=6 字节，两个 stride 与保留项为零；GlobalTensor 的 off 则是元素偏移，二者单位不同。依据 shared/rawdocs 中 DataCopyPad_GMToUB.md、DataCopyPad_UBToGM.md 的 A3 契约，GM 地址只需 1 字节对齐，UB 地址须 32 字节对齐，因此第二行的 6 字节偏移本身合法。搬入有效的 6 字节后，本地补齐至 32 字节，即增加 26 字节、13 个 half。pad={false,0,0,0} 不表示补零；文档说明这种左右 padding 为零的非对齐情形，dummy 使用数据块首元素值。Max 的 count=3 只计算前三个元素，搬出也只写 6 字节，dummy 不作为输出。尤其 P 请求的第三个 half 属于这 6 字节有效搬运范围，不能由 UB 对齐填充代替。

按 workload/sdk-contract.md，本题目标是 910C/Atlas A3、__NPU_ARCH__=2201。上述向量路径是 GM→UB→Vector→UB→GM：搬入对应 MTE2，Max 对应 Vector，搬出对应 MTE3，没有 Cube 矩阵计算。P/R 三个队列各 InitBuffer 一个 4096×2=8192 字节缓冲，共 24576 字节，即 24 KiB，与实际 count=3 无关。队列深度和缓冲数均为 1；InitBuffer.md 明确 num=1 不开启双缓冲，不能据此声称多 tile 的双缓冲重叠。每段先 Alloc、搬入、EnQue/DeQue，再计算、输出入队/出队、搬出和 Free；TPipe/TQue 框架协调搬入完成后计算、计算完成后搬出及缓冲复用的核内依赖。Scalar、Vector、DMA 可异步工作，但源码没有提供实际重叠程度或性能证据。三次调用都只有一个 block，无跨核同步；host 的 stream 同步保证回传在 kernel 完成之后进行。

其他分支中，KernelMaximumSame 按 blockIdx×blockLength 切连续区间，每块再按最多 4096 个元素循环，尾段仅搬有效字节。half、float、int32 直接向量 Max；A3 的 Max.md 列出这三种类型受支持。bfloat16 先转 float，Max 后以 CAST_RINT 转回；int8 经 half 转 float，Max 后经 half 转回 int8，half 临时区先后复用。Cast.md 的 A3 表支持这些转换组合，CAST_RINT 为最近偶数舍入。int64 即使同形也逐元素标量比较，保持整数比较而不经过 float。其他非 half 的异形分支使用同一套逐轴步长寻址；MaximumScalar 中虽有 half 转换代码，当前分派不会让 half 进入它。

因此，host 接受的广播形状范围大于 half 异形路径能够正确表达的范围。该路径直接读取 x1 的线性输出位置，并周期性读取 x2 的末轴段；R 满足这种映射，P 不满足。形状兼容检查本身不证明 kernel 的地址与广播语义正确。此外源码未显式检查零维长或形状乘积溢出，不能将普通正尺寸结论外推到这些边界。以上 Q/R 输出是成功编译执行条件下由源码与固定 API 契约推出的结果；本任务没有构建、仿真或设备观测，不能据此报告实测行为、时延或越界故障形式。
