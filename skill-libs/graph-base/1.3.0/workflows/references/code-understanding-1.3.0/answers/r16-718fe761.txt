该程序计算矩阵乘后接 LeakyReLU。输入 A、B 均为连续 ND 的 half，形状分别为 [512,128]、[128,128]，输出 Y 为 [512,128] 的 half ND。数学目标为 S[m,n]=ΣₖA[m,k]B[k,n]，非负结果保持，负结果乘以 0.001。实际数值顺序更具体：Cube 以 half 输入、float 累加得到 S，Fixpipe 先按 CAST_RINT 转成 half 中间值 T，再由 half LeakyRelu 处理 T，最终输出 half。因此激活判断和乘法发生在第一次 half 转换之后；斜率也先转换成 half，约为 0.00100040436，不能将其等同于在完整 float 结果上激活后只转换一次。依据是 source/matmul_leakyrelu_basic_api.asc 的 Process、LeakyReluCompute，以及 shared/rawdocs 中 Mmad.md、Fixpipe_L0CToGM.md 和 LeakyRelu.md 的契约。

host 的 main（源码197—259行）包含全部固定参数，没有独立 tiling 文件或动态 tiling 阶段。A、B、Y 的分配大小分别为 512×128×2=131072 B、128×128×2=32768 B、131072 B。程序初始化 ACL、选择设备0、建立 stream，将两个二进制输入复制到设备，启动 kernel，等待 stream 完成后复制并写出 output.bin，最后释放资源。data_utils.h 的 ReadFile/WriteFile 仅负责原始字节读写，没有生成输入、调整布局或验证计算结果。ReadFile 会将长度引用改为实际文件长度，而 main 未检查文件及 ACL 调用返回值，以下计算关系以文件长度符合题面、运行时调用成功为前提。

启动数为 (512/256)×(128/128)=2，kernel 声明 __mix__(1,2)（188行），所以对应2个 AIC 和4个 AIV，而不是总共两个执行核。本地 simd_builtin_keywords.md 规定混合场景下 GetBlockIdx 返回逻辑编号：AIC 为 b=0、1，AIV 为 v=0、1、2、3，后者对应组合编号 floor(v/2) 和组合内编号 v%2。Init（31—45行）据此让 AIC 沿 M 分工：b=0 读取 A 的0—255行并生成输出0—255行，b=1 读取256—511行并生成输出256—511行；A 和 C 的起点均为 b×32768 个 half，即 b×65536 B。两个 AIC 都读取完整 B，未沿 K 切分，也不交换部分和。

每个 AIC 只处理一个 256×128 输出 tile，K=128 一次完成；当前 singleCoreM=baseM、singleCoreK=baseK=K、singleCoreN=baseN=N。代码没有遍历输出 tile 或 K 块的循环，模板参数名不能证明它支持任意形状。这里所有维度均为16的倍数，没有尾块。全局共有65536个输出元素、8388608个乘加项。

AIC 的静态分配见52—61行，Alloc 的参数单位是元素：L1 中 A 占32768个 half=64 KiB，B 占16384个 half=32 KiB，合计96 KiB；二者来自同一 L1 allocator 的连续分配。L0A 占64 KiB，L0B 占32 KiB，L0C 保存32768个 float，占128 KiB。它们属于不同物理存储，不能把 L0C 的 float 数据量按 half 计算。这里使用 LocalMemAllocator 和手工事件，没有 TQue、TPipe 或双缓冲槽位。

65—68行的 DataCopy 由 MTE2 将 GM ND 转成 L1 half NZ。A 的 Nd2NzParams 为 {1,256,128,0,128,256,1,0}，B 为 {1,128,128,0,128,128,1,0}：各搬一个矩阵，GM 行跨度均为128个元素；目的相邻 C0 列组的跨度分别为256×32=8192 B、128×32=4096 B，目的相邻行跨度为32 B。这里 dstNzC0Stride、dstNzNStride 的单位是32 B，srcDValue 的单位是元素，依据 DataCopy_GMToL1_ND2NZ.md。half 的16×16分形占512 B，A、B 的 NZ 可分别按 [8,16,16,16]、[8,8,16,16] 描述；数据只改变物理排布，不改变数学坐标。

本题 __NPU_ARCH__=2201，实际执行75—91行的 LoadData2DParams 分支。A 循环16次，每次读取8个分形：源起点为 i×256 个 half，即 i×512 B，相邻源分形起点相差16×512=8192 B；目的起点为 i×2048 个 half，即 i×4096 B，dstGap=0，8个分形连续写入。于是128个分形覆盖整个 A tile，从 L1 NZ 重组为 L0A ZZ，可按 [16,8,16,16] 描述。B 循环8次，每次也搬8个分形，源起点 i×512 B、源跨度8×512=4096 B、目的起点 i×4096 B；ifTranspose=true 对每个16×16分形转置，使 L0B 成为 ZN。这里的转置是 Cube 操作数排布要求，计算仍为 A×B，不是 A×Bᵀ。LoadData_2D.md 明确其 repeat 和 stride 以512 B分形计，L1→L0 使用 MTE1。

115行调用一次 Mmad，尺寸为 m=256、n=128、k=128，cmatrixInitVal=true 令累加从零开始，不读取旧输出，也没有 bias。结果在 L0C 中为 float NZ。125—127行的 Fixpipe 使用默认行主序配置，完成 L0C NZ→GM ND 和 float→half；nSize=128、mSize=256，srcStride=256 的单位是16×sizeof(float)=64 B，因此相邻 N 列组相距16384 B；dstStride=128 在 NZ2ND 模式下是每行128个 half，即256 B。ndNum=1，只输出一个矩阵；reluEn=false，负数此时仍保留；Mmad 和 Fixpipe 的 unitFlag 都为0，没有开启分形级联动搬出。

每个 AIV 在自己的 UB 分配 (256/2)×128=16384个 half，即32 KiB。其 cGM 先指向所属 AIC 的输出块，再通过 gmOffset=(v%2)×16384 个 half 定位上下半块（131—176行）。所以 v=0、1、2、3 分别处理全局行0—127、128—255、256—383、384—511，起点分别为0、32768、65536、98304 B，四段覆盖完整输出且互不重叠。mIndex、nIndex 本次均为0。

AIV 的 DataCopyPad 参数为 blockCount=128、blockLen=128×2=256 B，每块对应一行；GM 行间隙 (N-baseN)×2=0，UB 行间隙也为0，每核搬入32768 B。256 B 已按32 B对齐，虽指定 isPad=true，左右 padding 都为0，不增加有效数据。V 流水随后对16384个 half 原地执行 LeakyRelu，再由 MTE3 用相同128行、每行256 B写回原 GM 区域。DataCopyPad_GMToUB.md 与 DataCopyPad_UBToGM.md 区分了 GM 间隙的字节单位和 UB 间隙的32 B单位；本次两者都为零。

关键依赖由显式同步贯通：72—73行 MTE2_MTE1 保证两份 L1 输入就绪后才能 LoadData；110—111行 MTE1_M 保证 L0A/B 就绪后才能矩阵乘；119—120行 M_FIX 保证 L0C 计算完成后才能 Fixpipe。129行 CrossCoreSetFlag<2,PIPE_FIX>(0) 在所属 AIC 的 FIX 前序写回完成后通知两个 AIV，136行等待该通知后才发出 GM→UB 读取。CrossCoreSetFlag/WaitFlag_ISASI.md 的模式2契约限定这一组合内的 AIC/AIV 协作，不是两个 AIC 之间的全局屏障；A3 上 Wait 的模板参数不直接决定硬件指令功能。162—163行 MTE2_V 保护 UB 输入就绪，170—171行 V_MTE3 保护激活结果就绪。最终194行 PIPE_ALL 屏障收束各核流水，host 的 stream 同步保证完整 kernel 完成后才读取最终输出。这里只有一次消费、没有下一轮覆盖，同一输出区的 AIC 写与 AIV 原地读写由上述核间通知排序。

910C/2201 的 Cube 与 Vector 分属 AIC/AIV，片上存储独立，本实现通过 GM 中间结果协作：AIC 走 GM→L1→L0A/B→Cube→L0C→FIX→GM，AIV 走 GM→UB→V→UB→GM；没有直接共享 L0C 或 UB。源码92—106行的3510分支使用 LoadData2DParamsV2，并将 L0A 按 NZ 组织，本题不执行，不能混用其布局契约。以上是题面、源码与固定 SDK 文档支持的静态行为；材料没有编译产物、设备结果或时间线，无法据此确认实际流水重叠、性能或逐位数值一致性，启动规模也不代表芯片总核数。
