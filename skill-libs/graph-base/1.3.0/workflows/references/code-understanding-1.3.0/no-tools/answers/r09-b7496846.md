# Maximum 代码理解说明

以下以 **H**=`source/op_host/maximum.asc`、**T**=`source/op_kernel/maximum_tiling.h`、**K**=`source/op_kernel/maximum_kernel.asc` 定位。数值和地址均为源码静态推导，不代表已编译或实测。

## 1. 输入输出与算法语义

目标是对两个同 dtype、连续 ND 输入进行右对齐广播，逐元素取最大值；输出 dtype 不变，shape 为广播后的 shape，无归约、核间合并或 workspace。

`ComputeMaximumTiling`（T:29–55）将较低 rank 的 shape 左补 1，逐维检查“两维相等或至少一个为 1”，输出维度取较大者。输入连续 stride 以**元素**计，广播维 stride 置零。`sameShape` 判断的是原始 shape 向量严格相等，并非补齐后相等（T:38）。

三次调用的数学目标分别为：

- P、Q：`[[3,4,8],[7,7,9]]`；
- R：`[[3,7,8],[3,7,9]]`。

但 **P 的实际分派不实现该广播关系，并发生越界读取**，不能将数学目标当成实际输出。

H:42–60 负责解析参数、查询 Vector 核数、计算 tiling、按逻辑字节数分配输入输出、H2D、启动 kernel；stream 同步后才 D2H 并写文件。没有额外输入 padding 分配。tiling 单独存放在 GM，kernel 通过只读指针访问。

## 2. 三次调用的 host tiling 与任务数量

由 T:35–54 推导：

| 字段 | P | Q | R |
|---|---|---|---|
| dtype 枚举 | 0 / half | 1 / float | 0 / half |
| 对齐后的 x2 shape | `[2,1]` | `[2,1]` | `[1,3]` |
| rank / outShape | 2 / `[2,3]` | 同左 | 同左 |
| x1Stride | `[3,1]` | 同左 | 同左 |
| x2Stride | `[1,0]` | `[1,0]` | `[0,1]` |
| totalLength / sameShape | 6 / 0 | 6 / 0 | 6 / 0 |

所有调用均有：

```text
tileElements = 4096
useful = ceil(6/4096) = 1
blockNum = max(1,min(4,1)) = 1
blockLength = ceil(6/1) = 6 元素
```

因此查询得到 4 个 Vector 核，不等于启动 4 个 block；这里仅启动 block 0，覆盖输出 `[0,6)`，无跨核尾块。

H:44、48、50–53 的实际分配量：

| 调用 | x1 | x2 | 输出 |
|---|---:|---:|---:|
| P | 12B | 4B | 12B |
| Q | 24B | 8B | 24B |
| R | 12B | 6B | 12B |

## 3. 实际分派、地址与输出边界

入口 K:173–182 按 dtype 实例化；`DispatchMaximum`（K:153–170）再按类型及 `sameShape` 路由。half 的所有非同形输入都进入专用 last-axis kernel，**没有检查 x2 是否真是共享末轴向量**。

### P：half，`[2,3]` 与 `[2,1]`

实际进入 `KernelMaximumHalfLastAxisBroadcast`，不读取上述广播 stride。Init 设置：

- `begin_=0,end_=6,row_=3`；
- x1/y 的 GlobalTensor 长度为 6；
- x2 的声明长度为 `row_=3`（K:87–97）。

声明长度不会增加实际只有 2 个 half 的 x2 分配。

Process 按输出行截断（K:100–114），执行两轮：

| off / count（元素） | x1 读取字节区间 | x2 读取字节区间 | 输出字节区间 |
|---|---|---|---|
| 0 / 3 | `[0,6)` | `[0,6)` | `[0,6)` |
| 3 / 3 | `[6,12)` | `[0,6)` | `[6,12)` |

区间均相对各自 GM 基址。两轮 x2 起点都是 `off%3=0`，每轮 `blockLen=3*2=6B`，但 x2 仅有有效 `[0,4)`；第三个 half 越界。该路径把实际的 `[3,7]` 当作末轴向量前两项，而不是按行广播单值。

若仅条件性地描述“搬运、计算完成且合法位置保持预期对应”时的有效 lane：第一行前两项为 `[3,7]`，第二行前两项也为 `[3,7]`；第三列依赖越界读到的内容。它既不同于目标广播，也不能据此承诺完整输出：越界可能影响执行完成，未知值也可能有特殊浮点编码。不能假设越界区为零、可读或由分配器额外保留。

### Q：float32，同 shape 组合

进入 `MaximumScalar<float>`（K:125–150），不分配队列、不调用 Vector Max，也不按 4096 分 tile。block 0 执行 `linear=0…5`，每个输出反解两维坐标：

```text
坐标：(0,0),(0,1),(0,2),(1,0),(1,1),(1,2)
ai：  0,1,2,3,4,5
bi：  0,0,0,1,1,1
```

x1 标量读取地址为基址加 `0,4,8,12,16,20B`；x2 为基址加 `0,0,0,4,4,4B`。执行 `av>bv ? av : bv`，写输出对应位置。全部在逻辑分配内；对题给有限、可精确表示的整数值，源码支持输出 **`[[3,4,8],[7,7,9]]`**。

### R：half，`[2,3]` 与 `[3]`

与 P 使用同一专用 kernel、同样两轮 `count=3` 和地址区间，但 x2 实际有 3 个 half，即 `[0,6)` 全部有效。两行均与 `[3,7,6]` 做 Vector Max，支持输出 **`[[3,7,8],[3,7,9]]`**。这里 x1 已是完整输出、x2 为共享末轴向量，正好符合该 kernel 的寻址模型。

## 4. 搬运、存储和同步

P/R 的每轮流程是：申请两个输入 UB tensor → 两次 `DataCopyPad` → 输入 EnQue/DeQue → 申请输出 → Vector Max → 输出 EnQue/DeQue → 写回 → 释放。三个队列深度均为 1，且各仅分配一个物理槽（K:95–97、121–122）；每槽容量 `4096*2=8192B`，显式数据区共 **24576B**，不等于每轮只处理的 3 个元素，也不包含隐含资源。

依据所给 A3 API 资料 H03–H08：

- VECIN、VECOUT、VECCALC 都映射 **UB**，不是三个物理存储层。
- 数据流为 `GM —MTE2→ UB —V/Max→ UB —MTE3→ GM`。
- 此处 `DataCopyExtParams{1,6,0,0,0}` 表示一块、有效长度 6B；普通 A3 GM→UB 路径在 local 侧按 32B 补齐，`isPad=false` 不承诺补零。
- local 对齐不把 P 请求的有效 GM 读取从 6B 缩成 4B，也不使越界合法；UB→GM 只写有效 6B，不会写满 32B。

队列与 TPipe 同步机制表达搬入完成后计算、计算完成后搬出，以及下一轮复用前旧消费者完成的依赖（K:109–114）。没有手写 flag 不等于没有同步；但单槽队列、异步流水也不能证明真实执行已重叠。Q 是 Scalar 直接访问 GM 的路径，不能套用这条 Vector 搬运链。各 block 输出独立，无跨核同步需求；host stream 同步保护最终回读。

## 5. 其他分支、910C 行为及边界

`KernelMaximumSame<T>`（K:6–77）按 `blockIdx*blockLength` 切连续区间，每核长度截断到剩余元素，再以最多 4096 元素循环，尾 tile 使用实际 count；DataCopyPad 的长度为 `count*sizeof(T)` 字节。

- 同形 half、float32、int32：直接 Vector Max。
- 同形 bfloat16：转 float，Max，再 `CAST_RINT` 转回。
- 同形 int8：经 half 转 float，Max 后经 half 转回 int8；题设类型的有限整数范围可精确表示，中间转换不引入整数精度损失。
- int64：无论同形与否均走 Scalar；其他非 half 的异形输入也走通用广播 Scalar，bfloat16 比较前转 float，再选择原输入值。

Scalar 的 `>` 在相等或无序比较时选择右操作数；不能据此认定 Vector Max 对 NaN、正负零具有完全相同的位级语义，材料未明确其特殊值契约。题给数值不触及该边界。

目标为 A3/2201：上述为 Vector/Scalar 工作，无 Cube、L1/L0 矩阵路径。K:79–81 注释明确说明 half 广播采用 Vector 比较，是为避开 2201 aicore 中 half 标量运算限制；但这不证明专用寻址适用于全部 host 接受的广播 shape。其一般边界是要求 x1 可按输出线性读取、x2 可按共享末轴读取，代码没有验证这些条件。host 不使用架构宏选择 tiling，不能将 device 宏与 host 参数混同。

此外，rank 和广播兼容性有检查，但零维尺寸、乘积溢出等未形成完整合法性契约。当前没有编译、运行、指令、耗时或 cache 测量证据；Q/R 是静态可支持的结果，P 是明确的地址越界与广播语义不匹配，不能虚构其实际返回值或设备故障表现。
