# Maximum 代码理解说明

以下用 **H** 指 `source/op_host/maximum.asc`，**T** 指 `source/op_kernel/maximum_tiling.h`，**K** 指 `source/op_kernel/maximum_kernel.asc`。源码事实、API 契约与静态推导分别说明；没有编译、运行或性能测量结果。

## 1. 输入输出与算法语义

目标是两个同 dtype、连续 ND 输入的广播逐元素最大值，无归约。Host 将 shape 右对齐、缺失维补 1；各维要求相等或至少一方为 1，输出维度取较大者。连续输入的 stride 以**元素**计，广播维 stride 置 0（T:29–50，`ComputeMaximumTiling`）。

Host 支持 float16、float32、bfloat16、int8、int32、int64；输入和输出共享一个 dtype。输入按各自逻辑元素数分配，输出按广播后 `totalLength` 分配，没有广播展开或额外工作区（H:26–33、42–57）。随后上传 tiling，启动 kernel，等待 stream 完成，再 D2H 写文件（H:58–60）。

数学目标：
- P、Q：按行广播，期望 `[[3,4,8],[7,7,9]]`。
- R：重复末轴向量，期望 `[[3,7,8],[3,7,9]]`。

但 **host 接受广播 shape，不代表所有 device 分支都按这些 stride 执行**。

## 2. 三次调用的 tiling 与分派

T:35–54 的公式给出：

| 字段 | P | Q | R |
|---|---|---|---|
| dtype | 0 / half | 1 / float | 0 / half |
| 补齐后的 x2 shape | `[2,1]` | `[2,1]` | `[1,3]` |
| outShape、rank | `[2,3]`、2 | 同左 | 同左 |
| x1Stride | `[3,1]` | 同左 | 同左 |
| x2Stride | `[1,0]` | `[1,0]` | `[0,1]` |
| sameShape | 0 | 0 | 0 |

三者 `totalLength=6`、`tileElements=4096`。虽然查询得到 Vector 核数为 4，但
`useful=max(1,ceil(6/4096))=1`，故 **blockNum=1、blockLength=6**。实际仅 block 0，输出范围 `[0,6)`，不是四核各处理部分数据。

入口按 dtype 选模板；`DispatchMaximum` 中：
- half 且不同形状，一律进入 `KernelMaximumHalfLastAxisBroadcast`；
- float 且不同形状，进入 `MaximumScalar<float>`。

依据：K:153–182。half 分派没有验证“仅末轴向量广播”的形状条件。

## 3. 实际地址、循环和结果边界

### P：half `[2,3]` 与 `[2,1]`

`KernelMaximumHalfLastAxisBroadcast::Init` 得到 `begin=0,end=6,row=3`；将 x2 声明为长度 3 的 `GlobalTensor<half>`（K:84–97）。**该声明不会把实际仅 2 元素、4B 的分配扩容。**

Process 的 count 同时受核范围、4096 和行边界限制，故运行两段（K:99–114）：

| 段 | off / count，元素 | x1、y 相对基址的字节范围 | x2 请求的字节范围 |
|---|---|---|---|
| 0 | 0 / 3 | `[0,6)` | `[0,6)` |
| 1 | 3 / 3 | `[6,12)` | `[0,6)` |

x2 地址始终为 `x2_[off % 3]`，两段均从元素 0 开始连续读取 3 个 half，**完全没有使用 host 的 `[1,0]` stride**。实际 x2 仅有 `[3,7]`；请求中的第三个 half 位于分配外。

因此 P 存在明确的越界读，不能承诺成功执行或给出完整确定输出。若假设两次读取及后续计算都完成，并将读到的第三值分别记作未知 `u₀,u₁`，局部计算相当于：
```text
[[3,7,Max(8,u₀)],
 [3,7,Max(9,u₁)]]
```
这是地址路径的条件描述，不是合法执行的输出保证。即使忽略未知值，已知位置也不是所需的按行广播结果。不能假定越界位置为零、两次取值相同，或必然报错。

### Q：float `[2,3]` 与 `[2,1]`

`MaximumScalar<float>` 逐个处理 `linear=0…5`，从末维向前用除法、取模恢复坐标，再累加广播 stride（K:125–150）：
```text
ai = 0,1,2,3,4,5
bi = 0,0,0,1,1,1
```
因此 x1/y 的字节偏移依次为 `0,4,8,12,16,20`，x2 偏移为 `0,0,0,4,4,4`。输入/输出分配分别为 24B、8B、24B，所有显式访问均在范围内。

每元素直接执行 GM 标量读取、`av > bv ? av : bv` 和 GM 写入；该路径没有 UB 队列或向量 `Max`。对题中可精确表示的有限值，源码支持输出：
`[[3,4,8],[7,7,9]]`。

### R：half `[2,3]` 与 `[3]`

分派、两段循环和字节范围与 P 相同，但 x2 实际有 3 个 half、6B，每段读取 `[3,7,6]`，均合法。x1、y 各 12B，覆盖恰为两行。

因此在 API 正常执行前提下，输出为：
`[[3,7,8],[3,7,9]]`。

P/R 各段只有 3 个有效元素，不能把 4096 的 buffer 容量当作搬运量，也不能把两段合并成一次跨行连续处理。

## 4. 搬运、片上存储与依赖

P/R 每条输入及输出队列均调用 `InitBuffer(q,1,4096*sizeof(half))`：各 8192B，三份用户 UB 数据区合计 **24576B（24KiB）**，每次各仅有 6B 有效数据。队列深度为 1，物理槽数也为 1；没有双缓冲证据（K:94–97、120–122）。

按给定 A3/2201 API 资料：
```text
GM --MTE2/DataCopyPad--> UB --Vector Max--> UB --MTE3/DataCopyPad--> GM
```
VECIN、VECOUT、VECCALC 均映射 UB，不是不同物理存储层（资料 H03/H04）。

每次 `DataCopyExtParams` 为单块，`blockLen=count*sizeof(T)`，单位是**字节**，stride 均为 0。2201 普通 GM→UB 非对齐搬运按 32B 组织 local 块；本例 6B 有效输入有足够 local 空间。`isPad=false` 不表示自动补零；`Max` 仅计算有效 count，UB→GM 仅写指定有效字节（资料 H05–H07）。这种 local 补齐**不能修复 P 的有效 GM 请求已经超界**。

源码通过 EnQue/DeQue 表达输入搬入后再计算、输出产生后再搬出的依赖，FreeTensor 与队列/流水管理约束槽位复用（K:109–114）。同形路径结构相同（K:35–66）。不能因没有手写 flag 就认定没有同步，也不能由队列存在推出实际流水重叠。

Q 是标量 GM 访问路径，不能套用上述整块 UB 数据流。各核输出区间独立，无核间归约或通信；host stream 同步负责等待整个 launch，并非替代核内依赖。

## 5. 其他分支及数值语义

- **同形且非 int64**：`KernelMaximumSame<T>` 按核号从 `blockIdx*blockLength` 开始，截断有效长度，再以最多 4096 元素循环；末 tile 使用真实 count，DataCopyPad 处理非对齐尾部（K:9–40）。
- **half、float、int32 同形**：直接向量 `Max`。
- **bfloat16 同形**：两输入转 float，float Max，再以 `CAST_RINT` 转回。
- **int8 同形**：输入经 half 转 float，Max 后经 half 转回 int8；int8 数值在这些中间格式中均可精确表示。以上见 K:44–61。
- **int64 任意形状**、其他非 half 的异形输入：均走通用标量广播索引。bfloat16 标量比较先转 float，最终选择原输入值（K:142–168）。

标量表达式在比较为假时选择第二输入，包含相等、浮点无序比较等情形；向量 `Max` 的 NaN、带符号零及相等值细节不能仅凭名称断言与其逐位一致。题中 Q/R 的普通小整数不涉及这些特殊值或舍入误差。

## 6. 910C 适用性与证据边界

目标 device 为 2201；本代码无按架构宏切换的业务分支，也没有以 host `NPU_ARCH` 选择另一条算法路径。按给定资料，向量工作对应 AIV/UB/MTE2/V/MTE3，无 Cube、L1/L0 或矩阵布局转换。K:79–81 注释明确说明 half 广播保留向量比较，是为避开 dav-2201 的 half 标量算术限制；这说明实现意图，不能扩大为任意 half 广播均正确。

当前 half 异形实现适用于诸如 R 的“x1 已连续覆盖输出、x2 是重复的完整末轴向量”情形；通用广播所需的 stride 并未在该分支使用，P 已展示其边界。Host 还未显式防护零维长度及 shape 乘积溢出，不能由三例推广到任意输入。

以上可确定静态访问、任务量与显式资源分配；实际 SDK 编译兼容性、P 的设备异常表现、隐含资源、真实访存事务及耗时均未测量，不据此裁定瓶颈或性能收益。
