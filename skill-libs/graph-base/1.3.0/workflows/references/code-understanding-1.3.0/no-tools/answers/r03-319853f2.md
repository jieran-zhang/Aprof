## 1. 算法、数据与 host 流程

目标语义是连续 ND 张量的逐元素 maximum：输入维度右对齐，长度为 1 的维度广播，输出取对应两值的较大者。但**host 接受的广播范围比 FP16 kernel 实际实现的范围更广**。

- `source/op_host/maximum.asc:26–33,42–48`：解析 dtype/shape，按元素大小计算输入字节数，查询 Vector 核数并调用 `ComputeMaximumTiling`。
- `source/op_kernel/maximum_tiling.h:29–55`：检查 rank 为 1–8；右对齐 shape，检查广播兼容性；生成输出 shape 和以**元素**为单位的 stride，广播维 stride 为 0。`sameShape` 判断的是原始 shape 数组完全相等，而非广播后相等。
- host 按逻辑输入大小及 `totalLength × itemSize` 分配 GM，无源码级 padding；传输输入和 tiling，启动 `blockNum` 个 block，等待 stream 完成后回传输出（`maximum.asc:50–60`）。三次调用彼此独立，不复用数据或结果。

正常有限数值下，各路径均意图实现 maximum。标量路径明确使用 `av > bv ? av : bv`，相等或比较为假时选择第二个输入（kernel:142–148）；向量路径使用 `AscendC::Max`。不能仅凭源码把二者在 NaN、正负零等特殊值上的行为视为完全一致。本题值均为小整数，可被相关浮点类型精确表示，不涉及舍入误差。

## 2. 本 workload 的 tiling 与任务数

以下 kernel 行号均指 `source/op_kernel/maximum_kernel.asc`。

三次调用共同得到：

| 字段 | P、Q | R |
|---|---|---|
| 右对齐的输入 shape | `[2,3]`、`[2,1]` | `[2,3]`、`[1,3]` |
| `outShape` / `rank` | `[2,3]` / 2 | 同左 |
| `x1Stride` | `[3,1]` | `[3,1]` |
| `x2Stride` | `[1,0]` | `[0,1]` |
| `sameShape` | 0 | 0 |

三者 `totalLength=6`、`tileElements=4096`。由 tiling:52–54：

- `useful=ceil(6/4096)=1`；
- 虽然查询到 4 个 Vector 核，实际 `blockNum=1`；
- `blockLength=6`，仅 block 0 处理元素区间 `[0,6)`。

输入/输出分配字节数分别为：P `(12,4,12)`，Q `(24,8,24)`，R `(12,6,12)`。不存在四核分工或跨核归约、同步。

## 3. P：FP16，`[2,3]` 与 `[2,1]`

### 实际分派及循环

入口按 dtype 进入 `DispatchMaximum<half>`；因 `sameShape=0`，无条件选择 `KernelMaximumHalfLastAxisBroadcast`，**没有检查 x2 是否真是末轴向量**（kernel:153–163,177）。

初始化得到 `begin=0,end=6,row=3`，并把 x2 的 GlobalTensor 长度声明为 `row=3`（kernel:87–97）。这只是访问描述，不能把实际仅 2 个 half 的 GM 分配扩为 3 个。

每轮 count 同时受剩余任务、4096 和行尾限制（kernel:100–110），所以实际两轮：

| `off`，单位：half 元素 | count | x1/y 起始字节偏移 | x2 起始字节偏移 | 每路传输字节数 |
|---|---:|---:|---:|---:|
| 0 | 3 | 0 | 0 | 6 |
| 3 | 3 | 6 | 0 | 6 |

每轮搬运后执行 3 元素向量 `Max`，再写回 6 字节（kernel:111–114）。不是一个 count=6 的 tile；两轮都因行界截成 3 元素短段。

### 语义与执行边界

此分支完全不使用 host 生成的 `[1,0]` 广播 stride，而是每行读取 `x2[0:3]`。实际 x2 只有 `[3,7]`：

- 两轮均从 x2 字节偏移 0 读取 6 字节；
- 字节 `[4,6)` 超出 4 字节逻辑分配；
- 即使忽略越界，它也把 `[3,7,…]` 重复用于每行，而不是把 3、7 分别广播至两行。

因此源码已足以确认 **P 存在越界读取和广播地址错误**。理想广播结果应为 `[[3,4,8],[7,7,9]]`，不能声称当前实现会输出它。若仅考察合法读取得到的比较，位置 0、1、3、4 对应结果会是 3、7、3、7；但完整执行可能出错，不能保证文件输出或任何部分结果。越界数据内容、是否触发设备错误，现有材料不能确定。

## 4. Q：FP32，同样的 shape

`DispatchMaximum<float>` 在 `sameShape=0` 时进入 `MaximumScalar<float>`（kernel:164–168）。不使用上述 half 分支，也不使用 tile 队列。

唯一 block 进行 6 次标量迭代；每次按输出 shape 从末维向前做整除/取模，再用 stride 计算输入索引（kernel:131–148）：

- `ai = [0,1,2,3,4,5]`；
- `bi = [0,0,0,1,1,1]`；
- 对应 x1 GM 字节偏移 `[0,4,8,12,16,20]`；
- x2 GM 字节偏移 `[0,0,0,4,4,4]`；
- 输出字节偏移与 x1 相同。

所有访问均在分配范围内，按源码语义结果为：

```text
[[3,4,8],
 [7,7,9]]
```

这里 `tileElements=4096` 不参与标量循环；没有 DataCopyPad、UB 队列或向量 Max，实际为标量索引运算、GM 读、比较与 GM 写。具体指令及缓存事务需编译结果确认。

## 5. R：FP16，x2 为 `[3]`

tiling 生成的 x2 stride 为 `[0,1]`，但 kernel 仍走与 P 相同的 half 专用路径。

同样在 `off=0,3` 各处理 3 个 half：x1/y 起始字节偏移分别为 0、6，x2 两次均从偏移 0 读取 6 字节。这次 x2 实际分配正好为 6 字节，且 `[3,7,6]` 正是可重复使用的完整末轴向量，因此访问和广播语义一致。按所用 API 的正常语义，结果为：

```text
[[3,7,8],
 [3,7,9]]
```

R 与 P 的差异不是调度或 tile 大小，而是专用路径的地址假设是否符合真实输入存储。

## 6. 其他分支、存储依赖与 910C 行为

**源码策略：**

- int64 始终走通用标量路径，即使 sameShape（kernel:156–157）。
- 其他非 half 类型：sameShape 走 `KernelMaximumSame`，否则用广播 stride 的标量路径。
- half：sameShape 走同形状向量路径；所有非 sameShape 都走末轴专用路径。后者还假设 x1 已按完整输出连续存储，不能据 host 广播检查通过就认定正确。
- 同形状向量路径按 block 连续划分，再以最多 4096 元素循环，最后一块用实际 count（kernel:12–40）。half/float/int32 直接 `Max`；bfloat16 转 float 后比较再转回；int8 经 half 转 float，比较后经 half 转回（kernel:44–61）。int8 的全部取值在这些中间类型中均可精确表示。

**平台/API层面的解释：**

这些向量路径使用 GM→UB 搬运、UB 向量计算、UB→GM 搬运，可对应 910C 的 MTE2、Vector、MTE3 执行资源；没有 Cube 矩阵计算。三个深度为 1 的 `TQue` 分别承载两输入和输出，`EnQue/DeQue` 建立搬运与计算间的依赖，`FreeTensor` 允许存储复用。源码没有双缓冲或显式跨 tile 预取；不能由队列存在推断搬运与计算充分重叠。

P/R 每核三个 half 队列各按 `4096×2` 字节申请，共 24 KiB 有效载荷容量，实际每轮只计算 3 元素。`DataCopyExtParams.blockLen` 在这里以**字节**计，传输请求为 6 字节；DataCopyPad 用于非整块长度搬运，不能把 UB 的内部对齐解释为 GM 可合法越界。向量计算 count 仍是**元素数**。

目标 device 为 `__NPU_ARCH__=2201`；源码注释明确 half 专用路径是为避开该架构的 half 标量算术限制（kernel:79–81）。本实现没有 host `NPU_ARCH` 或 device 宏条件分支，不能据此引入 3510 行为。

**证据边界：**以上是源码与 API 语义的静态推导，并非运行观测。未提供编译、profiling 或异常结果，不能量化带宽、延迟、流水重叠及 P 越界的实际后果。此外，tiling 未显式排除零维长度或检查乘法溢出；对这些输入也不能从普通广播检查推导出安全性。
