## 剩余扣分主要反映什么

B剩余5处partial、合计5.5分，全部涉及非活动3510/950静态对照：

- CU04.H04有1处未明确3510分支L0A的NZ格式，扣0.5分；另一个重复已写明。
- CU06.H01两次都未写3510对应950PR/950DT的具体平台名称。
- CU06.H04两次都给出了一般平台隔离和未实测边界，但未展开A3/A2与950的CrossCoreWaitFlag阻塞流水差异或另一项同样精确的额外契约。

后二项每个重复合计扣2.5分。A在这些平台对照项上有相同不足。两组都没有将3510分支当成910C实际执行，也没有声称跨平台编译或性能已验证。

这是沿用旧gold的评分范围与本版“只建设910C、950仅提示隔离”的目标之间的限制。保留全部原分，未删除这些题项或事后重算主指标；也不据此将950教学扩充列为本版必须补齐的缺陷。下一版题集应在冻结前分清910C必需事实和扩展平台对照，避免总分主要反映非目标平台细节。

## 如何用于AProf以及下一步

这次测量的是完整展开的skill包：方法、领域知识、例子及额外上下文共同作用。无工具场景如果只提供短SKILL入口而不内联参考，模型无法打开链接，本轮结果不能代表该形态。真正可用的相关正文需要随输入一起提供；本轮不按题挑选或裁剪B材料。

无工具测试已经显示局部910C知识可以把过度保留变为具体执行事实，但相对翻倍的输入成本，目前尚不能证明全面内联五篇参考对每个算子都划算。算法/策略两组均10/10，执行事实9.875→10，硬件对应9.375→9.542；主要难点是现有六组相关题目对该模型仍接近满分。

下一步应优先在新的实际算子工程上继续无工具对照，增加跨host/tiling/kernel的分派链、非连续地址、广播复用范围、数值转换和slot生命周期推导，先冻结执行事实，保持不预设Problem/Action。题目可先由开发工具和独立审阅定答案，被测模型仍不使用工具。只有出现对选型有影响、skill仍不能消解的具体理解缺口时，再比较针对该缺口的工具辅助；本轮不把调用工具加入常规workflow。

六组题目各两个重复，其中改名题复用既有结构；不构成24个独立新任务或盲留出泛化测试。与旧工具/SDK开放轮的输入资料和调用方式不同，不能用跨轮分差估计工具收益。本轮没有硬件、性能、HAP或优化选择效果结论，skill正文也未按答案修改。
