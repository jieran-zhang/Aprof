# AProf代码理解：无工具A/B协议

本轮只测模型在完整输入上下文中的代码理解能力。6组题目各2次独立A/B，共24份主体答案；保持旧59事实及权重。输入仍是同一固定源码和workload，只删除旧题面对外部SDK文档/工具权限的指引，新增相同的无工具任务说明。

A只得到源码、workload、910C平台元数据。B在相同输入后增加固定skill入口及全部五篇参考正文；不提供sources原文档案或整套SDK手册，不做按答案挑选的资料注入。这测量“已展开正文的skill”效果，未测只给短入口且无法访问引用的形态。

双方使用同模型/推理设置、同输出要求、max_output_tokens=12000（包含推理和答案）和900秒超时，新上下文；B的额外输入token属于干预成本，不作等输入token声明。源码行号与定位由外部预处理，双方相同；被测模型不使用工具、CPU检查、搜索、文件读取、子Agent或硬件。

使用单次Responses请求，显式tools=[]、tool_choice=none，不进入Agent执行循环。源码与skill只通过请求正文提供，不暴露文件系统或SDK。逐次保存请求/响应元数据，确认工具列表为空、工具选择为none、返回仅文本/推理且工具调用为0；任何工具输出均记录为协议失败，不以质量原因重试。服务容量/连接故障可同配置重试。预先做独立的基础设施冒烟，冒烟不计入24份答案。

每份答案由新上下文匿名逐事实评分，评分器只见当前答案、固定gold/protocol和当前源码，不见skill、条件、旧结果或兄弟答案。独立抽审处理明确错评并保留初始注释，最终注释hash先锁定再解盲；报告三维得分、unknown/遗漏、错误、具体差异和实际token/时间。

本轮与上一轮共享源码/事实标准，但不共享SDK资料和工具权限，因此上一轮只作历史背景，不能直接用分差估计工具的因果收益。此次不改skill内容、runtime、schema、P/O或默认版本，不做硬件实验。

工具选择语义参照[OpenAI官方Function calling文档](https://developers.openai.com/api/docs/guides/function-calling#tool-choice)。旧CLI关闭执行的技术探针不是正式主体调用；正式24次统一使用直接单次请求。
