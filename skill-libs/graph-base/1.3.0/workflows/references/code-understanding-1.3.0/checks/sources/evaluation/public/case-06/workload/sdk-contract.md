# 固定 SDK 契约与执行边界

所有题目使用同一份 `shared/rawdocs` 中的 asc-devkit 原始 API 文档，修订固定为 d378849769f9ee610af9d0ac38db2b3b6bed3209。目录中的文件是完整原始文档；原项目 README、教学解析和本评测答案不在可用材料中。文档清单、内容哈希和许可证见 `shared/API_MANIFEST.json` 与 `shared/licenses/asc-devkit.LICENSE`。

本评测的实际目标是 Ascend 910C（Atlas A3），源码分支以 `__NPU_ARCH__=2201` 为准。若题目给出 `3510`，它只作为另一个平台契约的静态对照，不代表本题有 3510 或 910C 的编译、运行或性能观测。对于定义在 host 侧的 `NPU_ARCH`，以 workload 指定值为准；不要把两个宏默认为可互换。

只进行静态源码分析及普通 CPU 算术验证。不得运行 NPU、SDK 构建、仿真、远程设备或生产源码修改。可以读源文件和本固定文档集，可以用普通 CPU 工具核对整数地址、切分或偏序。A/B 条件得到相同的源码、workload、API 文档和工具权限。

回答应区分：由当前源码直接推出的事实、由目标平台 API 契约补足的行为，以及仍需设备或编译证据确认的事项。解释整体算法、当前实现策略与硬件执行行为，不能以 API 名字替代数据路径或地址推导。存在边界或不确定性时说明其依据和范围；不必强行得出优化动作。
