# strided_slice：两轮无硬件分析

结论：11个case存在100至1048576等长度连续段，批量搬运同时去掉逐元素拷贝和段内rank解码；地址外提对其余9case有价值但保留每元素Scalar访存，作为最强替代。

R1选择 `action.reorder_contiguous_access`；条件方案：基于归一化metadata合并最长连续尾段：跳过size1轴，要求最后有效axis step=1，继续合轴条件sourceStep[d]=当前run长度。每核仍持有原64B边界输出区间，与run交集切段；每段起点只解码一次，用DataCopyPad按有效字节搬入单独UB槽并搬出同宽位模式。T∈{256,1024,4096}元素，U=2*Align32(T*itemBytes)+API_reserved≤availableUB；不补读GM、不跨不连续行空洞。run=1、负stride、未支持API保留原逐元素路径。

源码成本：Host将masks归一化为outputShape/sourceStep/sourceBase；kernel每输出做2*outputRank次除模并Raw单元素GM拷贝。输出64字节对齐分核，必须保留物理独占边界。所有原case正stride，负stride仍走原fallback。

适用原case：2,7,10,11,13,14,16,17,18,19,20。其余case保留原fallback；原20case全部纳入成本表与后续完整验证。
