# gelu：两轮无硬件分析

结论：直接删掉tanh永不使用的20*T+mask静态字节，给更大tile提供可核算空间；相比强行复用none临时区，避免Erfc输入/tmp重叠未证问题。容量节约本身不是加速，收益假设来自同算术较少tile循环/API发射。

R1选择 `action.dispatch_by_workload`；条件方案：保留none/tanh定义和全部Cast/尾部修正。在Init按mode分配：none保持原erfTmp/mask；tanh省去两项无用分配。基于mode,dtype合法容量选择T：tanh{1024,2048,4096}，none{1024,2048}，T均64整数倍。tanh U=2*Align32(b*T)+3*Align32(4*T)+APIreserve；none另加Align32(20*T)+Align256(ceil(T/8))。只有U≤actualUB且count API允许才选择较大T，否则原1024分支。直调用实际mode字段/template分支接线，不伪造TILING_KEY_IS。

源码成本：所有mode固定T1024；两Raw队列加fi/work/fo三个FP32区、Erfc5*T FP32 scratch以及mask无条件分配。显式UB=(2*b+32)*T+Align256(ceil(T/8))，尚不含API/编译保留；tanh不访问erfTmp/mask。none仍有Erfc和尾部特殊修正；tanh有2^-23网格RINT转换，不是无意义cast。

适用原case：4,5,6,8,10,12,14,17,19。其余case保留原fallback；原20case全部纳入成本表与后续完整验证。

候选比较：
- reuse_disjoint_onchip_buffers：复用none的work/fo与Erfc scratch需要API alias和最后读证据；当前fi跨Erfc、Mul、Compare仍存活，不能仅按C++作用域共享。
- coalesce_cast：移除tanh中FP32→int32 RINT→FP32会破坏明确2^-23概率量化；输入升精度/最终输出缩位也是数值契约。

R2复核：逐20case重算模式域，9个tanh和11个none；T1024节约20736B的等式成立。确认erfTmp在none还被saved复用，不能从none再减一块；tanh的work ReinterpretCast<int32>只是视图，未新增物理区。R2坚持保留2^-23 RINT和none负尾修正。

具体后继：核对目标Erfc/Tanh/CompareScalar count与API临时预算后才设T上限；先单独验证删除无用分配，再同意图内增加合法T，完整20case含NaN/Inf/零和负尾域。若较大T不改善，保留资源简化但不宣称性能接纳。
