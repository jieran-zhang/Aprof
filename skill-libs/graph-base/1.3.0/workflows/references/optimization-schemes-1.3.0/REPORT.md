# 完整优化方案与跨轮摘要：开发验收

本次在未封版 graph-base 1.3.0 中增加完整方案、多 Action 共同计划与任务内跨轮摘要，runtime 升为 0.8.0。D v0006、P v0003、O v0006、routing v0005 保持原身份，不切换默认版本。

流程与纸面例见[完整方案](../optimization-schemes.md)，摘要模板见[跨轮摘要](../optimization-history.md)。轮次和达标停止条件由外部任务提供；正确性、计时与工程判据保持原义。

## 已实现的变化

每轮以一个能够完成预期变换的完整方案为单位。一个 Action 足够时直接使用；必要的多 Action、P/O 方法及 Host/Kernel 配套修改可共同实施，不要求单因素、固定成员数或默认消融。选择前比较方案共同减少、新增和保留的工作、影响范围、联合生命周期资源及最强替代；不将共享工作重复计收益。

新增严格 `aprof.action-decision/v3` 和 `aprof.handoff/v4`。C1选择方案，C2对各成员真实路由后形成共同计划，C3逐成员选择方法、绑定实际参数/源码与共同兼容依据。依赖保证不是已发生事实；C3须在最终源码核实。保证绑定整个实际配置，生产者变参不能借用旧消费者保证。性能未知可支持有依据的试验，地址、数值、API、依赖及资源条件仍逐项满足。

P_KEEP须引用覆盖相关目标的完整有效共同计划；O_KEEP只是成员不增加局部优化，改变P仍须实现新计划。全KEEP才为NOOP；空命中、fallback、unsupported、缺证据不冒充KEEP。超出算法、owner、归并、同步、workspace、融合、通路或dispatch许可时返回C2。新旧协议显式分派，不能混装；沿用原校验和结果关联入口，不新增日常工具门槛。

协调者维护任务内三部分 `optimization-history.md`：当前状态、已尝试路线、剩余机会。每轮结果、修复或重规划后更新，区分已验收、仅正确的探索父本、失败、无效计时与未测。后继先消费摘要，按需展开证据并重评方案；可以继续同一Action，不能仅改名重复计试验。轮数、达标停止和重试来自外部，accepted不自动成为停止指令。摘要不进入memory或知识自动晋升。

## 无工具自主回放

GridSampler3D、Maximum、Transpose、Sum各两次新上下文，共8份初答；另有GridSampler3D和Maximum各R2/R3四份后继。输入原始源码、workload和静态展开资料，不预选Problem、Action或数量。主体全部完成，`tools=[]`、`tool_choice=none`，工具调用为0。

- GridSampler3D两答均选择按原运算顺序将三线性算术批量Vector化，联合考虑Scalar采样、暂存、有效尾块、输出和依赖；没有把不规则读取称为规则DMA。
- Maximum两答均选择同形int8转换链收缩，按完整int8值域说明精度，比较广播、整数Scalar路径和流水代价；没有把样例数据范围当作通用值域。
- Transpose一答采用块/条带DMA加原始位模式重排，一答自然组合搬运合并和地址递推。组合有具体共同目标，不靠要求增加Action数产生。
- Sum两答比较短归约的增核、归并及流水新增成本后保留现状，没有因“一轮优化”强制修改。

后继预算使GridSampler3D重算18个独立FP32数组及tile/槽数，Maximum分开计算删Cast与变tile的工作变化；R3无新增证据时保留R0和条件方案，按外部范围交付。逐份采用/参考/未采用的P/O正文、原因和原始回答见[行为明细](BEHAVIOR.md)。

独立评阅先固定执行事实与五维标准，再匿名审阅8答、锁定评分后解盲；40处回答引文与文档路径核查通过，静态评分80/80。**这次没有旧技能对照，不能据此声称能力提升。** 初答每份输入170815—181208 token，资料充分展开，只检验获得资料后的推理和采用，不证明检索效率。模型保留条件方案、必要API未知及未测状态，也不等于C3已可执行。
