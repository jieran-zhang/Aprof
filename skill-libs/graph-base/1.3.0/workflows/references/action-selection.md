## 怎样使用已有知识

来源审阅过的机制和方法是可采用的工程知识。结合当前 host、tiling、kernel 与 workload 证明适用结构后，可以用它形成具体方案、参数范围和假设试验；不要求每个算子先有性能实验、PMU 或因果证明。来源支持的是明确范围内的方法依据，当前收益由后续实验检验。不能因没有当前硬件数据就退回最容易证明等价的字段缓存。

区分三种判断，不用一个 ready 状态替代全部判断：

| 判断 | 依据与处理 |
| --- | --- |
| 结构适用与实施合法性 | 当前地址/索引域、数据依赖、生命周期、原数值契约、API 与资源预算。尽量从源码、原 host 约束及合法公式证明；确实缺少必要条件时给出条件方案，实施前补齐。 |
| 性能假设 | 来源中的原理加当前源码结构，例如每元素执行地址解码、重复加载同区间、合法 tile 被拆碎。支持提出可检验预测；关键路径占比、编译器消除和收益大小可以尚未测量。 |
| 本轮选择理由 | 解释完整方案可减少/新增/保留的工作、影响哪些 case、共同资源代价与最强可行替代，说明为何此时值得试。合法不等于优先，改动小或容易填满交接字段也不是性能依据。 |

代码中的 `mismatch`、`overhead` 等历史 Symptom 名称不是机制证明。性能条件迁出实施前提不代表将其置为 true；保留其实际状态、来源和预测，并使用新模板身份。

## unknown 的使用范围

- unknown 必须指向具体问题，例如“目标编译器是否已消除循环内三次字段 load”，并写清它影响收益预测、方案选择还是实现合法性。不能把所有机制都填成同一个 `profile.scalar_cost`。
- 已由源码、明确 API 契约或容量公式证明的事实不因没有 profiling 变成 unknown；来源适用范围不同则精确指出差异。
- 任务指定的目标平台可以作为 Context 的已知适用域，注明任务约束及平台映射依据，不冒充设备探测。目标型号、实际核数、可用 UB 和 SDK 能力分别记录；不能因尚未探测设备就清空已知目标平台，导致对应文档无法检索。
- 收益大小、是否主瓶颈、流水是否处于关键路径等性能 unknown，可以由本次假设试验检验，不能自动成为实施安全门禁。明确反证和不适用条件才支持否决方法。
- 只有会造成地址越界、依赖错误、违反原精度、API 不支持或资源不合法等具体风险的缺失事实，才设置“实施前必须补齐”。例如未知 UB 上限阻止承诺某个分配，仍可给出 `UB需求(tile,slots) ≤ 可用UB` 的候选范围。
- 缺乏性能数据时，不要求先证明真实瓶颈，也不把模板方法描述写成当前实测事实。条件规划、知识采用、实验就绪、实施成功和收益验证分别记录。

## 数据相关路径必须进入机会比较

当原实现或候选包含数值保护、稀疏判断、边界回退等数据相关路径，先把输入范围/特殊值、判断条件、触发粒度、受影响输出和执行工作连起来。只分析会影响当前候选的部分，写入已有 `path_overview`、域、`work_delta`、`coverage` 与 `tradeoffs`，不另建表单或执行模型。

“某个元素触发”与“该元素对应输出回退”不同。例如整行扫描发现任一值越界后整行转软件处理，覆盖单位是行；若一个 plane 有 I 个输入、S 个输出，每个软件输出执行 K 项，触发后工作是扫描 I 项加 S×K 次求值，而不是命中输入数×K。N 个 batch、C 个独立 plane 时再按真实 owner 累计。计数是源码工作模型，不是硬件指令数或时间。

先查任务已有的原矩阵、生成器与相关源码；本次输入范围用于判断当前覆盖，不能缩小算子的合法输入域，也不能按 case ID/已测赢家写分派。范围跨过阈值只能证明可能触发；有明确分布依据或实际数据才进一步推断频率。证据不足时给出可能覆盖和成本边界，不能称“罕见”或默认快路占多数。不要求为此读取全部输入、运行脚本或取得 PMU。

快路正确性、保护路径正确性与保护的成本分别判断。改变累加树、FMA/分离运算或输出 Cast 时，必须沿原 oracle 的最终 dtype、舍入和严格误差判据判断，不能用中间 FP32 误差小于 floor 代替最终输出保证。若新增保护使大量工作进入软件路径，比较保留原数学顺序、已有适用实现或缩小变换范围；这些替代仍须满足当前合法域，不能自动把父实现当作全域正确。

## 确定方案与成员 Action 之前

从当前完整计算与数据路径建立成本概览：任务分配、每任务/每元素工作、搬运粒度和复用、Vector/Scalar 计算、同步、尾块与分发差异。记录能从源码算出的次数、字节和容量，说明单位及 case 范围；没有可靠时间数据就不编造占比。按结构或数量级区分有差异的 workload，不为二十个 case 填同一段解释。

检索完整 Problem 轻目录并按需展开正文。每个候选的支持、反证及缺项针对自身机制。允许先阅读相应 family/branch/叶正文，了解可实现方案、约束和代价，再决定 Action 意图；这一步是可行性比较，不预先锁定 C2/C3 的最终选择，也不往路由 facts 注入意图。

对源码中会改变选择的重要机会，说明为什么采纳、暂缓或不适用。比较覆盖以当前证据为准，不规定候选数、Action 数或必读分支。只有一个合理机会可以选择它，但必须解释明显替代机会为何不足。多个机会同属一个 Action 时比较实例、目标和成本，而不是用 ID 去重掉差异。多个必要步骤可组织为同轮完整方案；单个 Action 足够时不用为配套修改增添意图，多成员则说明组合理由与依赖。不存在每轮单因素、Action 数、recipe 数或 patch 行数门槛。

每个拟采用方法及完整方案给出可检验预测：准备减少什么工作、增加什么代价、影响哪些 case，以及什么观察会削弱它。例如逻辑地址运算从每输出多次除模变为按连续段一次解码，是源码预测；最终编译指令数和 Task 时间仍待验证。不能直接从逻辑操作数推出固定加速比。

本轮比较完成的理由应说明已考虑的主要机会和剩余不确定性。找到一个 ready Action 或已读若干文档不代表比较充分；外部任务范围结束时报告已完成分析与缺项，不自行扩展轮数。重复同一意图有针对性依据时允许继续，不强制换 Action 或增大 patch。

## 工作量、覆盖与代价怎样影响选择

先冻结父源码和完整 workload；完整计算路径只分析一次，机会引用其中的阶段和语义域。语义域按真实 dtype、布局、广播/归约关系、连续长度或复用依赖划分，测试 case ID 仅用于成员定位。源代码存在但当前测试未覆盖的域另行说明，不能把已测列表当作完整 API 范围。

| 比较项目 | 怎样形成判断 |
| --- | --- |
| 原工作与变化 | 说明每元素、每段、每任务、每轮分别执行的工作，区分减少、新增与保留项。每个量带单位、符号定义及源码事实。逻辑地址运算减少不等于编译后指令或耗时同比减少。 |
| 覆盖与残余 | 对完整声明域分别标受影响、保持原样、不适用或未知；只优化一个阶段时说明部分覆盖。少数严重低效域可以优先，仍交代剩余域的问题和后续方向。 |
| 代价与替代 | 比较会改变结论的资源、访问顺序、同步、任务均衡、尾块、转换与代码体积。已知 UB 字节和未知寄存器压力分别记录；不把不同单位相加为总分。 |
| 选择敏感条件 | 指出哪项工作减少值得付出何种代价，以及什么变化会让替代方案更优。不要写“如果有更多数据就重新考虑”这样的空条件。 |

例如内轴长度 E、外层行数 R、rank d：逐元素解码约需 R×E×d 次轴处理，按行解码约 R×d 次，但新方法还可能引入 R×ceil(E/T) 个搬运/计算片段、补齐及同步。E 很短时“少了解码”与“多了小片发射”可能互相抵消；跨行组合还需核对广播位图、物理布局与 owner。该模型只说明竞争成本，不指定算子、Action 或最佳 T，也不直接预测加速比。

比较记录必须连接到所选机会的具体工作量/覆盖/代价及合理替代。没有合理替代可以说明理由；不要求凑足若干机会，不强求改选，也不以覆盖 case 更多自动胜出。若当前实现已消除某项工作，则减少该工作的机会应失去相应依据；若未覆盖域仍有明显逐元素工作，要解释为何暂缓，不能用整体 accepted 宣告其解决。

### 新增准备工作需要什么收益才能覆盖

打包、转置、索引表和多阶段复用通常把工作移到准备阶段。区分 API 调用数、descriptor block 数、逻辑有效/补齐字节、workspace 同时存活字节，以及尚未观测的 HBM 流量；它们不能互相替代。一次调用处理多个 block 可能只减少发射，必要读取仍保留。准备成本按每次完整调用及真实复用次数摊销，不能按理想重复调用免费复用，也不能重复计算共享收益。

先问“目标阶段的哪部分可能消失，新增工作要由多少节省偿还”。已有同范围、同父本且计时口径可信的阶段耗时，可以作为该阶段潜在节省的粗上界。顺序阶段可用 `净变化 = 新增准备时间 - 目标节省 + 其他变化` 讨论收支；必要算术/读取尚在时，不能把整个目标阶段都算成可省。阶段重叠时沿关键依赖解释上界，不能直接相加阶段中位数，也不能用链中旧时间代替当前父本。字节除以带宽只有具备适用带宽依据才可作模型，不能写成实测时间。

例如每次多写 B 字节，仅把消费者两个 DMA 调用合成一个，读取字节不变：复用次数很低、准备阶段已占明显时间时，原布局或无额外复制的批量描述是强替代；复用多且发射工作可观时仍可提出试验。没有可靠时间时保留 B、调用数和复用次数的符号竞争，不要求先证明净收益。

选中理由必须说明这些事实怎样改变了方案、范围、优先级或待检验预测。仅写“代价可能抵消收益”“实际测试决定”不是比较。若仍选新增代价较高者，指出其尚成立的收益机制、偿还成本的条件，以及什么观察会削弱它；不需要用自动总分或统一阈值裁决。确定的覆盖反证不能继续标 unknown，收益大小未知不因此变成实施安全门禁。

v3 延续 v2 允许尚无注册 Action 的分析机会，显式记录意图缺口；进入正式实施的选择仍需注册 Action。不能为套用 `hoist_invariant_control` 而将派生数值计算都称为控制，也不能将派生值的保存等同于原始输入块驻留。

联合比较将成员的减少/新增/保留工作连接到共同方案：相同读取、解码或中间结果只计算一次；资源按同时存活集合、别名和实际 scratch 核算，不能把单项峰值或节省量直接相加。

拟变更前保存当前决策及引用的来源。C2 新发现不可接受的访问/容量代价时，可以形成新决策返回比较；C3 若发现必要初始化/转换/同步抵消预期减少工作，也应回传。补证据创建后继记录，不在实现后回填旧决定。时间戳和 hash 只证明记录身份；独立审阅还须核对理由是否与源码及实际方案一致。

数值或正确性修复若新增整域回退、扫描、软件算术、额外阶段，或明显改变覆盖，即使未超出 C2 自由度，也须把受影响工作/代价带回本节重比，保存新 decision 与交接后继；越过算法/owner/通路等边界时同时返回 C2。修复合法只说明可以实施，不能沿用修复前已失效的性能理由。可在同轮保留原 Action，复用未变分析，无需逐个构建中间候选或强制换路线。普通不影响关键预测的等价修正无需重做全套比较。

有队列不表示搬运和计算已经重叠，有 Vector 调用不表示主要逐元素循环已经批量化，有缓存提示不表示实际驻留。检查当前具体执行路径后再决定这些方向是否仍值得分析。

## 分域与 Tiling Key 的位置

优先比较一个通用或参数化方案能解决多少实际工作。仅在算法、硬件能力、数值路径或资源需求需要不同实现时，才考虑分域，并解释新增路径/边界/维护成本。通常先改善通用路径再处理残余不适用域；天然不同的语义或硬件域可较早分开，但并不自动带来性能收益。

`dispatch_by_workload` 负责已明确方案的分派意图，Key 本身不是减少工作的方法。回归不自动触发新 Key，case 数或已测赢家不是生产分派条件；仅换 case 名称/顺序不得改变方案判据。性能边界尚未知可以提出待验证的参数域，不能捏造最优阈值。实际分派仍归 C2，C3 只在许可内接线。

## 补证据怎样改变选择

对影响决策的缺项，写明检查对象、case 范围、来源/后端、预期观察，以及不同结果将怎样改变选择。优先用已有源码、host 分派、原始矩阵和合法公式补齐；确需编译或 profiling 时提出有范围的请求。性能未知也可明确选择由本次实验判别，不强制增加前置 PMU。

补证据有三种结果：已有事实足够，采用具体假设试验；需要先补合法性/适用性条件，交 C2 条件分析；当前权限或工具不能回答，保留具体方案和待检查项。不能因为另一项简单动作已 ready，就略过会改变优先选择的竞争机会；也不能把“工具未提供”写成“该机制不存在”。

## C2/C3 的知识采用

方案确定后仍逐成员调用 P/O 内部 router，并逐项核对正文及共同兼容；P 形成覆盖全部相关目标的共同计划，O 在该计划下分别选择实际方法。命中条目不能简单取并集。前序产生的保证标明依赖和作用范围，C3 在最终源码核实；不要求测量中间候选，也不能把计划承诺写成当前 facts。记录具体哪段知识改变了任务划分、tile/slot 范围、数据通路、API 实现、代价评估或拒绝理由。路径/hash/展开回执证明读取身份，不证明理解；独立复核要将解释与源码事实和拟变更对照。

C0/C2 提取当前已有计划与实际改变计划分别说明。缺少父计划时建立计划在旧 contract 中仍编码 P_CHANGE，但报告标明“提取已有计划”，不得统计为并行优化。P_KEEP 保留许可自由度内的参数调整；算法、owner、融合/归并边界等越界仍重规划。

C3 实施必须满足新模板的安全与结构条件、已确认计划及所选方法的合法性条件。原理成立/收益未测量可以作为假设试验进入；当前版本不允许改精度、伪造事实或借其他实例的合法性证据来通过。

## 所有后继轮次的反馈

协调者更新任务根的[三部分跨轮摘要](optimization-history.md)；后继先读摘要，按需展开前轮/早期决策、实际变更及结果，先判断结果能回答哪些预测：

| 前轮反馈 | 下一步判断 |
| --- | --- |
| 编译/源码检查表明预期工作已被原编译器消除 | 削弱这项具体干预的价值，重新比较；不能只换几个字段继续同一假设。 |
| 有效计时改善但收益有限 | 分开讨论变换有效性与主成本；不由成功推导因果，也不由未达晋升门槛直接排除整个机制。 |
| 有效无收益或回归 | 检查预测是否实现、额外代价及 case 差异；继续同机制需解释新目标/参数会检验什么不同预测。 |
| 计时无效或缺正确性 | 明确不能判别的范围，选择补证据或有独立依据的下一方案，不当成机制反证。 |
| 联合方案有有效整体结果、未做消融 | 可以评价整个候选及其覆盖；不能把整体收益分配给单个成员或自动证明机制。缺消融不否决联合方案，也不要求默认补消融。 |
| 无硬件权限、未编译/未测量 | 只使用新增静态事实更新判断，记录 not_measured；本次无硬件回归给条件后继。在允许实验的任务中，也可据独立依据选择新试验，无须先测前轮；不得捏造 R1 加速比、正式晋升或已完成 R2 实施。 |

源码父本选择与机制判断分开。换回 R0 不意味着所有前轮证据失效；按目标/实现重新绑定可复用部分。相同 Action 可继续，条件是说明新增信息、不同预测或未解问题，不能仅因形式条件仍满足。不同 Action 也必须有依据，不用多样性配额代替推理。

## 后继轮次的分层复盘

包括 R2、R3 及以后的后继，先逐项核对“预期工作是否真的改变、实际覆盖、正确性、测量有效性、不同域结果及新代价”，再决定保留/重开哪些机制和方案。源码改动实现了某个减少工作预测，不代表它是主瓶颈；性能改善也不自动证明原因。

- 正确性/API 失败可在相同意图内修复，性能预测仍未测试；修复作为新尝试保留，不强制重走全部诊断，也不计作另一个性能方向。
- 局部改善而整体有限时，同时比较扩展方法、优化残余路径和其他机会。只因已投入第一轮就继续同一实现，不足以说明优先级。
- 不同域结果相反时，比较访问顺序、活跃状态、任务组织、同步及额外工作；可以返回 C2，不默认用 dispatch 隔离输家。
- 继续同一 Action 需指明新的对象、参数、判别预测或尚未回答的具体问题；新 Action 也要通过同样比较。相同 Action 的实例/计划可以不同，不用 ID 判断是否重新思考。
- 无效/未测结果、复合改动、范围不匹配分别保留限制；不将其变为机制反证。无硬件回放只用新增静态事实，不把前一轮纸面计划当成已实现候选。

父本选择、工程接纳和机制判断分别绑定。C5 传回实际 patch/范围/结果，C1 解释是否重开机制，C2 决定是否重规划，C3 在原自由度内修复或实现。未变化的结论可引用，不因后继轮次标签重复全部步骤。

## 外部迭代范围

轮数、达标停止条件和重试范围由 C0 引用用户或外层驱动约定，选择规则不默认增加轮数、要求持续到 accepted、连续无收益自动停止或强制换 Action。未指定多轮范围时，只完成当前明确请求的方案并报告状态及后续机会。正确性、计时有效性和工程判定不变；它们与外部停止目标分别报告。修复是新 attempt，成本连续累计，不借改名扩大授权范围。

## 审阅与扩展

运行时校验身份、引用、必要字段、条件去向、补证据状态和前轮关联；自然语言理由是否合理由独立审阅判断。新 family/branch 不自动产生 Action；适用知识可先参与比较，最终采用仍需真实路由与当前实例兼容。

新增 Action 必须区分结构/合法性与性能假设，给出未测性能时可开展的分析或试验边界。不得默认把 profile 指标当硬前提，亦不得把真实依赖/精度条件降为 advisory。旧条件的变更写入版本化审查，不回填历史快照。经知识提案纳入的新 Action 必须显式增加新版本条件策略行；其旧前提和迁移去向为空，新增实施条件逐项给定义/证明要求，不把缺席当继承旧约束。不需要改解析器的 Action 枚举，也不由 family/branch 扩充自动登记新意图。

## 决策记录与校验入口

先生成当前 Context、检索、正文展开与 reasoning，再将选择记录写成任务内 JSON。不要修改旧记录补证据；新增事实形成新的 reasoning 和 decision。

| 字段 | 怎样填写 |
| --- | --- |
| `reasoning_ref` / `reasoning_hash` | 同一任务推理文件的字节 hash 与规范 JSON 内容 hash；两者不可混用。 |
| `routing_ref` / `condition_policy_ref` | 用 `bindings.routing_snapshot_ref(root, bindings.load_routing(root))` 和 `action_decision.condition_policy(root, graph)[0]` 获取冻结身份。不要抄另一个版本。 |
| `opportunities` | 每项连接本任务候选机制，记录分析项与完整域覆盖，缺少对应 Action 时记录意图缺口。正式方案成员仍绑定注册实例，比较对象可同属一个 Action。 |
| `schemes` | 共同目标、成员机会/实例、步骤与依赖、联合分析、整体预测、替代与理由。一个成员足够时直接使用；共享工作和资源不能重复计算。 |
| `evidence_requests` | 缺项、检查方法、不同结果对选择的影响。只有实施合法性缺项使用 `required_before_implementation=true`；已完成检查须绑定结果文件。 |
| `knowledge_use` | 注册知识正文的包内路径/hash、`lines:N-M`、适用条件和阅读前后具体判断。仅引用 frontmatter 或列路径不够。 |
| `selection` | 绑定 scheme_id，不能同时保留旧的单机会选择字段。`experiment` 是拟开展有依据的方案试验；`conditional_plan` 尚需补合法性条件或只做纸面分析；也可 `collect_evidence` / `stop`。均不是收益证明。 |
| `previous_feedback` | 所有后继必填：前轮 decision、当前父本与理由、前轮所选方案整体预测更新、新信息和继续同方案的理由。性能 `not_measured` 与静态预测是否获支持分开；有需要再按成员说明归因限制。 |

用包内模块的 `jsonio.file_hash` 生成文件引用，`jsonio.content_hash` 生成规范内容身份。`schemas/action-decision-v3.schema.json` 是新严格格式，旧 v2/v1 schema 不变。C1 的 `artifacts` 附上唯一该记录的任务内 path/hash；C1/C2/C3 使用 `aprof.handoff/v4`，方案/成员身份贯穿共同计划与实际选择，复用原 P/O 内部 router。

```bash
"$APROF_PACKAGE/tools/aprofctl" diagnosis verify-decision   --root "$APROF_PACKAGE" --task-root "$APROF_TASK"   --input "$APROF_TASK/decision-r1.json"
```

`validate_decision(..., implementation=True)` 及新图的交接链校验会检查实施条件和所选实例，性能 unknown 不因此阻断。已测有效反馈须引用可回放的统一计时结果及同一算子/父实现；无效或未测结果不能确认性能预测，也不抹掉有单独依据的静态分析。校验通过仍不证明自然语言判断正确；实际阅读与技术适用性需审阅。

当候选已经点名某个 API、数值替换或数据通路时，应在选择前展开对应的具体叶，确认语义、实际调用粒度、有效长度与临时资源。通用 branch 的介绍不能替代具体 API 的约束。包内已有答案的未知项先查正文；没有答案再保留精确缺口。比如更换逐元素选择实现，需要分别比较被替代的 Scalar 工作、新增的 Vector 调用、padding 和临时存储，不能把不同单位相减，也不能以笼统“数值语义 unknown”略过已知的不等价条件。此规则不要求固定必读列表，不因缺少性能计时否决来源支持的候选。
