# symptom.source.dynamic_shape_mismatch → problem.dynamic_shape_mismatch

## 关系与对象绑定

symptom.source.dynamic_shape_mismatch —supports→ problem.dynamic_shape_mismatch。

- target→target：同一task与parent实现，绑定同一target身份；同一算子多个shape/dtype/feature区间的dispatch及参数域
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.source.dynamic_shape_mismatch=true
- constraint.diagnosis.dynamic_shape_mismatch.source_scope_verified=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

该源码复合观察绑定同一算子多个shape/dtype/feature区间的dispatch及参数域，与机制链“一套核数、tile、buffer或workspace覆盖不同资源主导区间 → 小shape付出不必要固定成本，大shape欠并行或流量/容量不适配 → 不同区间出现不同退化，需要条件化dispatch而非固定最优值”相容，因此只形成待核验候选与profile预测。它不证明现象已在profile出现，也不是因果充分条件。

- 按相邻边界shape核验coverage、唯一分支和fallback
- 比较每区间机制，再决定是否需要新参数或方案，不能按shape数量造分支

## 例外与代价

- 现dispatch已经区分机制所需区间且退化是单一布局错误时不支持过度特化
- 样例key仅按dtype区分不能证明通用shape阈值
