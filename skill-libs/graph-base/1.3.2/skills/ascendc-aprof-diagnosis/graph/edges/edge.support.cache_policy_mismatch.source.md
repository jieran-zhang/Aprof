# symptom.source.cache_policy_mismatch → problem.cache_policy_mismatch

## 关系与对象绑定

symptom.source.cache_policy_mismatch —supports→ problem.cache_policy_mismatch。

- target→target：同一task与parent实现，绑定同一target身份；具有明确访问次数和复用距离的GlobalTensor及其L2策略
- stage→stage：同一task与parent实现，绑定同一stage身份；只允许对应阶段及其已注明的直接依赖窗口
- workload→workload：同一task与parent实现，绑定同一workload身份；shape/dtype/layout/feature及有效元素域一致
- implementation→implementation：同一task与parent实现，绑定同一implementation身份；当前host/tiling/kernel及编译artifact一致，不把C2变换后属性充当当前观测

## 联合条件与边界

- symptom.source.cache_policy_mismatch=true
- constraint.diagnosis.cache_policy_mismatch.source_scope_verified=true

原conditions字段逐值保留。历史空数组没有表达无条件因果或普适适用性；新增条件必须来自绑定scope的证据。

## 依据与判别

该源码复合观察绑定具有明确访问次数和复用距离的GlobalTensor及其L2策略，与机制链“一次性流量和待复用数据采用不合适的缓存策略或共享工作集超过有效L2 → 缓存填充/替换增加成本，或重复访问未命中 → 额外GM访问或缓存管理影响关键路径”相容，因此只形成待核验候选与profile预测。它不证明现象已在profile出现，也不是因果充分条件。

- 按访问对象而非算子整体命中率划分，比较同一访问模式下的策略
- 一次性输入先比较禁用/默认的成本，不假定启用必快

## 例外与代价

- 低命中只来自首次或一次性读取时，不证明策略错误
- PERSISTENT虽有枚举但该固定修订明确暂不支持，不能作为可执行动作
