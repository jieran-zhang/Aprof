# 循环控制与元数据开销

## 对象、阶段与适用域

- 热循环中重复读取的TilingData字段、mask、索引和分支
- host元数据定义
- kernel Init与主循环

旧scope=all保留作检索范围，机制成立仍须核对目标架构、dtype、shape和API支持。

## 机制链

- 循环不变字段或公共地址前缀在每轮重复加载/计算
- Scalar为同一信息反复执行解引用、乘除或分支
- 指令发射被控制工作占用而拖慢有效流水

## 预测、支持检查与反证

- 合法外提或局部缓存不变量可减少每轮Scalar指令；这是prediction
- 区分按任务变化、按tile变化与循环常量，不能全局缓存动态字段
- 将TilingData大结构拷贝与少量热点字段重复读取分别核算
- 编译器已折叠/外提或字段随loop变化时，源码重复不等于运行重复成本
- 增局部缓存导致寄存器压力上升时需比较spill

## 具体替代解释

- problem.scalar_control_hot_loop：重复控制与逐元素数据处理不同；检查：按PC定位mask/index/metadata或元素load算术
- problem.register_spill：外提变量可能延长生存期并诱发spill；检查：前后核对编译spill与热循环LoadStore

## 候选动作与成本

action.hoist_invariant_control：把已证明不变的控制、地址前缀或热点字段移到合适外层并缓存。

原硬前提：symptom.source.control_metadata_overhead=true；constraint.control_equivalence=true；constraint.semantic_equivalence=true；constraint.capacity=true。

- 延长变量生存期和寄存器占用
- 代码特化或主尾分离可能增大指令体积

## 限制与缺口

- 不改变host/kernel ABI
- 跨paged/non-paged或mask分支必须重新证明不变量
- 本轮无同任务profile、无case_support、无收益或发生频率声明；源码形态只支持待核验候选。
