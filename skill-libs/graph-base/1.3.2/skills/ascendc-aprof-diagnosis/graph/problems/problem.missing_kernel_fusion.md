# 跨 kernel 融合不足

## 对象、阶段与适用域

- 连续launch的生产者/消费者kernel及GM中间tensor
- host launch序列
- 生产kernel输出
- 后继kernel消费

旧scope=all保留作检索范围，机制成立仍须核对目标架构、dtype、shape和API支持。

## 机制链

- 可组合的相邻子操作用独立kernel和GM中间张量连接
- 每步重复launch与中间写读
- 短链或低算术强度时固定启动和中间流量可能主导

## 预测、支持检查与反证

- 合法融合可能减少launch及GM中间字节，但增大活跃峰值；这是prediction
- 比较整个链的统一端到端范围，不能只比较融合后单kernel
- 核算多消费者、归约边界、layout和同步拓扑
- 外部可见性、跨核全局归约或API限制要求边界时不能直接融合
- 长计算链启动占比小且融合损失并行时收益可能为负

## 具体替代解释

- problem.redundant_gm_round_trip：单kernel片上直通不消除launch，本项跨kernel融合涉及执行边界；检查：先确认launch数量和中间GM用途
- problem.onchip_capacity_pressure：融合可能放大同时存活输入/输出；检查：沿融合后执行顺序计算物理峰值

## 候选动作与成本

action.fuse_kernel_chain：把满足完整语义和执行契约的生产消费链组合，并让中间值在合法层级直通。

原硬前提：symptom.source.missing_kernel_fusion=true；constraint.fusion_boundary=true；constraint.semantic_equivalence=true；constraint.capacity=true。

- 更大片上/寄存器存活集与编译体积
- owner、同步、dispatch或workspace结构变化需C2重新批准

## 限制与缺口

- Vector寄存器链融合文档只支持存活分析原则，跨kernel可行性须单独证明
- 本轮没有融合实测案例，不声称通用收益
- 本轮无同任务profile、无case_support、无收益或发生频率声明；源码形态只支持待核验候选。
