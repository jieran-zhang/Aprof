# 广播复用与容量分块

## 适用 shape、合轴与索引合同

输入为连续 ND 张量，按算子明确的右对齐广播规则产生输出。先在左侧补 1；对每一轴，所有非 1 输入维度必须相同，禁止以 max(dim) 掩盖不兼容 shape。对于零长度轴，直接遵循框架的空张量广播规则。一般 stride view 先保留真实 stride，不能套用本条仅根据连续 shape 累乘得到的 stride。

每轴记录“哪些输入在该轴广播”的完整位图，相邻轴只有位图相同且真实存储可合并时才能合轴。输入维度为 1 而输出大于 1 的轴设逻辑 stride=0；其他轴保留连续 stride。输出坐标 o 对输入 j 的元素偏移为 `offset_j(o)=Σ_i o_i*stride_ji`。这个零 stride 只表达读复用，绝不用于输出写地址。

例如 Add `[4,3,8] + [1,3,8]` 可压成 `[4,24]+[1,24]`；Mul `[2,1,4] × [2,3,1]` 的相邻广播位图不同，保留三轴。若合轴后只有一维且某输入仅一个元素，则它是标量输入：先比较 Adds/Muls 等 TensorScalar 路径，不必为一个标量分配完整展开区。

## 输出所有权、复用域与分核

从最内轴向外增加 tile，令 k 为切分轴，内轴积 I=∏_{i>k} D_i；每个 tile 覆盖固定外轴坐标和 k 轴上至多 u 个值，输出元素 E=u*I。外层逻辑任务数 `T=(∏_{i<k}D_i)*ceil(D_k/u)`。按均衡 q/r 将这 T 个 tile 唯一分给核，tile 中再按必要的小片计算。尾任务使用 `u_valid=min(u,D_k-u*tile_k)`。

每个输出元素只有一个核写，无归约、无需跨核同步。广播源为只读，可以被不同核重复读；“装入一次”只保证本核声明的复用域内，不表示全芯片只读一次。扩大复用域要说明同一源块跨多少输出 tile 驻留、何时失效、是否增加片上资源或减少独立任务。若同一源跨核共享需要另一个协议，本模板不默认引入。

输入 tile 的起点用当前坐标与该输入 stride 计算；若切分轴是广播轴，源偏移不随 tile_k 增长。若切分轴不广播，源起点随 `tile_k*u*stride_jk` 前移。广播轴被切片本身可以合法，但传给 Broadcast 的必须是当前 tile 的 dstShape 和对应的 srcShape，不能仍用全张量 shape 或把广播源也按输出长度前移。

## 三种实现路径与平台边界

| 路径 | 数据流、适用条件 | 主要成本与边界 |
| --- | --- | --- |
| 标量/索引复用 | 标量 Adds/Muls；或沿非广播连续内轴迭代 | 省完整展开区；需保持原操作的参数顺序、舍入与除法语义 |
| UB 广播 | GM 搬入独立源块，在 UB 展开到当前输出 tile，再计算 | 保留源区、展开区、API 临时区；适合在核内多次使用小源块 |
| NDDMA 搬入广播 | 950/DAV_3510 的 GM→UB 多维搬运，广播轴源 stride=0 | 到 UB 时已经展开；不能用于 UB 内中间结果；最多五轴由一次描述符覆盖，更多轴需外层循环 |

在 910C/A3 目标，先核对实际编译架构与 SDK；不能启用仅在 950PR/950DT 支持的动态 rank 1~9 Broadcast、NDDMA。当前 asc-devkit 的静态 Broadcast 只支持 dim=1/2、axis=0/1，ND、src/dst 不重叠；A2/A3 支持 int8/uint8/half/float。axis=0 的实际 srcShape[1] 对应字节需满足 32B 约束；把 UB 搬入长度向上补齐，不等于源 shape 自动满足该约束。官方 API 只对 Atlas 推理 AI Core 另列 axis=1 的 srcShape[0] 对齐限制，不能把该条泛化到 A3；cannbot 的概括与这里有差异，以固定 API 文档和当前编译验证为准。

950 动态接口 rank∈[1,9]、srcInnerPad=false，仍需合法地址、容量、形状和不重叠证明；“无静态 shape 对齐限制”不等于零临时空间。NDDMA 的描述符 stride 单位、轴顺序、计数字段范围按所选重载核验，逻辑元素 stride 不应未经换算直接写入任意 DMA 字段。

来源给出按 dcache、dtype、尾轴长度选 NDDMA/UB BRC 的经验决策链；在这里仅作为候选方向，未有相同目标的性能依据时不固化成阈值或必然排序。

## 字节容量、读流量与选择公式

设 E 为输出 tile 的元素数，U_j 为输入 j 在该 tile 中实际访问的不同元素数，s_j/s_o 为输入/输出字节，d_j 为实际 buffer 份数，A_a 为按 a 字节对齐。

UB 广播：
`B_UB = Σ普通输入 d_j*A_a(E*s_j) + Σ广播输入[d_src,j*A_a(U_j*s_j)+d_exp,j*A_a(E*s_j)] + d_o*A_a(E*s_o) + B_compute + T_broadcast ≤ B_available`。

NDDMA 广播通常省掉独立未展开源区和 UB Broadcast 临时区，但仍保留完整展开输入 E*s_j；额外中间计算或 SDK 内部分配不能漏算。若某广播源跨多 tile 驻留，按驻留区额外计入，并明确它是否与下一 tile 的展开区同时存活。

无缓存假设下，UB 显式复用每个 tile 读入的有效输入字节为 `Σ_j U_j*s_j`，写出 E*s_o；与按输出索引逐次读取相比，源数据量的理想减少是 `Σ_j(E-U_j)*s_j`。展开同时引入 UB 写/读与向量搬运成本，NDDMA 也可能重复发出源读，实际缓存命中与总耗时需测量。成本比较应同时列 `GM字节、UB展开字节、API调用数、task数`，不能仅凭节省一次 API 宣称收益。

取 u 时先满足所有输入的真实源 tile、展开区和临时区容量，再考虑 T 是否足够并行。增大 tile 有利于摊销索引/调用并复用源，减小 tile 可增加独立任务，两者按同一计时协议比较。所有容量用字节；上游 128B/256B、8KB 或“核数一半”的调整是来源启发式，不能代替合法 API 约束或当前硬件测量。

## 可执行索引与任务伪代码

```python
# 已完成合法补维/合轴，D 是输出维度，Sj 是逻辑元素 stride。
T = product(D[:k]) * ceil_div(D[k], u)
for t in balanced_owned_tasks(T, core_id, core_count):
    outer, tile_k = divmod(t, ceil_div(D[k], u))
    coord = unravel(outer, D[:k]) + [tile_k*u]
    uv = min(u, D[k]-coord[k])
    dst_shape = [uv] + D[k+1:]
    args = []
    for j in inputs:
        off = sum(coord[i]*Sj[j][i] for i in range(k+1))
        src_shape = [1 if broadcast[j][i] else dst_shape[i-k]
                     for i in range(k, len(D))]
        src = load_distinct_source(j, off, src_shape)
        args.append(expand_or_index(src, src_shape, dst_shape))
    y = frozen_elementwise(args)
    store_owned_output(coord, dst_shape, y)  # 仅有效输出坐标
```

## 有界 Ascend C 片段

下面是 A3/950 均可候选的 FP32 静态 axis=0 小片段，前提为实际 srcShape={1,8}、dstShape={m,8}、m>0，源与目标不重叠，容量足够，src 已通过队列完成搬入；sharedTmp 为查询所得大小的 LocalTensor<uint8_t>。8*sizeof(float)=32B 满足该特定源的接口约束，8 不是通用 tile 推荐值。

```cpp
uint32_t srcShape[2] = {1, 8};
uint32_t dstShape[2] = {m, 8};
AscendC::Broadcast<float, 2, 0>(expanded, src, dstShape, srcShape, sharedTmp);
AscendC::Add(out, x, expanded, m * 8);
```

若是 950 上 `[2,1,4]→[2,3,4]` 的 UB 内中间结果，可使用来源动态接口；不能在 A3 kernel 中无条件实例化：

```cpp
// 950/DAV_3510 专用编译分支；张量均为 LocalTensor<float>。
uint32_t dstShape[3] = {2, 3, 4};
uint32_t srcShape[3] = {2, 1, 4};
AscendC::BroadcastTiling brTiling;
AscendC::GetBroadcastTilingInfo<float>(3, dstShape, srcShape, false, brTiling);
AscendC::Broadcast<float>(expanded, src, dstShape, srcShape, &brTiling);
```

上述片段只展示广播与计算；输入/输出队列、跨流水同步和有效长度搬出须由 C3 工程补齐。若 API、不重叠、dtype 或容量依据缺失，采用已验证的按轴迭代/索引广播基线，不手写依赖未验证 dummy 填充值的快捷复制。

## 验证与来源范围

覆盖前补维、标量、交替广播轴、仅尾轴广播、仅非尾轴广播、维度 1/0、合轴前后索引等价、切分轴广播和非广播、最末 u_valid、每核最后一个 task。对比所有输出坐标的输入 offset，验证每个输出恰写一次，并检查最大工作集与额外分配。来源事实是维度塌缩、零 stride、UB/NDDMA 路径与固定 API 限制；字节账、合法切片说明和候选比较为工程推导。来源审读完成，未在 NPU 上验证性能。

## 按复用域比较三种骨架，而非一见广播就扩展张量

固定 RoPE 来源的 interleaved host 按 sequence/batch/head 和实际 UB、dtype 临时区选择切分；对应 kernel 每次搬入一段 headDim 的 cos/sin，再向当前 head 片广播。这直接说明“源块大小”和“使用该源块的输出大小”不同，也说明更大复用域受容量与任务数约束。RoPE 是组合依据，不是任意广播算子的 API 或数值合同。

令一个复用组输出为 `[R,H]`，源 B 为 `[1,H]`，另一个输入 A 为 `[R,H]`；元素宽分别 sB/sA/sY 字节。比较下列候选时，保持同一数值函数与输出所有权：

| 骨架 | 明确减少的工作 | 新增/保留代价及适用条件 |
| --- | --- | --- |
| 每元素通用零 stride 解码 | 无；覆盖任意合法位图，是比较基准 | 每输出 rank 级解码，逻辑源取数 RH 次；缓存命中未知，不能声称实际读取 RHsB 字节 DRAM |
| 每行/连续段解码＋局部广播 | 把解码从 RH 次降至每行或每段一次；在段内使用固定步长 | R 次源段装载，段尾和 Broadcast/标量指令限制；H 短时调用/同步仍可能多 |
| 同 owner 保留 B，连续处理 r 行 | 每组 B 逻辑 GM→UB 读取由 rH 降至 H 元素；不改变 A/Y 的必要字节 | B 驻留期跨 r 行；若展开 B 为 rHa 个元素会新增本地写入及存储；任务数可能减少，需足够独立组 |

第三种不必物化完整广播输入。可保留 B[H]，依次计算 A[row,H]；或根据合法 API 同时计算 r 行。按行实现的保守 UB 为 `A(Ha*sB)+dA*A(Ha*sA)+dY*A(Ha*sY)+Tmp+F`，A(z) 是字节对齐；r 行并行实现应把对应 A/Y 与展开区长度乘 r，不能仍套用逐行预算。B 若与其他队列共享物理区，最后一个消费完成前不能覆盖。

真实源重读次数由每个核、每个外层域与每个 tile 是否重新搬入决定，不能把跨核只读共享当片上共享。源码只证明同一 owner 内可复用时，跨核缓存命中和带宽效果仍是待测预测。扩大 r 导致核心不足时，比较保留较小 r、每核重读 B 的方案；允许有依据地选择重读。

短内轴 H 可将若干行组合，但只有所有输入广播位图一致的相邻轴才能合轴。`A=[P,1,H]、B=[P,R,1]` 的两类广播轴不同，不能错误合并成连续 RH 源。每行边界、部分尾行和输出物理搬出边界都应归同一 owner 或采用已经证明的非重叠写法。

**影响选择的结论**：记录保留源块、展开值、派生中间量三者的对象/生命周期；连续段处理未解决的昂贵函数、其他 dtype 和不规则 stride 作为残余范围。来源知识足以提出条件方案，不要求先测出 bandwidth；但 API、别名、容量与精度未知不能用性能假设代替。若现有 Action 只承载输入值驻留，不能用它隐含授权重排派生几何计算。
