# AR/ARA FullLoad 与行所有权

## 适用域、形状标准化与合同

连续 ND 输入经归约轴规范化后，将相邻且物理连续的保留轴合为 A，相邻归约轴合为 R。负轴先规范化，重复/越界轴按算子合同处理；size=1 维度的消除不能改变 keepDims 或输出 view。能够表示为 `[A1,R,A0]` 时，AR 是 A0=1，ARA 是 A0>1。AR 同一行 R 个元素连续；ARA 某一输出位置的 R 个值相隔 A0，但每个 r 的 A0 连续片段可向量搬运。

FullLoad 的条件是“一个输出组需要的完整 R 数据、所有计算中间区、队列和 API 临时区同时容纳”，不是 R 小于某个固定数。AR 至少可装一整行，ARA 至少可装 `[R,V]` 的有效 A0 小片及其对齐存储。若合轴后仍为 ARAR/ARARA，不得把所有 A/R 各自相乘后当连续 AR；用明确嵌套循环逐个输出组归约，或转本族 split/通用基线处理真实 stride。

先冻结操作的单位元、变换、累加 dtype、归约树及允许误差、均值除数、variance correction、arg tie/NaN、输出 dtype。普通 sum 的相加、norm 的先变换后还原、softmax 的行统计不可混用；多步统计在本模板内复用全载输入，数值状态按 statistics 条目。

## 输出所有权与任务映射

AR 每个任务拥有 h 个完整输出行，任务数 `T_AR=ceil(A1/h)`。ARA 每个任务拥有一个 a1 与 A0 上一段 V 个输出，任务数 `T_ARA=A1*ceil(A0/V)`；任务 t 解码为 `a1=t//ceil(A0/V)`、`a0_begin=(t%ceil(A0/V))*V`。每个核可执行多个独立任务，按 q/r 均衡分派；每个输出仅由所属任务写一次，归约只在核内，无跨核同步和 workspace partial。

ARA 的 GM 起点为 `(a1*R+r)*A0+a0_begin`。从第 r 行搬 V_valid 个元素，源行间跳过 `A0-V_valid` 个元素；UB 每行用 V_align 的存储步长。这里 `[R,V]` 在 GM 中是有行间隙的规则二维块，只有 V=A0 时整块连续，不能把一般 A0 切片当 R*V 连续一维搬入。

## 全载字节方程与参数求解

令 A_a(x)=ceil(x/a)*a；s_in/s_acc/s_out 为元素字节，d_in/d_out 为实际队列 buffer 份数；T_api(shape,dtype,pattern,reuse) 为当前 API 查询的临时字节。

AR 输入行存储字节 `L_in=A_a(R*s_in)`，若转 FP32 则 `L_acc=A_a(R*s_acc)`。一个 h 行批次的保守分配账为：

`B_AR=d_in*h*L_in + K_cast*h*L_acc + d_out*A_a(h*s_out) + B_state(h) + T_api + B_other ≤ B_available`。

ARA 输入每行 `L_in=A_a(V_valid*s_in)`，计算每行 `L_acc=A_a(V_valid*s_acc)`：

`B_ARA=d_in*R*L_in + K_cast*R*L_acc + d_out*A_a(V_valid*s_out) + B_state(V_align) + T_api + B_other ≤ B_available`。

K_cast 是独立计算区份数；B_state 包含多个输出、均值/方差、索引、mask 等全部状态。半精度输入配 FP32 累加会改变行 stride 与容量，不能仍用输入的 R_align/V_align 访问 FP32 计算区。对齐单位按各区的 dtype 与 API 分别求出。

枚举合法 h、V、队列深度和 API 临时区配置，逐项调用容量判定；T_api 可随 shape 改变，不能先用单个常数求 R_max 再忽略变化。若实际分配账超容，即使一行“理论输入字节”可放下也不是 FullLoad。来源 4KB tmp、固定 64 列、repeat≤255 属特定示例/API；当前高级 API 不应按这些数字设通用 R 上限。

单次 sum/min/max 全载的必要流量为 `A1*R*A0*s_in + A1*A0*s_out`。若全载输入被保留供 mean→centered variance→normalize 重复使用，可减少再次从 GM 读取输入；增加的 UB 中间区仍需入账。即使 T<C_available，也先比较减 h/V 增加独立输出任务，只有进一步拆 R 有收益时才比较 split；不能以核利用率低直接判全载错误。

## 有效长度与对齐长度的分工

| 使用位置 | 应使用的长度 |
| --- | --- |
| AR 搬入 blockLen、基础 ReduceSum count | R_valid，blockLen 再乘输入字节 |
| AR UB 行起点与分配 | 对应 dtype 的 R_align |
| ARA 搬入 blockLen、搬出结果 | V_valid 乘对应 dtype 字节 |
| ARA Pattern::Reduce::RA 的物理内轴 | V_align，存储确实按该宽度排列 |
| ARA 数学归约行数 | 完整 R_valid |

RA padding 列互不影响有效输出列，最终只写 V_valid；若换成 AR 归约则 padding 会进入同一结果，必须使用有效 count 或正确单位元。不能将任意未初始化的 pad 视为数学零。

## 可执行伪代码与关键 API

```python
for t in owned_output_tasks:
    if A0 == 1:
        rows = decode_ar_rows(t, h)
        x = load_rows(rows, R, storage_stride=R_align)
        for row in rows:
            state = reduce_valid(x[row], R, frozen_op_and_order)
            write_owned(row, finalize(state))
    else:
        a1, a0_begin, Vv = decode_ara(t, V)
        x = load_strided_rows(a1, a0_begin, R, Vv, storage_stride=V_align)
        states = reduce_R_for_each_valid_A0_lane(x, R, Vv)
        write_owned_vector(a1, a0_begin, finalize(states), Vv)
```

AR 的 FP32 sum 主片段使用固定 asc-devkit **基础** ReduceSum：xFp32 是已就绪、每行 rAlign 个 FP32 的 LocalTensor，result/tmpFloat 与输入满足该 API 的别名及空间要求；rValid>0 且不超过 int32 范围：

```cpp
// 包含 kernel_operator.h；tmpFloat 是 LocalTensor<float>。
AscendC::ReduceSum<float>(result, xFp32[row * rAlign], tmpFloat,
                         static_cast<int32_t>(rValid));
```

这个接口的第四个实参是 count，不应照抄上游草图给 sum 添加第五个 false。ReduceMax 的 calIndex 与本函数不同。ARA 使用 **高级** Pattern 接口，输入已经装成 `[rValid,vAlign]`，tmpByte 为查询后分配的 LocalTensor<uint8_t>，dst/src/tmp 互不重叠：

```cpp
// 高级 ReduceSum 的依赖头及库按工程配置；false 是模板 isReuseSource。
uint32_t shape[2] = {rValid, vAlign};
AscendC::ReduceSum<float, AscendC::Pattern::Reduce::RA, false>(
    result, xFp32, tmpByte, shape, true); // true 是 srcInnerPad
```

两个布尔位置含义不同。A3/A2 高级 ReduceSum 仅支持 float、srcInnerPad=true；950 支持的数据类型更宽，srcInnerPad 参数为预留。需要复用原输入执行第二步统计时保持 isReuseSource=false；true 允许内部破坏输入，容量与数值流水需整体重算。

## 替代方案、平台与验证

全载失败时 AR 切 R 为 ColSplit，ARA 切 R 为 RowSplit；若只是 A0 很大，先减 V，避免无谓跨核合并。同一输出组多步骤能保留原输入时比较 TwoPass/Welford，而不凭名称选择。索引变体额外保留 value/index/mask；ARA 的普通 Pattern::RA 无索引输出，不能仅改输出 dtype 获得 argmax。

来源说明 A2/A3 与 950 的 API 支持范围不同；910C/A3 实机需核实 SoC 对应编译目标，不能带入 950 寄存器实现或 NDDMA。验证 R=1、非对齐 R、V=1/V尾片、A1 多核尾任务、FullLoad 容量边界、不同输入/累加 dtype、keepDims、空归约轴和特殊值。R=0 的单位元/报错由算子合同单独处理，不把零 count API 当正确归约。

来源事实是 AR/ARA 路径、行所有权、有效/对齐长度区别和 API 约束；字节方程、任务映射及选择顺序为工程推导。仅来源审读，无 NPU 性能验证；C2 固定所有权和数值合同，C3 只能在已证明的容量/语义域内调 tile/API。
