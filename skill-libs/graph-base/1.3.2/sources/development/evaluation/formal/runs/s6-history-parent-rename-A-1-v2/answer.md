## 结论与证据边界

两个子例选择相同方案：

> **以完整覆盖的原始实现为父本，在原有每核输出区间内按固定 `(batch,channel)` 的连续空间段组织循环；段首解码索引，段内递增 grid 地址，保持每个输出的采样计算和读写次序不变。**  
> 用一个 `action.hoist_invariant_control` 实例承载，不夹带坐标、邻域或权重的跨通道预计算。

这是有静态依据的纸面试验选择，不是收益结论。最有竞争力的已注册替代是“同 owner 跨通道保留原始 grid 空间片”；另将“派生几何跨通道复用”明确登记为当前 Action 意图缺口。

本轮只完成分析和 C2/C3 交接说明：**没有调用工具，没有生成或修改文件，没有编译、运行、验证正确性或测量性能。** 以下身份均使用题目给出的源码标识；不虚构源码 hash、模板 hash、router 执行结果或机器契约校验。

# 子例 a：L0 / L1 / L2，`GridSampler3DScalar`

## 1. 当前实际路径、数学与数据依赖

### 实际执行路径

当前指定为 float，因此入口 `.asc:194–196` 选择：

```text
grid_sampler_3d_kernel
  → GridSampler3DScalar<float>
  → 每个 linear 调用 GridSampler3DOne<float>
  → GRID_NEAREST 分支
```

不执行 `GridSampler3DHalf`，所以其中的 UB 分配、Cast、DataCopyPad 和三处屏障不是当前 workload 的执行成本。

令：

- \(V=DHW=4096\)；
- \(S=256\)；
- \(E=NCS=2048\)。

原始输出索引为：

\[
p=linear\bmod S,\quad nc=\lfloor linear/S\rfloor,\quad
c=nc\bmod C,\quad n=\lfloor nc/C\rfloor .
\]

grid 地址为 `3*(n*S+p)`，不依赖通道；输入基址为 `(n*C+c)*V`，依赖通道。

当前 nearest 数学为：

\[
Y[n,c,p]=
\begin{cases}
X[n,c,z_n,y_n,x_n],&三轴索引合法\\
0,&否则
\end{cases}
\]

其中每轴严格沿用源码的 `GridUnnormalize → GridApplyPadding → GridRoundEven`。zeros padding 不改变坐标，但 `GridRead` 必须先判界，不能先越界读取再乘零。

### 当前输入的具体结果

`alignCorners=false`、尺寸 16、grid 为 0：

\[
((0+1)\times16-1)\times0.5=7.5.
\]

`GridRoundEven(7.5)=8`，因此每个输出读：

\[
X[c\times4096+2184],\qquad 2184=(8\times16+8)\times16+8.
\]

输入为 1，故所有 2048 个有效输出应为 1。**这只能用于解释原始记录，不能据此把 kernel 改成填 1，也不能省去运行时输入读取。**

### 数据与执行依赖

- 不同输出没有数学依赖，无跨核归约。
- grid 在通道轴上共享；X 的对应值仍随通道变化。
- float 当前路径使用 GM 标量读写，不能把每条 C++ 标量访问算成一次 MTE DMA。
- 原始分核边界按 16 个 float，即 64B 对齐。各核拥有不相交的线性输出区间；完整覆盖还要求启动与 `t.blockNum` 一致。可见文件给出了 tiling 计算，但没有完整 launch 调用端。
- 非有限 grid 经源码浮点到整数转换的完整目标行为没有在输入材料中定义。本方案不新增 NaN 归零、饱和或向量转换规则，保留原数值表达式；不能据此宣称原实现的所有非有限输入语义已经证明。

## 4. 方案比较与选择

### 主方案 A：固定通道空间段的索引解码与地址递推

保留每核 `[begin,end)`，将其分成不跨越 `nc` 的空间段。每段：

1. 在段首计算 `p,nc,c,n`；
2. 计算本段终点、`xBase` 和首个 `gridBase`；
3. 逐输出执行原采样计算；
4. `gridBase` 每点增加 3，输出索引增加 1。

不改变各输出的处理顺序，不复用派生坐标，不把 nearest 改为其它舍入，也不改三线性表达式。

设非空 owner 数为 \(M\)，总空间段数为 \(R\)。当前输出有 8 个通道平面，每平面 256 点：

\[
R=8+\#\{\text{非空核间边界，且该边界不落在256元素边界上}\}.
\]

因此：

\[
8\le R\le\min(128,8+M-1).
\]

四项索引除模的源码工作由：

\[
8192\longrightarrow4R.
\]

例如只作范围推导，\(R=8\) 时为 32 项，\(R=128\) 时为 512 项；实际值取决于传入 `cores` 和原 tiling，不能填一个假定核数。

**减少：**

- 每输出重复的 `linear→p,nc,c,n` 解码；
- 每输出重复构造的通道输入基址和 grid 公共地址前缀；
- `inputSpatial` 可在非空 owner 初始化时计算一次。

**保留：**

- 2048 次输出计算与写回；
- 6144 次 grid 标量读取；
- 全部坐标浮点计算、round-even、判界和 X 读取；
- 原分核、布局、所有权、launch 数和 workspace。

**新增代价：**

- \(R\) 次段边界计算；
- 段内地址递增与双层循环控制；
- 少量更长存活的整数标量；
- 为满足用户的 fallback 范围，每核入口增加一次真实元数据条件判断；
- 编译器可能原已完成部分强度削弱，新增结构也可能增加代码体积或 spill。

选择它并非因为“容易等价”，而是当前源码每输出存在四项除模和基址重建，本方案直接减少这一整类逐元素工作，同时不增加输入物化、局部数据访存、异步同步或任务收缩。收益是否兑现仍取决于编译结果和实际关键路径。

### 最有竞争力的已注册替代 B：同 owner 跨通道保留原始 grid 片

使用 `action.reuse_input_tiles`，对象必须是**原始 grid 三元组**，不是生成的坐标/索引。

一个具体可比较参数是 `Ct=8, St=16`：

- 每个 task 拥有 `[n,全部8通道,p0:p0+16)`；
- 首次读入 16 个 grid 三元组；
- 每个通道仍按原公式重新计算坐标、舍入及判界；
- 通道内输出空间点连续，输出地址保持 NCDHW。

当前有 16 个这样的 task。原始 grid 片驻留数据为：

\[
AlignUp(3St\times4,32)=192\text{B}.
\]

若配一份 `St` 个 float 的输出暂存，再加 64B；其余 API、同步及框架资源另计。不能把 256B 当作已经核验的目标总 UB 需求。

| 工作 | 原始 | 替代 B |
|---|---:|---:|
| grid 有效 GM 读 | 24576B | 3072B |
| grid 计算消费 | 6144 float | 仍为 6144 float，本地读取 |
| 坐标变换/round-even | 各 6144 次 | 不变 |
| X 读/输出写 | 各 8192B | 不变 |
| 有效逻辑 GM 总量 | 40960B | 19456B |

**全部新增或改变的工作与代价：**

- 增加 16 个 grid 片的搬入和本地消费依赖；
- grid 保留到第 8 个通道的最后消费者完成；
- 原来线性 owner 改成跨通道矩形 owner，必须重做 tiling 和 launch 映射；
- 最多只暴露 16 个 task；当原有效 owner 多于 16 时可能降低并行度；
- 按通道切换输入基址，相邻通道相距 4096 float；输出每通道每片为 64B；
- 若仅标量写出，仍有 2048 次 GM 输出赋值；若再批量写回，须计 UB 写、DMA 与同步，不能算免费配套；
- 需要证明输入/输出别名不会使原算法本该观察的新 grid 版本被旧驻留值替代。当前材料没有给完整别名合同；
- 实际可用 UB、目标 SDK 重载及 Scalar 消费本地数据的完成边仍需绑定。

本轮没有选择 B：它能明确减少重复 GM 请求，但不减少主要坐标与舍入计算，且引入本地读、任务收缩和新的生命周期。若后续发现原编译器已消除主方案的大部分索引开销，或者原有效 owner 不超过 16 且 grid 标量读代价明显，B 的优先级会提高。**未测收益不是排除 B 的理由；上述联合代价才是当前选择依据。**

### 算术机会更强、但有意图缺口的替代 C：派生几何跨通道复用

生成一次 nearest 的空间索引和有效标记，再给 8 个通道消费，可将几何生成次数：

\[
NCS=2048\longrightarrow NS=256.
\]

三轴坐标变换及 round-even 各由 6144 次降至 768 次。X 仍依赖通道，逻辑读取仍为 8192B，不能因几何共享而删掉它。

例如采用每点两个 `uint64_t` 保存空间偏移和有效标记，记录为 16B：

- `St=16` 时记录区为 256B；
- 全部 256 点记录写入为 4096B；
- 8 通道消费记录为 32768B 本地读；
- 另有输出区、生成临时状态、记录读写及任务收缩成本。

这是实质性的数学数据组织变化。输入的 `coordinate_neighborhood` 正文明确区分：

- 原始输入驻留；
- 派生几何复用；
- 控制/地址外提。

**现有 `reuse_input_tiles` 和 `hoist_invariant_control` 均不能自动承载 C。** 当前没有提供覆盖该独立意图的注册 Action，因此保留任务内提案，不伪装成主方案的内部实现。用户的一轮纸面授权不自动完成 Action 注册或放宽语义边界。

### 其它明显机会的处置

- **批量输出写回：**注册意图可用 `action.batch_writeback`。保持 owner 时，容量 \(T\) 的 float 输出槽需 `AlignUp(4T,32)`B，DMA 数为 \(\sum_c\lceil L_c/T\rceil\)。它把 2048 次 GM 标量赋值变为 2048 次 UB 写加若干 DMA，并增加生产完成、搬出及复用等待；当前并无 2048 次“小 DMA”可供直接合并。暂不与主方案组合，避免遗漏其新增成本。
- **全量 X 搬入或布局转换：**X 为 131072B，而当前 nearest 有效 X 请求仅 8192B；不能因输出空间连续就假设源访问连续或局部窗口成立。
- **整体向量化：**可能覆盖更多工作，但输入材料没有闭合当前坐标转整数、round-even、异常值与目标 Gather 的完整等价链。不能从 Vector feature 或 float Cast 的名字补出这些条件。
- **同步、Cube、跨 kernel 融合：**当前 float 路径没有相应阶段，不能把 half 或教学样例中的成本移植过来。

## 6. 统一 C2 计划

### 采用正文与实际影响

采用 `planning.indexing.coordinate_neighborhood` 的**“输出连续空间块、独立生成几何”骨架**，绑定：

- G：源码三轴 `GridUnnormalize`；
- B：源码 padding；
- H：当前 nearest 的三轴 `GridRoundEven`；
- F：判界后读取合法 X，否则返回 0；
- 输入 stride：NCDHW；
- 输出 stride：`(n*C+c)*S+p`。

没有把该条说成上游 GridSampler 移植。没有完整采用 `planning.elementwise.continuous`：输出虽然连续，X 是数据相关取数，并非同下标逐元素输入；只参考其唯一写者和有效区间核验原则。

### 共同所有权、布局与资源

| 项目 | 冻结内容 |
|---|---|
| owner | 保持原核 `[b*blockLength,min((b+1)*blockLength,E))` |
| 段 | owner 内按 256 点通道平面裁切，不跨 owner |
| 输出 | NCDHW，不相交且完整覆盖；全部步长为 1 |
| 输入通路 | 保持 GM 标量读取，不新增 Gather、DMA 或转置 |
| reduction | 无 |
| workspace | 新增 0B；kernel 没有新增 workspace 参数 |
| 片上显式分配 | 新增 UB/L1/L0 均为 0B |
| 私有状态 | 常数个整数标量，无按 S/St 分配的数组；实际寄存器/栈待编译 |
| 同步 | 不新增异步阶段或事件；保持原单输出内部依赖和核内顺序 |
| 核数 | 沿用原 tiling；不假定设备实际核数 |
| 实现自由度 | 可整理纯整数局部变量；不得改数值表达式、owner、通路或几何生命周期 |

### 分派与 KEEP

仅在题目列出的完整元数据条件成立时进入新循环；`outD/outH/outW` 只要符合原 host 且乘积为 256，仍按既有展平语义处理。其它形状、模式、padding、alignCorners、FP16 路径均进入原通用 fallback。

使用原 entry 内的元数据条件，不新增 Tiling Key，不修改 tiling 结构。新增判断是限定试验覆盖的成本，不宣称分派本身减少计算。

没有输入一份可引用的完整有效旧计划，因此不能伪填 `P_KEEP`。本次 C2 是：

1. 提取已有分核和数据通路；
2. 确认 owner 不变；
3. 授权段内地址递推和指定域的接线。

若按材料要求编码，应说明“建立/提取已有计划”，不能统计成已经完成并行优化。O 有真实拟议变换，故不是 `P_KEEP + O_KEEP` 的 NOOP。

## 7. C3 准确实施步骤与 O 正文影响

以下是交接步骤，不是已实施 patch。

1. **冻结父本身份。**从 L0 建候选；若使用 L2 内容，仍分别保留分析父本和实际实现身份。不得从 L1 继承 `+=2`。
2. **接入互斥元数据条件。**当前域调用新循环，其余路径调用完整原 fallback；不改变 FP16 分支。
3. **先处理空 owner。**`begin>=end` 时不解码，不产生无效地址。
4. **构造段。**对当前 `linear`：
   - 原式解码 `p,nc,c,n`；
   - `len=min(end-linear,S-p)`；
   - 计算 `xBase` 和首个 `gridBase`。
5. **段内逐点执行。**
   - 按原顺序读三项 grid；
   - 调用原浮点变换、舍入和 `GridRead`；
   - 原 float 结果直接写当前输出；
   - 下一点 grid 元素偏移加 3，输出偏移加 1；
   - 不预取无效下一点，不用同一输出覆盖多点。
6. **段末推进。**完成全部 `len` 个输出后再构造下一段。宽整数计算须证明范围；不得把地址运算窄化到 32 位。
7. **保持 fallback 原数值代码。**三线性仍是源码 k=0…7 顺序及原乘法结合，不预合并权重、不使用 FMA 替换或重结合。
8. **未来获执行授权时**再审查、构建、完整 oracle、运行检查和同窗口计时；源码变化后不得复用旧候选正确性。

实际采用的 O 方法是 `implementation.scalar-control.hot_loop_address`：它要求保持任务序列、原有效域与整数溢出条件，因此本方案选择“段首解码＋段内递增”，而非重排通道或生成共享几何表。

`tilingdata_access` 正文使本方案**不做整结构体本地复制，也不把已存在的 GM 指针读取再算一次优化**。`precision-boundaries.numeric/bounds` 使其保留原数值链、有效访问范围及宽整数地址检查。`buffer-lifetime.reuse` 关于派生值与原输入的区别，使替代 C 留作提案，而没有塞入当前 Action。

## 2. 主方案、替代、覆盖及成本

本轮以 **Pine** 为分析父本，保留 Oak 的独立 identity，不以表面最短记录选 Oak，不以 Fir 为父本。

选择同一个完整方案：`RunIndexed` 的每核输出区间内，按固定通道的连续空间段解码并递增地址。由于事实没有改变，成本不是“近似相同”，而是上述模型的**相同数值**：

- 四项除模：8192 项 → \(4R\) 项；
- \(8\le R\le\min(128,8+M-1)\)；
- grid/X/输出有效逻辑量仍为 24576/8192/8192B；
- 几何、舍入和判界不变；
- 新增 0B workspace、0B 显式片上缓冲；
- 新增段控制、入口条件及常数个私有标量。

最有竞争力的注册替代仍是原始 grid 驻留：

- `Ct=8,St=16`，16 个 task；
- grid GM 读取 24576B → 3072B；
- GM 有效逻辑总量 40960B → 19456B；
- grid 驻留数据区 192B；如增加一份输出暂存，再加 64B；
- 保留全部坐标和舍入计算；
- 增加本地读取、生命周期与任务收缩代价，别名/API/容量条件不因改名而消失。

派生几何复用仍可把几何生成 2048 → 256 次，但依旧具有 16B/点记录读写、跨通道 owner 和生命周期代价，且仍是注册意图缺口。批量写回、全量搬入 X 和整体向量化的竞争关系也不变。

## 3. Action、C2 与 C3 交接

登记独立纸面实例 **A-b**：

- Action：`action.hoist_invariant_control`；
- parent：Pine；
- target：`RunIndexed` 调用链中对应的索引解码、grid 前缀和通道基址；
- workload、约束、性能预测和状态与 A-a 相同；
