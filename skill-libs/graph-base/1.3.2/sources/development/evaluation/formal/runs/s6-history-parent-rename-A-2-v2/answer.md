## 结论与证据边界

两个子例应作出**相同的优化选择**。函数名和历史标签不改变地址、依赖、覆盖或资源成本；输入材料没有给出“改名会改变生成代码”的证据，不能据此改变方案。

本轮选择一个**条件化纸面试验方案**：

> 从完整写回的原始实现出发，保持逐输出采样计算及原核间所有权不变，将 FP32 相邻输出先写入单槽 UB，再按有效连续段统一 DMA 写回。使用一个 `action.batch_writeback` 实例，不附加几何预计算、输入驻留或软件双缓冲。

选择它不是因为已证明写回是瓶颈，而是它有明确的连续输出域、有限的新增存储，并且不减少有效计算、不改变采样数值路径，也不减少已有独立输出任务。最有竞争力的已注册替代是**跨通道 owner 内保留原始 grid 小片**；另外，跨通道复用派生几何也值得保留，但当前材料明确指出了其 Action 意图缺口。

状态仅为 **conditional_plan / not_measured**。未修改源码、未运行 router、未生成真实 hash、未编译或验证候选；下文不是正式 runtime 校验通过的交接产物。

# 子例 a：L0 / L1 / L2，`GridSampler3DScalar`

## 1. 当前实际路径、数学与数据依赖

### 实际执行路径

当前讨论的实现是 FP32 分支：

```text
grid_sampler_3d_kernel
  → GridSampler3DScalar<float>
  → 每个有效 linear 调用 GridSampler3DOne<float>
  → nearest 分支
  → GridRoundEven + GridRead
  → float 原样写回
```

依据为 kernel 第 190–196、137–148、101–117 行。FP16 类中的 `Cast`、三个 `PIPE_ALL` 和 DMA **不在当前执行路径中**，不能将它们诊断为当前同步或转换成本。

外部输出可表示为 `Y[n,c,p]`，其中 `p∈[0,S)`；它只是 NCDHW 输出空间维度的展平，不改变外部布局。源码地址为：

\[
\begin{aligned}
p&=linear\bmod S,\\
nc&=\lfloor linear/S\rfloor,\\
c&=nc\bmod C,\qquad n=\lfloor nc/C\rfloor,\\
gridBase&=3(nS+p),\\
xBase&=(nC+c)DHW.
\end{aligned}
\]

grid 的三个值依次用于 x/y/z 坐标；**同一 `(n,p)` 的 grid 被各通道共享，但 X 的基址依赖通道**。

当前 `alignCorners=false`，每轴使用源码原括号顺序：

\[
u=((g+1)\,size-1)\,0.5.
\]

zeros padding 不修改坐标；最近邻使用源码 `GridRoundEven`，合法坐标读 X，否则贡献 `0.0f`。对当前数据：

- `grid=0`、每轴大小 16，因此坐标为 `7.5f`；
- ties-to-even 得到 `(8,8,8)`；
- 通道内空间偏移为 `(8×16+8)×16+8=2184`；
- 每个通道的所有 256 个输出均读取该通道的同一输入元素；
- `x=1`，所以完整输出应为 2048 个 1。

这只解释当前数据结果，**不授权把候选写成填 1，也不授权按 grid=0 特判**。

通用 fallback 仍包含三线性路径：按第 125–132 行的 k=0…7 次序逐项累加，保留各项乘法顺序及越界零贡献。不得重结合为另一个插值表达式。

### 当前所有权

令 `B=t.blockNum`、`L=t.blockLength`。原核 b 拥有：

\[
I_b=[bL,\min((b+1)L,2048)).
\]

空区间不计算；非空区间按 `linear++` 完整写回。tiling 对 FP32 使用 16 元素，即 64B 分核边界（头文件第 40–45 行）。实际 launch 代码未提供，不能虚构物理核数或已启动 BlockDim；本方案不改变它。

## 3. 工作量、主要方案与竞争替代

### 原实现的静态账

令输出数 \(M=NCS=2048\)。当前所有源读取均合法：

| 项目 | 源码级数量 |
|---|---:|
| 完整采样调用 | 2048 次 |
| grid 标量读取 | \(3M=6144\) 个 float，24576B |
| 坐标 unnormalize / nearest round | 各 \(3M=6144\) 次 |
| X 标量读取 | 2048 个 float，8192B |
| 输出标量 GM 写入 | 2048 个 float，8192B |
| 上述有效逻辑 GM payload 合计 | **40960B** |

`linear` 解码每输出有两次除法、两次取模的源码表达式；编译器可能配对、外提或消除，不能直接当成 8192 条机器除模指令。

当前数据下唯一 grid 字节为 3072B，唯一被采样的 X 字节只有 32B；这与重复逻辑请求不同，也不等于实测 HBM 流量。完整 X 分配为 131072B，不能为了 8192B 的有效采样请求就假定全量搬入更划算。

### A. 选定方案：同 owner 的 FP32 输出批量写回

**域：**仅给定元数据域：FP32、`N=1,C=8,D=H=W=16,S=256,nearest,zeros,alignCorners=false`。不限制输入数值；未列形状及其余 dtype/mode 保持原 fallback。

纸面起始参数为单槽 `U=64` 个 float。它是实验参数，不是硬件最优值。对每核有效长度 \(\ell_b=|I_b|\)：

\[
Q=\sum_{\ell_b>0}\left\lceil\ell_b/64\right\rceil .
\]

工作变化：

- 保留 2048 次原 `GridSampler3DOne<float>`；
- 保留原 grid/X 读取、坐标计算、round-even、边界检查和输出顺序；
- 将 2048 次标量 GM 输出写，替换为：
  - 2048 次 UB `SetValue`；
  - Q 次 UB→GM 写回，每次仅写 `valid×4` 字节；
- 输出有效 GM payload 仍为 8192B，**没有删掉最终输出字节**；
- 新增每核一份 `AlignUp(4U,32)=256B` 显式 UB；
- 起始保守实现新增约 `2Q` 次本核全流水完成边，以及 Q 次 DMA 参数构造。

当前分区下非空长度均为 16 元素倍数，故本方案各片有效输出均为 64B 倍数，且：

\[
32\le Q\le128.
\]

例如 B=32、L=64 时 Q=32；B=64、L=32 时 Q=64。这里不能宣称“DMA 从 2048 次减为 Q 次”：**原来是标量 GM store，并非 2048 次 MTE3 DMA。**

**选择理由：**输出连续、无核间合并、计算可以完全原样保留，且不会将现有通道/空间独立任务合并为较少 owner。  
**主要反例预测：**如果标量写已高效、每核只有 16/32 个输出，或新增 SetValue、完成边和 DMA 发射超过替代成本，本方案可能变慢。

### B. 最强已注册替代：保留原始 grid 小片，仍逐通道重算坐标

取 `Ct=8, St=16`，一个 task 拥有所有通道的同一空间片。流程为：

1. 搬入原始 `grid[p0:p0+16,3]`，保持只读；
2. 依次处理八个通道；
3. 每通道仍执行原坐标/round/bounds 计算；
4. 按该通道的连续 16 个输出写回。

全部工作变化及新增成本：

- task 数为 \(N\lceil C/Ct\rceil\lceil S/St\rceil=16\)；
- grid 逻辑 GM 读由 `3NCS` 降至 `3NS`：
  - 6144 → 768 个 float；
  - 24576 → 3072B，删去 21504B 重复逻辑读；
- grid 原值仍被消费 8 次，本地读取没有消失；
- 2048 次采样、6144 次坐标及 round 计算、2048 次 X 读取保持；
- 每 task 一份 grid 区 `12St=192B`，一个通道输出区 `4St=64B`，基础显式 UB 为 256B，另计框架资源；
- 全调用约 16 次 grid 搬入、128 次通道输出写回；增加输入就绪、长期只读保护和输出复用完成边；
- 核间所有权改变：一个 owner 写八个相隔 S 的输出段，需要重新证明所有段；
- 仅 16 个独立 task，可能低于原有效 owner 数，减少并行度。

它可由 `action.reuse_input_tiles` 表达，保存的是**原始 grid**，不是派生几何。它比选定方案多减少了重复读取，但没有减少主要坐标计算；当前原始 grid 工作集又只有 3072B，缓存可能已承担部分复用。因此本轮优先保留原 owner 的输出方案，不把逻辑删读量换算成确定收益。若未来确认原 owner 数本就不超过 16，或 grid 标量读取成本明显，该替代的竞争力会上升。

### C. 不能略过的机会：跨通道复用派生几何

若相同 task 内只生成一次 nearest 源偏移/有效标记：

\[
\text{几何生成次数}: NCS\rightarrow NS=256.
\]

可少做 1792 次三轴几何生成，即坐标 unnormalize 和 round 分别少 5376 次；X 请求与最终输出仍各为 2048 元素。采用 `Ct=8,St=16` 时仍只有 16 个 task。

例如用每点 8B 空间偏移＋8B 有效标记，几何区为 `16St=256B`；若原始 grid 区、几何区、单通道输出同时分配，基础显式 UB 为：

\[
12St+16St+4St=32St=512B.
\]

再加表写读、生成/消费依赖、初始化及真实 API 资源。若使用 Scalar 私有数组，则必须另列寄存器/栈/spill 风险，不能将它算作“零容量”。

**能力缺口：**输入的 Action 正文明确不允许用 `hoist_invariant_control` 自动承载派生几何重排，也不允许用 `reuse_input_tiles` 把新计算的几何表冒充原始输入驻留。原实现又没有几何表的 GM 往返，不能套 `keep_intermediate_onchip`。因此该方向保留为任务内提案，不能作为本轮已注册正式成员夹带实施。

其数值合法性还须覆盖原 round-even、非有限值及 float→int64 转换边界；源码没有给这些转换提供完整可移植定义，不能自行规定 NaN/Inf 对应坐标或输出。

### 其他显著方向的处理

- **完整 Vector 化：**可减少逐元素算术，但给定正文没有提供本任务所需的完整 A3 不规则取数、int64 转换及 round-even 等价链。Compare/Select 的 256B 比较粒度、predicate 和 8KB 临时区也不能直接解决这些问题。本轮不点名一个未经证明的 Gather/舍入 API。
- **字段缓存/地址递推：**可合法研究，但不能消除跨通道几何重算及实际数据计算；现有代码已是 GM tiling 指针直读，没有整结构体拷栈事实。不因它容易实施而优先。
- **同步收窄、双缓冲：**当前 FP32 没有 half 路径中的三个屏障；本轮也没有足够事实证明更深流水有净价值。
- **带宽饱和、bank 冲突、spill：**均未由当前证据确认。

## 5. 统一 C2：所有权、布局、workspace、同步与 KEEP

### 提取已有计划

- AIV kernel；
- 按输出线性区间分核；
- FP32 在 Scalar 上逐输出计算并标量写 GM；
- 输入/grid 只读意图，无显式 GM workspace；
- 无跨核归约或通信；
- 核数、可用 UB、SDK 版本及实际 launch 接线未提供。

### 实际改变计划

本轮为 **P_CHANGE**：不仅是补文档，还实际改变输出通路、片上存储及核内完成关系。不是 P_KEEP。

- **所有权：**完全保留 \(I_b\)，不换核、不换遍历轴。
- **布局：**GM 保持 NCDHW；UB 为 `float[U]`，槽 i 对应 `out[pos+i]`，无转置。
- **GM workspace：**新增 **0B**，入口 ABI 不变。
- **UB：**

\[
U_{\rm alloc}=AlignUp(4U,32)+F_{\rm pipe/API/other}
=256+F\le U_{\rm available}.
\]

  只有一槽，不乘队列 depth；FP16 与 FP32 分支不同时初始化，不能把两条路径的声明简单相加为当前峰值。也不能用物理 UB 标称容量代替可用容量。
- **同步依赖：**
  1. 全部有效 UB 标量写完成且对 MTE3 可见；
  2. MTE3 才读该槽写 GM；
  3. MTE3 最后读取完成后，下一片才可覆盖该槽；
  4. 退出前排空最后写回。
  
  起始使用保守 `PIPE_ALL` 完成边，不宣称重叠。仍须核对目标 SDK 的 `SetValue → MTE3` 可见性及具体位置支持；不能只凭 barrier 名称宣布该边已验证。
- **派发：**沿现有 kernel entry，以真实元数据判断目标域；互补域进入原函数。无需为本轮发明 TilingKey ABI、添加新 entry 或按 L0 标签分派。未见正式 Host key 框架，不能伪造 `TILING_KEY_IS` 接线。
- **许可自由度：**单槽、原 owner、原计算；U 的调整必须满足容量和 API 范围。增加双槽、跨通道复用、改 owner 或派发域应返回 C2。
- **KEEP：**FP16、非目标元数据的原路径保持；这只是未改范围，不构成整个方案 P_KEEP/O_KEEP，也不是 NOOP。

### P 正文的实际影响

采用 `planning.indexing.coordinate_neighborhood` 的**输出连续空间块、独立生成几何**骨架，绑定：

- G：第 107–109 行读 grid 并 unnormalize；
- B：当前 zeros 模式不变换坐标；
- H：原 round-even 和边界判定；
- F：K=1 的合法取数或返回零；
- 通用三线性 fallback 的 F：第 125–132 行固定顺序。

它阻止了“输出连续，所以 X 连续”的错误推断，也要求将原始 grid 与派生几何分开记账。`planning.elementwise.continuous` 仅参考其输出区间/容量原则，**不完整套用**：本算子输入并非与输出同形同下标逐元素读取。

## 6. C3 准确实施步骤与 O 正文影响

以下是后续实施指令，不表示本轮已执行：

1. **冻结父本。**从 L0 创建隔离候选，保留 L1 失败与 L2 独立身份；获得真实源 hash 后再绑定决策和计划。
2. **先关闭硬缺口。**核对目标 SDK、可用 UB、实际 BlockDim/tiling、GM 基址与别名契约；确认所选 TBuf 位置、float `SetValue`、UB→GM 重载及 Scalar→MTE3 完成语义。
3. **保留计算函数。**不修改 `GridSampler3DOne`、`GridFloor`、`GridRoundEven`、padding 或 float 转换，不添加数据值特判。
4. **新增独立输出暂存路径。**在目标 FP32 元数据域初始化一个 256B 输出 TBuf；初始化只执行一次，不能放进 tile 热循环。
5. **按原 owner 遍历：**
   - 计算原 `begin/end`；
   - `pos<end` 时取 `valid=min(64,end-pos)`；
   - 对 `i=0…valid-1` 调用原采样函数，将结果放入 UB[i]；
   - 建立 UB 写完成→MTE3 读取依赖；
   - 用 A3 无 mode 的 UB→GM `DataCopyPad`，`blockCount=1`、`blockLen=valid*sizeof(float)`、两个 stride 为 0；
   - 等待 MTE3 读完后推进 pos，复用同槽；
   - 空 owner 不发 copy，末片完成后才退出。
6. **统一写法。**目标域的 Y 只经这一 DMA 路径写，不对同一区间混合标量 GM store 和 DMA，不跨其他 owner 汇总。
7. **fallback 接线。**互补元数据直接运行原实现；不能先计算部分新输出再遇错静默重跑原路径。
8. **审查与验证后再计时。**需要真实代码审查、构建、完整 oracle 和存储检查；候选源码一旦变化，不能沿用旧候选正确性。

实际采用的 O 方法及影响：

- `implementation.memory-transfer.coalesce`：决定只汇总同 owner 相邻输出；保留有效输出字节，单独核算 UB 滞留和同步。
- `implementation.tiling-tail.valid-length`：决定 `valid` 与 64 元素分配长度分离，不扩大 GM 写域。
- `implementation.pipeline-sync.fallback`：起始选单槽最浅完成链，不把新增 buffer 当作有效流水证据。
- `implementation.precision-boundaries.numeric/bounds`：保持原计算和舍入，核对整数乘加、字节单位、最后地址及特殊值；不接受“数学公式相同”替代完整数值审查。

本方案没有采用 Vector 算术 recipe，也没有采用输入驻留、bank padding 或缓存 hint。不能把路由目录中出现的条目全部登记为已实施方法。

## 1. 当前实际路径与关键事实

对应关系为：

- Pine ↔ L0：完整 `linear++`；
- Fir ↔ L1：`linear+=2`，漏写一半；
- Oak ↔ L2：与 Pine 程序内容相同、历史身份独立；
- `RunIndexed` ↔ `GridSampler3DScalar`：仅函数标识改变。

因此实际仍为 FP32 Scalar nearest 路径，数学、地址及依赖完全相同：

- 2048 个有效输出；
- grid 的 6144 次逻辑 float 读取；
- 2048 次 X 读取及输出写入；
- 当前坐标 7.5，round-even 为 8，通道内偏移 2184；
- Fir 的 1024 个错误来自遗漏输出，不是数值舍入问题；
- Oak 的计时在 synchronize 前结束，不能证明快于 Pine。

本轮父本选 **Pine**。不能因为名称听起来与某类树、索引或采样有关而改变 family 或方法。

## 2. 方案、替代与成本

选定方案仍为原 owner 内单槽 FP32 输出批量写回：

\[
U=64,\quad U_{\rm data}=256B,\quad
Q=\sum_b\lceil\ell_b/64\rceil,\quad32\le Q\le128.
\]

保留 2048 次完整采样；新增 2048 次 UB 写、Q 次 DMA 和起始约 2Q 次完成边，输出有效字节仍为 8192B，新增 GM workspace 为 0B。

最强已注册替代仍为 `Ct=8,St=16` 的**原始 grid 驻留**：16 tasks，grid GM 逻辑读从 24576B 降为 3072B，基础显式 UB 256B，坐标重算不减少，约 128 次通道输出写回。跨通道派生几何复用仍可将几何生成从 2048 降为 256 次，但有相同的 Action 意图缺口及状态/数值审查成本。

**成本没有变化**，因为两例唯一差异是命名，不是工作量、布局或所有权。

## 3. Action、C2 与 C3 交接

- 纸面实例 **b-A1**：`action.batch_writeback`；
- 父实现：Pine；
- 目标：`RunIndexed` 内对应原第 146–147 行的输出写回；
- 参数、域、不变量和硬缺口与 a-A1 相同；
- 真实 source/template hash 仍未生成，不伪造正式注册成功。

共同 C2 计划为子例 a 第 5 节，身份重新绑定 Pine：

- P_CHANGE：输出 Scalar GM→UB→MTE3；
- 原输出区间、NCDHW 布局及采样数学保持；
- 单槽 256B＋实际额外资源不超过可用 UB；
- GM workspace=0B；
- 保留写就绪与最后读取完成两条边；
- 其余元数据原 fallback；
- 不因缺工具或缺正式父计划而标 P_KEEP。

C3 严格采用子例 a 第 6 节的八步，仅替换父本及函数定位。P/O 正文对本例的实际影响也相同：索引模板约束间接取数与几何依赖；coalesce/valid-length 约束输出汇总；pipeline fallback 选择单槽完成链；numeric/bounds 禁止舍入和有效域偷换。**没有来自材料的改名敏感来源。**

## 待验证与选择敏感条件

1. **实施前硬条件**
   - 实际 SDK 的 TBuf/SetValue/DataCopyPad 支持与可见性完成边；
   - 256B＋框架/API 资源的真实可用 UB 预算；

   - 实际 launch 与原分核区间一致，输出基址/边界满足所用写回路径。

2. **完整正确性**
   - 检查所有 2048 输出及每输出唯一写者，而非只检查被写位置；
   - 当前 `x=1,grid=0` 能暴露漏写，却不足以验证所有索引、round-even 和异常值；

   - 覆盖空 owner、单片、多片、最后片及重复运行。

3. **性能预测**
   - 原标量输出成本是否足以抵消新增 UB 写、DMA 和完成边；

   - 编译器是否已经优化字段/除模，是否新增 spill；
   - 若后续 owner 数本就≤16，重新比较原始 grid 驻留；若几何计算确为主要残余，推进派生几何复用的独立 Action 提案，而非套错意图。
