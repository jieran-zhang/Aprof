## 结论与交接状态

本轮选择两个有不同成本依据的纸面候选：

- **子例 a：保留全输入 packed 布局，把几何生成、采样和最终输出组合到同一消费者 kernel。** 当前四阶段变为“全输入 pack → 融合采样并直接写最终输出”两阶段。
- **子例 b：取消全输入 pack，直接从 NCDHW 按需读取八邻居；几何、采样、输出由同一 owner 完成。** 只处理 8 个空间点，不为其转换整个输入。

两者均保持八邻居 `k=0..7` 的消费顺序，不改权重计算、普通 Mul/Add 路径及 `GridFma32Bits` 备用路径。**不是把当前实现替换为原始 `GridSampler3DOne`**：两者浮点表达式组织不同，不能仅凭实数公式相同认定舍入等价。

以下是可交给后继实现者的条件化 C2/C3 计划；未修改源码、未构建、未验证正确性、未计时。实际可用 UB、SDK 和 Host 接线仍须闭合，不能把源码中的预算常量当成已探测容量。本文登记任务内 Action 实例，不伪造模板 hash、源码 hash 或 router 执行记录。

# 一、当前实际路径与共同事实

## 1. 数学及数据依赖

令输入空间长度 \(I=DHW=32768\)，空间输出点为 \(p\)。

当前路径先按 `GridGeometryRange:243–270` 生成与通道无关的几何：

\[
(i_x,i_y,i_z)=\operatorname{Unnormalize}(grid[n,p,:])
\]

本例 `alignCorners=false`，每轴保持源码表达式：

\[
((coord+1)\times size-1)\times 0.5
\]

由下取整得到基坐标、分数和八个邻居，权重保持：

\[
w_k=\operatorname{fp32}\bigl(\operatorname{fp32}(w_xw_y)w_z\bigr)
\]

随后对每个通道独立执行八邻居有序累加。当前普通路径是预生成权重后的逐邻居 Mul、Add；备用路径按同一 `k` 顺序调用 `GridFma32Bits`。不得重结合、改成树归约、改累加 dtype，或用新的 FMA 替换普通路径。

输入值依赖通道，几何不依赖通道。因此：

- 当前几何已经是 **每个空间点生成一次**，不是每通道重复生成。
- 保存几何属于派生中间值，不属于原始输入驻留。
- 输出 `[n,c,p]` 相互独立，无跨核归约。

## 2. 当前四阶段的数据流

1. **Geometry**：grid → GM 中八组 uint32 字节偏移和八组 FP32 权重。
2. **Pack**：NCDHW → GM packed 输入；`cp=64`，第 64 个通道补零。
3. **Sample**：读几何和 packed 邻域，UB 内计算、转置，写 padded NCS workspace。
4. **Compact**：读 padded NCS，有效元素压紧写最终输出。

三线性 pack 的布局可解释为：

```text
packed[n,i,0,c] = X[n,c,i]
packed[n,i,1,c] = X[n,c,i+HW]，超出上表面时为零
```

每个 `i` 占 `2*cp` 元素，另有零哨兵。严格内部点沿用 `1162` 的一次多块搬运，取得全部八邻居；**并不存在内层逐通道发 63 次 DMA 的问题**。

跨 kernel 的生产消费必须由调用序列的执行依赖保护；核内 `PipeBarrier` 不能替代它。源码中的 UB→UB `DataCopy`、Gather、Mul/Add 也不是免费的搬运或寄存器直通。

## 3. 可复算的当前数量

FP32，字节为单位；这些是源码逻辑 payload，不是实测 HBM 流量。

| 项目 | 公式 | a：S=32768 | b：S=8 |
|---|---:|---:|---:|
| 原输入有效字节 | \(4CI\) | 8,257,536 | 8,257,536 |
| packed 输入段 | \(8(I+1)cp\) | 16,777,728 | 16,777,728 |
| 几何表 | \(64S\) | 2,097,152 | 512 |
| padded 输出分配 | \(4C\,sa,\ sa=16\lceil S/16\rceil\) | 8,257,536 | 4,032 |
| 最终输出有效字节 \(Y\) | \(252S\) | 8,257,536 | 2,016 |
| sample 邻域有效搬入 | \(8cp\times4S\) | 67,108,864 | 16,384 |

b 的 padded 输出虽然分配 4,032 B，sample 实际只写每通道 8 个有效元素；不能把整段分配都算成有效写流量。

由当前初始化公式推导：

- Pack：`p_=224`，输入空间 tile 数为 147。
- Sample：`batch_=48`、`gTile_=64`。
  - a：683 个 sample tile，最后有效点数 32。
  - b：仅一个 sample tile，有效点数 8。
- Sample 显式 UB 分配为 **163,840 B**。
- Pack 显式 UB 分配为 **174,080 B**。
- Compact 两块 8192-float buffer 合计 **65,536 B**。

这些分属不同 kernel，不能相加为同时 UB 峰值。实际可用容量与隐含开销仍未确认。

# 二、子例 a：保留 packed 输入，融合几何—采样—最终输出

## 1. 主要方案及选择理由

当前 `S=I`，全输入转换成本能在大量采样点间摊销；packed 布局使每点八邻域由当前一次多块 API 搬入。选择保留这一通路，同时消除两个没有外部消费者的阶段交接：

```text
当前：Geometry → Pack → Sample → Compact
候选：Pack → [本 tile 几何 → Sample → 最终 NCS 输出]
```

Geometry 与 Pack 没有数据依赖，可以先 Pack，再在消费者自己的空间 tile 内生成几何。每个 tile 仍拥有全部 63 个有效通道，不增加几何重算次数。

本例 `sa=S=32768`，padded NCS 与最终 NCS 的行跨度本来相同；Compact 实际是一次额外复制。因此直接写最终输出不需要改变输出布局。

### 工作变化

**删除：**

- 几何表 GM 写、读：\(128S=4,194,304\) B。
- sample 输出中间写及 compact 输入读：\(2Y=16,515,072\) B。
- 独立 Geometry、Compact 两次阶段启动。

合计删除逻辑中间读写：

\[
128S+2Y=632S=\boxed{20,709,376\text{ B}}
\]

**保留：**

- 原输入读、全输入 pack 及其零通道、上表面零值、哨兵初始化。
- 每点八邻域搬入 \(2048S\) B。
- 每点一次几何计算。
- 权重 Brcb、数值路径选择、有序累加、结果转置及最终输出。

**新增或改变：**

- 将原几何的标量 GM 写改为本 tile LocalTensor 写。
- 同一 kernel 内增加 Scalar→Vector 就绪关系。
- 消费者代码体积及标量活跃状态可能增加。
- 几何生产从独立全域阶段变为各 sample owner 内的工作；其调度与编译成本未知。

不将这些变化表述为已确认瓶颈或确定收益。

## 2. 最有竞争力替代：完全取消 pack，直接读取 NCDHW

直接路径利用 x 邻居相邻的事实，对每个 `(z,y)` 组合一次跨通道 strided 搬运：

- 每点 4 次 API；
- 每次 63 行，每行 2 float；
- 八邻居总有效输入为 \(8C\times4=2016\) B/点。

与主要方案相比：

- 删除原输入全扫描和 packed 全量写：
  \(8,257,536+16,777,728=25,035,264\) B。
- 邻域 payload 每点再少 32 B，即有效通道 padding 的差额。
- 但邻域 CopyIn 从 \(S\) 次增至 \(4S\) 次，增加 **98,304 次源码 API 调用**。
- A3 普通 DataCopyPad 每个 8 B 通道行在 UB 按 32 B 排布。四组行的暂存为：
  \[
  4\times64\times32=8192\text{ B/点}
  \]
  而 packed 原始邻域区为 2048 B/点。
- 还需 UB Gather/重排、索引表、较小 tile 或不同暂存安排。

若同样融合几何和输出，直接路径的主要有效 payload 为：

\[
12S+2016S+252S=2280S=74,711,040\text{ B}
\]

主要方案对应：

\[
25,035,264+2312S=100,794,880\text{ B}
\]

直接路径逻辑字节更少，但搬运发射和 UB 行 padding 明显更多。**本轮选择主要方案，是保留已经具备的一次八邻域搬入优势，试验消除明确中间交接；不是认定直接路径一定较慢。** 若 Pack 时间高、packed 复用收益弱，或直接四组搬运发射成本较低，替代方案应重开。

# 三、子例 b：按需读取 NCDHW，取消全输入转换

## 1. 当前成本为何改变选择

b 只有 8 个采样点、504 个输出，却仍执行与 a 相同的全输入 pack：

- 读原输入 8,257,536 B；
- 写 packed 段 16,777,728 B；
- sample 内部只有一个有效 tile。

每次调用只执行一次，没有既有 packed 副本，也不能跨调用摊销。此时为了节省每点三次搬运发射而转换整个输入，静态成本明显不利。

## 2. 主要方案

一个 owner 处理全部 8 点、全部通道：

```text
原始 grid、原始 NCDHW
    → 本地几何
    → 每点四组跨通道 x 邻居对
    → UB 重排为现有八邻域槽位
    → 原数值分支与有序累加
    → 一次写最终连续 NCS
```

严格内部的四组搬运参数为：

```text
blockCount = 63
blockLen   = 8 B
srcStride  = (I-2)*4 = 131064 B
dstStride  = 0 个32B块
```

每行 UB 跨度为 32 B，不是 8 B。显式右 padding 6 个 float；第 64 个通道行另定义为零。不能依赖 `isPad=false` 自动清零。

### 工作变化

- 删除全输入扫描、完整 packed 写入、packed GM 分配。
- 删除几何 GM 表和 padded 输出 GM 中间段。
- 删除三个独立阶段启动。
- 邻域 CopyIn：当前 8 次变为 32 次，多 24 次。
- 原输入有效读取：
  \[
  8SC\times4=\boxed{16,128\text{ B}}
  \]
- grid 读 96 B，最终输出写 2,016 B；合计主要有效 payload：
  \[
  \boxed{18,240\text{ B}}
  \]
- 保留八邻域、63 通道的数学工作；UB 中仍处理第 64 个零通道，但不写入外部输出。
- 新增配对行 UB 暂存、Gather 索引及重排、padding 初始化和相应完成边。

这不是“只缩 workspace”：原实现确实读写了整个转换段，候选实际取消该工作。

## 3. 最有竞争力替代

**保留独立 Geometry kernel，随后直接 NCDHW 采样并写最终输出。**

其采样搬运、计算、输出与主方案相同：

- 两次阶段启动，而非一次；
- 保留几何表 512 B；
- 几何写读额外 \(128S=1024\) B；
- 主要有效 payload 为 **19,264 B**。

此替代同样解决主要的全输入 pack 问题，且几何生产消费代码改动更少。主方案优先减少短调用阶段交接；若融合代码增加显著标量开销或实现复杂度，该两阶段版本是合理回退。

另外，直接复用原始 `GridSampler3DOne` 虽然代码少，但它可能每通道重算几何，且乘法/累加组织与当前路径不同，不作为可直接认定等价的最强替代。

# 四、Action 实例登记与知识边界

## a：`A-a-chain`

- **Action**：`action.fuse_kernel_chain`，输入提供的 D v0006 正文。
- **parent**：本次给出的实际四阶段入口及 `GridGeometryRange`、`GridSampleChannels`、`GridCompactOutput`。
- **target**：几何表及 padded NCS 输出连接的生产消费链。
- **stage/workload**：FP32、指定形状、S=32768；Pack 保留。
- **结构依据**：独立阶段由 GM 中间张量连接；当前调用内无其他消费者。
- **实施条件**：C2 批准边界变更；本地几何完整定义；直接输出唯一所有权；容量、别名及同步合法。
- **预测**：四阶段变两阶段，删除上述 20,709,376 B 逻辑中间读写。
- **代价**：融合代码体积、标量生命周期及调度变化。

一个融合 Action 已足够表达目标，不再为同一中间字节删除重复登记 `reduce_memory_traffic` 收益。

## b：`A-b-demand-read`

- **Action**：`action.reduce_memory_traffic`，输入提供的 D v0006 正文。
- **parent**：同一四阶段实现。
- **target**：仅供采样使用的全量 packed 输入及其相关 GM 交接。
- **stage/workload**：FP32、指定形状、S=8。
- **等价值关系**：每个有效 packed 邻居通道值来自原 NCDHW 的确定地址；候选直接读该原值。
- **实施条件**：逐邻居地址映射、边界零贡献、原计算次序、最终输出及容量合法。
- **预测**：按需读取取代全量转换；相关几何/输出交接在同一 owner 内直接完成。
- **代价**：四组 strided 读取、UB padding、索引和 Gather。

该 Action 正文明确允许改变通路以消除中间读写，不要求先证明带宽饱和。派发和局部融合是完成本方案的配套实现，不以文件或 API 数量拆 Action。

**共同不采用：**

- `reuse_input_tiles`：没有证明这两个 workload 的任意采样点存在可利用的同地址输入窗口；几何也不是原输入。
- `hoist_invariant_control`：当前几何已全域生成一次，不能再宣称消除跨通道几何重算。
- 小搬运合并：a 的八邻域已经一次搬入，不能把“cp 通道一次处理”再记一遍优化。
- bank padding、cache hint、双缓冲：当前无实际地址/等待证据支持优先选择；缺实测不是统一否决，而是本轮已有更明确的工作删除机会。

# 五、统一 C2 计划

## 1. P 正文实际采用

主要使用 **`planning.indexing.coordinate_neighborhood`**：

- 绑定 \(G\)：当前反归一化表达式；
- \(B\)：当前 zeros 边界规则；
- \(H\)：当前八偏移和顺序权重；
- \(F\)：当前数值分支及 `k=0..7` 累加。
- 选择完整通道复用域，由空间 tile owner 一次生成几何后消费所有通道。
- 不假设 grid 有源地址局部性，不建立未经证明的 halo 窗口。

使用 **`planning.layout.transpose`** 的有效宽度/物理跨度及“消费者接受原 stride 可避免转换”原则：a 保留 packed；b 把转换替换为消费者内原 stride 寻址。不套用其小通道 `TransDataTo5HD` 配方。

输出独占分区借用 continuous 的所有权原则，**不声称 GridSample 满足同形 elementwise 模板的全部适用条件**。

## 2. 所有权与同步

| 项目 | a | b |
|---|---|---|
| 任务 | `[p0,p0+count) × 全部通道` | 全部8点×全部通道，一个owner |
| 初始空间 tile | 48点，尾32点 | 8点 |
| 输出 | 每通道对应连续空间段 | 完整连续504元素 |
| 跨核归并 | 无 | 无 |
| 跨阶段依赖 | Pack全部完成后采样 | 无GM中间生产消费 |
| 本地复用 | 几何到最后消费者；输出到MTE3读完 | 配对行到Gather完成；raw到最后计算；输出到MTE3读完 |

a 的所有空间分界均为16个 float 的倍数，每个通道段满足原64 B所有权粒度；b 不拆通道或点给不同输出 owner，避免短行交界的物理粒度问题。

均保持最浅、可证明的同步，不在本轮同时增加跨 tile 流水。

## 3. workspace 与容量

### a

取消几何和 padded 输出段：

\[
W_a=8N(I+1)cp=\boxed{16,777,728\text{ B}}
\]

融合消费者复用现有几何 UB 区，不增加独立几何 TBuf，初始显式 UB 仍为 **163,840 B**。Pack 为 **174,080 B**。另计实际编译/API及系统预留。

### b

算法数据 workspace 为 **0 B**；框架保留区不能凭本文删除。

为便于复用当前计算，先保留独立物理区，8点的显式 UB 账为：

| 区域 | 字节 |
|---|---:|
| 四组配对通道行 | 65,536 |
| 现有顺序 raw | 16,384 |
| 配对行→raw Gather索引 | 16,384 |
| values | 4,096 |
| weights | 2,048 |
| acc | 2,048 |
| geometry | 4,096 |
| 输出转置索引 | 2,048 |
| **合计** | **112,640** |

不把串行阶段的独立 `InitBuffer` 自动取 max，不把标量数组算成 UB，也不假定无 spill。

实施门禁为：

\[
U_{\rm explicit}+U_{\rm actual\ extra}\le U_{\rm available}
\]

a 的新消费者不超过当前显式规模，b 小于当前 sample 显式规模，构成有界试验依据；仍不等于资源验证通过。

## 4. dispatch、fallback 与 KEEP

建议本轮两个互斥元数据分支：

- a 的精确元数据域 → `grid_sample_channels_fused_final`；
- b 的精确元数据域 → `grid_sample_ncdhw_demand_final`；
- 其余全部元数据 → 原完整四阶段 fallback。

可在纸面计划中分别预留 uint64 key 1、2、0；真正接线前须核对当前工程既有 key 命名空间。输入没有当前 Host 完整接线，故不宣称这些 entry 已存在或可达。

这两个域来自不同转换摊销及资源需求，不建立未经测量的 `S<阈值` 生产规则。`grid内部`、`x∈[-1,1]` 不是普通 shape 元数据，**不能据此无条件删除 kernel 边界或数值备用路径**。

两方案均 **P_CHANGE**：融合边界、通路、workspace 已改变。没有可引用的完整父计划，不能写 P_KEEP。原 Pack 或数值函数保持不变，也不代表整个方案 O_KEEP；本轮不是 NOOP。

# 六、C3 准确实施步骤与 O 正文影响

## a 的实施顺序

1. 保留 `GridPackChannels<float>` 及其完整初始化、输出和完成依赖。
2. 新消费者接收原 grid、packed work、最终 y。
3. 把 `GridGeometryRange:249–268` 的逐点表达式原样移入本 tile，写现有几何 LocalTensor 的八索引/八权重平面；保留原 stride 口径。
4. 本地几何就绪后执行原 Brcb；保留 `1161–1172` 的邻域搬入、数值判断和计算。
5. 保留输出 Gather，但把输出 GlobalTensor 改为最终 y，行跨度使用 `S`。
6. Host 删除本域 Geometry、Compact 启动及对应 workspace 段，改为 Pack→新消费者。
7. 保留最后消费者完成及输出排空，不把核内 barrier 当成 Pack 的跨阶段完成通知。

## b 的实施顺序

1. 同 owner 为8点生成本地几何，表达式、权重及索引单位不变。
2. 对每个内部点，按四个 `(z,y)` 组合发上述63行、8 B的 strided copy。
3. 定义所有会被读取的 padding及第64通道。
4. Gather 为现有 raw 槽位。若邻居号为 \(k\)，保持当前槽位：
   \[
   slot=2(k\&3)+(k>>2)
   \]
   配对行中使用 \(r=k>>1,\ q=k\&1\)，通道行 pitch 为32 B。偏移表以字节计，只乘一次元素宽。
5. 配对区 MTE2→Gather 完成后，复用当前 `GridNeedsFma32`、备用路径、Apply及有序累加。
6. 转置为 `[63,8]`，用一次63块、每块32 B的输出搬运写紧凑 NCS；只写63通道。
7. 删除本域全输入 Pack、独立 Geometry及Compact调用。
8. 保留一般边界处理：有效邻居才读原地址，非法邻居写零；非内部点可用保守逐邻居取数路径。不得先越界读取再乘零。此路径不影响给定内部 workload 的上述计数，但扩大了正确性审查范围。

## 所选 O 正文带来的具体约束

- **`memory-transfer.strided-pad`**：决定 b 的 GM stride 用字节、UB 每行32 B、blockLen=8而不是对齐32；禁止把任意不同点合为规则多块。
- **`memory-transfer.coalesce`**：b 全输出同时由一 owner 生成后可批量写；a 不跨其他 owner 拼接写回。
- **`buffer-lifetime.reuse`**：本轮先不额外别名压缩；a 只在既有几何区生命周期内改其生产方式，b 独立区如实计账。
- **`vector-api.batch`、`compare-select-tail`**：不额外合并有依赖的八次 Add；保留现有比较辅助函数的256 B执行域及mask压缩逻辑，不从普通Add推断Compare尾语义。没有引入Select，不能凭该配方随意增减8 KB临时区。
- **`precision-boundaries.numeric/bounds`**：禁止FMA替换、权重重结合和改变特殊值策略；padding只定义实际读取域，有效count与物理跨度分别保存。
- **`tiling-tail.dispatch`**：只接C2冻结分支，所有其他形状保留原路径，不根据case名或运行结果选择。

这些是正文对计划和实施的实际影响；未声称执行过自动 router 或采用了输入之外的 API 能力。
