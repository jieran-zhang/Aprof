# 来源头文件的文本归档

## 用途和存储

技能包包含 39 份第三方头文件快照，用于诊断、规划和优化知识的来源核对。
快照保留上游修订、相对路径、许可证声明和原始字节，存储文件名追加 `.txt`。
例如，逻辑路径 `kernel.h` 对应物理文件 `kernel.h.txt`。

API_Check 的包内、包间重复头文件检查会扫描这些快照。
文本归档使其用途在交付结构中明确可辨。四份实际运行代码使用的头文件保持原路径。

## 路径和身份校验

[映射清单](../tools/source-archives.json) 逐项记录逻辑路径、物理路径和 SHA-256。
映射只允许位于技能来源目录下的头文件，物理路径必须是原路径追加 `.txt`。
运行时读取逻辑路径时验证归档字节，拒绝同路径影子文件、路径越界和哈希不一致。

知识记录和诊断图继续记录原始逻辑路径与哈希。
诊断编译器的原始字节位于 `_diagnosis_v1.py`，公共入口 `diagnosis.py`
将清单中已验证的物理归档路径恢复为逻辑路径，保留既有图的生成器身份和来源清单。
`_knowledge_v1.py` 同样使用经过校验的来源路径解析。

导入 asc-tools 时，`tools/check_import.py` 还会把归档哈希与冻结清单独立比对，
同时核验文件集合。文档阅读链接指向实际的 `.txt` 文件，证据原文单独保存并校验。

## 阅读和复用

可直接打开 `.h.txt`、`.hpp.txt` 阅读源码。需要编译上游示例时，从来源清单中固定的
仓库修订获取完整工程及其依赖。若需要提取某份证据，在包外复制该归档并恢复原文件名，
再对照映射中的 SHA-256 核验内容。

本包针对映射读取、篡改拒绝、知识记录身份和诊断图身份提供针对性测试。
独立包仍通过 `python tools/release.py --allow-unsealed` 验证完整结构和知识关系。
