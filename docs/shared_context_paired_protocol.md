# 共享 context 的进程内配对与跨进程复现协议

规范版本：`shared_context_paired_v1`，2026-09-10。

状态：**设计已记录，runner、专用报告 adapter 和实机资格验证尚待完成**。这个 ID 是新测量协议的标识，与数据集 v2、runtime/v1 episode 版本相互独立。它不表示现有命令已经支持本协议。

本文是[优化实验组织手册](optimization_experiment_playbook.md)的测量部分。设备保持暂停；本文中的执行顺序用于以后明确启动的实验。

## 1. 要检验的问题与测量对象

当前观察是进程内相对稳定，而不同进程或阶段的绝对延迟可能不同。应检验：**当绝对延迟变化时，原实现 A 与候选 B 是否一起变化，配对倍率是否复现，有无角色或顺序偏差。** 不能先假设所有进程间变化都正常，也不能只因跨进程绝对延迟变化超过 2% 就否定一个可复现的比较。

主要对象是 prepared-input、预热后、完整算子的 ACL event interval。它包含完整 TensorList；`foreach_norm` 包含每个成员的 partial 和 finalize。初始化、分配、输入读取和 H2D 不计入；提交造成的设备可见空隙可能计入。因此它描述本协议下完整算子的调用时长，不是冷启动延迟、端到端应用时长或纯 kernel busy time。

例如，两个进程分别观测 A/B 为 `170/150 μs` 和 `180/159 μs`，倍率均约 1.13×，值得检验是否是共同变化。这个示例是说明统计对象的假设数值，不是已有新协议测量，也不能单独证明无偏。

## 2. 实验单位和冻结配置

**一个 A/B 独立启动对应一个原生进程，只比较一个固定候选和一个固定比较源码，并顺序执行全部声明 case。** 每次重新初始化 ACL，A/B 在其内部共用一个显式 context、一个显式 stream。前一进程完全退出后才启动下一进程。PID 之外还记录 host、启动时间和唯一 session ID，避免 PID 复用。

默认规范如下；任何变更必须在采样前冻结到协议 manifest，影响执行或统计语义的变更使用新版本，不能结果揭示后选择更有利的配置。

| 参数 | 默认与含义 |
|---|---|
| A/B 顶层重复 | 固定 6 次独立启动，不按结果追加 |
| case 范围 | 一次比较的全部预声明 case；6 个进程范围一致 |
| 预热 | 每 case、每实现各 10 次完整算子调用，正式计时前完成 |
| 样本 | 每个 event interval 执行同一实现的 100 次完整算子，除以 100，统一为 ns/call |
| 配对 | 每 case、每进程固定 30 对；需要更多时事前确定一个偶数，至少 30 |
| 顺序 | 默认逐对交替 AB、BA，各 15 对；6 个进程中首对方向各占 3 次，具体序列与种子封存 |
| case 顺序 | 各进程使用事前固定的交错/置换顺序，记录实际执行顺序；不能由运行速度动态排序 |
| 对照 | A 是此次比较的真实父本或原始 baseline；两个不同对照各自运行完整的独立 6 次启动 |
| 并发 | 本机一个活跃硬件任务；计时期间不并发编译、profile 或重型导出/hash |
| 原始数据 | 不删离群值，不只存均值；保留失败、预热/控制范围、全部正式样本与输出校验 |

一对指两个 event interval：一个 A、一个 B。30 对不是 30 次单独调用，也不是 30 个 ABBA 四样本块。ABBA 可作为另一个事前声明的方案，但必须定义配对单位、权重和顺序检查，不能混用计数。

同一进程内的 case、配对和重复调用均不是新的独立进程重复。若将来改成“每 case 各启 6 个进程”，必须另定义统计结构；不能把不共享进程的 case 拼成这里的 process-suite。

## 3. 原生 runner 的执行和资源约束

主 runner 必须在同一原生进程中调用 A/B 的真实入口。Python 父进程调度两个 native 子进程不满足条件；两个 context 轮流激活也不满足条件。

AscendCL 官方文档说明，同一 stream 内的任务保持提交顺序；context 管理 stream、event 和设备内存等资源。这里据此选用共享 context/stream 的串行比较，但保序本身不保证测量无偏。[AscendCL 基本概念与资源关系](https://www.hiascend.com/document/detail/zh/canncommercial/81RC1/developmentguide/appdevg/aclcppdevg/aclcppdevg_000004.html)

每次启动按以下顺序执行：

1. 获取主机串行锁与兼容的设备锁，核对空闲、健康、物理 chip 映射和 CPU affinity。锁不能阻止不遵守协议的外部程序，须保留实际占用检查。
2. 初始化 ACL 和唯一的测量 context/stream，加载两个实现。确保符号、kernel 注册与模块入口可区分，记录各入口的源码、binary 和加载顺序；不能因符号覆盖而把 A/B 都调用成同一实现。
3. 为当前 case 准备相同内容的输入。只读输入在语义允许时共享；输出和 workspace 分离并按真实算法需求安排。记录大小、对齐、地址/角色、初始化与重置方式。候选需要不同大小的 workspace 时如实记录，不强行让其失去必要资源。
4. 完成 H2D、必要状态初始化和每实现 10 次预热。清空待执行工作，确认输入/tiling/launch 数符合完整算子语义。A/A 资格试验切换资源配置时，第二个配置也独立准备并为每实现预热 10 次，不能继承第一个配置的预热资格。
5. 按冻结顺序测量。单个样本为 `start event → 100 次该实现的完整调用 → end event → 等待完成 → 读取 interval`，A/B 分别记录。准备、输出拷回和外部校验不进入 interval。原始 API 单位与换算系数一并记录，拒绝靠文件名猜单位。
6. 当前 case 完成后分别校验 A/B 的输出，记录在哪些 launch 后校验。默认至少检查每进程、每 case、每角色最后正式样本的最终输出；不声称检查了全部 100 次中间调用。单独的 20-case correctness 与此处 prepared 路径验证均须保留。
7. 同一 context/stream 中继续其余 case。全部完成后释放资源、退出进程，记录退出码，再启动下一重复。

原地算子或有状态算子必须明确初始状态契约。如果连续 100 次会改变下一次调用的输入语义，应使用预准备的独立状态，或另设能满足契约的测量方式；不能悄悄把状态恢复算入某一角色，也不能把变了语义的重复执行称为可比。当前协议只接受已经核验语义的执行方式。

共享输入、交替执行会影响缓存与运行状态。这是预热后交错比较的实验条件，不代表独立部署时的所有运行条件。使用固定的状态恢复/预处理协议检查 carryover；发现 A 后的 B 与独立预热的 B 不同，应记录并设计方法试验。不得因 AB/BA 平衡就声称已消除全部缓存影响。

### A/A 不只改一处路径名

A/A 的两个入口运行相同实现，却保留与 A/B 相同的角色调度、输出/workspace 管理和计时路径。核验源码/binary/入口身份和输出，避免测量的只是一个被意外合并的入口。A/A 也不能保证不同实现之间没有特有交互；当候选改变输入状态或资源布局时，需要事前声明相应控制，例如候选 B/B 或专门的资源试验。

## 4. A/A、稳定性与偏差标准

质量控制分为方法资格与每个测量阶段的控制。以下阈值是本协议的**待校准实验选择**，不是硬件常数或现有 gate 行为。

### 方法资格

先用任务 baseline 做 A/A；校准必须覆盖将要引用结论的 case、实现资源路径、harness、主机/chip 和环境版本。只有 sentinel 校准时不能声称其余 case 已合格。

资格试验须分别识别提交顺序、模块加载顺序和缓冲区角色，不能将三者一起反转后声称定位了某一种原因。一个可执行的默认设计是：

- 预先固定 6 个校准 block；每 block 启动 2 个独立进程，分别采用两种模块加载顺序，先后顺序交错平衡。
- 每个进程对每个 case 运行两种可交换的缓冲区角色配置，每配置各 30 对，15 AB、15 BA；两个配置的先后顺序平衡。不可交换的资源明确标注并使用相应专门控制。
- 得到每个条件的 6 个 block 级结果，以及同 block 内的加载、缓冲区和 AB/BA 对比。按 block 聚合，不把同 block 的多个条件当作独立启动次数。分别报告条件均值和对比，防止相反偏差在平均值中抵消。

本设计共 12 次 A/A 进程启动，成本另计。它用于隔离因素的首次资格检查；不是每个候选都无条件重做完整因素试验。源码的资源路径、harness、设备或相关环境改变后，既有资格范围必须重新核对。

为避免对比尺度含糊，对每个 case 定义 `q[b,l,u,o]` 为 block `b`、加载配置 `l`、缓冲配置 `u`、顺序层 `o` 中 15 对样本的平均 `log(A/B)`。A/B 始终指逻辑角色，反转提交或资源时不颠倒分子。三个主对比均为完整差值，不取半差：

```text
load_contrast[b]   = mean_(u,o)(q[b,0,u,o] - q[b,1,u,o])
buffer_contrast[b] = mean_(l,o)(q[b,l,0,o] - q[b,l,1,o])
order_contrast[b]  = mean_(l,u)(q[b,l,u,AB] - q[b,l,u,BA])
```

每个预声明条件及对比均有六个 block 级值，按第 5 节的 t 公式使用 `n=6, df=5`；校准区间留在 log 尺度，与 `[-log(1.005),log(1.005)]` 比较。除了三个主对比，也检查全部声明的条件，避免交互偏差抵消。若资源不能按此设计交叉，须预先定义可识别的专门对比和资格范围，不能假装缺少的条件已验证。

### 每个测量阶段

一次候选比较在方法已具备相应资格的前提下，预先安排 **before 正常 A/A、reverse 角色反向 A/A、A/B、after A/A**。每段各 6 次独立启动，每 case 30 对；A/A 不消耗候选数量，但消耗独立登记的控制成本。反向控制交换角色调度/资源映射，配置写入 manifest；它是整体偏差检查，具体因素归因仍依靠资格试验。

只有比较源码、case、harness、环境和时间覆盖均一致，且在执行前声明时，连续组才可共享边界 A/A；不能事后借用一个恰好通过的控制替代失败控制。父本与原始 baseline 不同，其 A/A 绑定各自的控制源码。

| 检查 | 默认规则与处理 |
|---|---|
| 完整性与身份 | 全部计划进程、case、样本、单位、A/B 身份及 prepared 输出验证完整；缺失则保留原始数据，不能标整组合格 |
| 进程内稳定性 | 对每进程每 case、每资源配置的 A、B 各自 30 个样本计算 `sample SD / mean`，默认均 ≤5%；资格试验两种配置不混成 60 点算 CV；同时报告配对 log-ratio 离散、随时间趋势和 AB/BA 分层 |
| A/A 比较偏差 | 以 log-ratio 为尺度，默认等效容限为 `±log(1.005)`，即倍率 `[1/1.005,1.005]`；相关 case 和预声明条件/对比的双侧 95% 区间应完整落入容限 |
| 角色/顺序差异 | 保留方向、大小和区间；资格设计中的对比使用上述预声明容限。无法估计或精度不足标未解决，不能用 suite 平均掩盖 |
| 跨进程绝对延迟 | 保存每次 A/B 中位数、变化范围、阶段变化与共变；不再以绝对漂移 >2% 单独否决 |
| 跨进程倍率 | 保存全部 6 个 case/suite 倍率、区间、范围、方向和异常；对顺序/时间敏感时标条件依赖，不能只看平均数 |

0.5% 容限是为研究约 3% 或更大效应设置的初始分辨目标，须在资格试验前冻结。它不自动证明 0.2% 的变化，也不意味着 A/A 偏差就是 A/B 偏差的严格上界。过去的 2% 角色容限仅属旧协议，不能一边允许同量级偏差，一边宣称更小收益已经确认。若要研究更小变化，需要独立计划更精细的控制，不事后收紧或放宽阈值。

“A/A 与 1 无显著差异”不等于 A/A 足够无偏；宽区间跨 1 也可能包含很大偏差。本规范要求区间**包含于**预声明等效范围，而不是只要求区间包含 1。区间不满足时区分观察到偏差与精度不足，不能都解释为优化无效。不得自动用测得的 A/A 均值去修正 A/B 倍率。

CV 不合格或 A/A 不合格时，仍可保存逐 case 的观察与源码事实，但本组性能证据未取得协议资格。不能删除异常 case、只导出稳定样本后宣称完整组通过。确需另一种对共同变化更稳健的质量规则时，建立独立的方法实验和版本，不在已有结果上挑选规则。

## 5. 分层估计：先进程，再汇总

令 `r=1..6` 表示一次完整 A/B 进程启动，`c` 为声明 case，`j=1..30` 为其配对。`A[r,c,j]`、`B[r,c,j]` 都是正的有限 ns/call，来自同一进程/context/stream 中的一对 event interval。

```text
pair_log[r,c,j]    = log(A[r,c,j] / B[r,c,j])
case_log[r,c]      = mean_j(pair_log[r,c,j])
case_speedup[r,c]  = exp(case_log[r,c])
suite_log[r]       = mean_c(case_log[r,c])
suite_speedup[r]   = exp(suite_log[r])

L                 = mean_r(suite_log[r])
reported_speedup  = exp(L)
```

case 等权，进程等权；不按元素数、case 延迟、已完成样本数或运行更快的进程加权。每 case 的跨进程估计将上面的 `suite_log[r]` 换成 `case_log[r,c]`。条件分组同样先在每个进程对组内 case 等权，再跨进程汇总。事后分组注明探索性。

这一 suite 指标是典型倍率的几何平均，不等于总执行时间减少比例。不同 shape 的原始延迟不直接拼接算 CV；同一 case 的 6×30 对也不展平为 180 个独立重复，更不能把 repeat=100 中的调用当作额外样本。

### 固定的主区间算法

首版采用 **6 个进程级 log effect 的 Student t 区间**。令 `s` 为六个 `suite_log` 的样本标准差，`SE=s/sqrt(6)`：

```text
two_sided_95_CI = exp([L - t(0.975,5)*SE, L + t(0.975,5)*SE])
one_sided_95_LCB = exp(L - t(0.95,5)*SE)
t(0.975,5) ≈ 2.570582；t(0.95,5) ≈ 2.015048
```

区间形式采用均值的 t 区间；这里把均值对象定义为进程级 log 倍率，是本协议的分析选择。[NIST 均值置信区间](https://www.itl.nist.gov/div898/handbook/eda/section3/eda352.htm)

这个算法依赖进程级效应近似独立、具有可解释的共同分布，且小样本 t 推断所需的分布近似适用。新 PID 不能证明独立：温度、频率、长时间漂移或同一机器会话可能使多个启动相关。六点也不足以可靠检验正态性。因而必须同时展示原始六点、执行时间顺序和各条件结果；存在显著阶段结构或异常时，保留区间为带假设的摘要，标注复现性未解决，不赋予“已稳定推广”的含义。

可以预声明按进程/block 重采样的敏感性分析，但不能在 t、bootstrap、删点等算法中事后挑一个通过的结果。所有进程内样本展平的 bootstrap 不满足本协议。改变顶层样本数或算法应预先版本化。

### 倍率、回退与复现性分别报告

- `S>1` 为加速。候选延迟变化为 `1/S - 1`；正值是回退。`S=1.03` 是倍率增加 3%，对应约 2.913% 的延迟降低；不要混称“延迟降低 3%”。
- 每 case 同时保存点估计与区间。倍率区间 `[l,u]` 对应延迟变化区间 `[1/u-1,1/l-1]`。低于 3% 的回退也记录。
- 报告六个进程的方向计数和最小/最大值，但不能用“六次都快”替代效应和区间。均值区间不保证未来每个进程都快；有明显反向进程时，检查时间、顺序和资源依赖，说明结论的条件敏感性。
- 全部 case 的单独 95% 区间不是“同时覆盖所有 case 的 95% 保证”。最大 case 点回退与统计保证分别报告；若未来需要所有 case 同时满足界限，应预先采用同时区间/多重比较方案，不能看完 20 例后挑选。
- 在质量控制达到相应分辨能力时，区间高于 1 可支持正向性能命题，低于 1 可支持负向命题；跨 1 表示方向尚不确定，不证明等效。接近残余校准偏差的微小效应须保留偏差限制，即便随机误差区间很窄。

## 6. 研究评价与正式 gate 的边界

新报告必须分别保存测量质量、性能效应、跨进程复现性、机制证据、已测适用范围和正式准入状态。性能收益不能单独证明机制；正式 gate 拒绝也不能抹除已经有证据的局部观察。

现有“speedup 单侧 95% LCB≥1.03、最大 case 回退≤3%”保留为正式生产准入的历史业务口径。新报告可以列出相同数值门槛下的**研究侧筛选结果**，其中 LCB 来自本协议的进程级估计、最大回退默认是 case 点估计；它不是现有 gate verdict，也不是所有 case 的同时统计保证。

当前 runtime 的旧样本接口、最小样本数及重放逻辑不能自动理解本协议。不得复制 6 个进程均值凑 30 个样本、展平 180 对、伪造 propensity，或把新分析的布尔值写成旧 gate 的“通过”。正式集成需单独设计兼容接口与验证，保持旧 v1 outcome/hash/replay 不变；在此之前明确正式准入未按新协议评估。

历史独立进程协议结果、原 gate 值和历史阻断保持冻结。新协议复测同一源码，只新增 evaluation/session 和协议引用。即使新结果支持收益，也不改写旧 exp 漂移判定，更不能把不同协议的原始样本合并。

## 7. 失败恢复与成本

执行前固定 6 次 A/B 启动和控制计划，不以区间是否通过决定再采几次。每个 session 的计划序号、实际启动、退出、已完成样本与未完成原因全部保留。

预启动编排/环境故障，在尚未产生该计划 session 的任何正式样本时，每测量阶段最多恢复一次，并写明客观故障及修复。恢复不是删除旧日志。执行中崩溃、输出校验失败、缺样本或预声明质量规则失败，不得自动替换成第七个“好进程”。保留已完成内容并标整组未完成/不合格；针对客观问题确需继续时另立新组，源码不变则仍属同一 attempt。

反向倍率、意外的大收益或未通过收益区间本身不是执行失败。只要满足事前质量规则，就保留为完整实验结果，在固定六次中评估其复现性和条件依赖；不能仅因结果不符合预期而新开一组重测。诊断性后续实验须有独立的问题、预声明设计和预算，不能替换或隐藏这组结果。

新源码修复计新候选。统计不稳定与基础设施不可执行分开记录。若质量规则或 runner 需要修复，停止候选收益比较，先做方法修复与重新资格验证；不得边看收益边调采样规则。

最低配置下，一个 A/B 比较每 case 的正式成本是：

```text
6 processes × 30 pairs × 2 roles = 360 event samples
360 samples × 100 complete calls = 36,000 timed complete calls
6 processes × 2 roles × 10 warmups = 120 warmup complete calls
```

20-case 一组为 720,000 次正式完整调用；有父本和原始 baseline 两个比较时加倍。before/reverse/after 的三个 A/A 段若各用同样配置，另需每 case 108,000 次正式控制调用。首次资格试验、额外资源控制、profile、校验和失败消耗另计。这些是计划调用数，不是性能加速或墙钟成本估计。

成本账本同时记录源码候选、构建、计时组、比较、控制段、进程启动、case、样本、完整调用、profile launch 及墙钟区间。设备 event 时间与 wrapper 墙钟差额含准备、提交、等待、验证和 I/O 等，不能把残差直接命名为“ACL 初始化耗时”。

## 8. 原始报告与证据绑定

下表定义新报告需要表达的内容，**不是现有 schema 已接受的字段声明**。实现时应提供封闭结构的版本化 JSON Schema、finite 数值校验与只读 verifier，并由 v2 adapter 关联，不向旧 schema 塞未知字段。

| 层级 | 必需内容 |
|---|---|
| 比较 manifest | 协议/分析版本及 hash、run/task/attempt、parent/original 对照身份、source/binary/patch/harness、case/input/oracle、预算/顺序/种子、硬件指纹 |
| 原生 session | 比较 ID、replicate ID、PID/启动时间、argv/cwd、host/物理 chip/逻辑映射、context/stream 身份与创建/销毁事件、模块/资源角色、case 顺序、退出和日志 |
| 样本 | case/属性、pair ID、角色、实际先后与时间、event 原始值/单位/换算、repeat、ns/call、完整算子 launch 数、输入/输出/workspace 身份、校验范围 |
| 校准 | A/A 实现身份、配置/block/条件/对比、质量规则、原样本、区间、资格作用域、缺失/不合格原因 |
| 统计报告 | 每进程每 case 的 A/B 延迟、CV、log ratio/倍率、顺序分层；6 个 suite 倍率、主区间、逐 case/分组结果、异质性/绝对漂移及假设限制 |
| 过程来源 | 实测前后判断、原始 profile、源码位置、事件引用、producer/提取版本；缺失值的具体原因 |

context/stream 的指针值仅是进程内的辅助身份，不能跨进程当作全局 ID；应与 session ID 和创建事件绑定。唯一 session、pair 和样本 ID 支持去重恢复。失败退出不能以缺一行数据的方式消失。

原样本先封存，再生成统计和短证据引用。JSONL 正文保留关键条件和结果，全部原始数组、日志和文件 hash 存索引/报告；同一证据只校验一次内容。无论输出是否合格，验证不得触发 gate 或修改已封存数据。

真正开始优化采样前，需要完成以下验收：

1. 原生集成证明 A/B 两个真实入口共享该进程/context/stream，且没有隐藏的角色子进程或错误符号绑定；相同资源准备和输出契约可审查。
2. 正确性重新验证 20/20，prepared 配对路径也验证输出；完整列表/partial/finalize、单位、repeat 和 profile 捕获范围无缺失。
3. 统计/只读验证检查覆盖缺 case、非有限/非正时长、错误单位、重复 ID、进程层级错误、异常值保留和失败恢复；用“各进程绝对值变、比值不变”及“比值变但进程内 CV 低”的数据验证判断差异。
4. 实机 A/A 完成所声明条件的资格验证，再用已知正例检查比较能力，例如 norm 粒度优化；旧倍率只能作先验，不要求新协议复现完全相同数值。
5. exp 的既有阶段漂移作为方法问题复查，检验共同变化、角色偏差与比值变化；不能预设新 runner 一定解决。
6. 冻结合格的方法 manifest 和解释范围，再开始正常的“修改—反馈—下一步”探索。若资格失败，记录明确阻断、释放设备并停在可恢复 checkpoint。
